# 本地作者工作台：实现状态与边界


## 按章节工作的新版服务界面

以下功能已随 v0.6.3 发布；下方逐轮验证记录保留其当时范围。

1. **按章组织。** 左栏可切换“按章查看／按文件查看”；章节分页包括已规划但未写的章节，同章号材料只作导航关联。相同草稿显示“与当前正式稿逐字一致”，不伪造采用记录。仅有工具计划也有只读入口，不为显示页面生成空正文。
2. **当前进度。** 顶部显示正式章数、计划数、下一章及刷新时间。记录文件、规划材料提示其内容保留编写时状态；工作台不擅自改旧报告。右栏提供本章目标、前章摘要、停笔点、约束及可展开的正式稿审查记录。
3. **写作与阅读。** 正文按章计划口径、章名计数设置核对字数，显示目标区间与选中文字数；材料单独计数。大纲支持基础 Markdown 标题、列表、表格、代码及链接预览，原始 HTML 不执行，也可切换源码。支持字号、行距、字体与专注阅读；浏览器设置按本地地址保存，更换服务端口后可能恢复默认。
4. **修改与审稿。** 对照高亮删除与新增行，超大对照改用明确标注的整块高亮。“审稿”生成绑定已保存文件和校验值的任务，并展示基础字数、占位和重复检查结果；复制后交给助手执行。它不在后台调用模型、不代表已语义审查、更不自动正式采用。
5. **全文搜索。** 搜索全书正式正文和可读 Markdown／TXT 材料的实际内容，返回片段和文件入口，按30个结果分页。单次至多检查3000份文件、约32 MiB文本，单文件不超过1 MiB；受限、读取失败或正式稿外改时明示覆盖不全。不搜索图片、数据库字段及待恢复JSON记录。
6. **多书切换。** 启动时用 `--library-book "<另一书目录>"` 登记作品，可重复指定，最多30本（含当前书）。只打开登记范围，不扫描磁盘。点击“打开作品”会在新标签页打开，原编辑保留；可确认的服务复用，未登记或已正常停止的服务可启动，不可达实例须先核对。

```bash
python3 -B -X utf8 "<核心技能目录>/scripts/story.py" workbench-serve \
  --book "<当前书目录>" --library-book "<另一书目录>" --open
```

后续稳定性修复：细纲等材料另存为候选、自动恢复或待核对记录时保留材料类型与标题，不套用正文篇幅目标或正式章节对照；旧候选可根据明确的原材料来源识别。按章目录刷新保留折叠状态与滚动位置；只有工具计划时默认打开计划。目录搜索不影响右栏同章材料，清空全文搜索会同时清空结果说明与翻页状态。

这些功能使用同一份本地运行时，不增加外部依赖。现有来源核验、候选独立保存、恢复保护与同书单实例限制保留。自动刷新正文、页面内正式采用、云同步和平台上传不在本次实现范围。

## 版本状态

当前发布版为 **v0.6.3**，包含 8 个技能、39 个载荷文件。[发布记录](releases/v0.6.3.md)区分本地验证、Windows/Linux CI、附件与 Packages 结果。本机安装不会自动更新。

工作台第一版的定位是：**把一本书已经保存的正式状态变成可核对的本地只读视图。** 它帮助作者回答“写到哪里、下一步是什么、哪些正式文件需要处理、是否已有离线发布材料”，可另开本地服务编辑候选稿，不是平台后台。

## 现在可以做什么

运行时提供快照、静态阅读和候选编辑命令：

```bash
python3 -B -X utf8 "<核心技能目录>/scripts/story.py" workbench-snapshot --book "<书目录绝对路径>" --limit 10
python3 -B -X utf8 "<核心技能目录>/scripts/story.py" workbench-export --book "<书目录绝对路径>" --limit 10 --open
```

`workbench-snapshot` 返回 `story.workbench.v1` JSON 快照。它使用只读 SQLite 连接，在同一次捕获中核对核心状态、本地发布记录和已登记文件，给出：

- 书名、长篇／短篇／分析类型和核心 revision；
- 已正式保存章节数、下一章和下一章是否已有工具计划；
- 最近正式章节的章号、实际相对路径和摘要；
- 正式导出文件是否待同步或被外部修改；
- 到期卡片数量、世界状态数量、历史分支和分析来源摘要；
- 本地发布准备清单与导出回执数量，以及对应 ZIP 是否存在、字节数是否匹配的摘要；
- 草稿、候选稿、可读大纲、封面等未登记产物的明确缺口；
- 基于核心状态、发布记录和文件清单生成的复合快照标识。

`workbench-export` 从同一快照生成自包含 HTML。默认路径是：

```text
<书根>/.story/workbench/index.html
```

也可用 `--output` 指定 `.story/workbench/` 内的其他 `.html` 文件；工具拒绝写到该目录之外。页面没有远程脚本、网络请求、表单提交或平台登录，默认提供三栏正文阅读与章节摘要；`--overview-only` 提供书名、进度、章节链接和本地问题概览。

`--open` 只是导出成功后调用系统默认浏览器。回执分别记录：

```text
path / sha256 / bytes / snapshot_id
open_requested / opened / open_error
git_ignore_status / backup
```

浏览器未配置、系统拒绝打开或调用报错时，已经生成的 HTML 仍保留；`opened` 为 false，`open_error` 保存原因。页面生成成功与浏览器成功打开是两个结论，不能互相代替。

## 当前页面覆盖范围

当前静态 HTML 提供**总览和本次获取的一页章节**，可选嵌入这页的正式正文。默认取最近 10 章，`--limit` 可设 1 至 100。JSON 快照在 `chapters.next_cursor` 返回下一页游标；继续读取时使用：

```bash
python3 -B -X utf8 "<核心技能目录>/scripts/story.py" workbench-snapshot \
  --book "<书目录绝对路径>" --limit 10 --cursor "<上一页游标>"
```

游标绑定复合快照；书库、发布记录或受管文件变化后，旧游标会以 `stale_snapshot` 被拒绝，必须从第一页刷新。不能把不同时间取得的页面拼成同一状态。

其他区域目前只有摘要：

| 区域 | 当前提供 | 当前未提供 |
|---|---|---|
| 卡片 | 分类／状态计数、到期总数和少量到期项 | 全量列表、卡片详情、独立游标 |
| 世界 | 各类结构化记录数量 | 某章视角下的完整世界状态、独立游标 |
| 历史 | 分支状态计数、最近分支、快照总数 | 完整分支检查与决定记录、独立游标 |
| 分析 | 来源总数、待分析来源数、最近来源 | 全部来源与 findings、独立游标 |
| 发布 | 本地清单和导出回执数量、ZIP 存在／大小状态及最近摘要 | 完整清单、完整回执、ZIP 逐字节哈希核验、来源重新核验、独立游标 |

因此，工作台不能替代 `context`、`recall`、`history-inspect`、`findings`、`publish-list`、`publish-export-list` 或 `publish-verify-export`。页面列出的只是本地导出回执；ZIP 缺失或字节数不符会进入必须处理项，但工作台不做逐字节哈希核验。回执存在也不表示当前正文仍匹配，更不表示七猫、番茄后台已保存、审核或上线。

## 为什么使用复合快照

一本书的可见状态不只来自 `.story/state.sqlite3`。发布准备使用独立 `.story/publishing.sqlite3`，正式正文、短篇全文、分析报告和材料 ZIP 又在文件系统中。如果只记录核心 revision，页面可能把已经外改的正文或后来生成的发布包误当作旧快照的一部分。

工作台的快照标识同时绑定：

1. 核心书库 revision；
2. 核心状态摘要指纹；
3. 本地发布记录指纹；
4. 已登记正式文件和本地发布材料文件的清单摘要。

捕获期间若数据库或文件反复变化，工具最多重试有限次数，仍不稳定则返回 `workbench_changed`，不输出看似一致的混合结果。该机制证明的是“这一页来自同一组本地状态”，不能证明文学判断正确或作品质量达标。

## 草稿、大纲和封面为什么显示未登记

当前书库能可靠识别正式章节、受保护导出、分析报告和离线发布材料，但普通文件夹里的下列产物没有统一的权威登记表：

- `.story/drafts/` 里的多个草稿；
- 候选稿和历史候选；
- `01_大纲细纲/` 的可读总纲、卷纲和章细纲；
- 封面图片及其他作者自定义产物。

文件名、目录名和修改时间都不足以证明“哪份已采用、哪份最新、哪份可交付”。因此 v1 的 `artifacts.registry_exists` 为 false，完整性字段使用 `unregistered`，页面明确提示未登记。它不会扫描出一份看起来最新的文件后自行宣布为当前稿。

后续若增加作者产物登记，应作为独立、显式写操作：记录产物类型、相对路径、摘要、采用状态和来源 revision。只读快照和 HTML 导出仍不应自动登记文件。

## 只读边界

“只读”是指工作台不改变作品权威状态：

- 核心数据库使用只读连接并启用 query-only；
- 不写正文、章计划、卡片、事件、世界状态、历史分支或分析记录；
- 不写发布准备账本，不新建清单或材料包；
- 不调用平台，不上传、不提交审核、不排期；
- 默认三栏阅读仅嵌入本页已核对的正式正文；`--overview-only` 只显示摘要与链接，不修改原稿；
- 不展示平台账号或作品标识。

`workbench-export` 唯一的持久写入是派生页面本身，以及替换旧页面时 `.story/workbench/.backups/` 下的页面备份。它使用现有安全写入能力，输出失败时不应留下半页，也不把失败页面登记成作品状态。

## Git 忽略要求

工作台页面可能包含书名、章节摘要、文件路径和本地进度，属于可重建的私有派生产物。书根如果处于 Git 仓库内，导出前必须满足两项：

1. 整个 `.story/workbench/`，包括 `.backups/`，都被当前仓库忽略；
2. 该目录下没有已经被 Git 跟踪的文件。

推荐规则：

```gitignore
**/.story/workbench/
```

也可以只在该书库的 `.git/info/exclude` 添加 `.story/workbench/`，避免修改共享忽略文件。只忽略 `.story/workbench/index.html` 不够，因为备份仍可能进入版本控制。若目录已经被跟踪，先人工核对并停止跟踪，再重新导出；工作台不会自动改 Git 索引。明确不属于 Git 仓库的书根回执为 `not_a_repository`；只要发现仓库标记但无法运行 Git、命令超时或无法确认忽略状态，就以 `workbench_git_check_failed` 停止导出，不在未知状态下写页面。

本仓库根 `.gitignore` 已加入 `**/.story/workbench/`。这条仓库规则不会自动出现在作者的其他书库中。

## 路径和浏览器安全

输出路径必须留在目标书的 `.story/workbench/` 中并以 `.html` 结尾。路径解析、父目录和目标文件都要经过现有绑定路径防护；越界、链接父目录、重解析点风险或并发替换应被拒绝。页面中的书名、摘要和路径在写入 HTML 前转义，并使用限制性 Content Security Policy，避免作品文本被解释为脚本。

Python 官方说明 `http.server` 只提供基础安全检查，并且会跟随符号链接，因此 v1 没有启动通用本地 Web 服务器，而是直接生成 `file://` 可打开的静态页。[Python `http.server` 文档](https://docs.python.org/3/library/http.server.html)

Python 的 `Path.is_junction()` 从 3.12 才加入，而项目最低支持 Python 3.10。候选实现继续复用现有目录绑定和 Windows 重解析点防护，不能只依赖该新方法。[Python `pathlib` 文档](https://docs.python.org/3/library/pathlib.html)

Windows Python 3.10/3.12 的自动检查结果见发布记录。本轮尚未在真实 Windows 桌面浏览器中人工打开页面，因此不能把 CI 或 macOS 本机打开结果写成 Windows 浏览器已验证。

## 常见失败怎样处理

| 回执或错误 | 含义 | 处理方式 |
|---|---|---|
| `book_missing` | 目标不是已初始化书根 | 核对 `--book`，不要在父目录重新初始化覆盖旧书 |
| `stale_snapshot` | 使用游标后作品状态已变化 | 丢弃旧分页，从第一页重新获取 |
| `workbench_changed` | 捕获期间状态或文件持续变化 | 等待写作／导出进程结束后重试 |
| `workbench_not_ignored` | Git 仓库未完整忽略工作台目录 | 忽略整个 `.story/workbench/` 及备份后重试 |
| `workbench_tracked_output` | 工作台文件已经被 Git 跟踪 | 人工核对并停止跟踪，不让工具改索引 |
| `workbench_git_check_failed` | 已发现 Git 仓库，但无法可靠核对跟踪或忽略状态 | 修复 Git 命令、仓库所有权或权限后重试，不绕过检查 |
| `path_escape` | 输出离开书根或工作台目录 | 改用 `.story/workbench/*.html` |
| `opened: false` | 页面已生成，但系统浏览器没有打开 | 按回执的 `path` 手动打开，并查看 `open_error` |

工作台报出正式文件外改或待同步时，不在页面中直接修复。按[恢复指南](recovery.md)使用 `status`、`reconcile`、`export --safe-only` 或相应历史流程；完成后重新生成快照。

4. **保持候选编辑边界。** 已提供受限保存命令、CSRF／来源校验、并发基线；采用仍走现有审查闭环，不能让浏览器直接改数据库或正式正文。有关写操作风险可参考 [OWASP CSRF 指南](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。
5. **补真实平台与系统验证。** 分别记录 Windows 真实浏览器、不同文件系统和候选分发的实际结果，不把自动测试扩大为人工验证。

v1 的完成标准不是“像在线写作平台一样功能齐全”，而是作者看到的每项状态都能追溯到当前书库或文件，页面刷新不会改稿，缺失信息如实显示，打开失败与导出成功分别报告。

## 页面内阅读

v0.6.2 导出默认使用三栏阅读；`--include-text` 保留兼容，`--overview-only` 可生成仅摘要页面。

```bash
python3 -B -X utf8 "<核心技能目录>/scripts/story.py" workbench-export --book "<书目录绝对路径>" --include-text --open
```

阅读区采用三栏布局：左侧按实际父目录分组的章节目录，中间一次显示一章正文，右侧显示所选章节摘要及原稿入口。切换章节保留本次页面会话中的阅读位置；右栏可以收起，进度信息放入作品概览。小屏幕默认隐藏右栏。页面脚本仅负责本地切换，由内容哈希限定执行，不访问网络。正文作为纯文本转义，不执行其中的 HTML。默认嵌入本页核对后的正文，`--overview-only` 才仅导出摘要；JSON 快照不包含正文。每章最多 1 MiB，本页正文合计最多 8 MiB。缺失、无法解码或与登记哈希不同的正文会阻止阅读页导出；原稿更新后须重新导出。页面及备份此时包含正文副本，应按私有书稿保管。

静态阅读页不包含多书切换或编辑保存，也不自动纳入未登记的大纲和草稿；候选编辑须另开下述本地服务。默认仅最近 10 章，数量受 `--limit` 控制，不代表全书阅读器。

三栏阅读支持按章名或编号搜索本页目录，上一章／下一章按本页原有顺序切换，首尾按钮禁用。搜索不会改变正文顺序或自动换章；目录无结果有明确提示。作品概览与章节共用阅读位置恢复逻辑。窄屏不显示右栏开关，避免出现点击无效的控件。

三栏作品概览保留交付准备及正式文件同步摘要，目录注明已载入数量、全书登记数量和章号范围。指向未载入章节的地址会显示提示并转到概览，不会静默显示另一章。禁用脚本时提示直接阅读章节原稿。

## 本地候选编辑（v0.6.2）

运行 `workbench-serve --book "<书目录绝对路径>" --limit 100 --open` 启动本机 HTTP 页面。原有 `file://` 页面仍是只读快照，编辑需打开服务输出的新地址；关闭服务进程即可停止。

中间栏的“编辑本章／阅读预览”切换不会丢失本次编辑。“保存候选稿”在 `.story/drafts/workbench/` 创建独立 Markdown 文件，文件名含原稿基线 SHA-256；每次保存生成新文件，原正式稿和书库状态不变。确认保存的路径后，按既有审稿、历史修订或提交流程采用。当前不自动恢复先前候选，刷新页面会重新载入正式稿。

服务仅监听 127.0.0.1 随机端口，保存校验 Host、Origin、随机会话令牌、章节范围、请求长度、基线状态和原稿哈希。没有通用文件读取接口，不提供正式提交操作。每章候选最多 1 MiB；冲突时保留当前页面文字供复制，重新打开工作台核对后再编辑。未保存内容关闭页面前会触发浏览器离开提示，该提示不替代实际保存。


## 候选与材料编辑补全（仓库开发更新，尚未发布）

`workbench-serve` 的三栏界面可列出候选、草稿、拆书分析和创作材料，文本可阅读并另存候选，PNG/JPEG/WebP 可预览。目录按原文件夹折叠；正式章节分页，搜索覆盖全部正式章名和已发现材料路径。扫描范围为 `.story/drafts/`、`.story/analysis/`、书根文本与图片，以及编号或名称包含大纲、细纲、封面、策划、分析的顶层目录；不遍历全部隐藏文件。

保存新建候选和来源记录。重开候选可继续修改；正式稿对照为并排全文，不是逐行差异标注。没有来源记录的旧稿明确显示关系未登记，章号只用于建议对照。编辑器不执行正式采用。

停止输入后写入本书自动恢复文件，左栏可重新打开；恢复不依赖浏览器端口或缓存。关闭前仍应保存候选或下载，因为尚未完成的恢复请求不能保证文字落盘。来源或正式状态变化时保存被拒绝，编辑器保留文字供恢复和对照。刷新目录与状态会重新读取书库；有未保存编辑时先提示处理。

静态导出保持原有只读能力，不因升级技能自动更新。结构化卡片、世界状态、历史修订与发布明细仍需原命令，工作台不执行平台发布。

本轮本机验证：工作台专项 45 项通过；全量回归 751 项，17 项跳过，其余通过。隔离测试书完成浏览器编辑、自动恢复落盘、保存候选、刷新重开及正式稿对照；真实书库只读取展示，未作为写入测试对象。尚未执行本轮 Windows CI 或发布。

后续交互修复：刷新目录保留展开状态及滚动位置；快速切换只展示最后选中的文件；同一文档自动恢复串行执行，未变化内容不重复写入。本轮工作台 46 项测试通过，含请求乱序与恢复顺序验证；本轮未重复全量回归。

补充修复：重复打开同一文件不再覆盖已有编辑缓存；恢复稿保存来源、章名及基线，连续写入使用独立备份目录；每次对照重新读取正式稿；“保留恢复稿并重新载入”仅在全部待保存文字恢复成功后重新读取来源，恢复失败或期间又有输入则保留编辑。本轮专项 47 项通过，未重复全量回归。

重新载入的后续保护：先读取来源成功，再替换编辑缓存；读取失败、期间新增输入或切换文件均保留原编辑。保存与重新载入互斥，过期打开请求不再写入缓存。本轮工作台 48 项通过，包含读取失败、期间输入、成功替换及保存阻断检查；未重复全量回归或浏览器实测。

恢复稿外部冲突与目录容错：自动恢复核对上次内容校验值；检测到外部修改则另存恢复稿并保留外部文件。旧恢复稿无校验记录时同样另存。创作目录中的符号链接或目录链接跳过并在目录区提示，打开文件仍执行原路径检查。本轮 50 项工作台测试通过；全量及 Windows 回归未重复执行。

多文件编辑提示：左栏顶部集中列出所有待保存文件，不受当前搜索或章节页影响；标明当前文字是否已写入恢复稿，点击可返回编辑。页头界面标识独立于服务令牌，用于辨认界面更新，不代表发布版本。本轮 52 项工作台测试通过，隔离测试书验证搜索无结果时待保存入口保留、恢复状态更新和重新载入后清空列表。未重复全量或 Windows 回归。

重新载入前的恢复核验：每份待保存编辑都重新执行恢复保存并读回核对，不能只信任页面缓存；失败清除旧的恢复成功标记并保留编辑。目录扫描按文件或子目录捕获读取错误，跳过并列明路径，正常章节和材料仍可用。本轮 54 项专项测试通过；浏览器在隔离测试书中验证删除恢复文件后重新载入会重建文件，实际文件逐字匹配原编辑。

本次累计修复后全量回归：760 项，743 项通过、17 项按平台或环境条件跳过；本机运行，未执行新的 Windows CI。

大小与保存失败处理：完整候选文件含恢复章名上限为 1 MiB，超限在写入前拒绝，恰好上限可重新打开。来源记录写入异常时将不完整正文移入暂存备份；若更新已有恢复稿则还原旧正文。回退失败明确返回残留文件、暂存路径与失败原因，页面显示路径，避免笼统提示后重复保存。本轮 58 项工作台测试通过，覆盖完整文件边界、来源写入失败、恢复稿还原及回退失败报告；未重复全量或 Windows 回归。此阶段尚无进程中断恢复记录，后续补全见下文。

来源记录与章号校验：来源文件不存在时保留旧稿兼容；无法读取、JSON 损坏或字段无效时明确提示原因和记录路径，候选正文只读展示，禁止以缺失来源继续另存。章号在正式文件入口、候选记录及恢复入口校验为 SQLite 可表示的正整数，不允许布尔值、字符串或超大整数。本轮 60 项工作台测试通过，覆盖损坏记录、非对象记录、空前缀、非法章号、只读保护、缺失记录兼容与原文保留；未重复全量或 Windows 回归。


来源与中断保存补全：打开候选时记录来源文件的实际校验值，保存时一并核对正文、来源记录和正式状态；新增、删除或改变来源记录均会阻止旧页面保存。旧版“基线／修订”文件名仅在首行与对应正式章名完全一致时隐藏章名，BOM、原换行和章名仍逐字保存在文件前缀中。

每次保存先落盘单个完整待核对记录，再写入正文和来源文件；两者写完后才移走记录。进程被强制关闭后，目录自动发现遗留记录，归入“自动恢复”，无需依赖旧进程或浏览器缓存。打开后可直接点击“恢复为新候选”，不必先改字；原文件不被覆盖，遗留记录保留供核对。存在待核对记录的原目标文件只读，后续自动保存不得覆盖它。可捕获错误仍尝试回退；回退失败保留待核对入口。兼容保存接口也使用同一路径。

这提供已落盘编辑的找回与不完整保存识别，不是两文件原子事务；请求尚未写入完整记录时的文字、磁盘损坏或断电持久性不作保证。并发中的短暂待核对记录也可能出现在其他工作台，勿据此认定已经崩溃。

本轮验证：66 项工作台测试通过，包含独立进程在正文写入前、来源记录写入前及写完后强制退出，再由新工作台读取恢复记录；同时覆盖恢复稿旧备份、外部修改保护、来源新增／删除／改动冲突、旧文件名与 BOM 前缀逐字保留。全量 772 项，755 项通过、17 项按平台或环境条件跳过；随后兼容入口的未改字另存行为专项通过。隔离测试书浏览器实测“恢复为新候选”和来源冲突后文字保留，并检查实际文件。已备份并更新本机脚本，真实书稿仅重新打开展示；未执行本轮 Windows CI 或 GitHub 发布。


自动恢复与服务管理补全：恢复请求带回上次正文和来源文件两份校验值，只有两者一致才覆盖原恢复稿；旧请求没有完整回执、来源被修改或删除、来源损坏、存在待核对记录，均生成新恢复文件并把新标识与回执交还页面。待核对记录在读取正文前检查，正文尚未创建的中断也不会卡住后续输入。来源写入继续使用操作开始时读取的校验值，不接受写正文期间出现的外部改动。

新增 `workbench-status --book "<书目录>"` 和 `workbench-stop --book "<书目录>" --saved`。新工作台持有独立的系统文件锁，同书重复启动会被拦截，不阻塞小说状态库的其他操作；进程退出后锁由系统释放，不凭 PID 或删除锁文件处理。状态通过回环接口核对实例身份，可显示运行地址及代码是否过期。停止命令要求先保留所有页面的编辑，服务确认实例后正常结束；未保存页面不会被命令自动读取或代存。正常退出登记停止状态，不可达则明确表示无法确认。旧版没有注册机制的进程不在新命令的识别范围内，首次迁移须核对现有页面并单独退出，不猜测或批量结束其他 Python 进程。
