# 全仓审查与优化：本地 v0.4.0

本页保留 v0.4.0 发布前的审查、试用和测量记录；下文“本轮”“当前”和尚未完成项均指该历史阶段。当前 v0.5.5 的实现与发布状态见 [版本说明](releases/v0.5.5.md) 和 [发布验证](github-release.md)。

本页保留 2026-09-10 发布前的审查快照；文中的“本地”“尚未发布”和验证边界描述该次检查时点。后续版本发布、远端 CI 与 Packages 同步状态见 [安装与发布](github-release.md)，不回写原始试用和测量回执。

本轮覆盖七个技能入口及其参考、五个运行时模块、项目安装与升级、ZIP/npm 分发、GitHub 工作流、中文小说试写，以及测试和测量证据。按具体触发条件复现问题后修复；未改动真实小说、全局安装或已发布版本。这里只说明本轮覆盖和证据，不能理解为已证明不存在其他缺陷。

## 修复的问题

| 范围 | 修复前的触发与影响 | 修复后的行为 |
|---|---|---|
| 召回完整性 | 底层搜索已完成，但字节预算丢掉结果后，仍可能报告 `complete: true` | 标记预算裁剪和不完整，保留遗漏数；不能误判没有相关事实 |
| 并发复合读取 | 搜索命中与卡片正文、世界记录与哈希、缓存值与依赖声明可能分别读到不同版本 | 三处复合读取使用同一数据库快照，保留调用者已有事务 |
| 历史依赖 | 历史依赖补录或修订候选漏掉必读卡，仍能声明检查完整 | 依赖补录、候选暂存及最终发布均核对对应计划的 `requires` |
| 资源时间 | 按章计划起点余额检查所有行动，会提前使用未来收入，或漏算场景中途收入；未给计划时间时还可能漏掉透支 | 以每次行动的故事时间合并已发生流水与待写行动，连续扣减；未知时间和数量保持不确定性 |
| 伏笔证据 | 旧伏笔的正文版本已失效，新兑现记录可能遮住旧证据问题 | 新兑现前核对前序记录的当前正文证据，不把失效铺垫当有效事实 |
| 文本和整数输入 | NUL 导入使 SQLite 文本位置截断；超大整数可变成底层异常 | 新导入/基线文本的 NUL 提前拒绝；超出 SQLite 整数范围返回结构化错误 |
| 普通连载路径 | 跨章重复、旧办法后果和阶段成果指导仅在有条件加载的超长篇文件中 | 移到普通章节流程，保留支线的专用定位；合并重复写法以控制指令成本 |
| 输入说明 | 实际作者试用误填卡片类别、遗漏增量引用字段，产生额外工具往返 | 项目状态指导明确六种 `kind` 与每项 `changes.quote`，不让 `source` 代替正文引文 |
| 发布归属 | Git remote 与 API 已是 `NingCui29/story-skill`，工作流和 npm 包仍绑定旧账号 | 新版作用域、仓库元数据、下载查询、工作流和安装链接使用当前归属；旧包身份单独保留 |
| 干净检出的测试 | 迁移单测依赖被 Git 忽略的 `dist/` ZIP | 29 KB 历史 ZIP 成为带 SHA-256 的仓库夹具；补充 Linux/Windows CI 配置 |
| 跨平台审稿夹具 | Windows 检出将已审稿样文从 LF 变为 CRLF，导致原始审稿 SHA 不匹配 | 示例 Markdown 与文本固定 LF 检出，不重算旧审稿哈希来绕过检查 |
| 验收脚本的依赖录入 | 多线演练在声称历史复核完整时遗漏计划必读卡，被加强后的运行时拒绝 | 演练按实际读取的卡片记录依赖；CI 加入中文实稿和多线历史修订演练 |

主要实现见 [核心运行时](../skills/story-skill/scripts/story.py)、[历史修订](../skills/story-skill/scripts/story_history.py)、[世界状态](../skills/story-skill/scripts/story_world.py)、[章节流程](../skills/story-skill-write/references/chapter.md) 和 [分发说明](github-release.md)。`story_storage.py`、`story_search.py` 及现有安装恢复路径也已审读；未发现可复现的问题就未做风格性改写。

新增的核心与世界/历史专项回归分别有 7 项、8 项，涉及实际预算裁剪、WAL 双连接并发、事务保留、输入拒绝、依赖遗漏、现金流顺序及陈旧伏笔；打包测试另验证新版归属、旧包装字节和旧作用域禁止重发。历史迁移夹具来源和 SHA 见 [夹具说明](../tests/fixtures/README.md)。

## 中文连续章节试用

《空船照夜》使用冻结的修改前技能，实际初始化、规划、逐章自审、提交并导出前三章：2,357 / 2,418 / 2,254 字，共 7,029 字。作者自审时发现日期冲突，通过最新章替换流程修订第二章；两次 CLI 字段错误和一次补丁匹配失败均保留原始回执。字数是含标点、不计 H1 的非空白可见字符。

独立评阅只读取题目和正文，不读取技能、作者计划与自审。前三章未发现确定的硬矛盾，主要谜面闭合，关系与代价能延续；仍记录了验记时间歧义、渡工会合表达和收费印结算的后续承接，未把建议或未完债务冒充矛盾，也未为改善评价回写原始样稿。

另一个新会话在书库副本上使用最终技能，完成第4章《验到哪一步》2,268 字：实际规划、自审、提交和导出成功，修订号推进到 11；前三章哈希不变，四章导出核验通过。原始三章绑定修改前的指令和运行时哈希，不能把新代码的通过结果追认给旧稿。[完整试用与评阅](../benchmarks/results/v0.4.0/serial/manifest.json)

第4章独立评阅也未发现确定矛盾：收费印仍被抵押，限运与工钱不足继续约束人物，有限复航和收入分配带来推进。评阅保留了“临行”的措辞歧义及章末反复强调查验原则的阅读建议；后者是节奏偏好，不要求强行加新危机。[前三章评阅](../benchmarks/results/v0.4.0/serial/review.md) · [第4章评阅](../benchmarks/results/v0.4.0/serial/followup/review.md)

这些是单一架空悬疑故事的小样本，未与另一个版本进行三章同题对照，供应商使用量仍为 `null`；它不证明文学质量整体提高，也不证明百万／千万字真实连载稳定。首轮两题四稿的混合结果继续保留，见 [首轮场景对照](中文冲突与看点.md)。

## 指令成本

在新增跨章入口与字段说明后，普通冷加载从本轮开始的 **4,537 降至 4,509 tokens**，多线流程从 **6,300 降至 6,149**。七个技能的发现元数据仍为 308 tokens。相对最初较短的本地流程，创作指导有额外成本；静态 tokenizer 不包含正文、推理、工具返回和修改次数，不能当作实际账户账单。[v0.4.0 逐文件基准](../benchmarks/results/v0.4.0/tokens.md)

## 验证与交付边界

首次干净检出中 311 项单测全部通过，但中文实稿重放暴露了换行转换问题，多线演练暴露了依赖补录遗漏。两项均按真实失败修复，未关闭原来的哈希或完整性检查；[首次失败回执](../benchmarks/results/v0.4.0/audit/clean-first-failure.json) 与 [首次检出信息](../benchmarks/results/v0.4.0/audit/clean-first-checkout.json) 保留供复核。

修复后再次从 Git 暂存树导出到新的空目录，独立构建 ZIP，并通过 **311 项单测（零跳过）与 12 项整包检查**。检出初始不含本机 dist、虚拟环境或已安装技能；检查覆盖真实临时安装、7 个技能校验、中文实稿重放、77 次 CLI 的多线历史修订演练、分发载荷和报告哈希。容量和三本旧书副本迁移已经另行重跑，verify 再核对其成功结果与当前运行时绑定。[最终干净检出](../benchmarks/results/v0.4.0/audit/clean-checkout.json) · [项目安装核对](../benchmarks/results/v0.4.0/audit/project-install.json) · [整包回执](../benchmarks/results/v0.4.0/verification.json) · [容量复验](../benchmarks/results/v0.4.0/scaling.json) · [旧书副本迁移](../benchmarks/results/v0.4.0/migration.json) · [v0.3→v0.4 升级](../benchmarks/results/v0.4.0/upgrade.json)

当前本地套件与分发包已更新，v0.4.0 尚未提交发布。新增 CI 的远端运行、当前新作用域的 Packages 发布和下载权限、跨数百章的创作质量，以及真实账户成本均未由本轮本地检查证明。已含 NUL 的旧数据库未自动清洗；未知事实、时间、数量与作者声明的依赖完整性仍需要语义复核。

仓库当前归属和稳定 v0.3.0 Release 已只读核对；旧 v0.3.0 的 `--prepare-only` 已实际下载、重建并运行临时 CLI，旧 npm 包装文件保持原哈希。[旧版准备回执](../benchmarks/results/v0.4.0/audit/package-legacy.json)
