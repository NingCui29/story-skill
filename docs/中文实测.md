# v0.2.0 中文小说实测

本页保留 v0.2.0 的原始稿件与恢复经过。2026-09-10 的本地 v0.4.0 已通过这些固定稿件的 CLI 重放；另外完成的新三章与第4章续写见 [全仓审查与优化](全仓审查与优化.md)。重放旧稿与新会话实际创作是两种不同证据。

本次在真实 助手 任务中创作与审查中文稿件，再用实际 CLI 子进程完成保存和恢复。样稿、各轮修订、可继续打开的书库以及 JSON 回执都已落盘；不是把几百字的合成夹具当成真实小说验收。

## 审稿与状态验证

长篇由一个代理创作，另一名未参与写作的代理连读三章并复核主代理的两轮修订。短篇由主代理创作，另一名代理独立审查；修正了衣物数量、第一条裤子的完工交接和取衣信息送达。两份具体观察见 [长篇审稿记录](../examples/渡口夜账/审稿记录.md) 与 [短篇审稿记录](../examples/留半寸/审稿记录.md)。

每次提交前读取受预算约束的计划与状态，用 prepare 绑定稿件、书籍与版本，再填实际观察、精确引文和状态变化。五次长篇提交包含第三章两轮替换；每轮都重申相对章前基线的完整增量，核对人物已知信息、泵的去向、纸张保管和已兑现承诺没有丢失。所有提交还进行了原命令幂等重试。

第三章最终修订额外模拟“第1章文件缺失，同时第3章被外部改稿”：普通导出与直接对账均被拒绝，safe-only 恢复第1章且保留外稿，随后审查并对账最新章。最终全书无待导出或外改冲突，长篇 revision 为10，下一章编号为4，但本次示例未授权自动续写第四章。

## 真实环境发现的问题

本项目 D 盘为 exFAT。第一次真实稿件提交后，旧硬链接发布方案返回 WinError 1；SQLite 中第1章已经保存，版本为5。这一问题在 C 盘 NTFS 临时目录的早期测试中没有出现。

Windows 发布改为同目录完整暂存后拒覆盖重命名，失败恢复保留备份。随后使用原书 ID `84608a48-85a3-49e2-8560-bebb6797a209` 和原审查 delta 幂等重试，成功导出，再从同一状态推进余下章节与修订。两本书和拆文工程的保留目录均在本项目 D 盘上。

## 复现与范围

[机器回执](../benchmarks/results/chinese.json) 记录稿件 SHA、口径、实际上下文字节数、版本、命令结果和最终状态。[实测工程长篇回执](../examples/实测工程-v0.2.0/渡口夜账/验收回执.json) 可以与正文和数据库一并复核。

```powershell
python -B -X utf8 scripts/chinese_acceptance.py --workdir "D:\临时\新的空目录"
```

这是对固定、已审稿件的程序重放，不会再次调用模型创作。输入正文哈希变化会拒绝复用旧审稿记录；已有非空目录默认拒绝覆盖。验收脚本不安装到作者书内，技能包只包含写作流程与运行时。

此次覆盖现实悬疑三章和现实关系完整短篇，证明这些样稿可以完成当前流程。尚未证明百万字连载稳定性、所有中文题材的效果、同题盲评胜过上游或实际账户总 token 更低。静态指令基准保持独立口径，不用缩短正文或减少审稿来替代用量证据。
