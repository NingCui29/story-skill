# WPD-20261106-05：Windows 只读检查在浏览器断线后继续等待

记录日期：2026-11-06。范围：Windows 工作台第 86—135 章的只读差异检查；未授权或执行平台草稿写入。本记录只保存脱敏事实与查询编号，不保存正文、账号、凭据或浏览器会话数据。

## 现象、证据与根因边界

- 工作台窗口响应正常，书架服务返回 HTTP 200（本次约 50 毫秒）。界面长时间显示第 86 章、0/50；因此不能将本次故障归为整个程序无响应。
- 任务编号 `c421e94aa04b462b82f370291717b90f`，执行诊断编号 `78200a8600344d0594571cafae8bd692`。已通过任务与执行配置核对归属，未仅凭时间接近建立关联。
- 任务 19:30:35 创建、19:47:02 结束（Asia/Shanghai），总计约 16 分 27 秒。最终为 `inspection_blocked`，错误 `platform_chrome_worker_cleanup_unconfirmed`。50 章中只形成第 86 章的一条阻断结果，成功核对 0 章；该行原因为 `platform_chrome_request_timeout`。没有 create/update 结果。
- 执行诊断从约 19:30:37 开始：+76.214 秒桥接就绪；+96.163 秒进入 `queue_operation`；+138.598 秒出现 `platform_chrome_worker_health_expired`；+410.661 秒记录 `platform_chrome_worker_turn_failed` / `responseStreamDisconnected`；随后回合为 `interrupted`、收尾为 `cleanup_unconfirmed`，+411.017 秒记为 `closed`。
- **确认的等待缺陷**：`HostAdapter._request` 派发后只等待响应并核验本地 lease，没有检查本任务所属控制器已经失败。只读操作可有 900 秒预算，已认领请求的 lease 又可延续至其期限后 30 秒。因此浏览器执行已失败/关闭，任务仍继续等到队列超时。
- **确认的诊断缺陷**：任务连接诊断主要在启动时更新；收尾未确认可先抛错，遮住后来的响应流断开信息。任务顶层错误和逐章错误不能单独呈现完整链条。
- **仍未知**：真实浏览器健康过期和响应流中断的上游原因。现有记录不证明网络、插件更新或宿主授权中的哪一项导致本次故障；`closed` 也不等于执行端已确认正常退出。用户截图中的 ChatGPT Chrome 侧栏加载失败是另一项观测，尚不能证明与本任务同因。

### WPD-20261106-06：安装后启动遇到本地端口冲突

- **症状与范围**：首次重新打开窗口短暂出现后退出；书架状态查询返回 `workbench_service_mismatch`。这是安装后新观察到的启动问题，不能与 WPD-20261106-05 的浏览器响应流断开归为同一根因。
