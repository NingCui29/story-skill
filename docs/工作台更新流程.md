# 工作台更新流程

本说明对应已发布的 Mac 0.1.19、Windows 0.1.10，当前构建与验收范围见 [v0.6.20 发布记录](releases/v0.6.20.md)；上一正式版为 [v0.6.19](releases/v0.6.19.md)。正式下载附件与候选构建分开；检查更新查询 GitHub 最新正式 Release，不将 Actions 候选或 Story Skill 运行时版本当成客户端新版。

## 入口与状态

Mac：顶部应用菜单“写作工作台 → 检查更新…”。Windows：应用工具栏“检查更新”。

| 阶段 | 可见反馈 | 可执行操作 |
|---|---|---|
| 检查中 | 正在检查；网络错误、超时和限流分别说明 | 等待结果，失败后重试 |
| 发现新版 | 当前版本、目标版本 | 开始下载，或稍后处理 |
| 下载中 | 真实接收字节、百分比、总大小、速度和预计剩余时间 | 取消；当前编辑页继续保留 |
| 校验中 | 正在校验 SHA256；校验失败有明确原因 | 等待，失败后重新下载 |
| 下载已校验 | 安装包已准备好 | 打开安装包或所在目录 |
| 等待安装与重启 | 明确提示系统安装步骤 | 保存各处编辑，完成安装后重新打开客户端 |

速度和预计剩余时间根据实际已接收字节估算，网络变化会使估计波动。校验与系统安装阶段不伪造百分比。取消或下载失败后，不完整文件不得作为可安装文件使用；重试重新下载并完整校验。

## 校验与下载来源

下载起点只能是官方仓库的对应 Release 附件，重定向仅允许 GitHub 的 HTTPS 下载域名。客户端核对对应附件名称、平台架构、版本、大小和 SHA256。优先使用 GitHub 返回的 `sha256:` 摘要，缺少时使用同一发布中与安装包同名的 `.sha256` 文件；没有可核对的摘要则不开始安装。

SHA256 证明下载内容与官方发布的摘要一致，不等于 Apple 公证或 Windows 代码签名。当前客户端分别使用 Mac 本地临时签名和 Windows 未签名安装包。

Release 附件元数据依据 [GitHub 官方说明](https://docs.github.com/en/rest/releases/assets)。进度使用 [Apple 网络数据委托](https://developer.apple.com/documentation/foundation/urlsessiondatadelegate)及 [Qt 后台任务与进度窗口](https://doc.qt.io/qtforpython-6.8/PySide6/QtWidgets/QProgressDialog.html)提供的实际传输反馈。

## 安装与稿件保留

Mac 校验后打开 DMG 或 ZIP。先保存所有客户端窗口及外部浏览器里的文字，退出客户端，再将新应用放入原安装位置；保留旧应用以便回退。不要将旧进程仍在运行误认为已载入新版。

Windows 安装包校验后可启动向导，客户端会先核对所有标签的编辑状态。安装器不自动关闭应用或后台服务；先保存并正常退出客户端，再按向导安装。便携 ZIP 需要解压到新目录，保留旧目录，随后启动新目录中的 `StoryWorkbench.exe`。

客户端与书架、作品编辑服务分别运行。替换应用并重新打开后，已有服务仍可能使用旧代码。保留每个页面的编辑，再从作品管理正常停止对应服务，重新打开加载新版。更新过程不自动停止这些服务，也不上传正文。

“安装包已打开”仅表示交给系统处理；当前版本不会冒认安装向导已经结束、客户端已经重启或全部后台服务已经更新。安装结果回执、重启后自动确认及自动回退仍是后续需求。
