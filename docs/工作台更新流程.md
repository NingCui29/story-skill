# 工作台更新流程

版本递增和发布准备按[统一版本管理规则](版本管理.md)执行。各端正式版本、内置 Story Skill 版本和固定下载链接分别见 [Mac 说明](../desktop/macos/README.md)与 [Windows 说明](../desktop/windows/README.md)，源码开发版本另行记录。

Mac 当前仅检查 GitHub 主发行的 latest，并从该发行附件解析适用架构的客户端版本；该发行缺少 Mac 包时会提示不可用，可按 Mac 说明使用原正式版固定链接。更新器不比较 build，正式换包必须同时提高客户端版本。Actions 候选和 Story Skill 运行时版本均不作为客户端新版依据。

Windows 0.2.1 起读取独立 `windows-v*` 正式发行列表，按客户端版本检查更新；固定 EXE 与 SHA256 下载见 Windows 说明。0.2.0 及更早版本需按 [Windows 安装说明](../desktop/windows/README.md)手动升级一次，此后使用独立 Windows 通道。

主发行与独立 Windows 发行分别核对固定标签、构建来源和实际分发清单；主发行保持 latest，Windows 保留独立更新通道。各版来源与实际验收范围见[发布记录索引](README.md)及各端说明，不沿用历史版本的通过结论。

当前源码新增快速更新：Mac 0.2.0 / build 40、Windows 0.3.0 使用经过官方摘要核对的分块清单，最多 3 路下载，暂停后复用已校验分块。Windows 同时支持复用已有 WebView2 的精简更新包，完整离线包仍用于缺少运行时的设备。实现、构建命令及尚待原生验收的范围见[工作台快速更新](工作台快速更新.md)。上述开发版本尚不代表下载链接或本机安装已经更新。

## 入口与状态

Mac：顶部应用菜单“写作工作台 → 检查更新…”。Windows：应用工具栏“检查更新”。

| 阶段 | 可见反馈 | 可执行操作 |
|---|---|---|
| 检查中 | 正在检查；网络错误、超时和限流分别说明 | 等待结果，失败后重试 |
| 发现新版 | 当前版本、目标版本 | 开始下载，或稍后处理 |
| 准备下载 | 核对分块清单和已验证缓存 | 等待，或停止 |
| 下载中 | 真实接收字节、百分比、总大小、复用量、速度和预计剩余时间 | 暂停并保留已校验分块；当前编辑页继续保留 |
| 合并中 | 还原完整安装包，核对整体摘要 | 等待，或停止 |
| 校验中 | 正在校验 SHA256；校验失败有明确原因 | 等待，失败后重新下载 |
| 下载已校验 | 安装包已准备好 | 打开安装包或所在目录 |
| 等待安装与重启 | 明确提示系统安装步骤 | 保存各处编辑，完成安装后重新打开客户端 |

速度和预计剩余时间根据本次实际网络接收字节估算，复用缓存不计入下载速度，网络变化会使估计波动。校验与系统安装阶段不伪造百分比。暂停或下载失败后，不完整文件不得作为可安装文件使用；续传重新核对已保存分块，重试也优先复用按当前官方元数据重新校验的完整包。未提供分块清单或明确不支持范围响应时走完整下载；错误清单、错误范围或摘要不匹配直接停止。分块缓存按 512 MiB、2048 条和 30 天策略在任务边界清理；Windows 完整包仍按最多两份、30 天策略清理。被占用或无法安全核对的条目保留，不删除未知目录内容。

## 校验与下载来源

下载起点只能是官方仓库的对应 Release 附件，重定向仅允许 GitHub 的 HTTPS 下载域名。客户端核对对应附件名称、平台架构、版本、大小和 SHA256。优先使用 GitHub 返回的 `sha256:` 摘要，缺少时使用同一发布中与安装包同名的 `.sha256` 文件；没有可核对的摘要则不开始安装。

SHA256 证明下载内容与官方发布的摘要一致，不等于 Apple 公证或 Windows 代码签名。当前客户端分别使用 Mac 本地临时签名和 Windows 未签名安装包。

Release 附件元数据依据 [GitHub 官方说明](https://docs.github.com/en/rest/releases/assets)。进度使用 [Apple 网络数据委托](https://developer.apple.com/documentation/foundation/urlsessiondatadelegate)及 [.NET HttpClient 流式下载](https://learn.microsoft.com/dotnet/api/system.net.http.httpclient.sendasync)提供的实际传输反馈。

Mac 校验后打开 DMG 或 ZIP。先保存所有客户端窗口及外部浏览器里的文字，退出客户端，再将新应用放入原安装位置；保留旧应用以便回退。不要将旧进程仍在运行误认为已载入新版。

Windows 安装包校验后可启动向导。客户端先核对全部标签中的文字、书架表单和进行中的操作，再正常退出。安装器要求确认外部页面也已保存，认证并正常停止对应服务，等待进程退出和文件释放后才替换文件。静默安装遇到运行中的服务会拒绝继续。便携 ZIP 仍需保存并正常停止旧服务后解压到新目录。

Windows 覆盖安装将整个已核对旧安装目录保留到相邻 `.previous-<唯一标识>` 目录；失败时尝试恢复旧目录；恢复受阻会提示并保留备份，成功后也保留备份供用户核对和清理。卸载同样先核验服务与占用。安装器期间启动客户端会提示等待，防止文件替换时启动旧服务。

Mac 客户端与书架、作品服务分别运行；替换应用后已有服务仍可能使用旧代码，应保留各页面编辑后按原流程正常停止并重新打开。以上 Windows 安装器交接不代替 Mac 的操作。

“安装包已打开”仅表示向导已经启动；以向导最终结果和重启后的运行版本确认升级。安装取消或失败后可重新打开客户端，重新检查并复用完整安装包；不会因上一次启动标记而永久禁用安装按钮。
