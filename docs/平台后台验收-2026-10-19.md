# 三平台真实后台验收进度（2026-10-19）

本记录只包含脱敏的入口、实际页面观察及验收结果，不包含账号、作品 ID、书稿、登录资料或敏感截图。初次公开入口检查使用 macOS 上的 Codex 内置浏览器；作者随后指定 Google Chrome，连接后使用已登录的 Chrome 会话完成番茄单章测试。用户最后将本轮真实后台验收限定为番茄，七猫和起点暂缓。

**当前结论：** 使用既有已登录 Google Chrome 的工作台第13章功能测试已通过新建、保存、独立只读全文回读及同清单重复执行。重复任务识别已有一致草稿，没有新增创建；原十章目录、链接和排期与基线一致。完整脱敏结果见[生产链路验收](../benchmarks/results/development-20261019-platform-drafts/fanqie-live-acceptance.json)。这证明指定范围内的草稿功能，不等于无人值守运行、真实多页验收或小说文学审查。

## 番茄实际保存与回读

作者明确指定已有测试作品。先在章节管理页核对第 1—7 章已发布、第 8—10 章待发布并已有排期，草稿箱原为零篇；未改动这些章节或排期。通过实际“新建草稿”链接打开新标签页后，平台立即分配章节 ID，并在草稿箱生成未命名的零字草稿。这证明打开新建入口已经可能产生远端写入。

使用第 11 章、标题“工作台草稿保存验收”，正文仅为功能验收说明。填写后点击“存草稿”，页面显示“已保存到云端”；刷新草稿箱看到一篇、对应标题和 54 字，随后从该行编辑链接重新打开，核对编号、标题与完整正文一致。没有点击“下一步”，没有提交审核或增加排期；测试草稿留在草稿箱。

**通过范围：** 用户指定作品中，Chrome 浏览器控制的单章测试草稿创建、保存、列表刷新和重新打开完整回读。此次操作未经过工作台 `BrowserAdapter`、正式稿冻结清单或执行回执；不能将该结果标成工作台完整自动链路通过，也不证明正式书稿已上传。

上述记录是首次单章人工控制验收，后续的身份、目录和段落采样见下节；不能把代码补齐或页面采样计作生产执行器完整链路通过。生产页面配置仅保存在本机私有位置，没有随分发包公开。

实际富文本为 `.serial-editor-content .ProseMirror`；单段重开后的 DOM 含正文段及末尾空段，`innerText` 比输入多三个换行，而 `textContent` 不能保留多段间换行。执行器继续严格比较，不裁剪尾部或改用会丢段落的读取来制造通过。其通用“新建按钮打开弹窗／当前页”能力与完整回读校验已有离线测试，但仍需真实页面配置及多段验收。

## 追加：身份、目录和多段正文采样

继续使用已连接的 Google Chrome，进入实际账号设置页，核对“番茄小说网ID”的唯一字段；笔名不作账号标识。作品身份和动态草稿 ID 由实际列表及编辑器 URL 的完整模板提取，编辑器不再依赖不存在的作品 DOM。现场配置同时匹配作品管理、修改草稿、新建草稿及修改非草稿的已观察路由；不使用宽泛的路径正则或忽略查询参数。

章节目录采样覆盖实际的“章节管理”及“草稿箱”。两类表格均限定当前激活标签，核对加载完成、搜索折叠和状态“全部”等范围。章节管理现场为一卷、十行，包含七条已发布与三条待发布；草稿箱为一条已命名测试草稿并有精确总数。现场没有下一页或虚拟列表。生产配置据此使用完整表格模式：核对已配置的分页／虚拟列表拒绝信号，滚动表格与页面到两端，验证行、尺寸和总数稳定。适配器另保留下一页／明确末页模式，并新增动态分卷逐项读取；多卷或实际多页后台尚未现场验收，不能由这个十章作品推定通过。

在原第11章功能测试草稿内，采样单段、连续段、中间空段、开头空段和结尾换行，保存并从目录重新打开后读取实际段落 DOM。采样证明恰好一个追加空段是编辑器哨兵，其余空段属于输入内容。读写器按此具体结构还原完整纯文本，只移除该一个哨兵；保留空格、标点、首尾换行和其他空段。未知内联格式、非段落节点或缺少哨兵均停止。整字段填写曾折叠预期空行，故改用原生逐段输入并在保存前逐字核对。采样后已恢复原54字功能说明并确认云端保存；现有小说章节和排期未改。脱敏 DOM 观察见[段落采样记录](../benchmarks/results/development-20261019-platform-drafts/fanqie-richtext-observations.json)。

账号守护页、完整目录、草稿状态与 ID 在敏感步骤重新核对；编辑器“存草稿”按钮只用作加载就绪信号，不单独证明当前章节是草稿。实际草稿状态须来自完整草稿／非草稿目录及同一 ID 的再次确认。以上是代码能力和页面采样证据，真实执行器结果另记。

独立代码复核发现：列表显示“未命名草稿”时，编辑器可能已存在章号，不能跳过后创建同章。最终补丁对无法核对章号的旧稿先停止查找；新建阶段只按本次明确分配的 ID 识别自己的空稿，其他未命名 ID 仍阻断。离线联动测试覆盖“新建点击已产生空稿，随后发现其他未名稿”：未填写文字，持久结果保持 unknown，后续看不到列表也不重新创建。该故障注入不是在真实作品中制造中断或冲突。

## 工作台到生产执行器的真实任务

使用隔离的本地功能测试书与冻结清单，经实际工作台“平台草稿”入口启动原生执行器，绑定作者指定的现有番茄作品。正文仅为83字符功能说明，包含首行空行、中间空行与结尾两个换行；标题“一键草稿完整链路验收”，第12章。隔离书的正式稿资格由测试夹具建立，不计作小说文学审查或小说正文交付。配置不含登录状态，实际使用可见的独立 Google Chrome 临时会话；没有替换执行器、目标锁或持久日志。

首次任务在身份核对前因登录导航等待 DOM 的15秒超时退出，只有 `blocked` 事件，没有发送意图、远端 ID 或新建行为，第12章没有写入。修复后人工登录导航等待页面提交，仍要求真实账号字段；只读诊断完整等待60秒期限后返回 `login_required`，没有提前失败或写入。工作台实际登录期限已设为十分钟，后续写入／回读保持严格加载和身份核对。

修复后的独立会话真实工作台任务曾重新启动，最终仍未取得人工登录。作者随后明确要求使用既有已登录 Chrome，不要独立新窗口。已停止该服务及其临时浏览器；最终持久记录为两条 blocked、零条 sending、无远端草稿 ID，日志文件停止前后哈希一致。没有终止或修改日常 Chrome，也没有创建第12章。

后续改用 `host_assisted_cua`：生产执行核心通过本地认证队列，将核对、目录查找、创建与回读交给当前助手已连接的 Google Chrome 工具；继续沿用发送意图与去重日志。该模式需要当前助手的浏览器执行工作器，无工作器时须明确阻断，不能标成脱离助手的无人值守运行。它不读取 Cookie 或接入 Chrome 内部调试连接，不新开独立浏览器会话。完整保存与回读结果将按此模式单独记录；旧独立执行器的尝试不计作此模式通过。

## 既有 Chrome 链路的追加边界

工作台通过认证队列实际创建过第12章功能草稿，第一次输入检查没有通过，持久结果保持 `unknown`，没有把它记成保存成功，也没有重新创建同章。83字符冻结样本包含尾部两个换行；后续手工功能采样曾回读81字符，不能裁剪原清单后改称一致。原清单、发送意图和失败历史继续保留。

真实只读核对同时暴露了三项执行问题：账号 DOM 等待可能在字段已出现时仍超时；分卷菜单在点击后暂时没有选项；逐格读取目录会耗尽任务期限。修复分别采用同一期限内的正向轮询、仅点击一次后等待稳定菜单，以及原子批量读取同一表格的字段。账号、作品、章号、状态、链接、目录范围、滚动端点和前后快照校验没有删减，期限没有放宽。

另有重要现场现象：仅进入或刷新第12章测试草稿编辑页，也观察到重复的功能说明增长；单页复验仍出现增长，原因尚未确定，不能归因于并发编辑。此后暂停新建测试，关闭本轮测试编辑页，改查草稿行实际提供的只读预览。预览的大段正文在刷新前后保持一致；正文 DOM 是直接文本或空的 `P` 节点，末尾有一个额外空 `P`。

已手工将第12章异常副本恢复为81字符的简短功能说明，保存并关闭编辑页，再从只读预览回读：7个段落节点中仅移除最后一个已观察哨兵，保留开头空行和中间空行，完整正文一致。清理不改83字符冻结稿、日志或同章防重建记录；它不是工作台新建链路通过。原十章的全部目录单元格、编辑链接和排期再次与基线逐项一致。

番茄对账与保存后回读已改接这一路径；缺少独立只读预览配置时在本地阻断。实际空段另观察到精确的 `<p><br></p>` 形式；解析器只将这两种已观察空段当作正文空行，仍只移除末尾一个零子节点空 `P`，拒绝其他内联结构和属性。脱敏现场证据见[回读边界记录](../benchmarks/results/development-20261019-platform-drafts/fanqie-readback-observations.json)。

## 第13章工作台完整链路及重复执行

为复验建立独立的81字符功能稿，保留首行和中间空行，不含额外尾部空行；没有改写第12章原83字符清单或失败比较口径。经工作台真实入口启动生产执行核心、认证队列、既有 Chrome 驱动及目标锁。完整目录先确认第13章不存在，持久化发送意图后只点击一次新建；填写编号、标题与正文，保存成功后关闭驱动拥有的编辑页，从实际只读预览重新核对完整内容，再由执行核心另开预览独立核对。工作台显示“已保存并完整回读，1/1章”。

重复执行同一清单，工作台显示“已有一致草稿，完整回读匹配，1/1章”。只查找并读取同一草稿，没有第二个创建请求。持久记录恰为一次 `sending`、一次 `saved`、一次 `reconciled`，全局发送意图及解决记录各一条且对应相同尝试与内容。最后独立刷新只读预览，标题及81字符完整正文仍一致。草稿箱恰为第11、12、13章三篇功能稿；原七条已发布及三条待发布的全部目录字段、编辑链接和排期与最初基线完全一致。

第12章原清单、准备第13章前的十三条历史事件及未决防重建记录逐字节不变，最新结果仍为冲突。没有发布、送审或新增排期。页面配置、真实目标、队列、正文与截图保存在本机私有目录；公开记录只有脱敏结果。诊断及重复标签已关闭，任务只保留工作台与最终只读预览，原有用户页面保留，执行工作器已分离。

此阶段冻结源码的全仓库回归运行2089项：2069成功、20跳过，零失败或错误；回执见[预览回读最终回归](../benchmarks/results/development-20261019-platform-drafts/fanqie-host-assisted-unittest.preview-readback-final.json)。随后用户提出工作台自助配置账号与作品绑定，作为下节本地配置增量另行开发和验证，不混入上述真实保存结果。

## 作者自助配置与真实只读核对

工作台新增“平台草稿 → 配置番茄账号与作品”：填写番茄小说网ID、章节管理或草稿箱的完整官方链接，以及连续正式章节范围，点击“保存绑定并生成清单”。默认仅最新正式章，每批最多1000章；仍执行正式稿健康、审查资格、版本和并发检查。该按钮只保存本书私有配置并生成或复用冻结清单，不访问平台、不保存登录凭据，也不自动启动远端任务。

在原Google Chrome工作台标签实际填写第13章范围，成功生成新页面配置并复用原清单；界面明确显示“尚未访问平台”，未连接当前助手工作器时执行按钮禁用。私有审计确认旧配置、清单正文及绑定、创作状态、发送日志和旧未决记录不变，没有产生任务或远端写入。

随后将自助生成的配置用于同一工作台的“只读对账”，经生产核心及认证队列核对真实账号和作品、完整目录及原第13章草稿，两次独立只读预览的81字符全文均一致，界面显示“本次对账完成，1/1章”。队列只有身份核对、查找和读取，无创建、填写或保存请求；草稿箱仍是三篇功能稿。临时目录与身份页已关闭，保留工作台、最终只读预览和原用户页面，执行工作器分离。脱敏结果见[自助配置验收](../benchmarks/results/development-20261019-platform-drafts/fanqie-self-service-acceptance.json)。

此增量的真实验收证明本地表单到新配置再到真实只读核对；前一节的新建与保存验收使用同一固定页面模板。没有另增功能草稿来重复新建测试，不把只读对账称作新的保存验收。UI/API专项72项通过；三种最终分发包及9项技能校验通过，未安装或发版。[此增量冻结源码全量回归](../benchmarks/results/development-20261019-platform-drafts/fanqie-host-assisted-unittest.self-service-final.json)运行2109项：2089通过、20跳过，零失败或错误，耗时576.300秒。
