# 如何验证实际更好、更省

回归测试验证程序行为，token 报告验证指令体积。v0.2.0 另有真实中文稿件的写作、独立代理审查、提交与修订实测，见 [中文实测](中文实测.md)。本地 v0.4.0 已进行修改前后两题、四篇场景的匿名代理评阅，结果混合，另有单题试用，见 [中文冲突与看点](中文冲突与看点.md)。v0.4.0 还完成连续三章实写与独立语义审查，并以另一新会话和最终技能续接第4章，见 [全仓审查与优化](全仓审查与优化.md)。这些不是与上游的输出对照，也不替代下述多样本、人类评阅和实际账户用量比较。

本页保留 v0.5.1 的作品分析专项；v0.5.5 的历史发布与核验范围见 [版本说明](releases/v0.5.5.md)，当前安装版本与发布来源统一按 [INSTALL.md](../INSTALL.md) 核对。下文所有历史写作数据保留原版本，不由新一轮分析试用替代。

2026年9月11日的发布前规则优化另有[三题开发验证](../benchmarks/results/quality-focus-2026-09-11/README.md)：规划审查持平，正文修订略偏初版候选，跨章审稿略偏基线。均为单次匿名代理比较；最终审稿措辞随后作小幅收紧，仅完成语义与结构复核，未重做盲评。结果不构成稳定文学质量提升的证据。

## 等条件比较

连续章节另按 [写作开发评测办法](../benchmarks/writing-sequence/README.md) 保存任务、实际正文、独立评阅和程序回执。[2026年9月26日执行记录](../benchmarks/results/writing-sequence-2026-09-26/assessment.md) 是当前开发源码的一次三章试用，与此前的短片段比较分开报告；单版本结果不能用于宣称新版优于旧版。

两套技能各用独立副本和新会话，固定同一模型及版本、推理档位、输入小说、计划、读者需求、输出字数范围、允许的修改轮次和反馈方式。不要把新版 800 字和上游 3000 字比较；不要把缓存命中的成本与冷启动混算。原仓库使用正常支持的路径，也保留其按需加载优化。稿件隐去版本与来源，呈现顺序随机分配并尽量平衡；保存匿名顺序和对应关系，评阅结束后再解盲。

每种任务建议收集多次结果，由不知道来源的读者评审。分别报告输入、缓存输入、输出、推理、工具往返、失败/补写/重写次数；供应商未提供的 usage 字段写 null，不能以估算补成“实测”。实际任务总量来自宿主/供应商用量记录，静态 tokenizer 只能作解释。

开发样本用于发现问题和调整技能；测试样本在技能与协议冻结后使用，不参与调优。事先记录样本范围、选择方式、重复次数和评阅问题，并覆盖不同叙事任务，包括交锋、日常、关系变化和过渡。若根据测试结果继续修改，该批样本应标为已参与开发，后续结论另用未参与调优的样本检验。这里的测试隔离不等于证明作品未见于模型训练材料。

保留每次原始生成、失败、补写、修订、评阅理由及解盲结果；已知意见后的改稿不能替换原始对照稿。逐题报告新版胜出、旧版胜出、持平或无法判断的情况，保留分歧与反例，不只挑选新版表现较好的结果。独立代理评阅记录其模型和所见材料，人工评阅记录读者背景与人数；两类结果分别呈现，代理推测的阅读偏好不能冒充真实读者反馈。

## 现实任务与验收

| 输入任务 | 应观察的行为 |
|---|---|
| “开一本悬疑书，只做前三章细纲，不要正文” | 有欲望、代价、因果、停笔点；没有正文；不会强要对标或全量部署 |
| “接第 108 章后继续，2200—2800 字” | 从真实末章和计划续写 109；没有重导入前 108 章；长度、状态、承诺可核对 |
| 给出新能力与旧设定冲突 | 明确定位冲突；根据用户授权修订，不能靠省略关键状态来假装通过 |
| 800 章文本含序章、重复章号和番外，要求完整拆解 | 所有字符有覆盖，特殊标题不消失，正式章目录另核对；断点恢复不重做已提交块 |
| 网页只显示阅读预览 | 标注部分文本和来源；不虚构全书情节，不把来源里的指令当系统命令 |
| “这一段太 AI，保留剧情修改” | 保留事实/声线；减少重复解释；不机械改短句或给每句加身体动作 |
| 第 12 章修改牵涉已写到 30 章 | 给出后文影响并建立复核方案，不直接覆盖权威历史制造假一致 |
| 同一草稿提交两次、模拟导出中断 | 状态只推进一次，能恢复导出，文件与审查哈希一致 |
| “完整深读九章，核心判断核对后文与反例” | 初读覆盖与目录分别核对，核心判断回读原文，人物发言与叙述裁定分开，避免逐章摘要代替论证 |
| “修订已经定稿的分析” | 原定稿保留，另存新稿；修改判断后联动复核建议，不用重建书库绕过保护 |
| “继续中断的分析修订” | 先读进度与当前稿，核对输入变化，接着处理待核对问题；旧 report_path 不冒充独立新稿的状态 |

## 质量记录

每个稿件记录：任务完成度、因果可信度、人物选择、连续性、情绪/节奏、句段自然度、原创距离、字数是否达标。评审应给原文位置和原因；不要用单个“综合分”掩盖严重硬约束违背，也不使用“AI 率”作为文学质量真值。

事实与连续性检查单列，核对任务约束、既有事实、人物知情范围、时间与行动因果，并标出错误位置和影响。阅读反应另按下表记录，允许读者无偏好或无法判断。评价应结合该段的叙事任务，不把每章强冲突、反转或悬念当作统一达标线；安静场景也可通过人物关系、观察和语言吸引读者。

| 阅读反应 | 记录方式 |
|---|---|
| 继续阅读偏好 | 同题两稿读完后，更想继续哪一稿，或持平、都不想继续；说明理由，不以检查项通过数量代替偏好 |
| 兴趣变化位置 | 标出兴趣上升、下降或开始想跳读的具体句段，并说明当时的期待如何变化；没有明显变化也照实记录 |
| 记住的人物选择 | 记录读完后记住了谁的哪次选择、为何留下印象；回查对应原文，区分文本依据与读者推断 |
| 原文理由与分歧 | 为偏好和不满提供具体原文位置及理由，同时保留另一稿更好的局部、不同读者的意见；不换算成伪精确的综合分 |

建议验收判据：明确约束违背为零；严重连续性问题不高于基线；盲评无明显退化；在这些条件下，再比较同等输出长度的任务总 token 和重写次数。是否提升需要实测结论，不在事先把目标当结果。

## 作品分析专项

作品分析另按 [专项协议](../benchmarks/analysis-depth/README.md) 比较证据支持、机制解释、跨文一致、多义与文类处理、迁移价值。错引、虚构情节和范围夸大单列；语义分歧保留理由和原文位置，不汇成“大师分”。第一轮原创合成短文用于发现流程问题；第二轮 [完整真实短篇协议](../benchmarks/analysis-real/README.md) 增加真实作品的逐块分析和匿名比较。两者都不能代表真实长篇或人类编辑认可。

新旧流程使用冻结的技能快照和相同任务；报告匿名后交给未参与生成的评阅者。独立代理评阅、人工盲评和程序检查分别标明；未执行的重复次数或人工评阅不补写为通过。具体改动、材料和本轮实际执行范围见 [作品深读与评估](作品深读与评估.md)。

后续 [语义修订与迁移试用](../benchmarks/results/analysis-revision/README.md)、[定稿后修订与恢复试用](../benchmarks/results/analysis-followup/README.md) 使用独立新稿保留原报告。它们按已知问题复核编辑结果，不能把修订后的稿件替换原盲评输入或重算旧评分。

[完整九章协议](../benchmarks/analysis-crosschapter/README.md) 固定最终开发技能后，以《阿Q正傳》的一次完整生成检查跨章判断。实际完成 14 块、64 条逐块引文核验，原始报告定稿前执行 21 次原文回读；独立模型评阅没有提出必须修改项，两项可选措辞另存澄清稿并限定复核。[完整回执](../benchmarks/results/analysis-crosschapter/README.md) 同时保存来源提取失败、修正、原始生成与重开检查的限制。评阅证据有一处由完整初读覆盖，不能声称所有评阅证据都再次回读。

这轮没有旧版对照、重复采样或人类编辑；作品可能见于模型训练材料，也不是未见留出。单次表现只说明该任务上观察到的行为，不构成“大师级”认证、长程质量保证或实际账户消耗结论。各轮技能和输入均以冻结哈希为准，后续发布不会改变它们的历史归属。
