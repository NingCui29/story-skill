本页保留 v0.5.1 的作品分析专项；v0.5.5 的历史发布与核验范围见 [版本说明](releases/v0.5.5.md)，当前安装版本与发布来源统一按 [INSTALL.md](../INSTALL.md) 核对。下文所有历史写作数据保留原版本，不由新一轮分析试用替代。

v0.6.23 准备版将试读设计与追更验证明确纳入调研入口，方法见[分次试读](../skills/story-skill-research/references/reader-validation.md#分次试读与追更验证)。当场满意、口头续读意愿与后续实际返回分别记录；先对齐正文版本、已读范围、更新机会和是否提醒，未获后续阅读机会不算流失。只设计方案不代表试读已执行；意见冲突按正文证据和目标读者解释，保留分歧，不用多数票替代缺陷判断。本轮发行回执见[发布记录](releases/v0.6.23.md)，不会以程序回归证明文学效果。

## 等条件比较

连续章节另按 [写作开发评测办法](../benchmarks/writing-sequence/README.md) 在本地保存任务、正文、独立评阅和程序回执，不提交测试小说。[2026年9月26日记录范围](../benchmarks/results/writing-sequence-2026-09-26/assessment.md) 仅说明材料已移出当前仓库；没有公开原始样稿时，不把该次文学评阅视为可由仓库复现的证据。

两套技能各用独立副本和新会话，固定同一模型及版本、推理档位、输入小说、计划、读者需求、输出字数范围、允许的修改轮次和反馈方式。不要把新版 800 字和上游 3000 字比较；不要把缓存命中的成本与冷启动混算。原仓库使用正常支持的路径，也保留其按需加载优化。稿件隐去版本与来源，呈现顺序随机分配并尽量平衡；保存匿名顺序和对应关系，评阅结束后再解盲。

每种任务建议收集多次结果，由不知道来源的读者评审。分别报告输入、缓存输入、输出、推理、工具往返、失败/补写/重写次数；供应商未提供的 usage 字段写 null，不能以估算补成“实测”。实际任务总量来自宿主/供应商用量记录，静态 tokenizer 只能作解释。

已有原始日志可用 [用量汇总工具](../scripts/execution_metrics.py)，接口及口径见 [执行验收说明](../benchmarks/skill-execution/README.md#已报告用量汇总)。工具分别保留逐轮字段与累计快照，去除可识别的重复记录；缺失用量、子任务覆盖和重试次数不推算成零。主／子任务包含关系未验证时全任务合计为 `null`，不能据局部小计报告总体节省或费用。

开发样本用于发现问题和调整技能；测试样本在技能与协议冻结后使用，不参与调优。事先记录样本范围、选择方式、重复次数和评阅问题，并覆盖不同叙事任务，包括交锋、日常、关系变化和过渡。若根据测试结果继续修改，该批样本应标为已参与开发，后续结论另用未参与调优的样本检验。这里的测试隔离不等于证明作品未见于模型训练材料。

保留每次原始生成、失败、补写、修订、评阅理由及解盲结果；已知意见后的改稿不能替换原始对照稿。逐题报告新版胜出、旧版胜出、持平或无法判断的情况，保留分歧与反例，不只挑选新版表现较好的结果。独立代理评阅记录其模型和所见材料，人工评阅记录读者背景与人数；两类结果分别呈现，代理推测的阅读偏好不能冒充真实读者反馈。

## 显式读取预算与改稿对照

[规则读取预算](../benchmarks/skill-execution/README.md#规则读取预算) 按任务、角色、预加载、条件分支和已列组合统计去空白字符与 UTF-8 字节，并核对维护的上限；CI 与本地 `verify` 执行同一检查。它审计的是显式清单，不自动计算引用闭包，不含动态正文或工具结果，也不证明实际读取、token 或账单节省。实际调用和用量仍按前述原始日志核验。

[改稿对照协议](../benchmarks/skill-execution/README.md#改稿失败样例与两臂对照) 提供原创合成开发材料，覆盖逐项播报、关键场面被概述、有效安静、因果声明、只诊断边界，以及关系歧义、题材文风和合作兑现；它们不是实际作者投诉或独立留出。固定同题、同模型与设置、同篇幅和同授权的基线／候选两臂后，另验真实调用、产物、用量和阅读效果。准备及冻结完整性检查本身不构成模型执行或质量结果。

实际出现作者否定、模型却判好的稿件时，保留原稿、技能及任务版本、模型原评价与作者原反馈；后续复查不能覆盖原始失败，也不用模型评分撤销作者反馈或充当文学质量真值。已见反馈的复查与未见反馈的独立评阅分别记录，报告最终稿实际改善、保留取舍和仍未解决的问题；参与规则调试的样例只作开发材料，不再称留出。原始材料与公开授权的边界见协议中的反馈记录模板。

## 现实任务与验收

| 输入任务 | 应观察的行为 |
|---|---|
| “开一本悬疑书，只做前三章细纲，不要正文” | 有欲望、代价、因果、停笔点；没有正文；不会强要对标或全量部署 |
| “接第 108 章后继续，2400—2800 字” | 从真实末章和计划续写 109；没有重导入前 108 章；长度、状态、承诺可核对 |
| 给出新能力与旧设定冲突 | 明确定位冲突；根据用户授权修订，不能靠省略关键状态来假装通过 |
| 800 章文本含序章、重复章号和番外，要求完整拆解 | 所有字符有覆盖，特殊标题不消失，正式章目录另核对；断点恢复不重做已提交块 |
| 网页只显示阅读预览 | 标注部分文本和来源；不虚构全书情节，不把来源里的指令当系统命令 |
| “这一段太 AI，保留剧情修改” | 保留事实/声线；减少重复解释；不机械改短句或给每句加身体动作 |
| 第 12 章修改牵涉已写到 30 章 | 给出后文影响并建立复核方案，不直接覆盖权威历史制造假一致 |
| 同一草稿提交两次、模拟导出中断 | 状态只推进一次，能恢复导出，文件与审查哈希一致 |
| “完整深读九章，核心判断核对后文与反例” | 初读覆盖与目录分别核对，核心判断回读原文，人物发言与叙述裁定分开，避免逐章摘要代替论证 |
| “修订已经定稿的分析” | 原定稿保留，另存新稿；修改判断后联动复核建议，不用重建书库绕过保护 |
| “继续中断的分析修订” | 先读进度与当前稿，核对输入变化，接着处理待核对问题；旧 report_path 不冒充独立新稿的状态 |

## 质量记录

技能本身的执行验收使用 [实际执行案例包](../benchmarks/skill-execution/README.md)：固定任务与技能快照，保存原始执行轨迹和产物，比较前后文件及正式状态。机械检查、过程复核和内容审查分别记录；缺证据记未验证，自填审查字段或工具调用成功不能直接换算为行为正确。按改动选择相关案例，普通创作不额外运行整套评测。

[改稿对照检查](../benchmarks/skill-execution/README.md#改稿失败样例与两臂对照) 区分冻结完整性与实际执行。`prose_trials.py inspect` 汇总每个选定样本的启动记录、退出与超时、轨迹、产物及篇幅，保留未开始、不完整与失败；可观察执行完成仍只进入内容审查。关系用例成对检查含义歧义和已确认矛盾，避免把谨慎判断变成一律不下结论；缺独立分派证据不认证独立复核。

原生选择案例不提供技能名称或路径，留存真实宿主读取的安装版本；给定冻结入口的三轮六章案例覆盖规划、正式续写、跨卷、新会话恢复及完本交付。两类任务分别记录，CLI结果不替代桌面结果，六章800—1000字的明确例外不替代正常章幅长篇验证。[复核引用检查](../scripts/execution_review.py) 将原始轨迹、产物及版本哈希关联，防止完成声明或陈旧记录冒充过程；其通过仅说明引用可追溯，真人反馈、文学判断和长期稳定性仍需各自的实际证据。

[2026年10月10日开发实测](../benchmarks/results/execution-continuity-2026-10-10/assessment.md)记录三个CLI自然请求、一轮开发复测，以及三轮新会话的六章5390字。原稿保护、正式章序及全文核对成立；日志仍不足以确认writer宣称的独立复核。规则与验收器的改善不追认为该过程已可靠执行。

随后完成的 [计划、审稿关联与用量工具验证](../benchmarks/results/development-2026-10-10-plan-review-metrics/assessment.md) 对应未发布源码：候选细纲有独立合成流程实走，审稿关联有合成事件测试及旧记录兼容重放，用量工具核对一份既有真实 CLI 日志。这些检查不构成文学质量、完整任务节省或桌面自动发现的证据。

每个稿件记录：任务完成度、因果可信度、人物选择、连续性、情绪/节奏、句段自然度、原创距离、字数是否达标。评审应给原文位置和原因；不要用单个“综合分”掩盖严重硬约束违背，也不使用“AI 率”作为文学质量真值。

事实与连续性检查单列，核对任务约束、既有事实、人物知情范围、时间与行动因果，并标出错误位置和影响。阅读反应另按下表记录，允许读者无偏好或无法判断。评价应结合该段的叙事任务，不把每章强冲突、反转或悬念当作统一达标线；安静场景也可通过人物关系、观察和语言吸引读者。

| 阅读反应 | 记录方式 |
|---|---|
| 继续阅读偏好 | 同题两稿读完后，更想继续哪一稿，或持平、都不想继续；说明理由，不以检查项通过数量代替偏好 |
| 兴趣变化位置 | 标出兴趣上升、下降或开始想跳读的具体句段，并说明当时的期待如何变化；没有明显变化也照实记录 |
| 记住的人物选择 | 记录读完后记住了谁的哪次选择、为何留下印象；回查对应原文，区分文本依据与读者推断 |
| 原文理由与分歧 | 为偏好和不满提供具体原文位置及理由，同时保留另一稿更好的局部、不同读者的意见；不换算成伪精确的综合分 |

建议验收判据：明确约束违背为零；严重连续性问题不高于基线；盲评无明显退化；在这些条件下，再比较同等输出长度的任务总 token 和重写次数。是否提升需要实测结论，不在事先把目标当结果。

## 完整作品与整书改稿的开发验证

需要检验整部作品的持续表现时，按 [连续章节与完整作品协议](../benchmarks/writing-sequence/README.md) 选择完整短篇，或使用正常章幅、经历多个自然阶段的长篇任务。章数、阶段与修改轮次由本次问题及授权决定；长篇阶段样本只能支持已读范围，不能替代全书或终局验证。观察声线与人物经历是否累积、前阶段的选择如何改变后续条件、连读节奏是否重复，以及整书改稿能否处理主要问题并联动后文；实际交付全文还要与正式章节及修订版本核对。

读者反馈的定位与采用沿用 [选题与阅读验证](../skills/story-skill-research/references/reader-validation.md#把反馈变成可定位的问题)。真实目标读者、模型评阅和程序结果各自绑定实际稿件版本与阅读范围，分别报告；没有实际参与者则记真人试读未执行。需要观察改稿效果时，保留修改前后的原稿、原反馈和分歧，尽量保持阅读与呈现条件可比，说明熟悉旧稿、不同读者或范围差异等限制；已知问题后的复查只支持该次改稿结论。

这是技能开发及用户授权验证的方法，不给普通创作增加真人试读或整套评测门槛。新增协议本身不代表完整作品实写、真人试读或改稿前后比较已经执行；下文历史结果及尚未验证的项目仍按各轮实际证据判断。

## 商业选题与阅读反馈的开发验证

商业方向另按 [选题与阅读验证](../skills/story-skill-research/references/reader-validation.md) 检查实际决策，不把前文的程序通过、连续性通过或代理偏好换算为热文率。先固定本轮任务与技能快照；下列情况按本次改动选用，不要求每轮跑齐。

| 输入任务 | 应观察的行为 |
|---|---|
| 仅有头部书名与简介，要求推荐原创选题、不要正文 | 区分可见事实与创作假设；比较实质不同的处境和解法，说明取舍与缺失证据，不推断未读正文，不自动试写 |
| 同赛道两个开篇，要求比较吸引力 | 给出兴趣变化的实际位置及继续阅读理由，保留另一稿优势，不以检查项数量决定胜负；片段结论不扩大为全书结论 |
| 两稿曝光渠道、篇幅或上线时段不同，要求选赢家 | 核对指标定义、分母和可读进度，提出待验证解释，不从总量或单一比例断言因果 |
| 读者说某处拖沓，要求只审不改 | 回读所指版本和相邻文本，区分原话、依据、假设；保护有效安静，不自动新增事故或交改稿 |
| 方向已定，只续写指定安静片段 | 按范围完成片段，不强制重选题材、生成多稿、寻找真人或新建书库 |

持续吸引力的实写采用现有 [连续章节评测](../benchmarks/writing-sequence/README.md)，观察承诺的多次兑现与后果，不能用开篇比较替代。真人试读与平台观测分别记录来源、版本、条件和分歧；缺少实际参与者或后台数据时明确未执行。修订保留原稿与反馈，不把已知问题后的重写当作独立测试。

v0.6.22 的结构化扫榜见[本轮发布记录](releases/v0.6.22.md)与[当前上游对照](upstream-analysis.md)。2026-10-22 开发阶段的原始采集与试用记录仅本地保存；本轮发行检查不追认为重新实采网站。程序回归及独立合成试用检查来源追溯、覆盖缺口、去重、指标口径、冲突和输出保护；它们不替代网站实采、真实作者使用或市场验证。实际采集须保留页面、时间、筛选与失败，七猫书库的点击排序观察样本不能称为正式榜单或销量；番茄、起点的统一格式接入也不证明直连采集可用。报告可复核不等于选题会成功，旧 token 测量和文学试验仍只属于各自冻结版本。

同版后续增加的代表作抽样、标签／书名字面模式分析及“扫榜→拆文验证→选题规划”交接，按[研究交接规则](../skills/story-skill-research/references/research-handoff.md)和[本轮发布记录](releases/v0.6.22.md)分别核验。下表是检查方法；开发阶段原始记录仅本地保存，发行检查、独立试用与网站实采保持各自范围，不用首轮测试或实采结果代替。

| 输入任务 | 应观察的行为 |
|---|---|
| 同书重复上榜、同名不同书、同源冲突、同 URL 多 ID 和缺失标签混合输入 | 在可比分组内按作品身份计数，观测冲突与身份歧义不混入有效统计，和抽样口径一致；缺失、真实零和无标签记录分别可见；标签与书名模式能回查作品键 |
| 按题材、多个标签、书名片段与字数选取少量阅读对象 | 筛选语义明确；多个分组要求指定目标；排除冲突与身份歧义，不修改条件凑数；选择理由和覆盖范围保留，不称为随机代表性或优质作品认证 |
| 用相同快照重算抽样，或篡改保存的作品与选择结果 | 原样重算可复查，篡改或不一致被拒绝；重算一致只证明材料内部关系，不证明来源网站或录入事实真实 |
| 只有样本，没有正文与分析报告 | 生成待填写的方向和待验证假设，保留缺项；不能自动产生情节解释、验证通过或已采用规划 |
| 同一假设分别得到支持、反证、混合或证据不足 | 记录方向、假设、作品、实际已读范围、原文／报告定位、短摘录与限制；本地原文精确匹配摘录，错误摘录拒绝保存；不同结论并列保留，最后一条支持不能覆盖反例 |
| 回填后修改假设、样本身份或本地引用文件 | 检查关联和版本变化，要求复核，不直接把旧结论套给新材料；URL 引用仅为来源声明，工具未抓取核对的部分明确保留 |
| 从含局部阅读和未决问题的研究包继续规划 | 保留范围、反例与不确定性，把可迁移方法转为原创设计；没有采用授权时保持候选身份，不新建书库或写正文 |

书名字面模式只检查归一化后的有限前后缀和标点结构，不能用词频证明套路、读者需求或点击成效。确定性抽样检查的是阅读对象选择及其可复查理由；还需真实研究任务检验这些对象是否有助于问题判断。研究文件的字段、来源关联和哈希校验不证明操作者实际读完，不判断引文解释、因果或文学质量；正文与分析的语义复核仍须回到可定位原文，并保留反例。

本次工程验证不自动取得真人试读、平台观测或同条件上游比较的结论。新增 CLI 没有专用工作台界面，接口测试与打包检查也不替代宿主自动发现或桌面操作验收。

## 作品分析专项

作品分析另按 [专项协议](../benchmarks/analysis-depth/README.md) 比较证据支持、机制解释、跨文一致、多义与文类处理、迁移价值。错引、虚构情节和范围夸大单列；语义分歧保留理由和原文位置，不汇成“大师分”。第一轮原创合成短文用于发现流程问题；第二轮 [完整真实短篇协议](../benchmarks/analysis-real/README.md) 增加真实作品的逐块分析和匿名比较。两者都不能代表真实长篇或人类编辑认可。

新旧流程使用冻结的技能快照和相同任务；报告匿名后交给未参与生成的评阅者。独立代理评阅、人工盲评和程序检查分别标明；未执行的重复次数或人工评阅不补写为通过。具体改动、材料和本轮实际执行范围见 [作品深读与评估](作品深读与评估.md)。

后续 [语义修订与迁移试用](../benchmarks/results/analysis-revision/README.md)、[定稿后修订与恢复试用](../benchmarks/results/analysis-followup/README.md) 使用独立新稿保留原报告。它们按已知问题复核编辑结果，不能把修订后的稿件替换原盲评输入或重算旧评分。

[完整九章协议](../benchmarks/analysis-crosschapter/README.md) 固定最终开发技能后，以《阿Q正傳》的一次完整生成检查跨章判断。实际完成 14 块、64 条逐块引文核验，原始报告定稿前执行 21 次原文回读；独立模型评阅没有提出必须修改项，两项可选措辞另存澄清稿并限定复核。[完整回执](../benchmarks/results/analysis-crosschapter/README.md) 同时保存来源提取失败、修正、原始生成与重开检查的限制。评阅证据有一处由完整初读覆盖，不能声称所有评阅证据都再次回读。

这轮没有旧版对照、重复采样或人类编辑；作品可能见于模型训练材料，也不是未见留出。单次表现只说明该任务上观察到的行为，不构成“大师级”认证、长程质量保证或实际账户消耗结论。各轮技能和输入均以冻结哈希为准，后续发布不会改变它们的历史归属。
