## v0.3.0 历史改造记录（2026-09-08）

本版将原方案的存储、检索、创作状态和历史修订接入可执行的 Codex 技能。原有小说工程未迁移；验证使用系统临时目录与原工程的独立副本。运行时只用 Python 标准库，不调用模型 API。

### 已落地的能力

| 范围 | 可执行行为 |
|---|---|
| 长篇资料层级 | 全书卡片可限定卷、段、线或实体；计划支持 volume/arc/line/entities/time；本卷和情节段保存目标、条件与代价，未来设计和正文事实分开。 |
| 多线与认知 | 切线读取各自最后场景和未完动作；人物知道、相信、怀疑和明确不知分别存储；按故事时间处理倒叙；同名和化名不猜身份。 |
| 伏笔 | 保留铺垫、强化、休眠、履约、违约、放弃与重开记录，关联实体和故事线触发召回；作者预计章节与人物实际期限分开。 |
| 规则和资源 | 规则版本、生效区间、前置条件、用术时间及冷却；精确十进制余额与转移，数量不明保持未知。实际 chapter delta 的行为参与检查，已知矛盾阻断整笔事务。 |
| 人物与重复情节 | 保存欲望、策略、选择、代价、关系、结果与不可逆后果；重复模式给出带证据的审查提示，不自动判定文笔。 |
| 正文与状态 | 正文、卡片和 world_changes 同事务提交；正文对象按 SHA 去重且禁止原地改写；章节、历史与导出引用对象。 |
| 中文检索 | 单字和双字倒排，支持句内两字姓名；按候选回读原文确认。候选或输出达到上限明确标记不完整；无结果且搜索未完成不能声称不存在。 |
| 历史修改 | 依赖声明可与章提交一起保存；候选分支、直接/间接影响、逐项审查、世界证据重绑定或有理由撤销、外改哈希绑定、发布后导出恢复。旧版在候选阶段保留。数千章影响范围分页读取，默认 64,000 字节预算；只审当前页不能冒充全范围完成，预算失败不留下半次修改。 |
| 快照与缓存 | 按出版 revision 从快照和真实事件还原卡片基线，未知事件拒绝猜测；原文旧版本可按章与 SHA 定点读取；缓存绑定正文与依赖版本。 |
| 迁移与恢复 | schema1 显式迁移至 schema2，迁移前一致备份与完整性校验，失败回滚；导出在数据库写事务之外进行，采用版本核对和操作锁。 |
| 大文本拆解 | 状态查询不再把来源全文/全部分析正文装入 Python；空白块分类一次保存，之后按块读取，保留旧断点与番外。SQLite 的 Unicode substr 仍可能扫描文本前缀，不宣称所有源文本操作为常数成本。 |

### 使用边界

默认 strict 完整哈希核验历史导出，成本仍随全书增长；它允许检测时间戳和大小未变的外部修改。显式 local 只处理当前和队列中的文件，必须看未核验历史数量，`exports_complete: null` 不等于全书完成。新会话、故障恢复、发生外部改稿及阶段交付应完整 audit。

容量夹具使用重复汉字和受控状态，不含完整文学事件史。单次 warm 耗时受设备、文件系统、索引内容和并发工作影响；Python 分配峰值不是进程全部 RSS，逻辑读取量不是物理磁盘 I/O。100 张全局硬卡超预算会报错，不能靠静默丢弃来节省 token。

领域回归含跨 300 章编号的远期伏笔模拟，实际 CLI 演练保留精选短场景。它们验证状态与工具路径，不证明已经写成百万或千万字作品。依赖完整性仍要逐章语义审查；遗漏声明的后文会扩大复核范围，不能自动跳过。数字已知才能算账，缺失记录不能伪造事实。未声称真实账单降低固定比例，也未声称文学质量胜过上游。
