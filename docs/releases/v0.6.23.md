## 本版变化

### 采用新书名，保留作品身份和文件位置

已有书库可用 `book-title --book "<实际书根>" --title "<采用的完整书名>" --expect R` 更新书名。命令核对当前 revision，在同一事务中更新元数据并记录变更；同名调用不重复记录事件，旧 revision 请求会拒绝。工作台刷新后及新准备的发布清单使用新书名。

书 ID、书根、章节文件、已登记或预留的短篇全文路径保持原值。旧 `.txt` 全文按原登记名称迁移到 Markdown，避免改名后丢失既有全文位置。已有发布清单保留冻结书名，若需要新书名材料须重新准备。创作约定、规划、封面和平台书名按本次授权分别同步，命令不会替作者修改这些材料。候选命名或只读审查不触发书名更新。详见[已采用书名变更](../../skills/story-skill/references/project-state.md#已采用书名变更)。

### 平台草稿在实际操作前再次核对

浏览器与宿主 Chrome 桥接在读取、填入和点击前核对当前账号、作品、草稿身份、字段目标和操作按钮；已分配的草稿 ID 不能在保存期间消失或换成另一篇。正文输入核对实际焦点，保存按钮核对当前文字、可用状态和完整链接目的地，避免继续操作已经变化的页面。

回读结合当前字段快照及账号、目录核对；已读标题或正文在核对期间变化，字段消失、重复或被替换，均停止核对，保留实际错误。首次加载与已经观察到的页面变化分别处理，不能把变化隐藏为重新等待成功。产生远端副作用后仍不能确定结果时，先只读对账，不盲目重发。

番茄必须配置独立只读预览，缺失时在浏览器启动或连接前阻断；独立浏览器与宿主模式都不回退到编辑页查看旧稿。预览解析保留空段和字面空格，仅按已核对格式处理末尾哨兵；正文格式不同或未完整加载时拒绝猜测。新建、就绪与保存标志须来自实际 DOM，宿主配置中的账号、作品、草稿地址及目录页签映射也在连接前核对。

Chrome 连接的发现与初始化串行处理，初始化失败留下的元数据与尚未完成的请求分别判断；未知队列不被当作可忽略残留。草稿停用同样检查是否仍有可能创建稿件的操作。以上是程序行为修复，真实平台操作范围须依据本轮独立证据确认。详见[平台草稿说明](../../skills/story-skill-publish/references/platform-drafts.md)。

### 找回超过一页的恢复记录，恢复备份后重新连接 Chrome

书架恢复中心先选择作品，再与编辑页共用分批读取；每页最多100条，可继续加载尚未扫描的目录。记录按发现顺序追加，目录未扫完时保留未完成提示；游标过期、目录变化或读取失败时，已经列出的记录仍可打开核对，并可重新读取。它列出的是磁盘恢复副本，不能据此判断其他页面的未保存文字已经找回。

整书备份恢复保留原作品身份、文件和桥接请求证据，同时把恢复副本中的旧 Chrome 会话标记为不可继续使用，避免恢复旧连接租约后误接原执行端。恢复后须重新连接平台执行端；原作品与副本应分别核对，避免同时编辑。恢复仍只写入新目录，失败现场与旧副本保持可核查。

### 研究抽样兼容旧材料，静态页面来源更严格

- 重复标签按筛选前本组全部有效作品计票，不再受报告前50项的展示限制；新样本使用 schema 2、算法 2。历史 schema 1 样本按原方法严格重算，保留原样本 ID 和研究证据。采用新算法须另存样本和研究版本，不直接迁移旧验证。
- 七猫静态 HTML 解析排除 `template`、`script`、`style` 和带 `hidden` 属性的子树；嵌套行内标记不再人为插入空格，块级内容保留必要分隔。含糊的模板或自闭合结构拒绝猜测。
- 自动选择理由过长时，仅缩略可编辑的候选说明并标明完整理由位置；完整原始样本及 ID 保留。研究交接同时显示实际抽样方法，便于核对旧材料。

这仍是静态 HTML 解析，不执行 JavaScript、不计算 CSS，实际可见性须对照页面核对。内置来源仍限七猫公开书库的点击排序观察样本；没有新增其他平台直连采集器，也不据此声称网站重新实采、覆盖全站或商业效果已验证。详见[扫榜与抽样](../../skills/story-skill-research/references/rank-scan.md)和[研究交接](../../skills/story-skill-research/references/research-handoff.md)。

### 创作与试读按实际阅读位置判断

调研入口明确支持试读方案、追更验证及读者反馈分析。可先设计分次提供正文的试读，分别记录当场满意、口头续读意愿和后续实际返回；未获得下一次阅读机会不算流失，不套统一留存率。只设计方案时标明未执行，不自动邀请读者、上传作品或安排任务。不同意见先对齐版本、已读范围和目标读者，按原文区分理解障碍、兑现不足与审美偏好，保留分歧，不按多数票折中改稿。

规划、写作和审稿增加“同一回报的成稿对照”：事件已经成立却显平时，先检查兑现时刻、人物回应和叙述停留，不一律加阻力、误会或意外。规划下一卷先核对前卷结束条件是否已在正式正文达成；推迟目标须说明跨卷因果。短篇正式修订若改变封面表达的人物事实、关系、核心物件或阅读承诺，须查看已有封面并按授权处理失配；无关校对不重制封面。

规则与例子不构成真实读者偏好或文学质量提升的证据；纯审查、方案设计和候选材料仍按各自授权执行。详见[分次试读](../../skills/story-skill-research/references/reader-validation.md#分次试读与追更验证)、[成稿对照](../../skills/story-skill-write/references/drama.md#同一回报的成稿对照)与[短篇修订交付](../../skills/story-skill-write/references/chapter.md#短篇完本与修订交付)。

## 分发与版本

本轮拟保持八技能、69个源载荷文件和20个 Python／MJS 运行时文件；实际成员、摘要与构建来源仍须逐项核对。

| 分发入口 | 计划内容 |
|---|---|
| 主发行 `v0.6.23` | 标准八技能 ZIP、Claude 桌面单入口 ZIP、Codex 本地市场 ZIP、Intel Mac 0.1.26／build27 的 ZIP 与 DMG，各附 `.sha256`，共10附件 |
| 独立 Windows 发行 `windows-v0.2.2` | C#／WPF／.NET 10／WebView2 客户端，内嵌 Story Skill 0.6.23；安装程序与便携 ZIP，各附 `.sha256`，共4附件 |
| GitHub Packages | `@ningcui29/story-skill@0.6.23`，随主 Release 的正式发布自动同步；实际注册表下载与独立复核另行记录 |
| 版本分支 | 拟使用 `version-0.6.23`；远端建立与最终文档提交待实际回读 |

Windows 0.2.1 起检查独立的 `windows-v*` 正式发行；主 Story Skill Release 保留 latest 入口供技能与 Mac 使用。主发行和独立 Windows 发行分别核对标签、来源和资产，不把一个入口成功视为另一个已发布。Mac 使用本地临时签名、未经 Apple 公证；Windows 应用安装程序未签名。各自系统和原生验收范围见实际回执。

## 沿用能力与边界

<a id="平台草稿的实际范围"></a>

当前只沿用已公开的历史平台范围：番茄指定合成稿的单卷完整列表，以及另一篇经单独排版修复并只读全文核对的草稿。本轮程序修复不自动扩展为真实整批保存、分页、多卷、七猫或起点的实页验收。不执行提交审核或定时发布；新增实页结果须以本轮明确授权和独立回执登记。[历史范围](v0.6.22.md#平台草稿的实际范围)

发布技能、客户端或 npm 包不会自动更新本机安装、重启已有作品服务、采用候选或变更作者书稿。用户环境验收与 CI 分别记录；试读设计不等于已招募真实读者或验证持续追更。
