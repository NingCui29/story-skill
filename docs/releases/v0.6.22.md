## 本版变化

本版把市场观察、进一步阅读与原创选题连接起来。研究材料保留来源、样本范围和未决问题，后续任务可以沿同一研究版本继续核对。

- **保存与核对样本：** 记录来源 URL、采集时间、页码、覆盖范围、指标口径与限制；检查结构、同书身份和覆盖声明。缺失指标保持未知，同名不同书分别保存。
- **分组比较：** 对同书去重，保留相反观测；按平台、时间与指标等口径分组，分别统计分类、标签频次、字数和书名字面模式。跨来源的指标不合成热度总分。
- **挑选阅读对象：** 在一个可比分组中按分类、标签、标题或字数筛选，确定性选择最多20本进一步阅读的作品；保留选择理由、原始快照与可重算的抽样条件。
- **承接拆文与规划：** 从样本生成待填写的候选方向和写法假设。拆文后追加支持、反驳、混合或证据不足的记录，再导出可读的分析任务和规划候选；反例与未读范围始终随交接保留。
- **核对引用版本：** 本地原文和报告记录 SHA-256，正文摘录须精确存在于本地 UTF-8 原文；引用文件、假设或关联对象变化后拒绝直接沿用旧验证。网页引用保留为来源声明，不由研究命令自动下载。

新增 `rank-template`、`rank-collect`、`rank-check`、`rank-aggregate`、`rank-sample` 与 `research-init`、`research-check`、`research-verify`、`research-render`。这些命令无需 `--book`，输出到新的研究目录；不建立书库、采用规划或改写正式正文。八个技能入口保持不变，调研、拆文与规划按任务需要读取对应流程。

## 采集与研究的实际范围

当前唯一内置网络适配器是**七猫公开书库的点击排序新书观察样本**：30万字以下、3天内更新、连载中，最多10页、每页15本。该筛选不能证明近期首次发表；未解析频道，不能宣称覆盖全频道。它不是七猫正式排行榜，也没有公开的逐书点击数；无可靠指标时保持 `null`，不能用页面名次代替销量或读者人数。

采集支持有界公开 GET，或导入已授权浏览器保存的完整 HTML 与实际 URL。验证码、权限拒绝、WAF、未加载列表或结构变化均保留失败，不转成成功空榜；导入 URL 与导入时间不能证明页面的原始来源和抓取时间。番茄、起点等来源通过现有联网工具或已授权浏览器记录后，使用统一快照核对与聚合；本版没有为它们新增直连采集器。

代表作抽样是当前样本中后续阅读对象的覆盖选择，不是随机抽样、质量排名、市场代表性估计或爆款预测。书名模式只统计字面片段与标点结构，不能据此判断情节、流行原因或点击率。样本、假设与模型的阅读解释不能代替真实读者反馈或平台经营数据。

研究程序核对结构、来源关联、文件版本及字面摘录，不证明实际读完、文学解释成立或商业可行性。已有明确授权的规划按授权继续；没有采用授权的方向仍是候选，研究交接不扩大写作、试投或平台操作权限。

## 失败记录与修复范围

首轮1649d56的[源码CI](../../benchmarks/results/v0.6.22/before-utf8-fix/release/ci-attempt-1649d56.json)在Linux通过，两组Windows完整测试失败：独立研究入口未固定UTF-8编码，多行引文夹具在Windows被转换为CRLF；Python3.10另遇50毫秒真实时钟夹具的启动调度影响。a5ebaa5仅为两个独立CLI入口设置UTF-8输出，明确夹具字节并同时核对LF／CRLF精确摘录，将时限测试改为握手后推进模拟时钟。生产引文匹配与连接期限保持原规则；所有新发行物重新构建，原失败和构建归档在[修复前记录](../../benchmarks/results/v0.6.22/before-utf8-fix/)。

1649d56的Windows原生构建首次在4条原有外观用例中出现3次进程15秒超时及1次VM1000毫秒超时，随后17条同类用例通过；JS与测试文件同v0.6.21字节一致。一次同SHA失败任务重跑通过，源码、测试及超时均未修改，具体迟滞原因仍未知；见[只读诊断](../../benchmarks/results/v0.6.22/before-utf8-fix/release/windows-attempt1-triage.json)和[旧来源结果](../../benchmarks/results/v0.6.22/before-utf8-fix/release/windows-ci.json)。这不替代新来源的原生验收。

a5ebaa5的Windows原生构建首次已通过；随后发布任务因草稿标签与目标不符正确拒绝上传。原因是维护时仅更新目标提交而漏传`tag_name`、也漏核标签，草稿被改成`untagged`。显式同时修复标签和来源并回读后，仅重跑失败的publisher任务一次，沿用原native产物成功上传；源码与原生构建未因此改动或重跑。见[元数据修复](../../benchmarks/results/v0.6.22/release/windows-publisher-metadata-repair.json)、[首次失败](../../benchmarks/results/v0.6.22/release/windows-ci-attempt-a5ebaa5.json)及[最终回执](../../benchmarks/results/v0.6.22/release/windows-ci.json)。GitHub在attempt2展示的native记录不代表再次执行。

## 沿用能力与边界

<a id="平台草稿的实际范围"></a>

本版没有扩展平台草稿的真实后台验收范围。历史实页证据仍为番茄指定合成稿的单卷完整列表，以及另一篇经单独排版修复并只读全文核对的草稿；这不构成本版自动整批保存、真实分页或多卷验收。七猫、起点实页仍按各自实际结果登记，不执行提交审核或定时发布。详见 [v0.6.21 平台草稿范围](v0.6.21.md#平台草稿的实际范围)。

发布技能、客户端或 npm 包不会自动替换本机安装、重启已有服务或变更作者作品。Mac 验证限定 Intel；Windows 原生 CI 与各用户的 Windows 10／11 人工使用分别记录。完整技能规则安装到所用助手，客户端提供本地书稿管理与运行时。
