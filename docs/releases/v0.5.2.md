# v0.5.2：大纲规范、状态保护与修订恢复

> **历史名称遮盖：** 本页记录 v0.5.2 发布时的结果，但当时的固定标签、附件和包身份并未更名。下文名称替换后的路径仅供阅读，不能当作该版本可执行的安装地址；记录中的来源路径与哈希可能无法用遮盖后的文件复验。实际旧版资源请到[该版本 Release 页面](https://github.com/NingCui29/story-skill/releases/tag/v0.5.2)核对。

本版面向 macOS／Linux，沿用七个技能入口、33 个载荷文件和 schema 2。v0.5.2 已于 **2026-09-11 16:06:25（北京时间）** 发布，固定标签提交为 `c50bd28b14b128e287dc18f7cf12a692c4da82be`；固定标签、远端 CI、Release 附件、隔离安装与 GitHub Packages 的实际完成状态分别见 [发布记录](../github-release.md#v052-发布验证记录)。此前 v0.5.1 及更早版本的标签与附件未更名；验证数字保留，名称已遮盖。

## 作者会看到的变化

长篇规划按“全书总纲 → 第X卷 卷名／本卷大纲 → 第N章 章节名称”保存，细纲一章一文件，正文另存 `chapters/`。同一范围保留一个清晰的当前入口，旧版本归档到 `99_历史版本/`；继续细化时更新对应卷、章，不再平铺多份范围交叠的“前十章”“第十一至十六章”候选稿。已有等效目录继续沿用，整理不自动批准候选方案，也不批量移动托管正文。[规划用法](../中文小说上手.md#大纲细纲怎样保存) · [目录示例](../目录结构.md)

已经采用的细纲与工具章计划同步；续写前定点核对当前章的目标、场景、停笔点、章名、卷名、篇幅与约束。卷名决定文件位置，卷的稳定 ID 才参与局部约束关联；尚无这类关联时明确列入本章必需卡片，并确认实际召回。已有采用依据不需要重复确认，未决候选也不会写进当前计划。

在使用本版完整技能的会话中，可以直接说：

```text
$story-skill-plan 按全书总纲、具名卷纲和逐章细纲整理这本书的规划。
保留候选与已采用的区别，归档旧版，核对引用和已采用的工具章计划，不要写正文。

$story-skill-review 继续这次历史修订，先找分支断点，读取候选和依赖，
核对受影响的后文、状态卡及世界证据，保留原版，完成审查后再发布修订。

$story-skill-analyze 继续这份分析，找回已完成块与未完成问题，
回读所需原文并核对当前分析版本；已有定稿但未导出时先恢复交付。
```

## 状态与世界判定修复

| 触发情况 | v0.5.2 的处理 |
|---|---|
| 只更新已有卡片文字或来源 | 按 ID 合并显式字段，保留省略的硬性标记、类型、范围、标签及到期章；解除限制须明确填写 |
| 一个角色同时持有多件物品 | 规范明确事实是单值状态槽；按各物品的“持有人”分别记载，防止并存关系互相覆盖 |
| 有正文证据的起始余额为零 | 接受 `opening=true` 且 `amount="0"`，普通转移仍必须大于零，未知基线不冒充零余额 |
| 新认知、施术或故事线事件的时间未知 | 保留无法排序的候选和待核提示，不把未知时间当作最早发生，也不用发表顺序替代故事时间 |
| 只有甲获得新版能力规则 | 先按人物和故事线筛选适用范围，再选择版本，甲的升级不会解除乙的旧限制 |
| 同章同一伏笔在同一已知刻度多次变化 | 新增歧义被拒绝；旧有歧义保留并提示复核，不按记录 ID 决定最终状态 |

同刻度伏笔变化需要根据正文核对先后并统一更细的故事时钟；不能编造时间通过校验。未知时间的多条状态同样需要原文复核，程序提示不能代替语义判断。[世界状态实操](../超长篇实操.md)

## 历史修订与正文保护

最新章产生的卡片若在提交后已有更新，普通替换和外改对账会保留当前状态并要求进入历史修订。通过 `world-save` 后补的正文证据也纳入保护，不再只检查最初提交回执有没有世界增量。

历史修订增加独立的 `history-dependencies` 查询，能够读取早期章和本分支的候选依赖；`chapter-read` 支持按真实正文 SHA 分段读取尚未发布的候选。查询结果只帮助定位和核验，不把候选升级成正式正文，也不把当前卡片冒充旧章起草时的快照。

导入的已有作品若缺少受影响章节的计划，先根据已采用细纲补齐计划，再创建历史分支，避免分支建立后补计划导致基线过期。历史审查接受 `advice`，兼容旧 `minor`；`blocker` 与 `major` 仍阻断发布，不能降低级别绕过问题。[恢复步骤](../recovery.md) · [历史修订规范](../../skills/story-skill-review/references/history.md)

## 分析保存与断点恢复

`findings` 返回真实块号及 `start/end`，可用于 `source-read` 定点回读；复制查询结果进行修订时，范围属于只读元数据，不会写成分析正文。逐块替换和首次定稿绑定所依据的分析指纹，旧会话不能覆盖新结论或冻结过期报告；旧版本事件和已定稿报告继续保留。

手工调用工具或自编脚本需要更新两处：

- `record ... --replace`：先读取 `findings.results`，在输入中保留该条原有的 `analysis_sha256` 后修改内容；`chunk_sha256` 只标识原文，不能替代分析基线。
- 首次 `report`：聚合时保留 `findings` 顶层的 `analysis_sha256`，跨页必须一致，使用 `--expect-analysis SHA` 提交；基线改变后复核受影响论证，不只换 SHA 重交。

相同内容重试保留原有恢复能力。已登记 `report_path` 不代表报告文件已交付；先检查待导出和外部修改，按 `export` 或 `export --safe-only` 恢复，再核对文件哈希。已有工具定稿需要内容修订时，仍另存独立修订稿。[分析恢复与命令](../recovery.md#分析稿修订与续跑)

## 验证与成本

发布版已在本机 Intel macOS／Python 3.12 完成 443 项测试（436 项通过、7 项按条件跳过、零失败）与 12 项整包检查；v0.5.1→v0.5.2 整套升级 18 项、三类合成旧库迁移和四种合成容量组合也通过。远端 [最终 CI 34577137667](https://github.com/NingCui29/story-skill/actions/runs/34577137667) 中，Linux 443 项有 431 项通过、12 项按平台跳过，全部步骤成功；Windows 首项测试因已知报告导出 WinError 32 失败后停止，整体 CI 为失败。Release 附件回下载、官方固定标签隔离安装及公开 GitHub Packages 回下载均通过，33 个技能文件与发布源码一致，npm 的 2 个包装文件及独立运行检查也通过。工程与分发回执保存到 [v0.5.2 验证目录](../../benchmarks/results/v0.5.2/README.md)。历史文学评阅原稿、来源和模型意见保持原样，本版没有重新进行文学质量对照实验。[作品深读与评估边界](../作品深读与评估.md)

本版重新测量的普通／多线写作冷加载指令为 **6,324／8,511 tokens**，全篇深读／含教学示范为 **4,959／6,968 tokens**，审稿／冲突审稿为 **2,868／4,198 tokens**。七入口名称与描述合计 313 tokens，另行统计。计数不包含正文、推理、工具结果、宿主提示或实际账户消耗，也不能证明文学质量更高。[完整计数与文件哈希](../../benchmarks/results/v0.5.2/tokens.md)

## 安装与兼容范围

按 [INSTALL.md](../../INSTALL.md) 安装或升级完整同版套件，保留旧技能与本地修改。现有 schema 2 书库不需要重新导入；旧章路径继续按登记位置读取和恢复，新章仍为 `chapters/第X卷 卷名/第N章 章节名称.md`。套件附件为 旧名称 ZIP 附件（v0.5.2） 与同名校验文件，npm 包为 旧名称 npm 包（v0.5.2）；npm 不会自动注册为技能。

**Windows 正文和报告导出的已知 WinError 32 未在本版修复，Windows 用户继续使用固定 v0.4.0。** 已用 v0.5.x 处理的书先完整备份，不盲目降级或覆盖待恢复内容。远端 Windows runner 的执行与本机 Intel macOS 验证分别报告，不互相替代。
