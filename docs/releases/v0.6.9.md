# Story Skill v0.6.9 发布候选

候选源码包含八个技能、44 个载荷文件；当前已核验的公开发布版仍为 v0.6.8。运行时版本号和本地安装副本不证明本版已有固定标签、Release 附件或 GitHub Packages。下述变化以发布提交的最终差异为准。

- 新增已采用细纲与章计划的显式版本绑定。`outline-bind` 记录所审阅 Markdown 文件与计划的摘要；文件或计划改变后，`context`、`lint`、`prepare` 和提交会报告漂移。工具只核对版本与采用声明，不能证明自由文本和结构化计划在语义上相同。
- 新写完整章节要求纯文本首行章名与计划一致，章名在全书内不重复；卷号、卷名与稳定卷 ID 不得互相冲突。旧正式章、导入基线和未保存的历史章头仍按各自兼容边界处理，不能用新计划伪造旧章名。
- 新写完整章节默认按正文 2400—2800 个可见非空白字符规划。非默认篇幅或计数口径须在章计划保存 `length_exception` 的明确来源；引用书根 `创作约定.md` 时还须核对当前文件中的连续原句。旧正式章节不因本版规则自动扩写。
- 短篇完本阅读合本使用书名命名的 Markdown 文件，保留逐章正式稿的来源核对；旧文本合本的恢复与迁移按实际登记状态处理。
- 写作与审稿参考补充悬疑线索的知情、载体、时间和空间连续性，以及番茄、七猫投稿前内容风险核对。文学读感、内容登载要求与签约结果分别判断，本地检查不保证平台通过。

发布前须核对完整工作树差异、全部 44 个载荷文件与安装器和打包白名单，运行本地回归及 ZIP、CLI 验收。发布时固定同一提交建立 `v0.6.9` 标签和版本快照分支，再上传该提交构建的 `story-skill-0.6.9.zip` 与 `.zip.sha256`；发布后分别核对 Linux／Windows CI、附件回下载、固定标签隔离安装、GitHub Packages 工作流和注册表回下载。实际提交、摘要、测试数与运行链接在这些步骤完成后记录，不沿用 v0.6.8 的结果。

本地发布候选在 Python 3.12 下运行 880 项单元测试，35 项按条件跳过，零失败；CLI 冒烟、中文事务与长篇历史修订验收通过。ZIP 含 44 个载荷文件，大小 276,526 字节，SHA-256 为 `c0f20d7e63cb482cb1882aad4175191c78f3d21124ea098d182e127deae8321c`。这些是本地结果，远端 CI 与附件须在发布后独立核对。
