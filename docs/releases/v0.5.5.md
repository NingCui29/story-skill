## 历史修订：保存的决定可取回，关联后文须重审

新增 `history-saved --branch B`，完整读取分支已保存的卡片决定、世界记录修改和整体审查，包括删除用的 null、原引文与理由。原输入文件丢失后可据此接续；候选正文和逐章审查仍由 `history-inspect --chapter N` 读取。过期或已发布分支也可回读，但不刷新原哈希、不自动恢复旧审查效力。回执绑定同一次读取快照；预算不足时明确报错，不截断保存内容。

`history-deps --chapter N` 可以只读取得正式章的完整依赖声明，无需新建分支或补章计划。原始依赖哈希、完整性声明和说明保留，不将当前状态悄悄替换成当时使用的证据。

历史分支若额外改变卡片或世界记录，复核范围会沿已记录的依赖、正文证据及事实到认知／规则的显式关系扩展，包括经由作者计划记录衔接的消费者。实体／规则简写与类型化引用统一匹配；同值规范化不误作改变，已扩大的范围不静默缩小。新增范围会清空旧审查；旧候选及缺计划情况可按回执补齐、刷新并重交，未经复核不能发布。发布回执保留实际变更的世界记录引用，供下一次修订追溯。

范围推导只覆盖已记录的关系，无法代替对未声明剧情关联的人工阅读。依赖哈希记录原消费版本；审查后的世界修改仍可能使旧缓存失效。[历史修订用法](../../skills/story-skill-review/references/history.md) · [独立恢复与范围核对](../../benchmarks/results/audit-branch-recovery-2026-09-12/validation.json)

## 世界状态：保留不确定性，补齐后续变化

- 普通章计划即使没有可选的世界字段，也会召回已有全局规则；局部资料仍须正确关联实体、故事线等稳定 ID。
- 日期不明的流水不会被当作开账前事件而丢失。同刻度收支按持有人和资源合并检查：确定不足仍阻断，取决于收入先后的情况提示待核；未知额外支出不掩盖已知的最低资金缺口。
- 同刻度的事实、人物认知和故事线状态无法排序时保留候选，不凭记录 ID 或发表先后选出确定状态。作者计划、人物相信的命题与正文事实继续区分。
- 物件转手、人物认知变化时，会补读同一状态槽的后续记录，不因新记录未重复关联旧主人或物件就沿用旧状态；查询先去重状态槽，避免重复读取同槽历史。
- `status` 和 `world-check` 使用一致的读取快照；世界检查回执带书籍、章号与状态版本。写作依赖候选补齐所选卷段和故事线候选，并保留世界警告；哈希不代表歧义已解决。

## 日常用法与恢复说明

单次局部点评默认直接依据可见文本回答；需要恢复进度的全量、跨轮分析或用户要求建立工程时，再进入分析库流程。简单资料问答直接回答；需要跨轮复用、明确保存研究包或已有归档约定时才落盘。近期细纲按本次授权确定，3—5 章只是未指定范围时的默认值。这些调整不改变已有书目录、规划授权或用户明确保存的要求。

字数统计在计入标题时排除 Markdown H1 的可选尾部闭合标记，保留标题中的 `C#` 等实际文字。安装回退说明明确区分差分备份和完整套件：恢复前补齐并核验目标旧版七个技能，不把仅含变更目录的备份当作完整安装。[字数口径](../../skills/story-skill-write/references/chapter.md) · [回退步骤](../github-release.md#补齐依赖与历史回退)
