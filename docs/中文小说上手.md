# 中文小说怎么用

本页的新命名入口对应 v0.6.0 源码，完整套件有 8 个技能、38 个载荷文件；远程可用性以该版 Release 附件及回下载验证为准。本页的短篇全文合并、旧短篇补章与合法全文文件名、完本封面联动和总纲平台分类要求从 v0.5.10 起提供；v0.5.11 增加已审查章节的离线发布准备。

作者直接向 助手 说要求。助手 负责建目录、读断点、维护计划和审稿材料，不需要作者学习 JSON 或自己计算哈希。先按 [安装与升级说明](../INSTALL.md) 安装同版完整 8 个技能；本页沿用 v0.5.6 起的基础流程，实际安装版本、平台范围与发布状态以安装指引为准。已有旧版时保留旧版与本地修改，按原安装方式升级整套，无需重新导入书库。源码位于 `skills/`，克隆仓库后也需安装才能调用。下面的 `$story-skill` 总入口用法继续适用，任务明确时可直接使用 plan、write、analyze、review、publish 等专用入口。[目录与分工](目录结构.md)

v0.5.10 已修复 Windows 导出问题并通过当版原生 CI，验证范围以[版本说明](releases/v0.5.10.md)为准。以下使用 macOS 路径举例，请替换成自己的实际目录；不以示例路径或命令形式推定覆盖所有 Windows 环境。

v0.5.10 的变化包括完整短篇交付、全书完本审查和中文语法标点指导；当版固定标签、附件、CI 与 Packages 的真实状态见[历史验证目录](../benchmarks/results/v0.5.10/README.md)。v0.5.11 的远端分发与跨平台验证以实际[发布记录](github-release.md)为准。v0.5.6 奠定的拆书恢复、试写分流、正文纯文本格式及策划目录继续沿用；[历史记录](../benchmarks/results/v0.5.6/README.md)保留原范围。本机安装不会自动更新，工程验收不代替文学评估。

按现有创作指导，开书时核对书名、简介和题材承诺是否与情节安排相符；写正文时完整核清必要依据，按其对选择、关系和氛围的作用安排详略；审稿时补读疑点所需的前后正文，在授权范围内修订。可以直接说“检查主要阅读承诺是否得到阶段兑现”或“核对这段过程哪些细节需要呈现，保留有效的人物体验”。这些要求不统一规定兑现章号，也不按数字或手续这一信息类型删减。

## 从拆书开始新起一本书

准备参考作品原文与写作父目录，使用 `$story-skill` 依次推进“拆书 → 方法提炼 → 原创开书 → 大纲细纲”。拆书先核对原文范围与引文依据；只给写作父目录时，分析默认放在 `作品分析/<参考书名>/`。转化时在新书的 `00_项目策划/参考方法与原创重建.md` 写清来源范围、方法的适用条件和新书中的具体改造，再设计人物、关系、矛盾、事件链与结局。已有分析目录和同类策划文件沿用原位置；参考剧情不进入新书事实。

新书确定正式或暂定书名后，建立独立书名目录，保存策划、全书总纲、具名卷纲和近期逐章细纲。每阶段留下实际路径与下一断点；本轮只授权拆书和规划时，“继续”仍推进这两个阶段，不自动开始正文。[完整可复制请求](../README.md#从拆书开始新起一本书) · [深读方法与评估范围](作品深读与评估.md)

## 独立试写与局部设计

只想试一个场景或叙述声音时，可以直接说“写一段约500个汉字的小说片段，只交正文”，不需要先定书名、卷名或建立章计划。独立局部设计也只完成所需方案；已有总纲则核对相关部分，没有总纲也不为这个局部方案补建整本书。[可复制请求](../README.md#先试写一段)与[开发试用](../benchmarks/results/standalone-writing-2026-09-19/README.md)记录原始范围。

试稿涉及已有作品时，仍核对必要约定与原文，保留试稿身份。正式续写、完整短篇或修改已采用细纲继续按原有流程处理；之后要求将试稿纳入书内时，再完成规划、审查和提交。

试写后裸“继续”仍沿用试写任务。若目标是书内下一章，但只要候选正文，可指定“只保存草稿，暂不提交”；按相关细纲和前文起草、核对后交候选稿，正式章计划和正文状态待明确采用时再更新。

## 开一本长篇

```text
$story-skill 在写作父目录 /Users/作者/小说 下开一本《雾港来信》现实悬疑长篇。
第三人称限知视角，靠人的选择和实物证据推动，不要超自然。
先给核心冲突、人物关系、全书从开端到结局的走向和分卷粗纲，
再给首卷卷名、本卷目标和前三章细纲，不要写正文。
```

开书先建立可见的书名目录。本例的书根是 `/Users/作者/小说/雾港来信/`，根目录保存 `创作约定.md`，独立策划与设定默认在 `00_项目策划/`，大纲细纲在 `01_大纲细纲/`，状态在 `.story/`；进入写作后，正文再保存在其中的 `chapters/第X卷 卷名/第N章 章节名称.md`。没有定名时先拟暂定书名并注明；用户已经指定最终书目录或继续旧书时沿用原位置。开书完成会给出可打开的实际书目录。

这项默认书名目录规则纳入 v0.5.3，由技能先选择最终书根再初始化。CLI 的 `--title` 仍只登记书名，不会自动在 `--book` 后补一层目录；旧书已经落在父目录时，先核对已有文件，再按实际需要整理。[书根选择与兼容说明](目录结构.md#小说一书一目录状态与可见稿件分开)

缺少可自行选择的细节，助手 会提出并采用方案，记录在书内 `创作约定.md`。尚未授权正文时，单说“继续”会继续设计。决定开始写时明确说：

```text
$story-skill 按已定细纲开始写第1章，2200—2800字，含标点，不含标题。
完成正文、人物知识和物件状态核对，保存审稿记录和下一断点。
```

以后说“继续这本书下一章”即可。指定“连续写完前三章”时，按章闭环到第三章，不反复询问。不要把仅完成前三章称为整本小说完成。

## 大纲细纲怎样保存

长篇默认从 `01_大纲细纲/全书总纲.md` 进入，再看 `第X卷 卷名/本卷大纲.md` 和本卷的 `第N章 章节名称.md`。章细纲一章一文件，场面设计放进对应章，近期逐批补充；全书和分卷先说明走向，不要求一次写完所有章细纲。已有等效目录继续沿用，短篇可以简化成一份规划。[目录示例](目录结构.md#小说一书一目录状态与可见稿件分开)

v0.5.10 起，无论长篇还是短篇，正式全书大纲靠前位置都列出篇幅类型、目标平台、该平台的分类栏目和拟选／已确认标签，并写明本书内容依据、来源与核对日期。多个目标平台分别记录。番茄长篇与短篇使用不同栏目；其他平台按实际官方页面或用户提供的后台截图核对，不把番茄词表直接套用。[字段示例与未核实项处理](../skills/story-skill/references/project-state.md#大纲中的作品类型与平台分类)

当前稿在文档头写明状态和更新时间，旧版进入 `99_历史版本/`。说“继续细纲”时更新已有入口，不再新增一串“前十章”“第十一至十六章”的并排候选稿。若整理已有文件，助手 会先备份、核对各版内容与引用；“候选”仍保留候选状态，未确定的分歧不会被整理动作自动定案。修改已采用细纲时，同步工具中的章计划；续写前再核对本章当前细纲与计划，已有采用依据不重复确认。工具不会自动读取大纲文件。

## 写完整短篇

面向番茄规划短篇时，在总纲或等效规划中从[短篇截图可见选项](../skills/story-skill-plan/references/fanqie-tags.md#短篇作品分类写入总纲)按作品实际内容选择“主分类、情节、角色、情绪、背景”，并写明选择依据及拟选／已确认状态；不套用长篇的阅读标签和内容标签。其他平台的短篇使用该平台自己的短篇栏目。

```text
$story-skill 在 /Users/作者/小说/新短篇 写一篇完整现实家庭故事，4000—6000字。
重点写两个都有道理的人怎样做出有代价的决定。先确定结局，再完成整篇。
不要用悬念收尾替代核心冲突的解决。
```

篇幅按所选口径实测：默认可见字符含标点；也可以明确要求“只计算汉字”或“汉字、字母、数字计数，不计标点和符号”。这几种都是字符数，不能当作网站实际显示的字数。稿件文件只放必要章名与正文，使用纯文本自然段，段间空一行，不手工缩进或添加 Markdown 排版标记。换人发言默认换段，同一人物紧密相关的动作与短对白可同段；对白标点、禁用破折号及书信等特殊载体按[成稿规则](../skills/story-skill-write/references/drama.md#成稿格式)处理。仅排版时只调整普通段落换行、空行和缩进，不改字词、标点或事实；作者说明、审稿意见另存。

以下完本交付步骤从 v0.5.10 起提供；v0.5.11 的合并稿内容从第 1 章章名开始。短篇完本后保留分卷逐章文件，并把所有已提交章节按章号合并成书根下的 `<书名>.txt`。命令为 `assemble-short --book "<书目录>" --final-chapter <最终章号>`；最终章号须与已提交章节一致，章节导出须完整且无冲突。新合并稿只含各章章名和完整正文，并登记为受保护的导出文件。

`init`／`status` 的 `short_assembly_path` 给出预期或已登记的全文相对路径。特殊或过长书名会得到合法文件名，完整书名仍保留在书籍信息中；按回执交付实际路径，不自行改名。旧的含书名首行合并稿在新版只读状态中标为 stale；下次执行 `export` 或明确重新合并时保留旧版备份并刷新。通过 `adopt` 接入的旧短篇需先核对真实原稿，用 `adopt-backfill` 补齐导入末章之前的缺章，再合并全文；它不覆盖已有章或回退续写进度，缺原文时说明缺口。[命令与边界](../skills/story-skill/references/project-state.md#旧短篇补齐原章)

已有全文在正式修订、对账、历史发布或新增章节后随导出刷新，包含当前全部连续已提交章节。交付时核对 `status` 中的 `short_assembly`、导出回执和实际全文；缺失或待导出时运行 `export` 恢复，有外部改动先保留并解决冲突。`short_assembly` 只说明同步状态和已合并章数，确认完本仍须核对实际终章、结局和全文。仅审稿不触发这些写入，单章续写也不自动确认全书完本。

每次明确完本交付时，核对现行总纲或等效规划的篇幅类型、目标平台、平台原生分类标签、实际正文依据、来源日期，以及拟选／已确认／待核对状态。缺项或与终稿不符时，保留旧版并按 [分类规则](../skills/story-skill/references/project-state.md#大纲中的作品类型与平台分类) 补齐；平台已确认值不静默改动，未核实项如实标注，不每章重复查平台。旧短篇在正式审稿修订或历史修订后明确要求完整成品，尚无全文时也完成首次合并，并交付实际封面和总纲分类；普通单章修订只核对已有全文同步，纯审稿或候选稿不自动生成首次成品。

首次完本全文核对通过后，还要输出封面图片。沿用与最终书名和内容相符的已有封面，或按 [封面技能](../skills/story-skill-cover/SKILL.md) 生成并保存到本书目录；新书可放在 `04_封面/`。检查可读书名、已有署名、尺寸和文件能否打开，交付时同时给出全文文件与封面图片的实际路径。没有图片产物不能把仅有的提示词或版式称为完本交付；未指定投稿平台时，图片的本地检查不等于平台审核通过。后续正式修订沿用已有合格封面，仅在书名、署名、题材或投稿规格变化时复核并按需修订，不因普通文字校对重新制图。

## 章节离线发布准备

发布准备能力始于 v0.5.11；当前源码入口 `$story-skill-publish` 只处理已审查并正式提交、导出完整的章节。先核对目标平台、作者提供的账号与作品标识、所选连续章号及当前稿，再建立冻结清单；这些标识是用户声明，工具不会登录或验证平台账号。

```text
$story-skill-publish 为 <书目录绝对路径> 的七猫作品准备第1至3章离线草稿材料。
核对正式稿、审查收据和导出后生成清单、材料 ZIP 与包外回执，
复核每章内容和包的原始摘要，给出人工填写时要逐项核对的内容。
不要上传、提交审核或设置定时发布。
```

可以用 `publish-list` 找回清单，`publish-export-list` 找回对应回执，再以 `publish-verify-export --receipt` 核对包与当前正式稿；后续改稿不会自动更新旧包，过期时应重新准备和导出。作者自行在后台填写后，如提供草稿副本，可用 `publish-compare` 做本地差异核对，明确要求留痕时用 `publish-compare-record` 保存摘要。副本核对不证明后台已保存、审核或上线。短篇全文合并、封面和平台分类仍按前面的完本流程分别核对，离线材料包不替代完整成品。[命令、状态与边界](platform-publishing.md) · [材料恢复](recovery.md#离线发布材料恢复)

## 修改与恢复

v0.5.6 按稿件身份分流：

| 稿件身份 | 本次处理 |
|---|---|
| 独立试稿或未托管文件 | 按要求审稿、修改；不为改结尾另建书库 |
| 书内下一新章尚未提交 | 按要求改草稿；已授权提交时完成首次审查、提交和导出 |
| 已提交的章节 | 核对提交身份和外改状态，再走最新章替换、对账或历史修订 |

只要求审稿或修改候选稿时，保留现行正文与已采用计划，规划差异随候选稿记录；一次只处理一个文件，也不能据此把正式章节当作未托管文件。[改动与试用](../benchmarks/results/review-routing-2026-09-19/README.md)

```text
$story-skill 修改这本书最新一章：压缩重复解释，保留原有对白声线、线索和停笔点。
复核上一轮已经解决的问题没有复发，保留修改前的版本。
```

如果已在编辑器改过正文，说明“以我当前的外部改稿为依据”。助手 会读取并核对外部版本，保留备份后提交修订。某章文件缺失时先查状态；同时有外改阻断，可用安全恢复再逐项对账。[具体恢复命令](recovery.md)

较早章节的重写会进入历史修订分支；最新章产生的状态卡在提交后又有更新时，也进入此流程。它保留原版，并列出受影响的后文与状态。助手 逐项完成候选稿、依赖和证据复核后，再一起发布修订、恢复导出并更新断点；复核未完成时原版继续有效。不要直接覆盖旧章后假设后文状态已自动更新。

## 深读已有作品

```text
$story-skill-analyze 完整深读 /Users/作者/小说/参考作品.txt，
把分析保存在 /Users/作者/小说/作品分析。
解释人物选择、叙述安排与情绪变化如何起作用，核心判断核对前后文和可能反例，
区分原文事实与解释，给出有适用条件的创作方法。
```

短评可以只问开篇或某一场景，不会自动扩大成全书分析。完整深读会保存来源、逐块证据和报告；遇中断后说“继续这份分析”，助手 先找现有来源与未完成块，不重复导入。网页只有预览时，报告会说明可见范围；所有已导入块完成也不能单独证明全书无缺章。

修改已经写好的分析时仍用分析入口：

```text
$story-skill-analyze 复核这份分析的人物动机和结尾判断，回读相关原文，
保留原稿，另存完整修订稿，并留下未完成问题和下一步。
```

未定稿的逐块记录可以修正后继续聚合；已经定稿的报告另存修订稿，不覆盖原定稿。只有外部点评文档时直接修改文档，不必建书库。跨轮恢复会读取修订稿旁的进度并核对文件变化；书库里旧报告的路径不代表修订稿已完成。实际示例与评估边界见 [作品深读与评估](作品深读与评估.md)，具体恢复见 [分析稿修订与续跑](recovery.md#分析稿修订与续跑)。

## 看得到的结果

每本书包含可读的创作约定、按需设定/大纲、分卷正文，以及 `.story/` 内的计划、状态和审查凭据。新章固定保存为 `chapters/第X卷 卷名/第N章 章节名称.md`，例如 `chapters/第一卷 雨夜/第1章 雨中来客.md`；短篇与单卷作品也有明确卷名。助手 从已定规划补齐卷名和章名，已有旧章路径继续保留。完成回执至少说明实际篇幅与口径、已保存路径、未解决问题和下一断点。脚本通过仅说明字数、证据位置和保存一致；是否好看仍需读正文判断。

本仓库提供两套可读原创样稿：[长篇《渡口夜账》](../examples/渡口夜账/大纲.md)、[完整短篇《留半寸》](../examples/留半寸/drafts/01.md)。它们用于验证实际流程，题材和表达不是后续小说的固定模板。

复现同一批经过审查的稿件如何进入工具，可运行：

```bash
python3 -B -X utf8 scripts/chinese_acceptance.py --workdir "/tmp/新的中文实测目录"
```

目录必须新建或为空，避免覆盖已有小说。此命令重放已审稿件，不会重新调用模型，也不代表新一轮文学评测。
