# 工作台快速更新

开发目标：Mac **0.2.0 / build 40**、Windows **0.3.0**。这些编号表示当前源码中的新增能力；构建、正式发布、已安装及服务已加载分别验收。已发布安装包和下载链接继续按其原始版本记录。

## 用户流程

检查新版 → 核对分块清单及本地缓存 → 下载缺少的分块 → 合并及完整校验 → 保存作品并安装。

下载期间可以继续编辑。暂停、断网或退出后保留已经完整校验的分块，继续时重新检查缓存。单个尚未完成的分块重新下载，最多重复 4 MiB；缓存被清理或校验失败的分块也需要重新取得。进度按实际接收量及已复用量显示，速度与预计时间只按本次网络传输计算。合并、校验、安装使用独立阶段提示。

## 提速机制

| 机制 | 当前实现 |
|---|---|
| 按平台与架构选择 | 沿用各端的正式发行版本、平台及架构核对 |
| Windows 精简更新包 | 保留宿主、Python、.NET 和许可证；去掉重复携带的 WebView2 离线安装程序。检测到已有 WebView2 时优先选择，否则选择完整离线包 |
| 内容分块 | 对最终安装包的字节生成内容边界；前面内容增减后，后面相同区域仍可能复用。不是按版本维护补丁链 |
| 有限并行 | 最多同时下载 3 个缺少的分块；每个分块限制长度、偏移及 SHA256 |
| 暂停与续传 | 仅保存校验完成的分块；按内容摘要跨重试、重启及后续版本复用 |
| 完整包兜底 | 未提供分块清单，或服务器明确返回普通 200、没有提供范围响应时，使用完整下载。错误 206 范围、错误摘要或异常来源直接停止 |
| 安装保护 | 分块最终还原出完整安装包，核对官方整体大小和 SHA256 后才允许打开；沿用保存、正常退出、安装器备份与回退流程 |

缓存在任务开始和结束时按 512 MiB、2048 个条目及 30 天策略清理，活动任务为还原当前安装包保留所需分块。活动下载持有缓存锁，其他更新进程不能同时清理。Windows 原有完整包缓存仍保留最多两份、30 天策略。缓存限额可能使大安装包的一部分在后续操作时重新下载。

Mac 同版本优先选择有清单的包；都有清单时优先 ZIP，以复用按文件压缩的稳定内容区域。最终打开的仍是完整的 ZIP／DMG，不在运行中的 `.app` 内直接覆盖脚本。增量大小取决于实际相同的数据，不能按源码改动行数承诺固定百分比。

## 下载清单

固定格式为 `schema: 1`，只接受这一种格式。每个安装包附带：

- `<安装包>.sha256`
- `<安装包>.download.json`
- `<安装包>.download.json.sha256`

清单包括安装包名称、整体大小、整体 SHA256，以及连续覆盖全部文件的分块偏移、大小与 SHA256。清单本身最多 1 MiB、4096 块；生成器使用最小 256 KiB、平均约 1 MiB、最大 4 MiB 的内容边界。

客户端从当前官方 Release 元数据取得清单的 SHA256，再核对清单与所选安装包的名称、大小和摘要。缺少清单摘要或重复清单会停止；不能通过忽略错误清单绕过验证。范围请求始终从原安装包官方链接开始，重定向仍只允许既有 GitHub HTTPS 附件域名，不从清单读取任意网址。

首次采用本方案需要先安装一次包含新更新器的版本；既有客户端不会因发布新清单而自动获得续传能力。本次没有增加第三方下载镜像。若下载瓶颈是网络线路，需要单独配置和验证可控的分发源；并行请求不能突破线路总带宽。

## 构建与验证

Windows 先构建完整便携目录，再执行：

```powershell
python scripts/build_windows_installers.py --source dist/story-workbench-windows-x86_64 --output dist --compiler "C:\Program Files (x86)\Inno Setup 6\ISCC.exe"
```

脚本核对完整目录清单，生成独立精简目录；Inno Setup 分别编译完整离线安装器和 `-update-setup.exe` 精简安装器。精简安装器不使用跨文件固实压缩，便于后续复用相同区域；缺少 WebView2 时在停止作品服务前拒绝继续并提示完整包。完整离线安装包仍能为首次使用安装 WebView2。

Windows 工作流分别扫描完整／精简发布目录及实际安装目录，运行原生窗口和安装／卸载探针。草稿发布验证要求精简包的实际安装清单、安装器摘要、原生验收报告及所有下载清单都对应本次构建，方可上传候选附件；不能用仅构建成功代替 Windows 原生验收。

Mac 在完成 ZIP／DMG、签名及原有安装包验收后，为最终字节生成清单：

```sh
python scripts/package_update_manifest.py <最终ZIP路径> <最终DMG路径>
```

任何重新压缩、签名或修改安装包后，都必须重新在新的输出目录生成清单与校验文件。校验文件、清单和安装包属于同一次不可变构建。历史正式附件不覆盖。

## 本轮验收记录

- 内容边界生成、文件移位后复用、连续覆盖、整体及分块摘要、不可覆盖旧清单：由 Python 隔离测试验证。
- Windows 实际 C# 下载代码：验证最多 3 路、暂停等待所有任务结束、续传跳过缓存、缓存损坏、错误范围、错误编码、服务器不支持分块及最终整体摘要。
- Mac 实际 Swift 下载代码：在 URLProtocol 隔离网络及独立缓存中验证暂停续传、完全缓存后零分块下载、单块损坏重取、完整下载兜底、错误范围／编码／清单／正文及链接缓存拒绝。
- Windows 精简目录准备和分发拒绝条件有隔离回归；原生安装及窗口验收由 Windows runner 执行。本机 Mac 的 C# 编译及合约测试不代替该项。
- 实际通过数量和命令记录在本轮本地验收回执中；本文件不将尚未执行的 Windows 原生安装写成完成。

本轮提交快照的最终结果：桌面回归 122 项（118 通过、4 项原生 Windows 环境跳过），分发回归 32 项通过，C# 合约 48 项（36 通过、12 项原生 Windows 环境跳过），均无失败。Mac 完整原生源码类型检查、Windows WPF 交叉编译（零警告／零错误）、源码禁用技术检查和 Git 差异格式检查通过。交叉编译使用框架依赖模式检查代码，不能代替 Windows 自包含发行包或原生安装验收。

安装交接同时取消了对 `0.1/0.2` 的版本枚举限制，按三段数字识别本产品安装，避免 0.3.0 自身被后续覆盖或卸载流程拒绝。Windows 两种安装器共用 AppId，原生验收先完成并卸载精简包，再建立完整包升级场景；精简包探针发现已有登记安装时会在启动安装器前拒绝，防止测试覆盖正在使用的工作台。
