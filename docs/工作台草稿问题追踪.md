# 工作台草稿流程问题追踪

本记录覆盖从工作台发起的 Codex 平台草稿检查、确认同步、保存、独立全文回读和收尾。模拟测试、文件安装和真实后台验收分别记录；只有相应工作台路径实际通过后，才能关闭对应问题。

## 2026-11-06：历史助手收尾阻塞新检查

状态：处理中，尚未通过真实平台完整流程验收。

### 复现与证据边界

- 环境：Mac 写作工作台 0.2.10 / build 55，执行工具选择 Codex；现有番茄绑定，检查范围第 1—30 章。
- 从工作台点击“准备并检查差异”，复用本地批次后收到“当前作品已有助手协助任务运行，请等待完成”。本次检查为 0/30，没有执行平台保存。
- 点击“刷新任务状态”后，错误提示消失，恢复“尚未开始”的本地预览，但未说明具体占用任务或收尾状况。
- 展开“助手协助”，通过“读取助手状态 → 查看未完成任务批次”才能看到历史任务。该入口切换到历史执行工具和配置；任务已停止，但“等待收尾确认”不可操作，用户没有可用的恢复入口。
- 本机原始记录、模型运行依据及界面观察留在私有验收目录；本文不包含账号、作品 ID、私有正文、浏览器令牌或作者书根。

### 已核实原因

1. 工作台内置运行时与更新后的 Codex 插件不是同一安装副本。仅更新插件不会更新正在运行的工作台服务。
2. 旧工作台将“控制器已退出、但浏览器收尾尚未证实”的任务继续视为占用。这一保护不能直接删除；控制器退出不等于浏览器任务或已发送操作已经结束。
3. 本次有效阻塞项是两条历史 Qoder 只读任务。旧的 Codex `running` 原始记录已具有有效的外部会话隔离证据，不是本次阻塞源；排障必须计算有效状态，不能只按原始 `state` 字段判断。
4. 一条任务从未连接浏览器，新源码已有 `not_started` 识别；另一条任务的控制器已退出、租约和纯只读队列均已过期，但缺最终收尾回执，需要真实同浏览器标签清单证明原自建页面全部消失。
5. 新源码已有严格的只读会话对账机制，旧工作台内置版本缺少该能力，界面也没有将占用诊断及恢复串成可完成的流程。
6. 本轮由明确配置为 `gpt-6.1-terra` 的执行代理读取官方浏览器清单：当前连接标识与历史任务绑定不一致，旧标识未出现。因此不能用当前标签清单证明历史页面已关闭，不能按相同网址推定为同一浏览器。

只读会话隔离只解除已证实停止的旧执行占用，不代表旧检查成功、浏览器自然收尾成功或任何草稿已保存。写入结果未知的任务不可使用这两种只读恢复方式；必须保留原绑定和发送历史进行对账。

WB-DRAFT-006 的旧服务检查已实际确认：其停机门使用旧的任务状态计算，既不识别新源码的 `not_started` 证明，也不具备新的界面恢复入口。不能通过修改运行时文件、伪造完成回执、删除历史或直接杀进程处理；兼容恢复的实现及真实停机结果须另记。

### 实现与回归记录

- 作品页和书架的作品服务管理共用恢复界面与请求适配器；书架按登记的作品键和作品身份取根目录，不接收调用方提供的任意目录，也不另开编辑服务。
- 恢复交接固定原任务摘要、会话、绑定、队列与时效。回传原始观测后由服务端重新校验；旧失败内容和未知写入历史保留，不接受调用方直接声明清理成功。
- 未启动归档仅接受已结束、从未访问远端、两个控制进程均退出，且严格未启动证明通过的只读任务；原文件原样移入专用归档目录。回执与原字节校验、失败重试和历史读取均有测试，归档任务不能重新执行。
- 独立审查在开发过程中发现：磁盘任务若自行带有 `archived_never_started` 或 `origin_mismatch` 派生字段，可能提前被判为不占用。已在读取边界拒绝这些保留字段，只允许经实际归档回执核验后派生；新增运行中及未知写入负例，防止靠字段自声明解除阻塞。
- 后端组合回归已通过 111 项，命令：`python3 -m unittest tests.test_workbench_draft_cleanup tests.test_chrome_assistant_session tests.test_platform_draft_assistant tests.test_platform_draft_inspection_recovery -q`。禁止技术源码扫描及差异格式检查通过。测试使用合成书根，没有执行真实平台保存。
- 界面、HTTP 路由、书架管理、停机保护及相邻流程组合回归已通过 221 项，无跳过；使用真实 Node 运行模拟界面测试。共享脚本仅注入一次，关闭管理页会清除轮询，迟到响应不能污染重开后的页面。一次回归因其他代理同时修改源码触发运行时变更检测，冻结代码后整组通过；保留初次失败事实，不删除该保护。
- 主要回归文件：[恢复与归档](../tests/test_workbench_draft_cleanup.py)、[界面及 HTTP 路由](../tests/test_workbench_draft_cleanup_ui.py)。覆盖错误浏览器、仍存在的自建标签、活动控制器或租约、混入写操作、过期或变化的证据、异样重放、作品身份和请求来源、刷新失败、历史选择隔离及旧服务阻塞时的书架入口。

安装前已备份旧应用和 17 个作品根；58 份 SQLite 一致性备份通过 `quick_check`。当前可见正式稿已保存，另一个已注册旧页面无法在界面定位，仍须作者本轮确认其内容已保留；备份不代替未保存页面的确认。

本机 Codex 插件已同步，78 文件与冻结候选一致，八技能发现及实际安装副本的版本、帮助、隔离初始化／状态／审计和工作台 HTTP 检查通过。Mac build 56 候选已构建，严格签名和 25 模块摘要核验通过；原 build 55 尚未替换，正在运行的服务不能计作已更新。

### build 56 实页失败记录

- 新版书架在独立本机端口启动，仅登记原作品，不另开编辑服务。IAB 在本会话不可用，Terra 改用现有 Chrome 的一个自建临时标签访问工作台，原用户标签保留。
- 工作台“保存与停止”显示两条旧任务，但把后端明确返回 `mode=inspect_drafts`、`state=inspection_blocked`、两种恢复均可核验的任务显示为“保存结果未知”，两种恢复按钮禁用。直接只读业务接口回读确认后端状态正确，故不能将其归因于未知写入或用户未授权。
- 单击另一条任务的“原样归档未启动的旧任务”后，按钮和刷新入口持续禁用，未看到确认框或完成／失败反馈。Terra 未再次点击；浏览器无错误日志，现有可见对话框仍只有原书架管理框。尚未确认发出归档请求或生成归档回执，不能把该任务记为已处理。
- 后续只读核查更正上述“持续禁用”的判断：三个不同时间点的按钮状态为禁用、可用、可用，属于轮询期间临时禁用，并非永久死锁。两条任务原文件均存在且摘要与备份一致，未生成归档文件。
- 独立审查用生产脚本和合成 DOM 复现 WB-DRAFT-008：按下按钮后轮询开始，`replaceChildren` 移除原按钮并禁用新按钮，松开时无法向原目标派发点击，最终没有确认框或归档请求。该复现与实页观察一致；修复须保持稳定节点并处理确认期间的轮询。
- 本次未点击保存授权、未退出 Chrome、未重置内核、未停止原工作台服务、未执行平台保存。原通过的合成回归不能关闭 WB-DRAFT-007/008，修复后须重新从工作台复验。

### 修复与回归要求

- 占用提示直接显示实际阻塞任务、执行工具、时间、状态和未完成环节；刷新不能静默抹掉尚未解决的阻塞。
- 查看历史任务与本次准备执行的工具、批次分别展示，不能无说明地改变本次执行意图。
- 在工作台提供明确的只读收尾核验入口，复用现有身份、绑定、队列、租约及浏览器证据校验；不让作者手写 JSON 或手工清除记录。
- 从未启动的任务、控制器退出但收尾未知的任务、真实写入结果未知的任务分别处理。不得用超时、进程消失或按钮确认直接伪造 `cleanup_complete`。
- 真实写入结果未知时保留发送历史，并在原绑定下只读对账；不自动重建草稿、不重发、不跳过异常章节。
- 增加最小复现回归，并在实际工作台依次验证：进入面板、检查差异、处理阻塞、明确确认同步、实际保存、独立完整回读、停止和收尾。每阶段记录实际通过范围及未验证项。
- 安装后的工作台运行时、源码、插件与实际加载服务分别核对，记录版本、构建号及模块摘要。
