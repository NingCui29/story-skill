# 草稿执行工具选择

用户可以选择 Codex、Qoder CN 或 WorkBuddy AI 执行平台草稿任务。三端共用正式稿清单、平台目标、去重账本和独立全文回读，只保存草稿，不送审、不排期。工具不可用时明确停止，不自动切换；运行中的任务和写入授权始终绑定原工具。

## 工作台操作

在“平台草稿”的设置区，通过常显的“执行工具”选择器选择工具，再点击“检查差异”。原生工具会生成交接说明，由用户交给所选工具执行；工作台不会因生成了说明就显示已连接或已完成检查。

检查完成后，核对待新建、待更新和一致的章节，再确认生成同步任务。检查与同步必须使用同一工具。任务进行中或收尾尚未确认时不能切换；任务结束后可以更换工具，但需要重新检查，原结果保留为历史。当前选择仅用于本次面板，重新打开时默认 Codex。

选择器同时显示本机组件状态。找到 SDK 仅代表组件存在，仍须核验扩展连接及网站权限；组件缺失时保留用户选择并显示原因，不能执行，也不会改用其他工具。

## 助手命令

由助手根据实际本书清单与配置填写 `<tool>`、`<书根>` 和标识。`<tool>` 是同版 `story-skill/scripts/story.py` 的绝对路径。作者无需编辑 JSON、摘要或内部 ID。

```sh
python "<tool>" publish-draft-assist-prepare --book "<书根>" --id "<清单ID>" --profile "<配置文件名>" --host qoder-cn --allow-native-host-model
```

此步骤只准备本地检查任务，不访问平台。WorkBuddy 的宿主值为 `workbuddy`；未安装可核验的公开浏览器组件时，在领取任务之前停止。原生模型选项仅在用户明确授权本次任务后使用；默认工具仍为 Codex。

```sh
python "<tool>" publish-draft-assist-run --book "<书根>" --request "<请求ID>"
python "<tool>" publish-draft-assist-status --book "<书根>" --request "<请求ID>"
python "<tool>" publish-draft-assist-cancel --book "<书根>" --request "<请求ID>"
```

Codex 和 Qoder 的执行命令以宿主支持的异步方式运行，再按返回的 `assistant_context` 驱动官方 Node REPL。`first_call` 只调用一次，后续复用相同模块、SDK 和 factory。Qoder 返回 `running/cell_id` 时先用 `node_repl_wait` 等同一单元终态，不能重复发送操作。启动控制器前，须在同一已连接的 Chrome 中打开配置对应的目标作品管理页并完成登录；不因缺少尚未生成的 attach handle 而要求复制或伪造连接凭据。

WorkBuddy 使用不同的公开执行通道：交接说明先给出独立窗口的登录准备命令，登录完成后才启动本地控制器；再由 WorkBuddy 原生任务按 `assistant_context.runner_argv` 启动一次 CLI runner，持续等待同一进程。它不使用 Qoder 的 Node REPL/SDK，也不使用 Codex 自动执行器。浏览器或进程中断后保留真实停止原因与未知写入，不能重复运行已消费请求。

同工具的检查已完成、清理已确认且作者已授权同步后：

```sh
python "<tool>" publish-draft-assist-prepare --book "<书根>" --id "<清单ID>" --profile "<配置文件名>" --host qoder-cn --allow-native-host-model --mode sync_drafts --inspection "<检查请求ID>" --confirm-sync
```

已有整批授权无需逐章重问。只比较已有章节，缺失章节直接新建；仅去掉本地 MD 空白行，严格核对远端标题和正文。未知写入保留原 ID 和历史，先只读核对，不换工具、不重放请求来重发。切换工具后重新检查，不能沿用其他工具的写入授权。
