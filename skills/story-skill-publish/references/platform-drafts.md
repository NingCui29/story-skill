## 工作台入口

写作项目工具栏的“平台草稿”可列出全部已冻结正式稿清单，明确标识最新与历史批次；分析项目禁用。选择目标范围、匹配平台的本机页面配置和“检查差异并同步草稿”或“只读核对已有记录”模式。准备阶段核对现行正式稿并复用或生成本次冻结清单，不自动扩大范围。作者已有整批保存授权时，助手可按该范围执行；页面按钮不会因普通写作、采用或打开工作台自动运行。

“准备并检查差异”在本地资格、配置和签名预览就绪后，只读核对账号和作品，完整读取一次平台目录，只对实际已有章节读取全文并比较章名、正文；目录确认缺失的章节直接列为待新建，不逐章反复核对空目录。分别统计待新建、待更新、一致和无法确认，此阶段不保存平台草稿。检查完成后才提供“确认同步这些变更”，全部一致时无需同步。差异检查只绑定本书、批次、配置和正文版本，有效期十分钟且单次使用；同步开始重验一次完整目录，已有草稿写入前再核对其正文前镜像，检查后发生变化则停止。需要自动连接时，面板说明使用当前账号的 Codex 额度；组件可用不表示 Chrome 已就绪。

任务独立异步运行，面板分别显示本次检查、保存回读及历史记录；同步成功计数只包含本次已全文核对的章节。关闭面板不会取消已启动的本地任务，工具栏保留状态并可重新接回；“停止任务”等待正在保存及回读的章节完成，在下一安全边界停止。宿主模式仍需受控执行会话或当前助手持续服务，关闭工作台服务或执行进程不等于后台可无人值守继续；编辑器缓冲保留，未采用的内容不混入已冻结批次。未知结果先选择只读核对，过时或已取消批次也可核对冻结旧版；页面会说明它与当前正式稿的区别，不重建草稿。

本轮只操作用户既有、已登录且已通过官方 Chrome 扩展连接的 Chrome。`execution_mode="host_assisted_cua"` 需要活跃、通过健康探测的执行端；选择 Codex 时，实际 computer use 执行者须从运行环境确认模型为 `gpt-6.1-terra`。Qoder CN／WorkBuddy AI 只有在作者明确允许本次原生模型执行且公开浏览器组件可用时，才按下文原生宿主流程执行。工作台的 Codex 自动入口另要求受控执行会话模型核验，仍受官方宿主授权限制；当前助手的底层手工附着只能建立桥接租约，不能替代自动入口的模型证明。明确的助手协助任务使用下一节的独立交接流程，不冒充工作台已独立认证外部模型。没有合格执行端时阻断，不启动另一 Chrome、读取 Cookie 或切换到独立模式。进程退出后任务不会自动恢复执行，已持久保存的发送历史仍保留，不能据此自动重发。用户另行选择独立浏览器模式时，工作台默认给该会话十分钟人工登录时间；它与日常 Chrome 会话不同。等待不占用创作数据库事务。

**2026-10-29 接入历史：** Mac 0.2.9 / build 49 首次交付下述明确助手协助入口；之后已安装 0.2.10 / build 52，本节的旧验证记录不代表当前版本验收。独立自动检查最近一次真实验证在浏览器清单读取前断开，尚未确认恢复。公开 CLI schema 与桌面文档尚未确认供第三方工作台独立认证的“实时 Terra 会话身份＋浏览器授权”完整交接契约，`queue`、历史线程模型或上游 attestation 都不构成这一证明。已确认的启动期原生通道断线会暂停当前服务继续启动自动执行器；跨批次重试不能解除暂停，没有手工解锁或自动接回桌面会话的入口。下述助手协助不依赖该独立自动连接，也不宣称修复了它；本地准备、合成验收或当前宿主能读取 Chrome 清单，均不等于实际草稿保存通过。

页面配置保存在本书 `.story/platform-profiles/*.json`；番茄可用下述作者自助入口生成，其他已核对配置由助手维护。页面只选择配置名，不接收任意路径，自动生成的配置显示为“番茄本地配置 N”。预览绑定书籍、批次、配置哈希、操作模式、正文编码与比较策略，有效期十分钟；改稿、换配置或更改策略均须重新预览。重复点击只复用相同绑定的运行任务，完整执行历史仍以本地持久记录为准。

## 当前助手协助任务

源码在设置区常显“执行工具”选择器，用户选择 Codex、Qoder CN 或 WorkBuddy AI；“助手协助”区域提供检查、只读核对及交接说明。生成与复制仅处理本地数据，状态为等待所选工具认领，不代表已连接或检查。Codex 助手须先根据运行环境确认执行模型为 Terra；原生工具须有本次明确模型授权及可用的官方浏览器组件。所选工具不满足其执行条件或官方工具拒绝时停止，不自动更换工具。服务记录 `execution_origin=assistant_session` 与 `model_verification=executor_runtime_required`，不把助手声明写成 `model_verified=true`，也不解除自动连接暂停。

确认模型后，助手按交接说明异步运行 `publish-draft-assist-run --book <本书绝对路径> --request <请求ID>`。该单次请求包含目标、冻结批次、配置及内容版本，过期、取消、已认领或材料改变均拒绝执行。CLI 生成私有桥接配置并等待，将 `assistant_context` 输出给助手；其 PID 仅用于识别这次本地队列控制器，不是执行模型证明。助手在官方 Node REPL 中按 `tool_timeout_ms` 运行 `first_call`，再在同一 REPL 和模块实例连续等待 `next_call`，直到 `done=true`。工作执行器约每 20 秒在已完成 SDK 调用之间暂停，返回前等待本轮在途调用和健康检查结束；继续使用同一模块中保留的调用栈和已认领请求，不重新执行已完成的点击或保存。每次工具调用申请 240 秒，跨片段目录／回读总期限 900 秒、写入总期限 1200 秒。不要重置 REPL、重新导入、拆散未完成的队列操作或重复认领。CLI 与助手的 checkpoint 必须并行存活，不能先等待 CLI 完成才连接浏览器。

异常收尾保留业务结果并单独显示清理状态。仅绑定的 worker 最终回执、真实桥接分离和自建标签消失核验齐全，才称自动清理完成。当前源码在“平台草稿”和书架的作品服务管理中显示旧任务阻塞卡片，历史任务与本次选择的执行工具、批次分别保留；刷新失败不得隐藏未解决的占用。实际安装与界面验收状态见仓库 `docs/工作台草稿问题追踪.md`，不能用源码实现推定当前客户端已更新。

旧版本只读任务若丢失最终回执，从工作台准备一次性恢复交接，由已确认运行模型为 Terra 的助手取得原浏览器实时完整标签清单并回传工作台。服务端重核原任务、绑定、已退出控制器、过期只读队列及自建标签归属后，才记录“收尾已核验”；这不表示原检查成功。原浏览器标识缺席或不符时，不得用相同网址或新连接替代。

原浏览器无法核验时，须先取得作者本轮明确的保存确认与正常退出 Chrome 授权，再从工作台的“保存后结束旧浏览器会话”生成交接。由 Terra 正常退出全部 Chrome 窗口并执行官方内核重置，工作台完成入口调用既有严格隔离协议，核对精确绑定、完整进程消失、全部队列只读且过期及事件时序。记录为“外部会话已隔离”，不声称旧 Promise 自动结束或正常收尾；助手不得代替作者自行勾选保存授权。命令 `publish-draft-assist-reset` 仍保留维护兼容，但工作台流程验收必须由界面发起和回读，不能以手工维护命令替代。

已严格证实从未启动的旧只读任务，可在工作台明确确认后原样归档，保留原字节和可读历史，避免旧版服务误判占用而无法正常退出。活动任务、存在浏览器调用线索或未知写入均不适用。恢复与归档均不自动停止服务、不重放旧请求、不开始新检查或保存；下一步必须重新选择并发起只读检查。涉及未知写入的任务不允许走上述只读恢复入口，须保留原绑定和发送历史进行对账。

浏览器健康挑战通过且 session、队列控制器 PID／实例和绑定一致后，CLI 才用原 `HostAdapter` 和生产核心执行。第一次任务只读检查；工作台显示检查中的新增、更新、一致和受阻计数，作者明确确认后才能生成绑定该检查的单次同步任务。写入前重核远端前镜像，保留原草稿 ID、修改前备份和独立全文回读。比较时只去掉本地 MD 空白行，远端正文仍须严格符合转换后的内容。

本次助手进度与历史助手任务分别显示，刷新状态不会启动任务。撤销待执行任务使其不可认领；已执行任务只请求在安全边界停止。结束时向本任务写停止标记并等待桥接分离，不退出 Chrome 或共享助手；分离超时只表示清理未确认，不能把未知写入变为未写入。助手请求与结果在本书 `.story/platform-assistant-tasks/` 私有保存，包含目标及版本信息，不进入公开仓库；生产发送意图和去重日志仍使用原位置。

任务绑定实际书根路径。本机全局私有目录另外保留请求认领和检查消费标记，只有不透明标识和绑定摘要，不保存账号、标题或正文；因此把书籍恢复到较早备份不能使已执行请求重新有效。移动到其他书根的副本只作历史，不能沿用原认领。该保护依赖本机全局标记仍存在，不能承诺跨设备或同时丢失全局目录后的单次性；遇到这些情况应重新只读检查，并继续遵守原有目标级发送意图与未知回读要求。

## 作者自助配置（番茄）

本轮 MVP 仅接番茄，源码已实现并通过真实浏览器本地表单验收。打开工作台“平台草稿”→“配置番茄账号与作品”，填写“番茄小说网 ID”、粘贴该作品章节管理或草稿箱的完整网址，并选择连续已审查正式章节范围，每批最多 1000 章；点击“保存绑定并生成清单”。界面维护当前修订号，不让作者填写 JSON、选择器、哈希、私有路径或内部清单 ID。七猫、起点选项暂禁用。

配置仅在本机解析已观察的官方管理路径，按受控页面方案另存私有宿主配置并准备正式稿冻结清单，不访问所贴网址、不登录后台、不自动保存平台草稿。准备仍经过原有正式稿资格及当前修订核对；完全相同的目标、范围与正文可幂等复用原不可变清单，变化时另建清单，不覆盖旧配置、原冻结正文或未知发送历史，也不能用重新配置绕过未决写入。任务或绑定正在进行时禁止并发操作；本地版本变化须刷新后重新选择，不自动重发。配置成功后自动选中新配置和清单，显示本地预览；这只代表本地材料已准备。仍须“准备并检查差异”，核对真实账号、作品和完整正文后，再明确确认同步。

平台旧书删除后重新建书，即使书名相同，也按新作品 ID 作为独立同步目标。作者在“配置番茄账号与作品”粘贴新书的管理网址并选择正式稿范围，保存后核对界面中的账号、作品 ID 和范围，再检查差异。原目标的批次、成功记录和未确认结果继续保留在历史区，不计入新目标的本次进度，不复用旧书的草稿 ID。不能仅凭页面暂时不可访问就认定作品已删除，也不把删除平台作品作为修复同步失败的步骤。

新书首次保存仍先读取全部分卷、已发布章节和草稿箱；某一卷为空不代表全书为空。完整目录确认第 X 章及本批次后续章节均不存在后，后续直接逐章新建，不再做保存前的全文差异核对。若中间缺章而后面仍有章节，则按真实目录分别新建或核对，不能把缺口后已有的章也重新创建。所有新建与更新均在保存后逐章独立全文回读。若只是更新同一目标的页面配置，重新执行上述配置流程即可另存新配置；相同目标、范围与正式稿内容复用原清单，原配置与历史记录保留，无需作者编辑配置文件。

本批次新建中断后，仅在原发送记录能唯一绑定已分配的远端 ID，且本次只读确认其章号、标题、正文均为空时，才可将其列为“恢复上次未完成的空草稿”。明确同步时沿用该 ID，持久记录一次性恢复尝试，保存后独立回读；保留原失败历史。其他来源不明的空稿、非空的未知写入或重复恢复仍须停止核对，不能另建替代草稿。

此前真实表单已验证第 13→13 章本地绑定：生成新私有配置、复用原不可变清单、显示“尚未访问平台”，当时未连接工作进程时保存按钮禁用。该记录来自自动连接入口加入前，只证明本地配置流程；上文的保存、完整回读与不重复新建证据仍属于单独的实际平台链路。新增自动连接可用时，按下节显示连接按钮，不借用旧表单记录作为新入口的后台验收。

## 正文排版与比较策略

工作台和 `publish-draft-run` 的新草稿保存、同步更新统一使用 `body_encoding=plain_paragraphs_v1`：去掉正文全部空白行（包括首尾空行、仅含空格或制表符的行），其余每行之间只保留一个 LF。单次换行、连续空行与混合 CRLF 均可处理；有文字的行保留全部字符、标点、段首缩进和行末空格。正文按纯文本输入，不解释或删除 Markdown 标记。本地原稿与冻结清单不改。

工作台以固定说明展示平台排版，不再提供保留空行或旧段落转换选项。旧偏好不能恢复旧排版或宽松比较，历史记录保留当时的真实规则。服务端校验排版参数，旧页面不能绕过固定规则；刷新并重新预览后才能执行。若去掉空白行后正文为空，显示具体章号的中文错误，在访问平台前停止。

固定 `comparison_policy=strict`：独立回读的标题与正文必须和本地去空白行后的输入逐字一致。远端额外空行、末尾换行、缩进、空格和文字变化均算差异；远端回读不做去空行或裁尾处理。工作台、HTTP、CLI 与执行端均拒绝新编码搭配旧的末尾 LF 容差，旧偏好恢复后仍须重新预览。

`verbatim`、`markdown_paragraphs_v1`、`markdown_paragraphs_v2` 保留原有输出及校验语义，用于读取历史证据和必要的旧规则只读对账；新保存命令不接受它们。不能将旧回执自动升级为新规则，也不能因新规则与旧草稿不同就声称已经同步。

预览、执行、只读对账和手工桥接须使用相同编码与比较策略；两项均纳入签名预览和执行端绑定。CLI 默认使用新编码；手工桥接需明确传 `--body-encoding plain_paragraphs_v1`，不能复用旧排版连接。旧记录只读对账可用 `publish-draft-run --reconcile-only --body-encoding <旧编码>`；未知结果仍须先核对，不能盲目重发。

工作台按本书、清单和页面配置保存当前固定规则。偏好恢复与预览本身不连接平台、不启动保存。历史任务记录只说明当时观察，不覆盖当前规则或冒充本次核对。

追溯冻结原稿、实际输入和实际回读三层证据；编码／等价回执以 `source_content_sha256`、`encoded_content_sha256`、`observed_sha256` 分别区分摘要，不修改源稿、原清单或其原始哈希，也不补写旧记录。实际回读与源稿逐字一致才报告 `title_body_verified`；按明确排版或末尾 LF 规则接受时报告 `accepted_this_run`、`saved_equivalent`／`reconciled_equivalent`，并保留实际回读及所用规则，不能改写为逐字一致。旧未知尝试先只读对账；新策略不删除未知标记、不重建草稿、不覆盖旧发送历史。

## 工作台自动连接既有 Chrome

0.6.21 新增本机控制器 `story_chrome_worker.py` 与固定执行模块 `story_chrome_worker.mjs`。作者先登录本机 Codex、安装并连接官方 Chrome 扩展，在日常 Chrome 中打开本书已登录的番茄章节管理或草稿箱页；当前工作台通过“准备并检查差异”连接并执行整批只读检查，随后“确认同步这些变更”执行实际同步。不要求作者另开聊天、填写协议文件或粘贴令牌。自动连接会创建受控 Codex 执行会话，固定请求 `gpt-6.1-terra`，保留当前账号的推理设置并使用该账号的 Codex 额度。启动任务前须取得匹配的模型回执；缺失、不匹配、不可用或模型重定向均停止，不自动回退或修改用户默认配置。旧连接只有页面健康回执而没有自有执行会话的模型证明时，不予复用。模型已核验不代表浏览器已连接；仍须实际页面探测。组件缺失、额度或执行会话不可用时，说明具体原因并停止，不自动安装组件、重启模型或重试已领取操作。

首次连接尚未附着或领取操作时，若官方浏览器清单读取成功但暂未出现 Chrome 扩展连接，工作台显示“正在等待现有 Chrome 连接”，在同一执行会话中自动重新检测，最多等待 20 秒。等待计入原有 120 秒连接期限，并预留页面核验时间；模型启动较慢时等待会相应缩短。Chrome 恢复后仍需完成页面健康、账号、作品及目录核对，再执行原批次。等待结束仍不可用则明确停止，恢复连接后重新预览并执行；不会自行开启另一窗口或反复启动任务。

自动检测只能发现重新上线的连接，不能启用或唤醒离线的官方扩展。浏览器清单调用失败、权限拒绝、连接身份不符或无法唯一确定 Chrome 时立即停止；已开始平台操作后的断连不进入上述等待。结果不明的保存保留原发送历史，先只读对账，不自动重发。

执行模块加载本机原装官方 Chrome SDK，仅调用其公开浏览器 API，复用扩展已连接的 Chrome；不启动其他浏览器，不读密码、验证码、Cookie、浏览器配置文件或未公开传输接口。连接时先取得本地一次性健康挑战，再真实列出 Chrome、取得本书既有管理页并读取非空 DOM 快照，回传与当前绑定、浏览器及执行进程身份匹配的健康回执。控制器同时要求原执行进程和模型工具会话仍在运行；租约、心跳、进程已启动或模型声称成功均不能单独让 `ready=true`。健康探测定期更新，过期、进程退出或会话结束立即撤销就绪状态。

首次连接时，若已核对的作品管理标签失去控制，可在同一 Chrome 会话最多新建一个临时只读管理标签，重新核对本书网址和非空页面。探测连接不会点击“新建草稿”，临时标签随执行端结束清理，作者原有标签保留。开始执行后连接失效仍停止任务，不通过反复新开页面继续写入。

健康就绪只证明当前浏览器通道能够读取页面，并不证明平台账号、作品或内容已经核验。进入原生产执行核心后仍重新核对账号、作品、完整目录及冻结清单；连接期间正式稿或配置发生变化时拒绝新写入。只读对账也可自动连接，但不会创建草稿。任务结束或失败后关闭本次自建的核对、目录、编辑及预览页并结束自有执行会话，只保留作者原有标签；核验结果和截图另存本地。已成功关闭的标签不重复关闭，列表尚未更新时只做有界只读确认；真实失败仍报告，不把失联当作标签已关闭。断线或写入结果不明仍保留 unknown，先只读对账，不建立第二个任务重发。

本次新增自动连接流程的本地测试与实际平台验收分开记录；上文 81 字符稿的手工宿主成功不能直接证明自动连接已通过真实后台完整链路。

连接历史：2026-10-20 的独立执行会话曾在官方来源授权门被拒，辅助页随后关闭，当次未领取队列或写入。后续正确设置网站权限后的连接与正式稿尝试另记，不能继续把旧拒绝当作当前状态，也不能将手工宿主成功追认为独立执行会话成功。官方拒绝时停止，不换页面、换会话或自动返回批准绕过。

后续已核对 [Codex 官方浏览器设置说明](https://developers.openai.com/codex/app/settings#browser-use)：在 Codex 的“Settings／设置 → Browser／浏览器 → Agent permissions／代理权限”中可管理默认权限及网站例外；Browse、Download、Upload 分别提供 Requires approval、Always allow、Block 等选项。本任务仅为 `fanqienovel.com` 添加网站例外，将 **Browse** 设为 **Always allow**，保持 Download、Upload 权限不变，不调整全局默认权限。菜单名称以当前桌面版本为准，组织策略可能限制这些控件；找不到对应入口或无法设置时，须反馈当前菜单，由助手继续核对宿主支持的授权方式。此前 Chrome 扩展文档给出的 ChatGPT 桌面版 Computer Use／Manage 路径不能代替上述 Codex 设置入口。工作台以简短阻断原因及可展开帮助提供 Codex 路径和官方链接，不提供“我已授权”之类可直接改变连接状态的按钮。

设置完成后仍须重新预览、发起连接，通过本次目标管理页 DOM 健康核验，再核对平台账号、作品和完整目录。用户完成设置、打开官方说明或浏览器通道就绪，都不能代替正文保存与独立回读的验收。

## 已连接 Chrome 的宿主桥接

执行工具可由作者选择 Codex、Qoder CN 或 WorkBuddy AI。默认 Codex 仍要求 Terra；原生宿主须有本次明确模型授权并使用各自公开浏览器 SDK。任务、检查和同步绑定同一工具，不自动切换；不同工具的检查不能互相授权写入。源码能力、已安装组件和真实验收状态见开发仓库 `docs/宿主原生草稿接入.md`，助手入口为 `publish-draft-assist-prepare/status/cancel/run`。WorkBuddy 组件缺失时明确停止，不假定原生电脑任务代理可以提供全文回读。

助手在用户已授权原生模型时，用 `publish-draft-assist-prepare --book "<书根>" --id "<清单ID>" --profile "<配置文件名>" --host qoder-cn --allow-native-host-model` 准备只读检查；WorkBuddy 的宿主值为 `workbuddy`。准备不会连接浏览器。异步运行返回的 `publish-draft-assist-run --request` 命令，严格按 `assistant_context` 在所选工具的同一 Node REPL 中执行首轮与后续轮；不重新导入模块，不重建 SDK factory。Qoder 工具返回运行中的单元 ID 时，先使用该工具的 `node_repl_wait` 等同一单元完成，不能重发操作。

状态与停止分别用 `publish-draft-assist-status --book "<书根>" --request "<请求ID>"`、`publish-draft-assist-cancel`。检查通过且完整清理后，有整批同步授权时用同宿主再次 prepare，添加 `--mode sync_drafts --inspection "<检查请求ID>" --confirm-sync`。本次工具与原生许可随请求固定；不能拿其他工具的检查结果直接写入。组件缺失在领取前报告，不消费请求、不切换工具。

`host_assisted_cua` 保留原执行核心、目标锁、冻结清单和持久发送记录。Python 桥接模块 `story_platform_chrome_bridge.py` 通过本机受认证命令队列请求账号／作品核对、完整目录查找、新建及回读；`story_chrome_bridge.mjs` 由当前助手传入已连接 Chrome 的公开浏览器 API 对象执行，不自行连接、启动浏览器或读取登录资料。平台操作仍按本次指定账号、作品和整批章节授权执行。

下述手工接口说明桥接传输协议，不是绕过工作台模型校验的执行入口。`attach` 仅建立等待健康确认的会话；`heartbeat` 仅续租，均不建立就绪状态。健康挑战和真实 DOM 探测也只证明浏览器连接；在正式宿主身份交接未实现前，手工健康回执不能使工作台自动检查或同步获得执行资格。合格工作进程只领取本次队列中的明确操作，回传从实际页面取得的观察，不把作者副本、模拟数据或历史结果冒充本次 DOM 证据。未命名或无法核对章号的既有草稿、身份不符及目录覆盖不全时停止。主流程仍要求创建后重新打开，并完整核对标题和正文。

新建命令只允许领取一次。领取后若回执丢失、工作进程断开或执行结果不明，保留 unknown 并先只读对账，不重新领取或重发新建，不通过换清单或删除队列绕过发送记录。宿主桥接依赖当前助手连接；独立工作台缺少工作进程时明确阻断，不能宣传为无人值守自动发布。提交审核、排期和读者可见仍不在本轮范围。

以下命令保留给助手手工服务桥接队列，不要求作者填写协议文件。`<tool>` 是同版共享 `story-skill/scripts/story.py` 的绝对路径。`<handle>`、`<health>` 与 `<response>` 均为本机私有 JSON 文件，权限须为 `0600`；句柄内的本机桥接令牌不能作为命令参数值，也不能进入聊天或公开日志。`<profile-id>` 是本书配置文件名，`<request-id>` 来自该会话实际领取结果。

```sh
python "<tool>" publish-chrome-attach --book "<绝对书根>" --id "<清单ID>" --profile "<profile-id>" --handle "<handle>" --ttl-seconds 120
python "<tool>" publish-chrome-health --book "<绝对书根>" --handle "<handle>"
python "<tool>" publish-chrome-health --book "<绝对书根>" --handle "<handle>" --input "<health>"
python "<tool>" publish-chrome-next --book "<绝对书根>" --handle "<handle>"
python "<tool>" publish-chrome-respond --book "<绝对书根>" --handle "<handle>" --request-id "<request-id>" --input "<response>"
python "<tool>" publish-chrome-heartbeat --book "<绝对书根>" --handle "<handle>"
python "<tool>" publish-chrome-detach --book "<绝对书根>" --handle "<handle>"
```

第一次 `health` 返回绑定会话的一次性挑战，助手在挑战有效期内通过公开 Chrome API 实际执行列表、取页及目标管理页 DOM 快照读取，再把匹配挑战的浏览器、能力与当前活进程身份写入 `<health>`；第二次 `health --input` 成功且 `ready=true` 只代表底层浏览器健康门通过，不代表工作台的执行资格已通过。不填造健康回执，持续服务时重复真实探测更新健康状态，并另外按租期发送心跳。健康通过后仍须重新预览并核对模型资格、同一配置和目标；当前工作台拒绝只有手工健康回执的执行端。`next` 仅返回一次领取结果及私有请求路径；合格助手将该请求交给 `executeChromeBridgeRequest(api, request)`，其中 `api.listTabs`、`api.getTab`、`api.newTab` 必须绑定本次已经连接的 Chrome 公开工具，不由运行器自行连接。手工 CUA 的 Chrome 新标签封装为 `newTab: url => cua.createBrowserTab(browserId, url)`，其中 `browserId` 来自现有 Chrome 清单，不传入 IAB 专用的 `visible` 参数；其余会话选项按当前宿主工具文档核对。将返回的完整信封写入私有响应文件后调用 `respond`，不得自行拼造成功观察。

宿主服务循环必须在 `finally` 中清理每个已完成或失败的任务：调用 `closeChromeBridgeSession(api, sessionId, {keepReadback:false})`，关闭运行器自建页，包括最终预览页，只保留用户原有标签。核验结果和截图先保存到本地。重新附着前也须先安全结束旧任务并清理旧会话。清理在整个任务终结后执行，不能每领取一个请求就关闭会话。随后用 `detach` 断开旧租约；断开本身不关闭标签，也不自动删除句柄、请求、响应或原发送记录。

同一桥接会话只导入一次 MJS，后续核对、查找、新建及回读复用同一模块对象，转发 helper 显式接收该对象。本轮宿主 REPL 实测重复动态导入相同 URL 仍得到不同模块实例，会丢失运行器的会话状态；不要每次领取后重新导入，也不要沿用捕获旧模块的闭包。

## 使用条件与准备

复用发布技能的正式稿资格检查、不可变清单及目标标识。目标必须是平台上已创建的作品；三家分别准备各自的清单，不因支持多平台而自动把同一作品上传到全部平台。账号、作品和章节范围沿用用户本次授权，不让作者手填 JSON、哈希或内部清单 ID；由助手维护机器数据。

页面配置必须来自当前实际后台的可见控件和稳定标识。用 `template platform-browser-fanqie`、`template platform-browser-qimao` 或 `template platform-browser-qidian` 取得对应结构，由助手在核对真实页面后填写入口、账号和作品身份、章节列表、完整分页、编辑器和保存方式；模板中的待配置值不能作为已验证适配。`chapter_lists` 必须覆盖全部章节状态：可是一份 `all` 目录，也可拆为 `drafts` 与 `non_drafts` 的多份目录。每份分别核对当前目录标志、筛选条件、加载完成信号 `ready`，以及完整分页或已经实页确认、排除分页和虚拟列表的完整表格（`all_rows`）；存在分卷时必须逐卷扫描，有草稿总数时另核对计数。只看到空白页不能判断没有目标章。同章已发布、审核中或其他非草稿状态会停止。配置保存在本书 `.story/platform-profiles/`，不含密码、验证码、Cookie 或令牌，不提交公开仓库。页面变化导致标识、字段、分页或保存行为无法明确识别时停止，不猜选择器或转用未公开接口。

本轮番茄配置可用账号核对页的真实 DOM 核对稳定账号，以完整 URL 模板核对作品和草稿 ID；不从书名或局部 URL 猜身份。没有编辑器草稿状态标志时，须在分开的完整草稿和非草稿目录中唯一确认真实 ID 与章号，并在回读后再核对；编辑器另需正向 `ready` 标志，初始空输入不能当作新稿已经加载完成。

`editor.body.source="prosemirror_paragraphs"` 仅用于已采样的番茄纯文本段落结构。读取时识别明确的空编辑器占位节点，并仅解码一个已观测的末尾空段哨兵；其余首段、尾段和连续空段全部保留。写入使用原生逐段输入，再比较完整正文，不使用整栏填充或裁剪空白来消除差异。未知节点、缺失哨兵或回读异文会停止，不能套用于未经核对的其他富文本编辑器。

2026-10-19 的 83 字符样本保存后重开只读到 81 字符，末尾两个 LF 丢失，因此不能承诺额外尾 LF 可在番茄持久保存；点击后 DOM 一致也不能代替重开回读。默认严格规则下该样本仍为冲突。旧版末尾 LF 等价记录仅作历史证据，不追认原样逐字通过；当前新任务统一按本地去空白行后的正文严格核对。

同日还观察到：仅打开或重载已有功能测试稿编辑页，编辑器中的正文长度也会增加，原因未确定，不能据此归因为并发。本轮番茄对账与回读已改用独立的只读预览路由；编辑页不作为只读回读通道。实际测试预览经重载保持稳定，生产回读完整取得 81 字符并对原 83 字符清单报告冲突。每份配置仍须按实页核对账号、作品、草稿 ID、章号、标题与完整段落；不能用预览总字数或局部文本替代完整正文，也不裁剪原稿来适配平台。

番茄配置缺少 `readback` 时，CLI 与工作台均在浏览器启动或连接前阻断；宿主桥接与独立浏览器模式都不回退到编辑页。由助手按实际页面配置独立 `readback.url`（固定作品，只含一个 `{remote_id}` 占位符）、来自精确 URL 的 `remote_id`、`header` 的 `chapter_title` 合并格式，以及 `body.source="fanqie_preview_paragraphs_v1"`；作品身份模板另覆盖该预览完整 URL。预览地址不能同时匹配编辑路由，草稿状态仍由完整草稿／非草稿目录共同确认。预览段落仅接受无属性的直接 P：非末尾空段可为零子节点 P 或已观测的精确 `<p><br></p>`，只解码最后一个精确零子节点 `<p></p>` 哨兵，保留其余空段及字面空格。运行器先关闭自身创建的同稿编辑页；发现用户原有同稿编辑页则阻断并保留该页，不擅自关闭，也不把此保护机制当作正文增长原因已经查明。

执行前核对当前入口适用的规则与接入范围。2026-10-19 已从七猫网页版直接读取[作家中心用户服务协议](https://zuozhe.qimao.com/front/page/agreement/user)，页面标示 2023-11-15；第 1.2 条包含网页作家中心，第 3.1 节涉及平台认可的使用方式及第三方工具。不能再只引用作家助手客户端协议来解释网页版。起点应核对实际作家入口适用协议；[阅文通用用户服务协议](https://passport.yuewen.com/pact.html?mobile=0)有第三方工具相关限制，但本轮未确认它是否覆盖实际编辑入口。番茄[用户协议](https://fanqienovel.com/protocal/agreement)的本轮公开抽取仅得到标题，正文需在实际入口重新核对。这些核对不是平台已授予本项目自动接入许可的证明。

宿主桥接复用当前助手已有的 Chrome 浏览器工具，不因选择该模式而安装或启动 Playwright。以下依赖仅适用于用户另行选择的独立浏览器模式：使用隔离 Python 环境安装 `playwright`；默认 Chromium 还需运行 `python -m playwright install chromium`，配置 `browser_channel="chrome"` 则启动已安装的 Google Chrome；[Playwright 官方安装说明](https://playwright.dev/python/docs/library)。离线命令不导入该依赖。桌面客户端当前不内置 Playwright 或浏览器，不承诺安装客户端即可执行上传。执行器使用独立可见的临时会话，用户在平台界面自行登录和完成验证；它与本次浏览器工具连接的日常 Chrome 会话不同，不读取其他浏览器的登录资料、不导出登录状态，也不把会话写进作品备份。Chrome 启动失败不会自动改用其他浏览器。

作品内容操作仅允许对应官网同一 origin。`login_origins` 可配置已从真实页面核对的精确 HTTPS 认证 origin，仅在人工登录等待期间放行；登录完成关闭多余认证页，重新核对账号与作品后收回额外导航范围。该配置不证明三家 SSO 全流程可用。新建若需要点击并打开新页，可配置 `create_action`（`mode="button"`、唯一 `selector`、实际 `expected_text`、`opens="popup"` 或 `"same_page"`），此时 `urls.create` 指向已核实的列表落点。打开新建页或点击新建按钮可能立即创建空白云端草稿，因此只有持久记录发送意图后才执行；弹窗丢失或中断不重试创建。

## 命令流程

`<tool>` 是同版共享 `story-skill/scripts/story.py` 的绝对路径。

1. 按发布技能运行 `publish-prepare`，取得绑定真实平台、账号、作品和正式章节范围的清单。
2. `python "<tool>" publish-draft-run --book "<绝对书根>" --id "<清单ID>"`：仅做本地预览，不启动浏览器或联网。核对目标与冻结章序。
3. 用户已要求保存这批草稿且页面配置和接入条件齐备时，执行 `python "<tool>" publish-draft-run --book "<绝对书根>" --id "<清单ID>" --profile "<本机页面配置JSON>" --execute`。只在这个显式入口执行平台操作，既有批次授权不逐章重复确认。宿主模式的 CLI 仍须先由助手连接工作进程并通过健康探测；它本身不启动自动连接控制器，没有健康工作进程时阻断。工作台可按上节自动连接后执行同一生产核心。独立模式的 CLI 默认人工登录等待三分钟，需要十分钟时显式加 `--login-timeout-ms 600000`；工作台默认十分钟。
4. `python "<tool>" publish-draft-status --book "<绝对书根>" --id "<清单ID>"`：查看本地执行历史；它不访问平台，不能当作本次远端状态。
5. 中断后先用带 `--execute --reconcile-only --profile "<配置>"` 的 `publish-draft-run` 对账。该模式只读远端，不创建草稿。结果未知且无法找到明确对应草稿时保持待核实，不通过删除日志、换清单或恢复旧备份重发。

每次继续执行都核对正式稿与远端草稿。当前清单过期、已取消或源文件变化时，停止新写入；历史回执仍保留。写入前持久记录意图，随后才打开可能触发自动保存的新草稿编辑页。网络操作不长期占用创作锁。创建后从独立只读入口完整读取标题和正文，按本次显式规则分别报告逐字一致或等价接受，不改实际观察来制造一致。

## 结果与恢复

执行历史独立保存在本书 `.story/platform-drafts/`，保存目标、清单指纹、章节、状态、尝试和内容摘要，不复制稿件全文或登录资料。本机另在 `~/.story-skill/platform-drafts/` 保存目标与内容的哈希及发送尝试标记，用于跨清单、书根副本和旧备份识别未决写入；不含账号原文、书稿或登录材料。丢失这些本机标记或转移到另一台电脑仍不能据此保证去重。原离线清单、比较历史和创作 revision 不因此变为远端发布事实。

宿主桥接队列与上述摘要日志分开：`.story/platform-chrome-bridge/` 下的私有目录为 `0700`、文件为 `0600`，请求和响应可含本次标题、正文及实际页面观察。外部句柄含本地桥接令牌，均不包含 Chrome Cookie；这些私有文件不进入公开仓库、测试夹具或技能包。当前断开与任务结束不自动清理它们。排查或恢复时保留必要证据；结束后可由助手按本机数据保留要求整理私有副本，不能借清理队列删除或绕过原发送记录。

向作者逐章说明已保存且源稿逐字一致、按明确规则核对通过、已有对应草稿、内容冲突、受阻或结果未知；批量部分成功列出具体断点。编码或等价接受不冒称源稿逐字一致。旧执行回执是当时观察，不能保证远端后来没有人工改稿。平台状态与本地执行状态分别解释，保存成功只证明进入草稿箱。

已有同章草稿必须回读后再判断；默认保存模式遇到同章不同内容时停止，不覆盖。只有作者明确授权更新已有草稿并选择同步模式，才按下述范围修改；同章多份草稿始终停止。列表分页不完整、只能读到正文片段或账号、作品变化时停止。写入后的超时、进程退出、回执落盘失败按结果未知处理，先查远端；找不到不能证明平台未收到。本机按平台、账号和作品串行，跨设备并发不能据此保证去重。

## 统一同步番茄草稿与本地状态刷新

工作台分别显示当前正式稿范围与已生成批次。新增或修订正式章后，每五秒及窗口重新聚焦时刷新本地范围，并使旧预览失效；旧批次和发送记录保留。生成新批次只读取本地已审查正式稿，不连接平台。

作者明确要求同步草稿时，使用“同步草稿（更新已有，补齐缺失）”：在同一批次内更新已有草稿的章名和完整正文，并新建缺失章节草稿。工作台初次打开选择最新生成批次；“重新预览”按所选批次范围重新准备最新正式稿，保留核对规则，再展示预览；明确执行后才访问平台。命令行对应 `publish-draft-run --sync-drafts --execute`，旧更新模式不再作为入口。此模式限已配置独立只读回读的番茄 Chrome 会话；只读核对不修改草稿，不修改已发布章节、不提交审核或排期。

同步逐章核对账号、作品、完整目录和唯一草稿 ID。无变化的章只读核对；缺失草稿新建；同章多份、已发布或目标含糊时停止。新增、更新、原已一致分别统计，只有本次独立回读通过才计入完成。修改前在本书私有 `.story/platform-draft-update-backups/` 保存含原章名、原正文的备份，再核对远端没有并发改动。保留原草稿 ID，同步章名并完整重填正文，保存后通过独立只读预览全文核对。发送结果不明时保留未知状态，先只读对账，不自动重发。

对已核实的番茄错字标记，只读取其原始文字，绝不采用纠错建议；标记结构或属性不符时停止。同步时重新填入完整纯文本正文，回读仍有错字标记则不能判为完成。

面板读取最新落盘记录，避免旧失败任务遮住后来的成功核对。显示“最近记录”及时间，并明确本次是否访问平台；本地历史刷新不等于当前远端核验。同步模式的工程回归使用合成材料，不推定真实作者整批草稿已同步成功。

未命名草稿也可能已经分配章号。遇到未命名或无法明确读取章号的旧稿，先人工核对；不能将其忽略后判断目标章不存在并重建。若此前已有发送意图但结果不明，仍须先只读对账，不能通过整理目录或换清单绕过未决记录。

本次只保存标题和正文。作者的话与配图、整篇短故事投稿、建书、已发章覆盖、提交审核及排期均需各自的实现和验收。未支持的动作不能通过点击“发布”“下一步”或修改本地回执来完成。
