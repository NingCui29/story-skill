# 平台草稿保存（开发候选）

本轮需求于 2026-10-19 明确：番茄、七猫、起点，只自动保存平台草稿；真实后台验收随后按用户要求限定为番茄。共享命令和工作台“平台草稿”入口已接执行核心及可配置浏览器适配器。番茄已有从实际后台采集的私有页面配置，并通过生产适配器的纯构造校验；公共模板仍保留待配置项，私有配置不随仓库分发。七猫、起点真实验收暂缓，尚无经实页核验的生产配置。

**2026-10-21 排版修复范围：** 新增纯自然段编码与独立的末尾 LF 比较策略。已有一篇正式草稿经单独修复后，从只读预览完整核对了段落和文字；这不代替工作台自动批次验收。源码、离线测试、本机安装、自动保存与实际回读分别记录，各书各批次状态以该次执行回执为准。

历史功能样本（2026-10-19）：独立 81 字符合成稿通过工作台保存、只读预览全文回读及同清单重复执行不重建；该样本没有额外尾 LF。原 83 字符样本的尾 LF 差异和未知历史保留，不能追认逐字通过。三篇功能测试草稿后来按作者授权清理；旧独立浏览器任务已停止。这些记录不证明当前正式稿批次或新增策略成功。

## 工作台入口

写作项目工具栏的“平台草稿”可列出全部已冻结正式稿清单；分析项目禁用。选择目标批次、匹配平台的本机页面配置和“保存草稿”或“只读对账”模式后，先显示账号、作品、章序、标题及字数的本地预览。作者已有整批保存授权时，助手可按该范围执行；页面按钮不会因普通写作、采用或打开工作台自动运行。

“保存到平台草稿”只在本地资格、配置、所选执行模式就绪和签名预览有效时启动。缺少连接但本机自动连接组件可用时，按钮显示“连接并保存到平台草稿”，另行说明将使用当前账号的 Codex 额度；这不表示 Chrome 已就绪。任务独立异步运行，面板显示连接、账号核对、目录核对、保存与回读进度；只按本次已全文核对的章节累计进度。关闭面板不会取消已启动的本地任务，重新打开可接回；宿主模式仍需受控执行会话或当前助手持续服务，关闭工作台服务或执行进程不等于后台可无人值守继续；编辑器缓冲保留，未采用的内容不混入已冻结批次。未知结果先选择只读对账，过时或已取消批次也可核对冻结旧版；页面会说明它与当前正式稿的区别，不重建草稿。

本轮只操作用户既有、已登录且已通过官方 Chrome 扩展连接的 Chrome。`execution_mode="host_assisted_cua"` 需要活跃且通过健康探测的工作进程；可由工作台自动建立受控 Codex 执行会话，也可由当前助手手工附着。没有健康工作进程时阻断，不启动另一 Chrome、读取 Cookie 或切换到独立模式。进程退出后内存任务不会恢复运行，但已持久保存的发送历史仍保留，不能据此自动重发。用户另行选择独立浏览器模式时，工作台默认给该会话十分钟人工登录时间；它与日常 Chrome 会话不同。两种模式的等待均不占用创作数据库事务。

页面配置保存在本书 `.story/platform-profiles/*.json`；番茄可用下述作者自助入口生成，其他已核对配置由助手维护。页面只选择配置名，不接收任意路径，自动生成的配置显示为“番茄本地配置 N”。预览绑定书籍、批次、配置哈希、操作模式、正文编码与比较策略，有效期十分钟；改稿、换配置或更改策略均须重新预览。重复点击只复用相同绑定的运行任务，完整执行历史仍以本地持久记录为准。

## 作者自助配置（番茄）

配置仅在本机解析已观察的官方管理路径，按受控页面方案另存私有宿主配置并准备正式稿冻结清单，不访问所贴网址、不登录后台、不自动保存平台草稿。准备仍经过原有正式稿资格及当前修订核对；完全相同的目标、范围与正文可幂等复用原不可变清单，变化时另建清单，不覆盖旧配置、原冻结正文或未知发送历史，也不能用重新配置绕过未决写入。任务或绑定正在进行时禁止并发操作；本地版本变化须刷新后重新选择，不自动重发。配置成功后自动选中新配置和清单，显示本地预览；这只代表本地材料已准备，真实账号与作品仍在执行前核对。实际保存另由作者点击“连接并保存到平台草稿”或已有健康连接时的“保存到平台草稿”。

此前真实表单已验证第 13→13 章本地绑定：生成新私有配置、复用原不可变清单、显示“尚未访问平台”，当时未连接工作进程时保存按钮禁用。该记录来自自动连接入口加入前，只证明本地配置流程；上文的保存、完整回读与不重复新建证据仍属于单独的实际平台链路。新增自动连接可用时，按下节显示连接按钮，不借用旧表单记录作为新入口的后台验收。

## 正文排版与比较策略

默认使用 `body_encoding=verbatim` 和 `comparison_policy=strict`：保留原始换行，标题与正文在统一 CRLF／CR 为 LF 后逐字核对。排版编码与回读比较是两个独立选择，不因发现差异而自动启用。

用户明确要求将纯自然段按平台段落排版时，番茄推荐选择 `body_encoding=markdown_paragraphs_v2`。它把正文内部恰好两个 LF（一个本地空行）编码为一个 LF，输入编辑器时对应一次平台换段，并去掉正文开头单个 LF 对应的首空段，避免标题下多出一段留白；段内汉字、标点和空格不变，末尾单个 LF 保留。只改变执行时的编码输入，不修改冻结原稿。

`markdown_paragraphs_v1` 作为旧版兼容选项保留：同样转换内部自然段分隔，但保留开头单个 LF，不追溯改写旧回执、旧输入或历史哈希。v2 共用 v1 的纯自然段校验：内部单 LF、三个及以上连续 LF、首尾多个 LF 会停止，不合并空白、不猜测段意。两者均不适用于标题、列表、引用、围栏代码等结构；遇其他 Markdown 语法先核对，不承诺通用 Markdown 渲染。驱动精确输入核心已编码的正文，不再转换一次。工作台“正文排版”提供原始换行、v2 推荐及 v1 兼容选项，默认仍为原始换行。

用户另行明确接受番茄保存后丢失或增加的末尾 LF 时，才选 `comparison_policy=fanqie_terminal_lf_v1`。比较仅在换行统一后移除正文末端连续 LF；标题、编码输入中的首行 LF、内部空行、空格及其他字符仍须一致，不使用 `trim()`。输入阶段仍与编码正文精确核对；此策略独立于 v1／v2 排版，不修复开头或段间空段，也不能绕过编码歧义检查。

预览、执行、只读对账和手工桥接须使用同一编码与比较策略；两项均纳入签名预览和执行端绑定，不能借旧连接套用另一种规则，也不把 v1 回执自动升级为 v2。CLI 可分别显式添加 `--body-encoding markdown_paragraphs_v2`、`--comparison-policy fanqie_terminal_lf_v1`；核对旧版排版时仍指定 `markdown_paragraphs_v1`。`publish-chrome-attach` 接受同名参数，省略时仍为 `verbatim`／`strict`；两种段落编码及末尾 LF 策略仅适用于番茄。

工作台将作者明确选择的两项规则按本书、清单和页面配置分别保存，重新打开面板或重启服务后恢复；旧任务记录不覆盖当前选择。换书、换清单或换配置后重新确认，不沿用其他目标的规则。修改选择后必须重新预览，保存偏好本身不连接平台、不启动任务。出现内容冲突时先核对本次使用的规则与实际全文，不能通过放宽比较或重建草稿消除提示。

追溯冻结原稿、实际输入和实际回读三层证据；编码／等价回执以 `source_content_sha256`、`encoded_content_sha256`、`observed_sha256` 分别区分摘要，不修改源稿、原清单或其原始哈希，也不补写旧记录。实际回读与源稿逐字一致才报告 `title_body_verified`；按明确排版或末尾 LF 规则接受时报告 `accepted_this_run`、`saved_equivalent`／`reconciled_equivalent`，并保留实际回读及所用规则，不能改写为逐字一致。旧未知尝试先只读对账；新策略不删除未知标记、不重建草稿、不覆盖旧发送历史。

## 工作台自动连接既有 Chrome

0.6.21 新增本机控制器 `story_chrome_worker.py` 与固定执行模块 `story_chrome_worker.mjs`。作者先登录本机 Codex、安装并连接官方 Chrome 扩展，在日常 Chrome 中打开本书已登录的番茄章节管理或草稿箱页；完成上述本地配置与预览后，点击“连接并保存到平台草稿”。该按钮为本批任务自动连接并执行，不要求作者另开聊天、填写协议文件或粘贴令牌。它会创建受控 Codex 执行会话，沿用当前账号默认模型与推理设置，使用该账号的 Codex 额度。组件缺失、额度或执行会话不可用时，说明具体原因并停止，不自动安装组件、重启模型或重试已领取操作。

首次连接尚未附着或领取操作时，若官方浏览器清单读取成功但暂未出现 Chrome 扩展连接，工作台显示“正在等待现有 Chrome 连接”，在同一执行会话中自动重新检测，最多等待 20 秒。等待计入原有 120 秒连接期限，并预留页面核验时间；模型启动较慢时等待会相应缩短。Chrome 恢复后仍需完成页面健康、账号、作品及目录核对，再执行原批次。等待结束仍不可用则明确停止，恢复连接后重新预览并执行；不会自行开启另一窗口或反复启动任务。

自动检测只能发现重新上线的连接，不能启用或唤醒离线的官方扩展。浏览器清单调用失败、权限拒绝、连接身份不符或无法唯一确定 Chrome 时立即停止；已开始平台操作后的断连不进入上述等待。结果不明的保存保留原发送历史，先只读对账，不自动重发。

执行模块加载本机原装官方 Chrome SDK，仅调用其公开浏览器 API，复用扩展已连接的 Chrome；不启动其他浏览器，不读密码、验证码、Cookie、浏览器配置文件或未公开传输接口。连接时先取得本地一次性健康挑战，再真实列出 Chrome、取得本书既有管理页并读取非空 DOM 快照，回传与当前绑定、浏览器及执行进程身份匹配的健康回执。控制器同时要求原执行进程和模型工具会话仍在运行；租约、心跳、进程已启动或模型声称成功均不能单独让 `ready=true`。健康探测定期更新，过期、进程退出或会话结束立即撤销就绪状态。

首次连接时，若已核对的作品管理标签失去控制，可在同一 Chrome 会话最多新建一个临时只读管理标签，重新核对本书网址和非空页面。探测连接不会点击“新建草稿”，临时标签随执行端结束清理，作者原有标签保留。开始执行后连接失效仍停止任务，不通过反复新开页面继续写入。

健康就绪只证明当前浏览器通道能够读取页面，并不证明平台账号、作品或内容已经核验。进入原生产执行核心后仍重新核对账号、作品、完整目录及冻结清单；连接期间正式稿或配置发生变化时拒绝新写入。只读对账也可自动连接，但不会创建草稿。任务结束或失败后关闭本次自建的核对、目录、编辑及预览页并结束自有执行会话，只保留作者原有标签；核验结果和截图另存本地。已成功关闭的标签不重复关闭，列表尚未更新时只做有界只读确认；真实失败仍报告，不把失联当作标签已关闭。断线或写入结果不明仍保留 unknown，先只读对账，不建立第二个任务重发。

本次新增自动连接流程的本地测试与实际平台验收分开记录；上文 81 字符稿的手工宿主成功不能直接证明自动连接已通过真实后台完整链路。

连接历史：2026-10-20 的独立执行会话曾在官方来源授权门被拒，辅助页随后关闭，当次未领取队列或写入。后续正确设置网站权限后的连接与正式稿尝试另记，不能继续把旧拒绝当作当前状态，也不能将手工宿主成功追认为独立执行会话成功。官方拒绝时停止，不换页面、换会话或自动返回批准绕过。

后续已核对 [Codex 官方浏览器设置说明](https://developers.openai.com/codex/app/settings#browser-use)：在 Codex 的“Settings／设置 → Browser／浏览器 → Agent permissions／代理权限”中可管理默认权限及网站例外；Browse、Download、Upload 分别提供 Requires approval、Always allow、Block 等选项。本任务仅为 `fanqienovel.com` 添加网站例外，将 **Browse** 设为 **Always allow**，保持 Download、Upload 权限不变，不调整全局默认权限。菜单名称以当前桌面版本为准，组织策略可能限制这些控件；找不到对应入口或无法设置时，须反馈当前菜单，由助手继续核对宿主支持的授权方式。此前 Chrome 扩展文档给出的 ChatGPT 桌面版 Computer Use／Manage 路径不能代替上述 Codex 设置入口。工作台以简短阻断原因及可展开帮助提供 Codex 路径和官方链接，不提供“我已授权”之类可直接改变连接状态的按钮。

设置完成后仍须重新预览、发起连接，通过本次目标管理页 DOM 健康核验，再核对平台账号、作品和完整目录。用户完成设置、打开官方说明或浏览器通道就绪，都不能代替正文保存与独立回读的验收。

## 已连接 Chrome 的宿主桥接

`host_assisted_cua` 保留原执行核心、目标锁、冻结清单和持久发送记录。Python 桥接模块 `story_platform_chrome_bridge.py` 通过本机受认证命令队列请求账号／作品核对、完整目录查找、新建及回读；`story_chrome_bridge.mjs` 由当前助手传入已连接 Chrome 的公开浏览器 API 对象执行，不自行连接、启动浏览器或读取登录资料。平台操作仍按本次指定账号、作品和整批章节授权执行。

手工方案由助手先确认已连接浏览器与可用工作进程，再完成健康挑战、真实 DOM 探测、本地预览和整批启动。`attach` 仅建立等待健康确认的会话；`heartbeat` 仅续租，均不建立就绪状态。工作进程只领取本次队列中的明确操作，回传从实际页面取得的观察，不把作者副本、模拟数据或历史结果冒充本次 DOM 证据。未命名或无法核对章号的既有草稿、身份不符及目录覆盖不全时停止。主流程仍要求创建后重新打开，并完整核对标题和正文。

新建命令只允许领取一次。领取后若回执丢失、工作进程断开或执行结果不明，保留 unknown 并先只读对账，不重新领取或重发新建，不通过换清单或删除队列绕过发送记录。宿主桥接依赖当前助手连接；独立工作台缺少工作进程时明确阻断，不能宣传为无人值守自动发布。提交审核、排期和读者可见仍不在本轮范围。

以下命令保留给助手手工服务桥接队列，不要求作者填写协议文件。`<tool>` 是同版共享 `story-skill/scripts/story.py` 的绝对路径。`<handle>`、`<health>` 与 `<response>` 均为本机私有 JSON 文件，权限须为 `0600`；句柄内的本机桥接令牌不能作为命令参数值，也不能进入聊天或公开日志。`<profile-id>` 是本书配置文件名，`<request-id>` 来自该会话实际领取结果。

```sh
python "<tool>" publish-chrome-attach --book "<绝对书根>" --id "<清单ID>" --profile "<profile-id>" --handle "<handle>" --ttl-seconds 120
python "<tool>" publish-chrome-health --book "<绝对书根>" --handle "<handle>"
python "<tool>" publish-chrome-health --book "<绝对书根>" --handle "<handle>" --input "<health>"
python "<tool>" publish-chrome-next --book "<绝对书根>" --handle "<handle>"
python "<tool>" publish-chrome-respond --book "<绝对书根>" --handle "<handle>" --request-id "<request-id>" --input "<response>"
python "<tool>" publish-chrome-heartbeat --book "<绝对书根>" --handle "<handle>"
python "<tool>" publish-chrome-detach --book "<绝对书根>" --handle "<handle>"
```

第一次 `health` 返回绑定会话的一次性挑战，助手在挑战有效期内通过公开 Chrome API 实际执行列表、取页及目标管理页 DOM 快照读取，再把匹配挑战的浏览器、能力与当前活进程身份写入 `<health>`；第二次 `health --input` 成功且 `ready=true` 后才能继续。不填造健康回执，持续服务时重复真实探测更新健康状态，并另外按租期发送心跳。健康通过后重新预览，核对同一配置和目标，再由工作台或显式执行命令启动已授权批次。`next` 仅返回一次领取结果及私有请求路径；助手将该请求交给 `executeChromeBridgeRequest(api, request)`，其中 `api.listTabs`、`api.getTab`、`api.newTab` 必须绑定本次已经连接的 Chrome 公开工具，不由运行器自行连接。手工 CUA 的 Chrome 新标签封装为 `newTab: url => cua.createBrowserTab(browserId, url)`，其中 `browserId` 来自现有 Chrome 清单，不传入 IAB 专用的 `visible` 参数；其余会话选项按当前宿主工具文档核对。将返回的完整信封写入私有响应文件后调用 `respond`，不得自行拼造成功观察。

宿主服务循环必须在 `finally` 中清理每个已完成或失败的任务：调用 `closeChromeBridgeSession(api, sessionId, {keepReadback:false})`，关闭运行器自建页，包括最终预览页，只保留用户原有标签。核验结果和截图先保存到本地。重新附着前也须先安全结束旧任务并清理旧会话。清理在整个任务终结后执行，不能每领取一个请求就关闭会话。随后用 `detach` 断开旧租约；断开本身不关闭标签，也不自动删除句柄、请求、响应或原发送记录。

同一桥接会话只导入一次 MJS，后续核对、查找、新建及回读复用同一模块对象，转发 helper 显式接收该对象。本轮宿主 REPL 实测重复动态导入相同 URL 仍得到不同模块实例，会丢失运行器的会话状态；不要每次领取后重新导入，也不要沿用捕获旧模块的闭包。

## 使用条件与准备

复用发布技能的正式稿资格检查、不可变清单及目标标识。目标必须是平台上已创建的作品；三家分别准备各自的清单，不因支持多平台而自动把同一作品上传到全部平台。账号、作品和章节范围沿用用户本次授权，不让作者手填 JSON、哈希或内部清单 ID；由助手维护机器数据。

页面配置必须来自当前实际后台的可见控件和稳定标识。用 `template platform-browser-fanqie`、`template platform-browser-qimao` 或 `template platform-browser-qidian` 取得对应结构，由助手在核对真实页面后填写入口、账号和作品身份、章节列表、完整分页、编辑器和保存方式；模板中的待配置值不能作为已验证适配。`chapter_lists` 必须覆盖全部章节状态：可是一份 `all` 目录，也可拆为 `drafts` 与 `non_drafts` 的多份目录。每份分别核对当前目录标志、筛选条件、加载完成信号 `ready`，以及完整分页或已经实页确认、排除分页和虚拟列表的完整表格（`all_rows`）；存在分卷时必须逐卷扫描，有草稿总数时另核对计数。只看到空白页不能判断没有目标章。同章已发布、审核中或其他非草稿状态会停止。配置保存在本书 `.story/platform-profiles/`，不含密码、验证码、Cookie 或令牌，不提交公开仓库。页面变化导致标识、字段、分页或保存行为无法明确识别时停止，不猜选择器或转用未公开接口。

本轮番茄配置可用账号核对页的真实 DOM 核对稳定账号，以完整 URL 模板核对作品和草稿 ID；不从书名或局部 URL 猜身份。没有编辑器草稿状态标志时，须在分开的完整草稿和非草稿目录中唯一确认真实 ID 与章号，并在回读后再核对；编辑器另需正向 `ready` 标志，初始空输入不能当作新稿已经加载完成。

`editor.body.source="prosemirror_paragraphs"` 仅用于已采样的番茄纯文本段落结构。读取时识别明确的空编辑器占位节点，并仅解码一个已观测的末尾空段哨兵；其余首段、尾段和连续空段全部保留。写入使用原生逐段输入，再比较完整正文，不使用整栏填充或裁剪空白来消除差异。未知节点、缺失哨兵或回读异文会停止，不能套用于未经核对的其他富文本编辑器。

2026-10-19 的 83 字符样本保存后重开只读到 81 字符，末尾两个 LF 丢失，因此不能承诺额外尾 LF 可在番茄持久保存；点击后 DOM 一致也不能代替重开回读。默认严格规则下该样本仍为冲突。若用户另选末尾 LF 策略，须在新一次只读对账中取得完整观察并新增等价证据，不改旧清单或旧失败记录，不追认原样逐字通过。

同日还观察到：仅打开或重载已有功能测试稿编辑页，编辑器中的正文长度也会增加，原因未确定，不能据此归因为并发。本轮番茄对账与回读已改用独立的只读预览路由；编辑页不作为只读回读通道。实际测试预览经重载保持稳定，生产回读完整取得 81 字符并对原 83 字符清单报告冲突。每份配置仍须按实页核对账号、作品、草稿 ID、章号、标题与完整段落；不能用预览总字数或局部文本替代完整正文，也不裁剪原稿来适配平台。

番茄宿主配置缺少 `readback` 时，工作台与执行器均明确阻断，不回退到编辑页。由助手按实际页面配置独立 `readback.url`（固定作品，只含一个 `{remote_id}` 占位符）、来自精确 URL 的 `remote_id`、`header` 的 `chapter_title` 合并格式，以及 `body.source="fanqie_preview_paragraphs_v1"`；作品身份模板另覆盖该预览完整 URL。预览地址不能同时匹配编辑路由，草稿状态仍由完整草稿／非草稿目录共同确认。预览段落仅接受无属性的直接 P：非末尾空段可为零子节点 P 或已观测的精确 `<p><br></p>`，只解码最后一个精确零子节点 `<p></p>` 哨兵，保留其余空段及字面空格。运行器先关闭自身创建的同稿编辑页；发现用户原有同稿编辑页则阻断并保留该页，不擅自关闭，也不把此保护机制当作正文增长原因已经查明。

执行前核对当前入口适用的规则与接入范围。2026-10-19 已从七猫网页版直接读取[作家中心用户服务协议](https://zuozhe.qimao.com/front/page/agreement/user)，页面标示 2023-11-15；第 1.2 条包含网页作家中心，第 3.1 节涉及平台认可的使用方式及第三方工具。不能再只引用作家助手客户端协议来解释网页版。起点应核对实际作家入口适用协议；[阅文通用用户服务协议](https://passport.yuewen.com/pact.html?mobile=0)有第三方工具相关限制，但本轮未确认它是否覆盖实际编辑入口。番茄[用户协议](https://fanqienovel.com/protocal/agreement)的本轮公开抽取仅得到标题，正文需在实际入口重新核对。这些核对不是平台已授予本项目自动接入许可的证明。

宿主桥接复用当前助手已有的 Chrome 浏览器工具，不因选择该模式而安装或启动 Playwright。以下依赖仅适用于用户另行选择的独立浏览器模式：使用隔离 Python 环境安装 `playwright`；默认 Chromium 还需运行 `python -m playwright install chromium`，配置 `browser_channel="chrome"` 则启动已安装的 Google Chrome；[Playwright 官方安装说明](https://playwright.dev/python/docs/library)。离线命令不导入该依赖。桌面客户端当前不内置 Playwright 或浏览器，不承诺安装客户端即可执行上传。执行器使用独立可见的临时会话，用户在平台界面自行登录和完成验证；它与本次浏览器工具连接的日常 Chrome 会话不同，不读取其他浏览器的登录资料、不导出登录状态，也不把会话写进作品备份。Chrome 启动失败不会自动改用其他浏览器。

作品内容操作仅允许对应官网同一 origin。`login_origins` 可配置已从真实页面核对的精确 HTTPS 认证 origin，仅在人工登录等待期间放行；登录完成关闭多余认证页，重新核对账号与作品后收回额外导航范围。该配置不证明三家 SSO 全流程可用。新建若需要点击并打开新页，可配置 `create_action`（`mode="button"`、唯一 `selector`、实际 `expected_text`、`opens="popup"` 或 `"same_page"`），此时 `urls.create` 指向已核实的列表落点。打开新建页或点击新建按钮可能立即创建空白云端草稿，因此只有持久记录发送意图后才执行；弹窗丢失或中断不重试创建。

## 命令流程

`<tool>` 是同版共享 `story-skill/scripts/story.py` 的绝对路径。

1. 按发布技能运行 `publish-prepare`，取得绑定真实平台、账号、作品和正式章节范围的清单。
2. `python "<tool>" publish-draft-run --book "<绝对书根>" --id "<清单ID>"`：仅做本地预览，不启动浏览器或联网。核对目标与冻结章序。
3. 用户已要求保存这批草稿且页面配置和接入条件齐备时，执行 `python "<tool>" publish-draft-run --book "<绝对书根>" --id "<清单ID>" --profile "<本机页面配置JSON>" --execute`。只在这个显式入口执行平台操作，既有批次授权不逐章重复确认。宿主模式的 CLI 仍须先由助手连接工作进程并通过健康探测；它本身不启动自动连接控制器，没有健康工作进程时阻断。工作台可按上节自动连接后执行同一生产核心。独立模式的 CLI 默认人工登录等待三分钟，需要十分钟时显式加 `--login-timeout-ms 600000`；工作台默认十分钟。
4. `python "<tool>" publish-draft-status --book "<绝对书根>" --id "<清单ID>"`：查看本地执行历史；它不访问平台，不能当作本次远端状态。
5. 中断后先用带 `--execute --reconcile-only --profile "<配置>"` 的 `publish-draft-run` 对账。该模式只读远端，不创建草稿。结果未知且无法找到明确对应草稿时保持待核实，不通过删除日志、换清单或恢复旧备份重发。

每次继续执行都核对正式稿与远端草稿。当前清单过期、已取消或源文件变化时，停止新写入；历史回执仍保留。写入前持久记录意图，随后才打开可能触发自动保存的新草稿编辑页。网络操作不长期占用创作锁。创建后从独立只读入口完整读取标题和正文，按本次显式规则分别报告逐字一致或等价接受，不改实际观察来制造一致。

## 结果与恢复

执行历史独立保存在本书 `.story/platform-drafts/`，保存目标、清单指纹、章节、状态、尝试和内容摘要，不复制稿件全文或登录资料。本机另在 `~/.story-skill/platform-drafts/` 保存目标与内容的哈希及发送尝试标记，用于跨清单、书根副本和旧备份识别未决写入；不含账号原文、书稿或登录材料。丢失这些本机标记或转移到另一台电脑仍不能据此保证去重。原离线清单、比较历史和创作 revision 不因此变为远端发布事实。

宿主桥接队列与上述摘要日志分开：`.story/platform-chrome-bridge/` 下的私有目录为 `0700`、文件为 `0600`，请求和响应可含本次标题、正文及实际页面观察。外部句柄含本地桥接令牌，均不包含 Chrome Cookie；这些私有文件不进入公开仓库、测试夹具或技能包。当前断开与任务结束不自动清理它们。排查或恢复时保留必要证据；结束后可由助手按本机数据保留要求整理私有副本，不能借清理队列删除或绕过原发送记录。

向作者逐章说明已保存且源稿逐字一致、按明确规则核对通过、已有对应草稿、内容冲突、受阻或结果未知；批量部分成功列出具体断点。编码或等价接受不冒称源稿逐字一致。旧执行回执是当时观察，不能保证远端后来没有人工改稿。平台状态与本地执行状态分别解释，保存成功只证明进入草稿箱。

已有同章草稿必须回读后再判断；同章不同内容或多份草稿停止，不覆盖。列表分页不完整、只能读到正文片段或账号、作品变化时停止。写入后的超时、进程退出、回执落盘失败按结果未知处理，先查远端；找不到不能证明平台未收到。本机按平台、账号和作品串行，跨设备并发不能据此保证去重。

未命名草稿也可能已经分配章号。遇到未命名或无法明确读取章号的旧稿，先人工核对；不能将其忽略后判断目标章不存在并重建。若此前已有发送意图但结果不明，仍须先只读对账，不能通过整理目录或换清单绕过未决记录。

本次只保存标题和正文。作者的话与配图、整篇短故事投稿、建书、更新既有草稿、已发章覆盖、提交审核及排期均需各自的实现和验收。未支持的动作不能通过点击“发布”“下一步”或修改本地回执来完成。
