# 开书与规划

先按需读取 `../story-skill/SKILL.md` 的“共同约束”；同版内容已在当前上下文中则复用。此入口已完成任务选择，不执行公共入口的路由。共享工具位于 `../story-skill/scripts/story.py`，记其绝对路径为 `<tool>`；下文所有书籍命令都显式附加 `--book "<书目录绝对路径>"`。公共技能或所需工具缺失时，说明缺失路径并提示安装完整 Story Skill 套件；不假称已执行。

从用户要求/已有项目确认题材、读者期待、主角欲望、代价、篇幅和不可改变的事实。缺少可自行选择的设定时提出并采用合理方案；涉及已有剧情的未知项先查证。不要求必须有对标书。

番茄、七猫商业连载的开书与细纲采用 [商业连载节奏](../story-skill-write/references/drama.md#番茄与七猫商业连载)，在本章具体内容中落实开头牵挂、中段变化、局部回报与章末钩子；这些是创作要求，不是平台分类或审核规则。

开书或复核总纲时，对照书名、简介和题材标签，核对最主要的阅读承诺由哪些情节建立、阶段兑现并影响后续；延后兑现应有本书理由，慢热也可通过小的关系或认知变化维持期待。发现定位与安排不符时，指出具体项，按本次授权校准定位或情节安排，再展开相关细纲，不统一规定兑现章号。

正式新开或维护任何小说的全书总纲（短篇可用等效规划）时，在靠前位置按 [大纲的平台分类字段](../story-skill/references/project-state.md#大纲中的作品类型与平台分类) 写明本书是长篇还是短篇、目标平台、该平台对应的栏目与拟选分类、每项内容依据、核对来源和拟选／已确认状态。用户指定多个平台时分平台记录，不把某平台的词和数量限制套给另一平台；未指定平台时从书内约定或本次投稿目标判断，仍无目标则暂定拟投平台并说明依据，不把暂定值说成后台已确认。番茄书才读取 [番茄标签选择表](references/fanqie-tags.md)：长篇用“阅读标签／内容标签”，短篇用“作品分类”的“主分类、情节、角色、情绪、背景”；其他平台核对其当前官方页面或用户提供的后台截图后使用原栏目名称。不能核实平台选项时列出待核对项和原因，不把自拟题材词伪装成可提交标签。已有平台分类先核对实际值，不擅自更改；平台分类不写入工具章计划的 `tags`。交付总纲前核对这些字段齐全，待核对项不能报为平台已确认。

设计主线矛盾、开篇看点、具体紧急处置、经营选择或数字安排、其他专业过程，或修整平淡大纲时，读取 [冲突与看点](../story-skill-write/references/drama.md)，具体取舍以该共享指导为准。不要把世界观清单或工具状态当情节来源。近期细纲写清具体尝试、阻力如何回应、选择造成的变化，以及读者会在哪场戏得到回报；可核验的办事流程只有实际改变人物选择、阻力或后果时才进入细纲，不能用它代替剧情推进，也不靠“强冲突、大反转、爽点”标签代替内容。关系、幽默和日常也可承担看点。

用户仅要求独立局部设计、且未要求更新已采用规划时，交付所需方案到本次范围完成为止；已有总纲则核对相关内容，没有则不为局部方案补建全书总纲或书库。正式开书、保存正式规划或更新已有工程时，再执行下述目录与状态流程。

新书落盘前先读取 [书名目录与开书落点](../story-skill/references/project-state.md#书名目录与开书落点)，确定最终书根。默认在写作父目录下先建以书名命名的独立文件夹，再执行 `init --book "<父目录>/<书名>" --title "<书名>" --kind long|short`；`--book` 已是最终书根，`--title` 不会再创建书名子目录。用户明确指定书目录或继续已有书时沿用原位置。初始化后核对回执中的 `created/title` 与实际目录；短篇同时核对 `short_assembly_path`，完整书名与合法文件路径分别记录。再把约定、策划和大纲保存到该书根；交付时给出实际书目录。需要独立策划或设定文件时，按 [参考分析与策划资料](../story-skill/references/project-state.md#参考分析与策划资料) 的默认目录保存，已有等效布局沿用。从拆书开书时，先把选用的方法及其来源、适用条件和原创改造写入策划资料，再据此设计人物、关系、事件链和结局；不把参考剧情当作本书事实。长篇先交代全书从开端到结局的走向与分卷粗纲，再展开近期细纲；说明本卷目标、升级代价和终局储备，未确定处标明待定，不为填满章节提前细化全书。短篇先有结局与关键选择，可用一份规划简化层级。不扩写未授权的规划部分。

保存可读规划时读取 [项目状态的目录约定](../story-skill/references/project-state.md#可读的大纲与细纲)：默认在 `01_大纲细纲/` 维护全书总纲、带卷名的本卷大纲和一章一文件的细纲，已有等效目录沿用。分批“继续”更新同一组当前入口，场面设计并入对应章，旧版本归档。普通修改或整理已采用的细纲，同步更新已有工具章计划；沿用已有采用依据，不重复确认，不把候选自动变为已采用。只做大纲时到已授权产物完成为止。

章计划明确章名 `title` 和带真实卷名的 `volume_dir`（固定为 `第X卷 卷名`，如 `第一卷 雨夜`），同卷各章保持一致。短篇与单卷作品也须明确首卷名称；已有 `volume` 时可沿用该卷已保存的完整目录，或已符合此格式的世界卷标题。缺少卷名时先核对已有规划；尚未命名则依据已授权的本卷内容拟定卷名后再提交，不以无卷名目录或内部 ID 补值。

用简短 `创作约定.md` 保存题材/读者期待、叙述视角、核心欲望与代价、篇幅口径、必须保留/禁止项、当前授权阶段和下一动作；它是本书约定，不是用户画像。已有书合并新要求，遇冲突指出具体项。只为本次有意义的约束建 `kind: contract, critical: true` 卡，不复制整份设计。每次真正保存完成后更新断点；新会话先查约定与 status，尚未导出不能记成完成。

既有 oh-story 或其他项目：原目录只读，选独立新目录运行 init。读取末章、当前细纲、相关角色与未回收伏笔，以 `notes` 建立紧凑基线，再 `adopt --chapter N --draft "<最后完整章>" --summary "<衔接摘要>" --volume-dir "第一卷 雨夜" --expect R`，示例卷名须替换为本书实际卷名；也可省略该选项，让工具从已保存的第 N 章计划取得完整分卷目录。R 取最新 status。工具只保存有证据的第 N 章快照，不假造前 N 章的审查或分析记录；原文件、原进度、原 hooks 都不改。短篇需要完本全文时，按 [旧短篇补齐原章](../story-skill/references/project-state.md#旧短篇补齐原章) 用 `adopt-backfill` 补齐真实旧章后再合并。没有必要先全量拆书。

需要保存状态卡或章计划时读取 [项目状态](../story-skill/references/project-state.md)。只做规划到已授权设计产物完成为止；用户明确要求正文后再切换 [正文写作](../story-skill-write/SKILL.md)，不把完成大纲视作自动授权正文。
