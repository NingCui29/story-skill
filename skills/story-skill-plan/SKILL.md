# 开书与规划

执行本任务前必须读取 `../story-skill/SKILL.md` 的“共同约束”并遵守本次适用规则；同版内容已在当前上下文中则复用。此入口已完成任务选择，不执行公共入口的路由。共享工具位于 `../story-skill/scripts/story.py`，记其绝对路径为 `<tool>`；下文所有书籍命令都显式附加 `--book "<书目录绝对路径>"`。公共技能或所需工具缺失时，说明缺失路径并提示安装完整 Story Skill 套件；不假称已执行。

从用户要求/已有项目确认题材、读者期待、主角欲望、代价、篇幅和不可改变的事实。缺少可自行选择的设定时提出并采用合理方案；涉及已有剧情的未知项先查证。不要求必须有对标书。设计新书开篇时按 [开篇切入与代入](../story-skill-write/references/drama.md#开篇切入与代入) 选当下场景：明确读者跟随谁、人物的切身目标与风险，以及开头事件怎样引向主线；不以一个脱离后文的“爆点”代替切入。

用户要求商业选题筛选、提高热文机会或检验卖点时，按 [选题取舍与验证](../story-skill-research/references/reader-validation.md) 区分读者需求、候选差异和未验证假设，明确本次采用方向的理由；已确定方向不强制重选，规划任务不自动试写。

为作品拟定或优化书名、卷名、章名，或新建卷纲、章细纲时，按 [小说命名的吸引力](../story-skill-research/references/reader-validation.md#小说命名的吸引力) 区分全书阅读理由、卷内阶段看点与本章阅读期待，核对名称的辨识度和相应内容依据；未定名或要求比较时给有实质差异的候选及推荐理由。已定名称沿用，发现偏弱处按本次授权提出建议或优化；只请求拟名或评估时完成该范围，不自动初始化书库、改正式名称或制作封面。

正式开书时随策划形成作品简介，已有有效简介则沿用；拟写、审查或优化简介按 [小说简介拟写与优化](references/blurb.md) 以吸引目标读者点开正文为目标，强化开头的独特看点与读完后的具体期待，核对本书事实、主要承诺和剧透范围，按本次权限交付成稿或审查意见。独立简介请求到该产物完成为止，不触发后续人物建档、平台分类或书库流程。

正式开书或实质设计、调整人物时，按 [主要人物定义与核对](../story-skill-write/references/drama.md#主要人物定义与核对) 先明确标出本次涉及的主角，并逐人注明本次范围关键人物的角色定位、身份及主线作用，建立可用基线，再展开相关事件与细纲。涉及说话方式时按 [人物对话方式](../story-skill-write/references/drama.md#人物对话方式) 明确有依据的关注点、接话倾向及面对不同关系的变化，不只给每人分配口癖。定义与主线设计保存于现有策划或设定，已有等效内容直接沿用；独立局部设计只完成所需角色和关系，不扩成全书建档。

章计划采用 [章幅与计数](../story-skill-write/references/chapter.md#章幅与计数) 的统一标准：新完整章默认正文 2400—2800 字、`visible_nonspace_v2`、不含首行章名，短篇按章交付同样适用。范围、口径或标题计数的明确例外按 [例外依据](../story-skill/references/project-state.md#状态卡与工具章计划) 保存真实来源；未写章的旧默认范围按授权同步，旧章和局部任务不自动扩写。

番茄、七猫商业连载的开书与细纲采用 [商业连载节奏](../story-skill-write/references/drama.md#番茄与七猫商业连载)。把开篇危机与情绪拉扯、各章可见回报和由本章后果生出的钩子落到具体事件；按 [钩子的承诺与兑现](../story-skill-write/references/drama.md#钩子的承诺与兑现) 连看本章停笔点与下一章的回应，明确下一场为何值得读者见证，不能只给每章单独填写一个悬念。连续规划时检查相邻章节是否只换人换物地重复。这些是创作要求，不是平台分类或审核规则。

独立设计或优化钩子方案时，也按上述钩子指导从本书已有设定、人物牵挂与具体阅读期待出发；开篇结合切入与代入，章末结合本章回报与后续回应。交付可落到本次规划中的事件和停笔安排，不只写“留下悬念”；仅要求方案时不自动写正文、采用方案或初始化书库。

开书或复核总纲时，对照书名、简介和题材标签，核对最主要的阅读承诺由哪些情节建立、阶段兑现并影响后续；延后兑现应有本书理由，慢热也可通过小的关系或认知变化维持期待。若卖点声称现实、关系或局势发生“变化”，规划须说清可观察的前态、变化和人物承担的后果，不能把新线索首次出现直接当成已证实的变化。发现定位与安排不符时，指出具体项，按本次授权校准定位或情节安排，再展开相关细纲，不统一规定兑现章号。

正式新开、维护总纲（短篇可用等效规划）或直接回答“分类／标签”时，默认同时给出**番茄、七猫**两套分类；本次要求或书内约定还涉及其他平台的，一并逐平台列出。主投平台可单独注明，不因此省略另一平台；只有用户明确要求本轮仅处理某一平台时才收窄范围。文件和答复均须完整覆盖，不能总纲写了两套、答复却只给一套。在各平台分类前统一列出主角与关键人物的角色定位，按共享规则标明姓名或稳定称呼、身份关系及主线作用；平台“角色”标签另按其原生栏目填写。按 [大纲的平台分类字段](../story-skill/references/project-state.md#大纲中的作品类型与平台分类) 为每个平台分别保存入口、作品阶段、原生栏目、具体分类、内容依据及来源日期，不能合写一组“通用分类”。每个平台还须按 [平台作者名与署名](../story-skill/references/project-state.md#平台作者名与署名) 分别列出作者名／笔名及依据、状态，不将一平台署名自动套给另一平台。

分别读取 [番茄标签选择表](references/fanqie-tags.md) 和 [七猫作品类型与标签](references/qimao-tags.md)，按本书在各平台实际拟选或已使用的入口、频道及栏目填写；篇幅类型不代替入口，不跨平台借词。各栏标拟选、后台已确认或待核对，经证实可选才标“不选”。某个平台暂不能核实，也保留该平台完整栏目和已有可靠依据，明确具体待核对项，不能省略该平台或自造官方标签。其他平台按其官方页面或用户提供的后台截图核对；已有分类保留实际值，变化单列说明。平台分类不写入工具章计划的 `tags`。

交付总纲前，默认对现行文件运行 `outline-audit --book "<书根>" --file "<书根内相对总纲路径.md>" --require-platform fanqie --require-platform qimao`，分别检查两平台字段与来源日期，避免一套字段替另一套补缺；明确仅处理一个平台时只要求对应平台。随后人工核对每个平台的选项、数量、状态与正文依据，其他平台未内置的规则也逐栏核查。等效格式未被工具识别时，说明未覆盖处并人工核对，不为通过检查改写真实布局，也不把待核对报成平台已确认。

设计主线矛盾、开篇看点、具体紧急处置、经营选择或数字安排、其他专业过程，或修整平淡大纲时，读取 [冲突与看点](../story-skill-write/references/drama.md)，具体取舍以该共享指导为准。不要把世界观清单或工具状态当情节来源。近期细纲写清具体尝试、阻力为何不能轻易绕过、尝试如何引出回应、人物如何应变或取舍，以及读者会在哪场戏看到局面变化和回报；连章安排按 [主线跨章推进](../story-skill-write/references/drama.md#主线怎样跨章前进) 核对前章结果怎样改变后章条件，不只排列各章独立事件；更新近期细纲时按同一参考回看阶段完成条件与正文积累，再安排尚未具备的条件。可核验的办事流程只有实际改变人物选择、阻力或后果时才进入细纲，不能用它代替剧情推进，也不靠“强冲突、大反转、爽点”标签代替内容。关系、幽默和日常也可承担看点。规划下一卷时，核对上一卷结束条件是否已在正文达成；有意推迟或改换目标，就明示新的跨卷因果并按授权更新卷纲，不能仅靠切换目录视作阶段完成。

设计近期细纲或优化已有剧情时，按 [剧情设计与优化](../story-skill-write/references/drama.md#剧情设计与优化) 明确阅读期待与人物目标，推演尝试、回应和后果，再倒查关键结果的支撑并安排章位与篇幅；已有结局可倒推，但仍须按发生顺序核对人物行动的依据。修改后连读受影响的事件链，核对原缺口、有效内容及后续条件，交付具体安排与未解决项；未发生的条件仍是计划，不能以字段审计通过代替这项语义复核。发现看点不足或明显撑长风险，先按本次授权处理情节或章节安排，再进入正文。

规划章节、阶段或全书高潮时，按 [高潮与阶段兑现](../story-skill-write/references/drama.md#高潮与阶段兑现) 核对先前哪些行动与关系使关键选择成立、对方如何回应，以及本次究竟兑现了哪项承诺；不以“爆点”“大反转”的标签代替决定性场景，也不为高潮临时换规则。

用户仅要求独立局部设计、且未要求更新已采用规划时，交付所需方案到本次范围完成为止；已有总纲则核对相关内容，没有则不为局部方案补建全书总纲或书库。正式开书、保存正式规划或更新已有工程时，再执行下述目录与状态流程。

新书落盘前先读取 [书名目录与开书落点](../story-skill/references/project-state.md#书名目录与开书落点)，确定最终书根。默认在写作父目录下先建以书名命名的独立文件夹，再执行 `init --book "<父目录>/<书名>" --title "<书名>" --kind long|short`；`--book` 已是最终书根，`--title` 不会再创建书名子目录。用户明确指定书目录或继续已有书时沿用原位置。初始化后核对回执中的 `created/title` 与实际目录；短篇同时核对 `short_assembly_path`，完整书名与合法文件路径分别记录。再把约定、策划和大纲保存到该书根；交付时给出实际书目录。需要独立策划或设定文件时，按 [参考分析与策划资料](../story-skill/references/project-state.md#参考分析与策划资料) 的默认目录保存，已有等效布局沿用。从拆书开书时，先把选用的方法及其来源、适用条件和原创改造写入策划资料，再据此设计人物、关系、事件链和结局；不把参考剧情当作本书事实。长篇先交代全书从开端到结局的走向与分卷粗纲，按 [情节与篇幅匹配](../story-skill-write/references/drama.md#情节与篇幅匹配) 判断各阶段是否有内容支撑预定全书规模，再展开近期细纲；本卷按 [可读的大纲与细纲](../story-skill/references/project-state.md#可读的大纲与细纲) 落下阶段承诺、关键人物策略与跨卷因果，未确定处标明待定，不为填满章节提前细化全书。短篇先有结局与关键选择，可用一份规划简化层级。不扩写未授权的规划部分。

保存可读规划时读取 [项目状态的目录约定](../story-skill/references/project-state.md#可读的大纲与细纲)：默认在 `01_大纲细纲/` 维护全书总纲、带卷名的本卷大纲和一章一文件的细纲，已有等效目录沿用。分批“继续”更新同一组当前入口，场面设计并入对应章；实质改动已采用规划时归档旧版，纯章节进度句更新无需每章另存大纲历史副本。实质调整已采用的总纲或卷纲时，按 [已采用规划的联动](../story-skill/references/project-state.md#已采用规划的联动) 定位并同步受影响的下级规划与工具计划，未完成项注明范围。普通修改或整理已采用的细纲，同步更新已有工具章计划；沿用已有采用依据，不重复确认，不把候选自动变为已采用。正式章细纲与工具计划核对一致后，按 [已采用细纲绑定](../story-skill/references/project-state.md#已采用细纲绑定) 登记所审阅的具体版本；候选不绑定。只做大纲时到已授权产物完成为止。

章计划明确章名 `title` 和带真实卷名的 `volume_dir`（固定为 `第X卷 卷名`，如 `第一卷 雨夜`）。新增卷纲、章细纲前核对同书既有目录和工具计划：各章名称全书唯一，不因分卷重置；不同卷的卷名也不能重复，同卷各章则共用该卷目录。短篇与单卷作品也须明确首卷名称；已有 `volume` 时可沿用该卷已保存的完整目录，或已符合此格式的世界卷标题。缺少卷名时先核对已有规划；尚未命名则依据已授权的本卷内容拟定卷名后再提交，不以无卷名目录或内部 ID 补值。

用简短 `创作约定.md` 保存题材/读者期待、[可执行的叙述约定](../story-skill-write/references/drama.md#叙述视角与场景转接)、核心欲望与代价、篇幅口径、必须保留/禁止项、当前授权阶段和下一动作；它是本书约定，不是用户画像。已有书合并新要求，遇冲突指出具体项。只为本次有意义的约束建 `kind: contract, critical: true` 卡，不复制整份设计。每次真正保存完成后更新断点；新会话先查约定与 status，尚未导出不能记成完成。

既有 oh-story 或其他项目：原目录只读，选独立新目录运行 init。读取末章、当前细纲、相关角色与未回收伏笔，以 `notes` 建立紧凑基线，再 `adopt --chapter N --draft "<最后完整章>" --summary "<衔接摘要>" --volume-dir "第一卷 雨夜" --expect R`，示例卷名须替换为本书实际卷名；也可省略该选项，让工具从已保存的第 N 章计划取得完整分卷目录。R 取最新 status。工具只保存有证据的第 N 章快照，不假造前 N 章的审查或分析记录；原文件、原进度、原 hooks 都不改。短篇需要完本全文时，按 [旧短篇补齐原章](../story-skill/references/project-state.md#旧短篇补齐原章) 用 `adopt-backfill` 补齐真实旧章后再合并。没有必要先全量拆书。

需要保存状态卡或章计划时读取 [项目状态](../story-skill/references/project-state.md)。只做规划到已授权设计产物完成为止；用户明确要求正文后再切换 [正文写作](../story-skill-write/SKILL.md)，不把完成大纲视作自动授权正文。
