# 正文单元的写作与提交

本流程用于正式托管的正文单元。起草前读取 [冲突、看点与中文场景](drama.md)，同版已在上下文中则复用；新书首章重点核对开篇切入，多章连载核对跨章推进，高潮章核对阶段兑现，章末核对钩子承诺与下章回应，按本次任务取用对应段落。使用共享 `<tool>`；下列所有书籍命令均附加 `--book "<书目录绝对路径>"`。本章计划和授权范围已确定后执行。

## 章幅与计数

新写的完整章节正文须在 2400—2800 字内，短篇按章交付同样执行。默认章计划为 `length: [2400, 2800]`、`count_method: visible_nonspace_v2`、`count_title: false`。v2 统计独立可见字符，含标点，排除普通空白、控制／格式字符、附着标记及已识别的空白外观填充符。

默认不计首行章名，兼容识别旧稿 Markdown H1；`count_title: true` 时计标题文字，H1 开头的 `#` 和可选尾部闭合标记不计，标题内容中的 `C#` 等实际文字仍计。导语属于正文，作者说明和审稿意见不混入正文。`visible_nonspace_v1` 沿用旧可见字符口径；`letters_numbers_v1` 只计 Unicode 字母与数字，中文／英文均逐字符；`han_v1` 只计 Unicode 已命名汉字及〇。各口径排除普通空白和控制／格式字符；使用其他口径的新稿仍以 v2 交叉核验最低字数，不用附着标记或填充符垫数。旧章保持历史计数，不追溯重算。

起草或已授权整章修订前核对本轮要求、现行 `创作约定.md` 与计划；旧范围只是先前默认值时，先同步相关计划和可读细纲。用户或书根约定明确要求其他范围、口径或标题计数时，在计划中按 [章幅例外依据](../../story-skill/references/project-state.md#状态卡与工具章计划) 留存真实来源与原句，再按约定核验；单改 `plan.length` 不能使无依据例外生效。已提交旧章、章中续写及局部修改不因新章要求自动扩写。

按所选口径报告实测数，不冒称平台后台字数。欠字只补足已授权且对人物选择、回应、感受或后果有作用的内容，超字压缩冗余；不展开无新作用的账目或流程凑字数，不补造情节。

## 正式章节流程

已按 [已采用细纲绑定](../../story-skill/references/project-state.md#已采用细纲绑定) 登记的章节，`context` 会校验可读细纲与工具计划的具体版本；版本漂移时先审阅并同步，再重新绑定。返回 `outline.status=unbound` 的旧章节仍要定点核对已采用细纲，不能把未绑定误报为一致。

1. `context --book "<目录>" --chapter N --budget-bytes 16000`。它完整保留本章工具计划、匹配范围的 critical 卡和到期承诺、requires 卡及上章摘要/末尾；已绑定细纲仅校验文件摘要，不返回细纲内容或判断语义一致。定点读取本章已有细纲及采用依据，与返回计划核对；不一致时按 [项目状态](../../story-skill/references/project-state.md) 同步已采用内容，再重新取得 context，不用候选覆盖现行计划。进入新卷时还须回读前卷结束条件和有关正文：若条件未达成，按授权说明推迟或修订卷纲，并让跨卷行动承接这一缺口，不能以新卷目录替代前卷回报。核对本章所需硬限制卡已在 required_cards 中；`volume_dir` 不建立 scope 关联，缺卡先修正对应稳定 ID 或 requires。预算是 UTF-8 字节，不是假称的模型 token；仅不相关的可选卡可被省略。过期/已完成伏笔也可按 requires 显式召回。查历史原因用 `recall --query "<人名或线索>"`，必要时读取精确原文。
2. 在 `.story/drafts/` 起草前按 [主要人物定义与核对](drama.md#主要人物定义与核对) 定点核对本章关键人物及当前状态，并按 [叙述视角与场景转接](drama.md#叙述视角与场景转接) 核对有关约定和衔接，再按已读场景指导展开章计划，保留本书声线与有功能的安静，不提前用尽终局底牌。起草前对照近期章节；若主要场景反复是核对条件、比对材料或登记结论，且没有带来新的取舍、关系或实际后果，先在授权范围内调整计划，不靠流程填足篇幅。衔接不清时定点补读原文。核对章名及所属卷的完整 `第X卷 卷名` 目录；完整章节沿用已确定的章号与章名，草稿首行使用纯文本 `第N章 章节名称`；正文依 [成稿格式](drama.md#成稿格式) 按语义分段，普通段间空一行，不手工缩进或插入装饰分隔线；[对白分段](drama.md#对白分段与说话人)以发言和说话人归属为准。同一人物紧密动作与短对白可同段。正文不添加 Markdown 的 `#` 标题、加粗、列表、引用、链接或代码围栏语法；作品本身需要的专用符号仍按原意保留。文件仍为 `.md`，章计划 `title` / `volume_dir` 的取值规则见 [项目状态](../../story-skill/references/project-state.md)。
3. `lint --chapter N --draft "<草稿>"` 检查计划中的章名与分卷导出路径、[篇幅及例外依据](#章幅与计数)、损坏字符、占位符和重复行。新完整章的首行须是纯文本 `第N章 章节名称`，章号、章名与计划一致；旧章原有的无章头或 Markdown 章头仅在首行和计划章名均未改时兼容，新改的首行须符合现行规则。`prepare`、提交和历史发布也核对章头。正文的工作材料、Markdown 标记、空行、对白归属、句号位置、破折号用途与语义标点仍须按 [成稿格式及校对](drama.md#成稿格式) 通读；`lint` 不识别这些语境，不能据此报告格式或语义已通过。
4. 先按 [正文内容审查](content-review.md) 读完本章与必要衔接，形成因果、连续性、约束与读感的真实结论；对照本章计划与明确阅读承诺，保留支持、反证及未解决问题。首章、中途章、高潮章按各自阶段复核，不逐场套同一构思公式。若字数与事实检查通过而读感仍平，如实保留该意见，不称质量通过。
5. `prepare --chapter N --draft "<草稿>"` 返回 lint 与绑定书籍、状态版本、稿件哈希的 delta 骨架；将其中 `delta` 另存文件，再依据第 4 步结论填写摘要、changes 和因果／连续性／用户约束／文风四项观察与最终稿原句，处理问题清单。四项和引文只是提交凭据的结构门槛，不能代替实际通读。骨架含待审阻断项，不能直接提交；`blocker` 未解决不能提交，普通建议可说明取舍。changes 仅记正文实际发生的变化，引文必须来自最终草稿；审查后稿件改变时重读受影响内容并重新取得骨架，不只更新哈希。
6. `commit --chapter N --draft "<草稿>" --input "<delta.json>"`。正文、审查凭据、增量状态在同一 SQLite 事务中保存；随后按分卷导出为 `chapters/第X卷 卷名/第N章 章节名称.md`，N 不补零，使用回执给出的实际路径交付。已有章的旧导出路径不自动批量迁移。重复同一提交不会推进两次。版本冲突先刷新上下文并复核，不能只改 revision 数字重试。导出失败运行 `export` 恢复，不能把未导出的章说成交付完成。交付前打开实际导出文件，核对章名、授权范围、正文完整性、段落和标点，与最终稿一致；已提交章若仍需去格式，转审稿修订流程，不直接改托管导出文件。成功导出后，若现行可读总纲、卷纲或细纲写了明确的提交进度，只更新涉及本次章节的状态句并对照 `status`，不把尚未兑现的卷目标标成完成；纯进度更新无需另存每章的大纲历史副本，实质规划变更仍按 [项目状态](../../story-skill/references/project-state.md#可读的大纲与细纲) 归档。外部改稿冲突转 [审稿修订](../../story-skill-review/SKILL.md) 的 reconcile。

提交后为下一章保存状态时，先看它是否依赖本章较早出现的关键原话、物件归属、人物知情或期限；`previous.tail` 与摘要未覆盖的关键内容，应定点回读正式正文，并在确需跨章召回时保存简短有来源的卡片、加入下一章 `requires`。不把每个观察都记成卡片，也不把卡片代替原文。

## 全书完本审查

写到本书实际终章并准备报告完本，或本次明确要求整书完本审查时，长篇与短篇都核对已采用总纲、开篇建立的主要阅读承诺和实际结局。以本次待交付稿为准，用目录、摘要和状态记录定位，再回读有关原文：核心冲突如何经由人物的关键选择走到结果，主要关系与代价的后果是否呈现，重点承诺与伏笔是否已兑现，或有作品内的依据说明其转变、放弃。

区分本书已收束的事项、有意开放的问题与续作引子；开放结尾可以留未知，不要求交代所有人物的余生，也不能用续作悬念遮住本书主线的缺口。此处审查的是主线与结局的结构性收束，不代替逐章全量读感审查；结论沿用本次审稿记录，指出依据、实际回读范围和未解决项。缺原文或结局尚未成稿时说明未核范围，不凭大纲、状态标记或单章通过报告全书完本。普通中途章节或局部校对不自动扩成全书审查。

## 短篇完本与修订交付

完整短篇交付时，无论新写还是修订后成品，都核对现行全书总纲或等效规划中的篇幅类型、目标平台、平台原生分类、各项实际正文依据、来源与核对日期及拟选／已确认状态。缺文件、缺项或与终稿不符时，按 [大纲的平台分类字段](../../story-skill/references/project-state.md#大纲中的作品类型与平台分类) 留存已有旧版并补齐或更新；已有平台确认值保持实际记录，差异和未核实选项明示待核对，不把本地拟选改称后台已确认。此项在完本交付时核对，不为每章重复查询平台。交付列出全文、实际封面和现行总纲／等效规划的路径，以及剩余待核对项。

短篇同样放入带卷名的首卷目录，可整篇作为第 1 单元，也可按用户要求分单元提交；范围对应当前单元。整篇单单元若超过默认每章 2400—2800 字，须有用户要求或书根 `创作约定.md` 明确采用单单元篇幅，并在写作前把实际范围写入该单元 `plan.length`、把真实依据写入 `plan.length_exception`；只给全书总字数不自动取消默认章幅。没有单单元例外时按有意义的叙事节点分章，不为凑字数机械切断场景。接入的旧短篇先按 [补齐原章流程](../../story-skill/references/project-state.md#旧短篇补齐原章) 核对并补存缺失原章。全书完本并完成逐章导出后，执行 `assemble-short --book "<目录>" --final-chapter N`，N 为本书实际最终章号；工具核对章节与导出，在书根新建全文并登记为受保护导出，逐章 `.md` 保留。普通书名使用 `<书名>.md`，特殊或过长书名使用回执中的合法文件名；完整书名保留在书籍信息中，预期与登记路径见 [书名与路径规则](../../story-skill/references/project-state.md#书名目录与开书落点)。新合并稿从第 1 章章名开始，按章号顺序仅包含各章章名和正文；旧版含书名首行的合并稿须重新合并并保留备份。核对章节完整、总长度、段落及导语没有重复，打开实际全文文件检查，再按 [全书完本审查](#全书完本审查) 核对文学收束并交付实际路径。

已有全文在正式章节修订、对账、历史发布或新增章节后随导出刷新，包含当前全部连续已提交章节。交付前核对 `status` 的 `short_assembly`、导出回执及实际全文；缺失或待导出时运行 `export` 恢复，全文外改时先把该文件移到 `.story/drafts/` 等非托管路径保留，再运行 `export` 恢复已提交版本；需要采用的改动逐章审查后提交，不直接用全文覆盖章节，也不把全文交给仅处理章节的 `reconcile`。`short_assembly` 仅说明同步状态和已合并章数；后续新增章节不受原终章号限制，是否完本仍须按实际终章、结局与全文核对。仅审稿或未采用的候选修改不刷新正式产物；单章要求不扩成全书，也不自动生成首次完本文件。

首次短篇完本合并通过后，读取 [封面技能](../../story-skill-cover/SKILL.md)，依据最终作品核对或制作封面；已有合格封面可直接沿用。把可打开的图片保存到本书目录，核对中文书名、已有作者署名和实际尺寸，与全文一起交付实际路径。后续正式修订仅在书名、署名、题材或投稿规格变化时复核并按需修订封面，不因普通文字校对重复制图。只交提示词或方案不算完成完本交付；没有生成能力时如实报告封面仍未完成。不为中途单章自动制作封面。

## 多章连载

多章连载按近期摘要和当前承诺，依 [主线跨章推进](drama.md#主线怎样跨章前进) 核对本章是否承接先前选择、阻力和解法是否重复；工作记录不为下一章自动生成同类情节。对手根据已知事件调整，旧办法留下后果；升级可改变合作条件、关系或责任。阶段所得要实际体验并影响后续，安静章容纳余波。摘要不够判断时定点补读原文，不把同一轮拖延或强塞新危机当推进。明确多章请求按章循环到授权范围完成。

写到已安排的高潮章时，按 [高潮与阶段兑现](drama.md#高潮与阶段兑现) 回看铺垫、正面碰撞、选择、结果和余波是否在正文中成立；不要只写到冲突将起便停章，也不要把关键胜负留给下一章的事后转述。高潮可以跨章，但前一章也要有实际攻守或处境变化，最终胜负在已规划的节点兑现。若本次授权只到高潮前的局部片段，按原停笔范围处理，不借这条擅自续写。
