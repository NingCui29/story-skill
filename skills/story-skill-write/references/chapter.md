# 正文单元的写作与提交

本流程用于正式托管的正文单元。起草前读取 [冲突、看点与中文场景](drama.md)，同版已在上下文中则复用。使用共享 `<tool>`；下列所有书籍命令均附加 `--book "<书目录绝对路径>"`。本章计划和授权范围已确定后执行。

1. `context --book "<目录>" --chapter N --budget-bytes 16000`。它完整保留本章工具计划、匹配范围的 critical 卡和到期承诺、requires 卡及上章摘要/末尾，不读取可读细纲。定点读取本章已有细纲及采用依据，与返回计划核对；不一致时按 [项目状态](../../story-skill/references/project-state.md) 同步已采用内容，再重新取得 context，不用候选覆盖现行计划。核对本章所需硬限制卡已在 required_cards 中；`volume_dir` 不建立 scope 关联，缺卡先修正对应稳定 ID 或 requires。预算是 UTF-8 字节，不是假称的模型 token；仅不相关的可选卡可被省略。过期/已完成伏笔也可按 requires 显式召回。查历史原因用 `recall --query "<人名或线索>"`，必要时读取精确原文。
2. 在 `.story/drafts/` 按已读场景指导展开章计划，保留本书声线与有功能的安静，不提前用尽终局底牌。衔接不清时定点补读原文。核对章名及所属卷的完整 `第X卷 卷名` 目录；完整章节沿用已确定的章号与章名，草稿首行使用纯文本 `第N章 章节名称`；正文依 [成稿格式](drama.md#成稿格式) 按语义分段，普通段间空一行，不手工缩进或插入装饰分隔线；[对白分段](drama.md#对白分段与说话人)以发言和说话人归属为准。同一人物紧密动作与短对白可同段。正文不添加 Markdown 的 `#` 标题、加粗、列表、引用、链接或代码围栏语法；作品本身需要的专用符号仍按原意保留。文件仍为 `.md`，章计划 `title` / `volume_dir` 的取值规则见 [项目状态](../../story-skill/references/project-state.md)。
3. `lint --chapter N --draft "<草稿>"` 检查计划中的章名与分卷导出路径是否合法，以及长度、损坏字符、占位符和重复行；`prepare` 也会预先检查计划中的名称，缺失时先补齐。草稿标题是否与计划一致、正文是否混入工作材料或 Markdown 标记、段间空行、对白归属、单对直接对白的句号位置、正文破折号用途及语义标点，须按 [成稿格式与校对规则](drama.md#成稿格式) 通读核对；`lint` 不识别这些语境，不因它通过就称格式与语义通过。`plan.length` 指定范围，`count_method` 默认 `visible_nonspace_v1`（含标点的可见字符）；`letters_numbers_v1` 只计 Unicode 字母与数字，中文/英文均逐字符；`han_v1` 只计 Unicode 已命名汉字及〇。默认排除首行纯文本章标题（旧稿的 Markdown H1 也兼容）、空白及控制/格式字符；`count_title: true` 计入标题文字。旧稿 H1 的开头 `#` 和可选尾部闭合标记不计入，标题内容中的 `C#` 等实际文字仍按所选口径计数。导语算正文，正文文件不混入作者说明或审稿意见。报告所选口径及实测数，不能冒称平台后台字数。欠字补足已授权场景过程，超字压缩冗余，不增造新剧情凑数。
4. `prepare --chapter N --draft "<草稿>"` 返回 lint 及绑定当前书籍、状态版本、稿件哈希的 delta 骨架；把其中 `delta` 另存文件，由 助手 填写摘要、changes 和因果/连续性/用户约束/文风四项观察与原句，并处理问题清单。在因果与文风观察中用原句核对人物为目标采取了什么行动、遭遇怎样的有效回应、局面或关系因而如何变化，阅读期待是否获得回报；工作记录不能代替这段故事。文风项同时按 [中文语法与标点校对](drama.md#中文语法与标点校对) 核对实际语句；用原句说明得失，不新增机器评分或“冲突数量”门槛。骨架含待审阻断项，不能直接提交；工具不代替审稿。changes 仅记正文实际发生的变化，引文必须在草稿中；`blocker` 未解决不能提交，普通建议可注明取舍。
5. `commit --chapter N --draft "<草稿>" --input "<delta.json>"`。正文、审查凭据、增量状态在同一 SQLite 事务中保存；随后按分卷导出为 `chapters/第X卷 卷名/第N章 章节名称.md`，N 不补零，使用回执给出的实际路径交付。已有章的旧导出路径不自动批量迁移。重复同一提交不会推进两次。版本冲突先刷新上下文并复核，不能只改 revision 数字重试。导出失败运行 `export` 恢复，不能把未导出的章说成交付完成。提交前按本项目成稿格式核对草稿；交付前打开实际导出文件，核对章名、授权范围、正文完整性、段落和标点，与最终稿一致；已提交章若仍需去格式，转审稿修订流程，不直接改托管导出文件。外部改稿冲突转 [审稿修订](../../story-skill-review/SKILL.md) 的 reconcile。

## 全书完本审查

写到本书实际终章并准备报告完本，或本次明确要求整书完本审查时，长篇与短篇都核对已采用总纲、开篇建立的主要阅读承诺和实际结局。以本次待交付稿为准，用目录、摘要和状态记录定位，再回读有关原文：核心冲突如何经由人物的关键选择走到结果，主要关系与代价的后果是否呈现，重点承诺与伏笔是否已兑现，或有作品内的依据说明其转变、放弃。

区分本书已收束的事项、有意开放的问题与续作引子；开放结尾可以留未知，不要求交代所有人物的余生，也不能用续作悬念遮住本书主线的缺口。结论沿用本次审稿记录，指出依据和未解决项；缺原文或结局尚未成稿时说明未核范围，不凭大纲、状态标记或单章通过报告全书完本。普通中途章节或局部校对不自动扩成全书审查。

## 短篇完本与修订交付

完整短篇交付时，无论新写还是修订后成品，都核对现行全书总纲或等效规划中的篇幅类型、目标平台、平台原生分类、各项实际正文依据、来源与核对日期及拟选／已确认状态。缺文件、缺项或与终稿不符时，按 [大纲的平台分类字段](../../story-skill/references/project-state.md#大纲中的作品类型与平台分类) 留存已有旧版并补齐或更新；已有平台确认值保持实际记录，差异和未核实选项明示待核对，不把本地拟选改称后台已确认。此项在完本交付时核对，不为每章重复查询平台。交付列出全文、实际封面和现行总纲／等效规划的路径，以及剩余待核对项。

短篇同样放入带卷名的首卷目录，可整篇作为第 1 单元，也可按用户要求分单元提交；范围对应当前单元。接入的旧短篇先按 [补齐原章流程](../../story-skill/references/project-state.md#旧短篇补齐原章) 核对并补存缺失原章。全书完本并完成逐章导出后，执行 `assemble-short --book "<目录>" --final-chapter N`，N 为本书实际最终章号；工具核对章节与导出，在书根新建全文并登记为受保护导出，逐章 `.md` 保留。普通书名使用 `<书名>.txt`，特殊或过长书名使用回执中的合法文件名；完整书名保留在书籍信息中，预期与登记路径见 [书名与路径规则](../../story-skill/references/project-state.md#书名目录与开书落点)。新合并稿从第 1 章章名开始，按章号顺序仅包含各章章名和正文；旧版含书名首行的合并稿须重新合并并保留备份。核对章节完整、总长度、段落及导语没有重复，打开实际全文文件检查，再按 [全书完本审查](#全书完本审查) 核对文学收束并交付实际路径。

已有全文在正式章节修订、对账、历史发布或新增章节后随导出刷新，包含当前全部连续已提交章节。交付前核对 `status` 的 `short_assembly`、导出回执及实际全文；缺失或待导出时运行 `export` 恢复，全文外改时先把该文件移到 `.story/drafts/` 等非托管路径保留，再运行 `export` 恢复已提交版本；需要采用的改动逐章审查后提交，不直接用全文覆盖章节，也不把全文交给仅处理章节的 `reconcile`。`short_assembly` 仅说明同步状态和已合并章数；后续新增章节不受原终章号限制，是否完本仍须按实际终章、结局与全文核对。仅审稿或未采用的候选修改不刷新正式产物；单章要求不扩成全书，也不自动生成首次完本文件。

首次短篇完本合并通过后，读取 [封面技能](../../story-skill-cover/SKILL.md)，依据最终作品核对或制作封面；已有合格封面可直接沿用。把可打开的图片保存到本书目录，核对中文书名、已有作者署名和实际尺寸，与全文一起交付实际路径。后续正式修订仅在书名、署名、题材或投稿规格变化时复核并按需修订封面，不因普通文字校对重复制图。只交提示词或方案不算完成完本交付；没有生成能力时如实报告封面仍未完成。不为中途单章自动制作封面。

## 多章连载

多章连载按近期摘要和当前承诺，核对本章是否承接先前选择、阻力和解法是否重复；工作记录不为下一章自动生成同类情节。对手根据已知事件调整，旧办法留下后果；升级可改变合作条件、关系或责任。阶段所得要实际体验并影响后续，安静章容纳余波。摘要不够判断时定点补读原文，不把同一轮拖延或强塞新危机当推进。明确多章请求按章循环到授权范围完成。
