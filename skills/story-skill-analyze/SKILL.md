# 小说拆解与证据

先按需读取 `../story-skill/SKILL.md` 的“共同约束”；同版内容已在当前上下文中则复用。此入口已完成任务选择，不执行公共入口的路由。共享工具位于 `../story-skill/scripts/story.py`，记其绝对路径为 `<tool>`；下文所有书籍命令都显式附加 `--book "<书目录绝对路径>"`。公共技能或所需工具缺失时，说明缺失路径并提示安装完整 Story Skill 套件；不假称已执行。

先确认分析范围。修订已有分析稿先按末节区分产物和保存方式。链接可用于查证，但网页预览不是全书。没有完整文本就只分析可见部分，标明缺章、取样方式和来源日期；不虚构剧情。保留番外、序章和特殊标题。此流程产物只作参考资料，不进入原创书的事实卡。

## 分析深度

用户要求深度／大师级分析、解释写法机制，或需要全书综合判断时，先读 [深读规范](references/deep-reading.md)。开篇简评和局部问题按范围作答；不因为进入本技能就扩大为全书分析。需要分析示范，或需纠正空泛概括、推断过强及评价尺度不明时，再读 [分析对照样例](references/examples.md)。深度由证据和解释决定，不预先授予“大师级”评价。

## 建立可恢复语料

单次局部点评或可在一轮完成的整篇短文深读，默认直接依据可见文本交付，不初始化语料工程。是否建工程取决于可恢复记录、跨轮处理或用户要求，不以分析深度本身触发；需要时进入下述语料、记录与聚合流程，已有来源沿用断点。

续跑先看 `status` 的 `pending_exports`、`changed_exports`，再看 `recent_sources` 的 source、next_chunk 和 report_path；更多来源用 `sources` 分页查找。报告可能已在数据库定稿但尚未落盘，不能只凭 `report_path` 判断交付完成。有待导出项先用 `export --safe-only` 恢复；冲突文件先保留并核对外部修改，不用正文的 `reconcile` 接管分析报告，也不覆盖冲突稿。已有来源直接 next，不重新 ingest。全部块完成且还没有 report_path 时从聚合继续。

`init --book "<独立分析目录>" --title "<作品>" --kind analysis`。若任务是拆书后另开原创作品，且用户只指定写作父目录，分析根默认选 `<父目录>/作品分析/<参考书名>/`；用户指定其他位置或已有分析工程时沿用原位置，不迁移旧资料。这个默认不改变上文单次点评无需建工程的规则。

`ingest --book "<目录>" --file "<原文.txt>" --coverage complete|partial|unknown` 保存不可变文本和来源哈希，按章节标题/字符上限切块；默认 coverage 为 unknown。支持 UTF-8，其他编码显式 `--encoding gb18030`。切块是工程边界，不能据此声称章节目录完整；用 `coverage --source ID` 与真实目录核对。无标题的文本同样可以分析，不凭空编号章节。

`next --source ID --limit 2 --budget-bytes 22000` 只返回未分析块，带原文范围与哈希；文本太大时明确报预算不足。块在语义中间切开时用 `source-read --source ID --start A --end B` 读取相邻证据。不得用不存在的上下文补因果。

纯空白块自动记为 `non_content`，保留原范围与哈希，不算语义分析；旧断点在 next 时同样恢复，已有分析不覆盖。

## 逐块积累

`template analysis` 给出结构。每块记：关键事件和选择、可证实的因果、情绪变化、有效/无效写法；每条 finding 包含 claim、kind 与精确 quote。短小完整句足够，不把原文复制成报告。用 `record --source ID --chunk K --input "<结果.json>"` 原子保存，哈希或引用不符会拒绝。相同结果重交幂等，已完成块不重跑。尚未定稿时，先从 `findings.results` 读取当前记录，保留该条的 `analysis_sha256` 再修改内容，以 `record ... --replace` 提交；它是旧分析的基线，与原文 `chunk_sha256` 不同。遇到 `stale_analysis` 须回读并核对他人或后续会话的修改，不能只换指纹重交。旧版本保留事件记录；已有 `report_path` 时按末节另存修订稿。

记录核心发现时，说明引文如何支持判断；同一句话中的事实与推断要能分辨。`record` 校验字段、原文哈希、替换基线和引文是否存在，不验证因果、人物动机或文学质量；保存成功不等于解释成立。继续使用现有 `summary` 和 `findings` 字段，详细论证放在阶段小结或报告中。

开篇点评只处理相关块并输出范围明确的预览；用户要求全量时循环 next/record 到覆盖完成，不再停在预览处确认。token 预算只控制一次读取，不缩减用户要求的总覆盖。

## 聚合与交付

`coverage` 检查块数、漏块和原文覆盖标签。`findings --source ID --offset 0 --limit 100 --budget-bytes 20000` 按字节预算分页读已保存的紧凑结果，沿返回的 `next_offset` 继续，不按 limit 推算偏移。每块返回 `start/end` 原文范围；续跑时直接沿用这些 Unicode 字符偏移调用 `source-read`。保留响应顶层的 `analysis_sha256` 作为本次聚合基线，它覆盖来源及全部块，与每条记录的指纹不同。各页指纹须一致；跨轮小结也保存这一基线和所用块指纹。基线变化时重新读取紧凑记录，定位变化并复核受影响论证，不在提交前直接刷新指纹。大量结果先按剧情单元生成带 chunk id 的小结，再合并；小结只用于定位，人物变化、伏笔回收或全书主题等核心判断须定点回读原文、核对前后条件与反例，不靠多层摘要代替证据，也不重复导入或重做全部记录。

报告按实际作品组织：开篇吸引力、人物欲望与关系、冲突/升级/反转因果、情绪与节奏、文风、失效场景、可迁移方法及不能照搬的具体表达。每个重要结论用短引文支持，并标明原文位置；已有语料工程沿用来源与块号，直接文本用实际章节、段落或可检索的短引文定位。事实、解释和建议分开。篇幅服从证据量，不为凑模板创建空文件。

交付前逐项核对核心结论是否有可定位的原文、证据是否支持判断、范围是否被夸大；存在歧义时保留竞争解释与证据不足。引用已保存的发现时保留来源与块号，跨块论证列出各处证据。工具完成检查与语义复核分别报告；没有独立评阅就不声称经过独立盲评。

`report --source ID --file "<报告.md>" --expect-analysis "<聚合时的顶层 analysis_sha256>"` 在所有导入块均完成且聚合基线未变化时接受最终报告。`stale_analysis` 表示需要复核变化并更新报告；拒绝不会定稿或冻结记录。已成功提交的同内容重试可沿用原基线，但须使用原输入文件，不能将带来源头的导出稿再次传入。核对 `exports_complete` 和 `.story/analysis/ID/report.md` 实际文件后才交付；导出失败按前述恢复分支处理。工具会注明 complete/partial/unknown；“所导入块全部完成”不等于“全书无遗漏”。阶段性预览直接另存 preview.md，不冒充最终报告。

## 修订分析稿与续跑

未定稿的逐块记录按上文替换后继续聚合。已定稿报告保持原记录与报告，另存修订稿；程序会以 `report_already_final`／`report_exists` 拒绝改写，不能通过删报告、改数据库或重建书库绕过。只有外部分析文档时直接修订，不为此初始化书库或重新导入。

修订稿沿用用户指定位置，否则另存到分析目录内、`.story` 外的独立路径。回读支持修改的原文，联动修改受影响的结论和建议；继承原有覆盖范围，不把修订扩大为全书分析。使用已有 source 与块号；外部文档则用实际页码、段落或短引文定位，不虚构工具编号。缺少原文时说明哪些判断无法核验。

需跨轮处理时，在修订稿旁保存简短进度，记录原文、旧稿与当前修订稿的路径和哈希，已处理／待核对的问题及下一步。恢复先读进度和当前稿，核对文件变化，再接未完成问题；`status.recent_sources` 中的 `report_path` 仍指向旧定稿，不能代表独立修订稿已完成。交付时给出新稿实际路径、修改说明与核验范围；只完成独立文件修订，就不称已更新书库定稿。
