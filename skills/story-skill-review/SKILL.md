# 审稿与修订

先按需读取 `../story-skill/SKILL.md` 的“共同约束”；同版内容已在当前上下文中则复用。此入口已完成任务选择，不执行公共入口的路由。共享工具位于 `../story-skill/scripts/story.py`，记其绝对路径为 `<tool>`；下文所有书籍命令都显式附加 `--book "<书目录绝对路径>"`。公共技能或所需工具缺失时，说明缺失路径并提示安装完整 Story Skill 套件；不假称已执行。

读取目标正文、用户修改要求和相关约束；需要核对矛盾、连载节奏、关系变化或期待兑现时，用现有摘要或目录定位，再补读必要原文，摘要不能替代读感判断。默认当前会话一次审查；不为了更高评分循环重写整章。本轮已定位问题解决、有效内容保留且没有新问题或新要求时，交付后停止；用户说“继续”时承接尚未完成的已授权工作，不自动生成仅换措辞的新版本，也不自动扩到下一章。若本轮已完成且没有明确后续，简述完成状态并询问要继续的范围。采用独立审查时遵循公共约束，并明确真实执行方式。

先判定本次是润色、仅排版、审校还是修改对照。润色只在授权文本内改表达，不凭润色补情节或事实；仅排版只调整普通段落换行、段间空行和手工缩进；交付前对照原稿，除允许调整的普通空白外，完整字符序列须一致，并逐项保护有意义的日期、署名、编号、原有错字和特殊空白，不能只比较字数。审校若只要求检查则报告问题，不擅自交改写稿；修改对照仅在用户要求时给原文与改稿的对应差异，和干净成稿分开。若原文的破折号、引号或句号违反项目格式而当前只有排版权限，保留原文并在正文外标明冲突，不暗改。局部修改不重复前文，也不新建章节。

按已知书目录、路径和提交记录识别稿件身份，不能仅因只有一份文件就当作未托管。未托管的独立片段或普通文件按本次要求直接审稿、修改并保留可审查的改动，不初始化书库或补建章计划；涉及已有作品仍定点核对必要约定与原文。下文涉及 plan、context、changes 和提交的步骤仅适用于托管章节。

本次明确要求整书审稿，或在修订后确认完本时，长篇与短篇都按 [全书完本审查](../story-skill-write/references/chapter.md#全书完本审查) 核对本次待交付稿的主线、主要阅读承诺与结局；纯审稿只报告结论，正式修改与产物写入仍按本次授权处理。

本次涉及情节、人物、连续性、约束或整体读感的内容审稿、改稿，才进入下列四项。仅排版不做这些判断；范围明确的错字、病句、标点和对白格式审校按下文格式规则处理，不含评价的修改对照只核对指定差异。

内容审稿逐项判断：
- 因果：人物具体争取什么，阻力能否改变其行动，尝试与回应是否展开，选择有哪些可见代价，信息揭露的线索与局势逆转的因果是否成立。
- 连续性：知识边界、时间、位置、伤势、能力、关系与承诺是否冲突。
- 约束：用户必发生/禁止发生、停笔点、篇幅与原创边界。
- 读感：读者在期待什么，哪段实际情节兑现了看点，哪里只用评价宣布结果；人物声线、对白潜台词、有效留白与中文语句是否自然，重复解释是否拖慢场景。

用户指出段落长、页面密集或要求平台分段对比时，按 [段落密度与移动阅读](../story-skill-write/references/drama.md#段落密度与移动阅读) 区分正文结构与显示折行，结合相邻段和整章检查；仅排版不升级为内容改写。

涉及错字、病句、标点或对白格式时，读取 [成稿格式](../story-skill-write/references/drama.md#成稿格式)、[对白分段与说话人](../story-skill-write/references/drama.md#对白分段与说话人) 和 [中文语法与标点校对](../story-skill-write/references/drama.md#中文语法与标点校对)，核对分段、外双内单引号、直接对白的句号位置及正文破折号用途。按语境区分明确错误与人物口语；只审不改交问题，已授权校对交修正稿，不擅自改剧情。

需要判断情节因果、冲突、看点、悬念、反转，专业过程是否压过人物行动，或经营数字是否必要、前后一致时，按需读 [冲突与看点](../story-skill-write/references/drama.md)。用户指出“平、冲突弱、看点不足”时，指出牵挂减弱的具体位置，区分有效安静与无事发生、可理解的阻力与强行刁难。优先修复无阻力兑现、重复拖延、回报一笔带过，不以每章争吵、反转或强悬念作为通用标准。纯审稿只交问题与建议，最小校对不升级为情节改写。

核对阶段回报时，区分尚未发生、已经发生但体验被跳过，以及已有余波仍在影响生活或关系；结合必要前后文，只说明与本次疑点有关的依据和取舍。修订后回查原先定位的问题及应保留的有效内容，未改项说明取舍，不把脚本通过写成吸引力已改善。

修订仍以本轮已确认身份的待修订稿和明确保留项为文字基线；它可以是用户提供稿、当前草稿、已保存的历史候选或现行正式章，不因尚未正式发布而丢弃本轮已采用的修改。推断既有人设或作品事实时，以现行正式正文、仍有效的已采用计划及用户本次明确确认为准。未经采用的候选内容或本轮草稿偏差不倒推成一贯人设。若本次授权要求保留人物原有选择，只承接正文已呈现或现有因果可合理推出的影响；结果达成不自动消除这些影响，后续也不套固定的悔悟或惩罚模式，不为满足规则另造情节。

问题记录为位置/原句、影响、证据和最小修改建议。内部严重度用 blocker（违反明确要求或关键矛盾）/advice（可选择的改善）；向作者交付时写“必须修复／可选择优化”，只有排障或用户要求结构化明细时才展示原字段。没有证据就标疑点，不做伪精确质量分或“AI 率”。

按问题影响范围作最小充分修改，同时核对过渡、后续伏笔和字数；涉及目标或布局的改动按本次授权先处理相关规划，不用局部润色冒充已解决结构问题。去 AI 味保留原意、语气和情节，不把情绪一律换成动作，不把长句一律切碎。压缩后回看关键选择是否仍有可感受的期待、取舍和后果，避免只剩情节摘要；增温不靠堆身体反应，行动优先不靠增加无作用的走动与小动作。人工判断有用的反复、对称和修辞可保留。

按当前有效授权区分改稿与发布：仅审稿或仅改草稿时，不更新已采用计划与正文状态，不执行提交、替换、写入式对账或历史发布；需要联动的规划改动随草稿记录为候选。已授权更新正式正文则按下述流程处理，不重复确认。

每轮合并新增要求与必须保留项，保留上一轮问题的解决状态；重点复核旧问题是否复发、人物知识与伏笔是否仍成立。已授权采用的剧情调整先同步当前章 plan 和创作约定；普通最新章修订再取新版 context，历史修订则在计划就绪后建立分支并读取 history-inspect / history-dependencies。不能用旧停笔点阻挡已授权修改。保存每轮稿件，changes 描述相对章前基线的完整最终增量；不能只写相对上一轮的差异，否则被撤回的旧事实会丢失。

托管工程中下一新章尚未提交的草稿，按本次要求修改和审查。已授权首次提交时读取 [章流程](../story-skill-write/references/chapter.md)，核对当前计划和状态后使用普通 `commit`，不加 `--replace-last`，也不进入历史分支。以下替换、对账与历史流程仅适用于已提交章节。

已提交章节的修订稿先改 `.story/drafts/` 副本，使用 `prepare --chapter N --draft "<草稿>"` 的 delta 骨架填写四项带引文的审查、摘要和完整状态 changes。仅最新原生章、不含结构化世界变化及绑定该章的世界证据、未合并历史分支，且该章产生的卡片在提交后未另有更新时，用 `commit --replace-last`；原版正文和增量留在 events，卡片描述修订后的状态。通过 world-save 后补的正文基线也须一起复核。其他情况先按下文进入历史分支。

若用户已在 `chapters/第X卷 卷名/第N章 章节名称.md`（或已有工程的旧导出路径）改稿，最新原生章先 `reconcile --chapter N` 取得修订上下文和 `external_edit`，读取该路径并另存草稿。用 `prepare --reconcile --chapter N --draft "<草稿>"` 生成带 `external_sha256` 的骨架，核对外部版本仍与已读一致后审查；执行 `reconcile --chapter N --draft "<草稿>" --input "<delta.json>"`。外部稿再变则重新读取和审查；不要只更新哈希跳过复核。其余文件缺失或待导出且有外改阻断时先 `export --safe-only`，按回执处理剩余路径；它只恢复安全路径，不代表外改已审查。导出保留被替换版本于 `.story/export-backups/`，失败查看回执，不手改数据库。

重命名期间新旧路径都被外部保存时，先把全部外部版本分别保留到 `.story/drafts/`，再合并审查。若当前托管路径也阻断对账，先从 `chapter-read` 取回完整已提交正文并核对后恢复该路径；外部副本继续保留，旧路径外改仍待处理。然后 `export --safe-only`，重新获取对账或历史分支回执中的路径与哈希，不把任一外改静默覆盖。

更早章节、导入基线、含结构化世界变化或绑定世界证据、已合并过历史分支，或该章产生的卡片在提交后另有更新时，使用 [历史分支流程](references/history.md)：先核对所需章计划再建立候选，核对依赖范围、后文、状态和原文证据，再正式发布。`context`、`prepare`、`commit` 或 `reconcile` 返回 `revised_state_conflict` 或 `history_revision_required` 时，也转入历史分支，不反复重试对账，不把卡片改回旧值绕过保护。候选未发布时旧版仍可用；缺少依赖声明不能证明后文无关。

本次明确要求采用修订并交付完整短篇时，先完成已授权的正式修订与导出，再按 [短篇完本与修订交付](../story-skill-write/references/chapter.md#短篇完本与修订交付) 核对实际终章、结局和总纲平台分类，合并或恢复全文并核验实际封面；此前未生成全文或封面，也须完成首次交付。已有合格产物按该流程复用，交付三类文件的实际路径及待核对项。

普通正式短篇修订且书内已有全文时，`commit --replace-last`、写入式 `reconcile` 或 `history-publish` 后核对 `status.short_assembly`、导出回执和实际全文，必要时按上述流程恢复导出；全文同步不表示情节已完结。封面仅在书名、署名、题材或投稿规格变化时复核或修订。普通单章修订不自动扩成首次完本交付；纯审稿、草稿修改不触发正式产物写入。

交付只含本次要求的成稿或审校、对照结果；小说成稿本身只放必要章名和正文，修改说明、建议、校验结果及权限或格式冲突另置正文之外，用户只要成稿时不默认附带。检查实际授权范围、格式与语义；有硬性字数时实测，正式导出后回读实际文件。未检查的项目不称通过，未完成的不称全文完成；“已过脚本”不等于“已过独立审稿”。

仅在旧版状态库需要升级时读取 [历史分支与迁移](references/history.md) 的迁移说明；普通审稿不运行 migrate。
