# 审稿与修订

执行本任务前必须读取 `../story-skill/SKILL.md` 的“共同约束”并遵守本次适用规则；同版内容已在当前上下文中则复用。此入口已完成任务选择，不执行公共入口的路由。共享工具位于 `../story-skill/scripts/story.py`，记其绝对路径为 `<tool>`；下文所有书籍命令都显式附加 `--book "<书目录绝对路径>"`。公共技能或所需工具缺失时，说明缺失路径并提示安装完整 Story Skill 套件；不假称已执行。

读取目标正文、用户修改要求和相关约束；需要核对矛盾、连载节奏、关系变化或期待兑现时，用现有摘要或目录定位，再补读必要原文，摘要不能替代读感判断。默认当前会话一次审查；不为了更高评分循环重写整章。本轮已定位问题解决、有效内容保留且没有新问题或新要求时，交付后停止；用户说“继续”时承接尚未完成的已授权工作，不自动生成仅换措辞的新版本，也不自动扩到下一章。若本轮已完成且没有明确后续，简述完成状态并询问要继续的范围。采用独立审查时遵循公共约束，并明确真实执行方式。

先判定本次是内容审稿、内容改稿、润色、仅排版、文字审校还是修改对照；只有审查授权时交问题，不擅自改稿。内容改稿可在授权范围内调整情节与表达，润色只改表达，不凭润色补情节或事实；仅排版只调整普通段落换行、段间空行和手工缩进；交付前对照原稿，除允许调整的普通空白外，完整字符序列须一致，并逐项保护有意义的日期、署名、编号、原有错字和特殊空白，不能只比较字数。文字审校若只要求检查则报告问题，不擅自交改写稿；修改对照仅在用户要求时给原文与改稿的对应差异，和干净成稿分开。若原文的破折号、引号或句号违反项目格式而当前只有排版权限，保留原文并在正文外标明冲突，不暗改。局部修改不重复前文，也不新建章节。

按已知书目录、路径和提交记录识别稿件身份，不能仅因只有一份文件就当作未托管。未托管的独立片段或普通文件按本次要求直接审稿、修改并保留可审查的改动，不初始化书库或补建章计划；涉及已有作品仍定点核对必要约定与原文。下文涉及 plan、context、changes 和提交的步骤仅适用于托管章节。

本次明确要求整书审稿，或在修订后确认完本时，长篇与短篇都按 [全书完本审查](../story-skill-write/references/chapter.md#全书完本审查) 核对本次待交付稿的主线、主要阅读承诺与结局；纯审稿只报告结论，正式修改与产物写入仍按本次授权处理。

本次涉及情节、人物、连续性、约束或整体读感的内容审稿、改稿，才进入下列四项。仅排版不做这些判断；范围明确的错字、病句、标点和对白格式审校按下文格式规则处理，不含评价的修改对照只核对指定差异。

审查开篇或用户指出代入慢、切入点弱时，按 [开篇切入与代入](../story-skill-write/references/drama.md#开篇切入与代入) 回读实际开头与后续场景：读者何时知道在跟随谁、人物想守住什么、现场阻力如何迫使其行动，开头事件是否通向本书承诺。指出读者失去牵挂的具体位置；必要信息不足与有意留悬念分开判断，不凭“前 300 字有事故”就认定有吸引力。

目标为番茄、七猫商业网文，或本次要求商业润色、网文化时，同时按 [商业连载规则](../story-skill-write/references/drama.md#番茄与七猫商业连载) 检查开中尾节奏、读者回报、对白与套语；仅排版不扩大为内容审查，改稿不越过已授权范围。

用户要求核对番茄内容审核风险，或提供番茄后台的具体退回理由时，按 [番茄内容审核退回原因](references/fanqie-content-review.md) 对照实际稿件和书籍资料定位问题。商业读感、内容审核与签约评估分别判断；平台历史公告只提供常见原因，不作为现行规则全集，也不保证修改后通过。只报告本次实际读到的证据和未核范围；纯审查不擅自改稿或改封面。

用户要求七猫投稿前内容风险检查，或提供七猫后台退回意见时，按 [七猫内容审核风险](references/qimao-content-review.md) 对照实际稿件、后台原话和当时适用的官方规则；资料不足的项目标明未核。文学读感、内容审核与签约评估分开判断，不把七猫专项要求强加给其他题材或平台。纯审查不擅自改稿，也不承诺平台结果。

本次若专门要求文笔优化，按 [文笔精修](../story-skill-write/references/drama.md#文笔精修) 先辨是事件缺戏、关键过程被概括，还是句子本身板滞；只在已授权的层面修改，不用辞藻替代情节，也不把有效的直写、留白和人物原有声线一并抹平。

涉及整体读感的内容审稿或改稿，在现有读感项内按 [人物在场与去 AI 味复核](../story-skill-write/references/drama.md#人物在场与去-ai-味复核) 连读本次可读范围及相邻场景。以原句说明声线、动作和旁白的具体作用；发现同质对白、无作用动作或重复解释时给出位置、读感影响及处理或保留理由。专门要求“有人味”或严格去 AI 味时须完整复核授权范围；未发现明显问题也说明实际读到的范围，不只凭套语词频或检测分数声称通过。纯审查不擅自改稿。

内容审稿逐项判断：
- 因果：人物具体争取什么，阻力能否改变其行动，尝试与回应是否展开；分清人物担心的将来代价、已改变的眼前选择和实际发生的后果，不把假设写成已兑现；信息揭露的线索与局势逆转的因果是否成立。
- 连续性：核对知识边界、时间、位置、伤势、能力、物件持有、关系与承诺；关键行动的路线、可见范围和人物知情须与正文相容，不能把人物猜测写成已证事实。故事转折依赖目击、监控、证据载体、设备时间或房间路线时，定点按 [证据与空间连续性](../story-skill-write/references/suspense-evidence.md) 核对。跨卷核对前卷结束条件是否由正文达成或有明确变更依据，目录切换本身不证明完成。
- 约束：用户必发生/禁止发生、停笔点、篇幅与原创边界。
- 读感：读者在期待什么，哪段实际情节兑现了看点，哪里只用评价宣布结果；人物声线、对白潜台词、有效留白与中文语句是否自然，重复解释或同一动作重做是否拖慢场景。已理解的证据边界若只换材料重说而未改变选择，指出可压缩段落，不把必要谨慎一律删除。

审查主线或连续章节时，按 [主线跨章推进](../story-skill-write/references/drama.md#主线怎样跨章前进) 回看前章结果是否成为后章条件、局部胜负是否影响阶段目标；若删掉或调换数章也不改变人物下一步，指出具体断开的因果与可保留的关系或余波，不以新增事故代替修复。

审查高潮时，按 [高潮与阶段兑现](../story-skill-write/references/drama.md#高潮与阶段兑现) 核对读者等待的关键场面是否真的发生、破局依据是否早已建立、人物选择是否承担代价，以及本阶段得到的回答有没有被立即撤销；区分有意留给后章的余波与跳过决定性过程。

审查章末钩子时，按 [钩子的承诺与兑现](../story-skill-write/references/drama.md#钩子的承诺与兑现) 说清读者会等待什么，再对照可读的下一章看它如何回应；只拿到当前章时将兑现情况标为未核，不推断下一章必然有效。钩子有吸引力不等于可以掩盖本章未完成的回报，开篇另起事故也不算兑现旧钩子。

托管章节另对照现行章计划的目标、场景变化和停笔点与最终正文；若创作约定、现行总纲、策划或正文对反复出现的机制有明确阅读承诺，逐个核对本次实例的实际作用，区分有意变奏与意外落空，不把该机制强加给其他作品。创作约定写明的核心代价须与正文及进度记录对照：风险预告、当下取舍、实际损失分别标注；尚未落地的后果可以是后续悬念，不能宣称本章已兑现。卖点声称某事已经“变化”时，还须核对可观察的前态和后态，不能把首次发现误记为变化。章名若以确定语气指认身份或结果，核对正文是否支持，或能否读出这是人物的误判与有意的悬念设计；不把标题暗示直接记成故事事实。审查记录、章摘要及状态卡不能把线索相似、人物推断或来源未核实的材料说成已证事实；状态卡的来源引文只是定位锚点，逐项核对卡片中其他事实也有同版正文依据，不能让一条只证明信文的引文代替投递、持有或身份的证据。若可读总纲、卷纲明确写了提交进度，也对照实际 `status` 与正式导出，纯审稿只报告过期记录。已保存计划只沿用旧默认字数时，先核对本书现行篇幅约定；`lint` 通过只能证明稿件符合该旧计划，不能证明符合新约定。只审稿时报告差异，已授权修订正式章时按对应流程同步计划、正文和凭据，不静默追改别的章节。

用户指出段落长、页面密集或要求平台分段对比时，按 [段落密度与移动阅读](../story-skill-write/references/drama.md#段落密度与移动阅读) 区分正文结构与显示折行，结合相邻段和整章检查；仅排版不升级为内容改写。

涉及错字、病句、标点或对白格式时，读取 [成稿格式](../story-skill-write/references/drama.md#成稿格式)、[对白分段与说话人](../story-skill-write/references/drama.md#对白分段与说话人) 和 [中文语法与标点校对](../story-skill-write/references/drama.md#中文语法与标点校对)，核对分段、外双内单引号、直接对白的句号位置及正文破折号用途。对白即使满足句号数量，也要连着动作和说话人读出自然停顿，留意是否靠分号、逗号或无作用的动作与引号切分规避限制；语法上可用的分号不能单凭出现就判错。按语境区分明确错误与人物口语；只审不改交问题，已授权校对交修正稿，不擅自改剧情。

需要判断情节因果、冲突、看点、悬念、反转，专业过程是否压过人物行动，或经营数字是否必要、前后一致时，按需读 [冲突与看点](../story-skill-write/references/drama.md)。用户指出“平、冲突弱、看点不足”时，指出牵挂减弱的具体位置，区分有效安静与无事发生、可理解的阻力与强行刁难；连读相邻章节，比较压力来源、主角解法与可见回报是否只是换人换物地重复。留意上章悬念被次章轻易撤销、人物只换一种材料继续核对、担忧没有影响取舍、末段重复已展示线索的情况；分别说明读者失去什么，而不把这些现象一律判错。计划与正文相符只说明计划得到执行；若拖延来自细纲连续安排核对步骤，建议先改相关细纲，不要求靠润色硬添事件。优先修复无阻力兑现、重复拖延、回报一笔带过，不以每章争吵、反转或强悬念作为通用标准。纯审稿只交问题与建议，最小校对不升级为情节改写。

核对阶段回报时，区分尚未发生、已经发生但体验被跳过，以及已有余波仍在影响生活或关系；结合必要前后文，只说明与本次疑点有关的依据和取舍。修订后回查原先定位的问题及应保留的有效内容，未改项说明取舍，不把脚本通过写成吸引力已改善。若本轮同时修技能规则与测试稿，分别验证规则已进入实际调用的技能、原问题在稿中是否消失；规则更新而正文未改时，仍把正文问题列为开放，不能合并声称“已修复”。

修订仍以本轮已确认身份的待修订稿和明确保留项为文字基线；它可以是用户提供稿、当前草稿、已保存的历史候选或现行正式章，不因尚未正式发布而丢弃本轮已采用的修改。推断既有人设或作品事实时，以现行正式正文、仍有效的已采用计划及用户本次明确确认为准。未经采用的候选内容或本轮草稿偏差不倒推成一贯人设。若本次授权要求保留人物原有选择，只承接正文已呈现或现有因果可合理推出的影响；结果达成不自动消除这些影响，后续也不套固定的悔悟或惩罚模式，不为满足规则另造情节。

问题记录为位置/原句、影响、证据和最小修改建议。审查引用一句支持局部判断时，仍要回看相邻动作与整场的反例，不能凭一条合格引文给整章的空间、对白或人物代价背书；影响承诺或因果的未解决问题须留在审查结论中，不能被四项正面观察或空的 `issues` 遮掉。内部严重度用 blocker（违反明确要求或关键矛盾）/advice（可选择的改善）；向作者交付时写“必须修复／可选择优化”，只有排障或用户要求结构化明细时才展示原字段。没有证据就标疑点，不做伪精确质量分或“AI 率”。

按问题影响范围作最小充分修改，同时核对过渡、后续伏笔和字数；涉及目标或布局的改动按本次授权先处理相关规划，不用局部润色冒充已解决结构问题。去 AI 味保留原意、语气和情节，不把情绪一律换成动作，不把长句一律切碎。压缩后回看关键选择是否仍有可感受的期待、取舍和后果，避免只剩情节摘要；增温不靠堆身体反应，行动优先不靠增加无作用的走动与小动作。人工判断有用的反复、对称和修辞可保留。

按当前有效授权区分改稿与发布：仅审稿或仅改草稿时，不更新已采用计划与正文状态，不执行提交、替换、写入式对账或历史发布；需要联动的规划改动随草稿记录为候选。已授权更新正式正文则按下述流程处理，不重复确认。

每轮合并新增要求与必须保留项，保留上一轮问题的解决状态；重点复核旧问题是否复发、人物知识与伏笔是否仍成立。已授权采用的剧情调整先同步当前章 plan 和创作约定；普通最新章修订再取新版 context，历史修订则在计划就绪后建立分支并读取 history-inspect / history-dependencies。不能用旧停笔点阻挡已授权修改。保存每轮稿件，changes 描述相对章前基线的完整最终增量；不能只写相对上一轮的差异，否则被撤回的旧事实会丢失。

托管工程中下一新章尚未提交的草稿，按本次要求修改和审查。已授权首次提交时读取 [章流程](../story-skill-write/references/chapter.md)，核对当前计划和状态后使用普通 `commit`，不加 `--replace-last`，也不进入历史分支。以下替换、对账与历史流程仅适用于已提交章节。

已提交章节的修订稿先改 `.story/drafts/` 副本，使用 `prepare --chapter N --draft "<草稿>"` 的 delta 骨架填写四项带引文的审查、摘要和完整状态 changes。仅最新原生章、不含结构化世界变化及绑定该章的世界证据、未合并历史分支，且该章产生的卡片在提交后未另有更新时，用 `commit --replace-last`；原版正文和增量留在 events，卡片描述修订后的状态。通过 world-save 后补的正文基线也须一起复核。其他情况先按下文进入历史分支。

若用户已在 `chapters/第X卷 卷名/第N章 章节名称.md`（或已有工程的旧导出路径）改稿，最新原生章先 `reconcile --chapter N` 取得修订上下文和 `external_edit`，读取该路径并另存草稿。用 `prepare --reconcile --chapter N --draft "<草稿>"` 生成带 `external_sha256` 的骨架，核对外部版本仍与已读一致后审查；执行 `reconcile --chapter N --draft "<草稿>" --input "<delta.json>"`。外部稿再变则重新读取和审查；不要只更新哈希跳过复核。其余文件缺失或待导出且有外改阻断时先 `export --safe-only`，按回执处理剩余路径；它只恢复安全路径，不代表外改已审查。导出保留被替换版本于 `.story/export-backups/`，失败查看回执，不手改数据库。

重命名期间新旧路径都被外部保存时，先把全部外部版本分别保留到 `.story/drafts/`，再合并审查。若当前托管路径也阻断对账，先从 `chapter-read` 取回完整已提交正文并核对后恢复该路径；外部副本继续保留，旧路径外改仍待处理。然后 `export --safe-only`，重新获取对账或历史分支回执中的路径与哈希，不把任一外改静默覆盖。

更早章节、导入基线、含结构化世界变化或绑定世界证据、已合并过历史分支，或该章产生的卡片在提交后另有更新时，使用 [历史分支流程](references/history.md)：先核对所需章计划再建立候选，核对依赖范围、后文、状态和原文证据，再正式发布。`context`、`prepare`、`commit` 或 `reconcile` 返回 `revised_state_conflict` 或 `history_revision_required` 时，也转入历史分支，不反复重试对账，不把卡片改回旧值绕过保护。候选未发布时旧版仍可用；缺少依赖声明不能证明后文无关。

正式修订发布后，按回执中的实际路径回读正文，并复核本次改动涉及的书名看点、阅读承诺、卷末条件、卷纲与章细纲、章名文件名、状态卡来源及可读进度。历史分支若改变了状态卡或世界记录，还须按 [历史分支流程](references/history.md) 核对受影响章的已发布依赖声明是否仍指向旧哈希；严格文件校验不能替代这项复核。已经改变的事实须同步到已采用规划；尚未兑现的目标留为后续目标，不能继续写作已完成的状态。只更新本次受影响材料，保留原审查报告的历史身份，另记问题关闭或余留情况，不用改旧报告来制造此前已通过的假象。纯审稿或未发布候选仍只记录待联动项。

本次明确要求采用修订并交付完整短篇时，先完成已授权的正式修订与导出，再按 [短篇完本与修订交付](../story-skill-write/references/chapter.md#短篇完本与修订交付) 核对实际终章、结局和总纲平台分类，合并或恢复全文并核验实际封面；此前未生成全文或封面，也须完成首次交付。已有合格产物按该流程复用，交付三类文件的实际路径及待核对项。

普通正式短篇修订且书内已有全文时，`commit --replace-last`、写入式 `reconcile` 或 `history-publish` 后核对 `status.short_assembly`、导出回执和实际全文，必要时按上述流程恢复导出；全文同步不表示情节已完结。封面仅在书名、署名、题材或投稿规格变化时复核或修订。普通单章修订不自动扩成首次完本交付；纯审稿、草稿修改不触发正式产物写入。

交付只含本次要求的成稿或审校、对照结果；小说成稿本身只放必要章名和正文，修改说明、建议、校验结果及权限或格式冲突另置正文之外，用户只要成稿时不默认附带。检查实际授权范围、格式与语义；有硬性字数时实测，正式导出后回读实际文件。未检查的项目不称通过，未完成的不称全文完成；“已过脚本”不等于“已过独立审稿”。

仅在旧版状态库需要升级时读取 [历史分支与迁移](references/history.md) 的迁移说明；普通审稿不运行 migrate。
