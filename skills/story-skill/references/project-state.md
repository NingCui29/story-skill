# 项目状态与近期细纲

规划和正文写作共用本说明。命令调用 `story-skill/scripts/story.py`；所有书籍命令显式传入 `--book "<书目录绝对路径>"`，`R` 取最近一次 status 的 revision。

## 书名目录与开书落点

“一书一目录”的外层是书名目录，先确定它，再保存本书材料：

- 用户明确指定最终书目录时直接使用；已有作品按 `创作约定.md`、状态和现有文件确认书根，继续规划不重复嵌套一层同名目录。
- 新书只指定写作父目录或使用当前写作工作区时，在其中建立 `<书名>/`。采用已给出的书名；未定名时按本次设定拟一个有辨识度的暂定书名并记录其暂定状态。目录使用适合本机文件名的书名，必要时替换不合法字符并记录完整书名与实际路径。目标已存在先核对归属，不把同名的另一部作品当作本书继续；另开新书也不写进已有书根。
- `init --book "<父目录>/<书名>" --title "<完整书名>" --kind long|short` 中，`--book` 是最终作品根，不是父目录；`--title` 仅保存书名。调用后核对返回的 `created/title`、实际书目录及 `.story/state.sqlite3`；短篇还核对 `short_assembly_path`，再创建 `创作约定.md`，写明完整书名、实际书根和本轮阶段。
- `创作约定.md`、策划、设定、`01_大纲细纲/`、正文 `chapters/` 与状态 `.story/` 都在同一书根内。只创建本轮需要的文件；规划阶段不生成正文。交付给出可打开的实际书目录，不能只说“已开书”或只报告隐藏的状态库。

书名暂定后变更不等于已经迁移目录。旧书若曾直接落在父目录，先核对实际书根和本书文件范围；不能靠再建空书名文件夹或重跑 `init` 把迁移报为完成，不自行搬动其他作品或托管正文。

短篇全文的预期相对路径由 `init`／`status` 的 `short_assembly_path` 给出。可用书名保持 `<书名>.md`；不适合作为文件名的字符会替换，必要时截短并保留可区分后缀，完整书名仍保存在书籍元数据中。新合并稿从第 1 章章名开始，仅含各章章名与正文，不在内容首行再写书名；旧的含书名首行合并稿在只读状态中显示为 stale，下次执行 `export` 或明确合并时刷新并保留旧文件备份。既有 `.txt` 全文在下一次 `assemble-short` 或 `export` 时迁移为 `.md`，旧文件保留在 `.story/export-backups/`；首次合并登记实际路径，后续刷新与恢复沿用登记值；交付按回执中的实际路径，不自行拼接文件名。同路径已有不明文件时先核对归属并保留，不为完成合并自动覆盖。

## 整体任务与续跑断点

多批、跨流程或跨会话任务复用现有任务单或断点入口，简短保留实际书名与书根、整体目标和有效授权、已完成、尚欠产物及下一动作。阶段完成后更新剩余事项；用户更正作品或范围时更新当前依据，不再以验收样例或旧对象回答。单次局部任务不新增表单，也不让作者填写机器字段。

恢复时把任务记录与现行约定、正式正文及 `status` 交叉核对。工具的 `next_chapter` 不等于任务下一步：终章已提交但全文尚未合并、导出待恢复、已授权审稿或配套仍未完成时，继续这些事项。已明确的正文、修改和采用授权贯穿必要流程切换；完成规划或一批问题不自动结束整体任务。报告完成须对应当前对象的实际产物。

## 作品类型修正

开书或用户要求调整长短篇定位时，结合本次明确要求、规划规模和交付形态核对 `kind`；已完结作品也看实际体量，卷数或章数不能单独决定长短篇。旧书库标注与有效定位不符时，核实差异及授权，使用 `book-kind --book "<书根>" --kind short|long --expect R` 修正元数据，保留原书身份、章节与历史，不重建书库或直接改数据库。类型变更不自动改写正文、重排章位或完成全文合并。

更正为短篇后，按现有流程处理缺章、外改与导出，再完成合并及实际完本审查。已登记受保护短篇全文时，反向改为长篇会被工具拒绝，以保护原登记；报告具体受限项，不删除全文登记来绕过。没有类型变更授权时，指出差异并继续能独立完成的当前工作。

## 旧短篇补齐原章

通过 `adopt` 接入的短篇只保存导入末章的快照。需要完本全文时，先核对原作真实章序、原文和卷名，在新书根用 `adopt-backfill --book "<新书目录>" --chapter N --draft "<原章文件>" --summary "<原章摘要>" --volume-dir "第一卷 雨夜" --expect R` 逐章补齐第 1 章至 `imported_through - 1` 的缺口；R 取最新 `status`，卷名替换为原章实际卷名。原目录只读，缺原文就说明缺口，不能用摘要或新写内容冒充旧章。

此命令仅用于已有 `adopt` 基线的短篇；补存有原文依据的旧章，不覆盖已存章、不回退当前写作进度，也不伪造旧章审查或重放旧章事实状态。相同输入可重复恢复，回执导出失败时先完成恢复；补齐后再核对全部章序、原文与导出，执行短篇完本合并。补章快照不是补做全文审稿，完本仍按 [短篇交付流程](../../story-skill-write/references/chapter.md#短篇完本与修订交付) 验收。

## 参考分析与策划资料

从拆书新开一本书、且只给写作父目录时，参考分析默认保存在 `<父目录>/作品分析/<参考书名>/`，原创新书仍在 `<父目录>/<书名>/`。用户指定其他分析根，或已有 `拆文/` 等目录时沿用，不为改名搬动资料；单次直接点评也不因这个默认路径而初始化分析工程。参考原文、分析进度和报告不进入新书的事实卡。

新书需要独立策划文件时，默认按类型放在书根的 `00_项目策划/`：`开书策划.md` 保存定位、[主要人物定义](../../story-skill-write/references/drama.md#主要人物定义与核对)与主线设计；从参考作品借鉴时另存 `参考方法与原创重建.md`；需要独立设定文件时可在此保存 `设定.md`。方法文档注明分析来源与实际覆盖范围、可迁移的机制及成立条件、新书中的具体改造和失效风险，并指向承接它的策划或大纲；参考作品的独特人物、事件链和解决方法不能直接登记为新书事实。已有书根下的同类文件与等效目录继续沿用，不为统一名称创建空目录或搬迁文件。

## 可读的大纲与细纲

各层最低内容、共同叙事逻辑、可选示例及人工质量验收统一见 [大纲细纲规范](../../story-skill-plan/references/outline.md)；本节负责保存层级、采用状态及工具同步。按本次范围读取，不因局部修改补建全书规划。

长篇默认按以下层级保存，沿用用户已有的等效目录，不为统一名字搬动工程：

```text
01_大纲细纲/
├── 全书总纲.md
├── 第一卷 雨夜/
│   ├── 本卷大纲.md
│   ├── 第1章 雨中来客.md
│   └── 第2章 一封旧信.md
└── 99_历史版本/                 # 修改前的版本，按日期或版本归档
```

卷名、章名取本书实际规划；细纲一章一文件，正文另存 `chapters/`。全书总纲说明主要矛盾、人物走向、结局与分卷粗纲，并链接已有卷纲；本卷大纲写明阶段承诺及完成条件、关键人物怎样调整策略或关系、决定性选择带来的回报与代价，并链接已有章细纲；有下一卷时，写清本卷结果怎样改变下卷的起点。不为这些内容另造固定表格。相邻章细纲要能读出前章留下的期待在后章如何回应，以及回应为后续行动造成什么新条件；只细化近期需要写的章节，不为目录生成空卷、空章；短篇规划可合为一份。

### 平台作者名与署名

同一本书可在不同平台使用不同作者名／笔名。按“本书＋平台”分别记录在下述平台定位块，列明本次指定或拟用署名、来源及日期、确认状态；总纲、分类答复、封面与投稿交接沿用这一对应关系。若同平台涉及多个账号或作品，按已有目标分别记录，不能只凭平台名选署名。作者名是作品署名，与账号标识、作品 ID、剧情人物姓名分别填写，不能互相推定，也不要求使用实名。

优先依据用户本次明确指定、书内有效约定及本平台资料；来源冲突时分别写清值与适用范围。用户明确各平台同名时可逐平台填写同一名称，否则不将一个平台的名字自动用于另一平台。未提供的写“待确认”，不自拟，不从封面、其他作品或账号昵称无依据地推成当前平台署名；署名未知不妨碍独立的规划与分类工作。

用户指定署名只证明本次采用意图，不证明后台已登记或改名。需要核对平台现状时，另记该平台后台当前署名、资料日期与实际核对状态；未查看则写未核对。同平台改名保留旧名及其时间或版本，新指定名称与后台现名不一致时列明差异，按授权更新本平台有关材料，保留旧版；不改动另一平台的名称或材料。

### 大纲中的作品类型与平台分类

每本小说的现行全书总纲（短篇可用等效规划）靠前保留本书的篇幅定位，并**默认分别列出番茄、七猫的完整分类**。直接回复分类或标签时同样给齐这两套；本次要求或书内约定包含其他平台的也逐个平台补上。主投选择不减少分类覆盖；只有本轮明确限定单一平台时才按该范围处理。维护旧大纲时补齐缺的平台，已有后台确认值原样保留，新增建议另标拟选或待核对；分类不写进工具章计划的 `tags`。

总纲、等效规划及分类答复在各平台分类前，统一列出“主角与角色定位”：明确主角，并按 [主要人物定义与核对](../../story-skill-write/references/drama.md#主要人物定义与核对) 逐人注明关键人物的姓名或稳定称呼、角色定位、身份关系及主线作用。双主角或群像中的核心人物分别列明；沿用已有姓名或称呼，依据不足的定位标待定／待核对，不为补栏改设定或新增人物。人物信息共用一份，平台“角色”标签仍逐平台填写，二者不能相互替代。

每个平台使用独立、带平台名称的定位块，不把两个平台合写在同一“目标平台”字段里；各自列出 [作者名与署名](#平台作者名与署名)，不合成全书唯一署名。以下为框架，各平台具体栏目按对应参考补齐；不能用“同上”“通用标签”替代另一平台的分类：

```markdown
## 主角与角色定位

- 主角：姓名或稳定称呼；角色定位：主角（多位时逐人列明）；身份及主线目标。
- 其他关键人物：逐人列出姓名或稳定称呼；角色定位；身份及与主角的关系；主线中的具体作用。

## 作品定位与平台分类（番茄）

- 篇幅类型：长篇／短篇；依据：本书预计篇幅与定位。
- 目标平台：番茄小说；作品阶段：按本平台实际情况填写。
- 作者名称／笔名：本平台本次指定或拟用值及状态；未提供写待确认；依据与日期：用户要求／书内约定／本平台资料及其日期。
- 平台入口：实际拟选择或已使用的入口；未确定则写待核对及原因。
- 平台分类：按番茄该入口的原栏目逐栏列具体值及拟选／后台已确认／待核对状态。
- 选择依据：逐栏对应本书人物、事件、关系或设定；未写成正文的注明规划中。
- 来源与核对日期：本平台官方页面、后台截图或实际设置；YYYY-MM-DD。
- 待核对：本平台仍未核实的项目；无则写无。

## 作品定位与平台分类（七猫）

- 篇幅类型：长篇／短篇；依据：与本书整体定位一致。
- 目标平台：七猫；作品阶段：按本平台实际情况填写。
- 作者名称／笔名：本平台本次指定或拟用值及状态；未提供写待确认；依据与日期：用户要求／书内约定／本平台资料及其日期。
- 平台入口：实际拟选择或已使用的入口；未确定则写待核对及原因。
- 分类频道：按本书在七猫的实际拟选或已用频道填写。
- 一级分类：按本频道填写具体值及核对状态。
- 二级分类：按所选一级分类填写具体值及核对状态。
- 风格／角色／情节／背景：逐栏填写七猫原词及核对状态。
- 选择依据：逐栏对应本书内容；未写成正文的注明规划中。
- 来源与核对日期：七猫官方页面、后台截图或实际设置；YYYY-MM-DD。
- 待核对：本平台仍未核实的项目；无则写无。
```

一部书只保留自己的篇幅类型；平台入口分别按实际创建选择，不从长篇／短篇直接推定，已有书库还要核对 `status.kind`。番茄按 [番茄标签选择表](../../story-skill-plan/references/fanqie-tags.md) 选用适用入口的完整栏目，七猫按 [七猫作品类型与标签](../../story-skill-plan/references/qimao-tags.md) 填写；不得跨平台、频道或入口借词。其他已涉及平台使用独立定位块，依据其当前官方页面或用户后台资料填写。

各平台的作品阶段和分类核对状态分别记录：尚未创建写拟投，未查看后台的现状写待核对，不能把一个平台的创建、签约或分类确认状态套到另一个平台。某个平台资料不足时仍保留该平台及其已知栏目，写出有依据的拟选和具体待核对项，不用缺资料省略整个平台；经该入口确认可选且决定留空的栏位才写“不选”。已有确认值与本次建议不同，保留原值并单列差异，不静默覆盖。

当前或候选总纲、短篇等效规划可用 `outline-audit --book "<书根>" --file "<书根内相对总纲路径.md>" --require-platform fanqie --require-platform qimao` 只读逐平台核对分类字段、分类来源日期格式及常见栏目，并检查番茄、七猫是否都存在；明确仅处理单平台时只保留相应 `--require-platform`。回执给出文件哈希、范围与缺项；`ok` 只表示这种结构检查未发现缺项，`manual_review_required` 始终为真。候选、草稿文件也可显式指定后只读检查，检查不改变采用状态；正式 `outline-bind` 仍拒绝候选等非采用文件。分类来源日期只取“来源与核对日期”字段，作者署名依据或其他备注中的日期不能补足该字段。主角与角色定位须对照已采用设定及正式正文人工核对；逐平台署名按上述来源核对，两者均不在此结构检查范围内。工具不核对每栏是否选了正确的词、数量限制、状态真伪、内容依据或是否已获采用；多平台或等效自由布局无法完整识别时仍逐平台人工检查，说明未覆盖处，不为通过检查改写真实规划。

番茄已填写的“平台入口”或“页面适用性”声明须明确，存在多条时须彼此一致；入口待定、互相冲突或无法解析时，不选择小说或短故事的栏目规则。入口已明确、仅标签待核对的备注不影响入口选择。该结构检查按每个平台一个分类块处理，不区分同平台的不同账号或作品。存在同平台多目标时，保留各目标的署名、分类及来源记录，逐目标人工核查并说明工具未覆盖；多个独立块产生的“重复平台／缺平台”提示不能解释为实际缺少该平台，也不能为了通过检查合并或删除真实目标。

同一范围维护一个清晰的当前入口，文档头注明状态、更新时间和必要的来源。保留“候选／已采用／待定”等真实状态，整理或版本号较新不代表已获采用。实质修改当前规划、替换已采用方案前，将旧版放入 `99_历史版本/`，保留原文件名与相对关系；只按 `status` 同步已提交章节的进度句，不必每章另存一份大纲历史副本。分批继续时补写相应卷、章文件，将重叠的前三章场面设计等内容并入各章，不再平铺多份范围交叠的候选稿；未决方案可留在对应章并说明分歧。

### 已采用规划的联动

实质修改已采用的开书策划、设定、全书总纲或卷纲时，先依据改变的目标、阅读承诺、结局、规则、人物关系或跨卷因果定位受影响的总纲、卷纲、章细纲与工具计划，并定点回读相关正式正文。在本次授权范围内同步这些规划，未能解决的冲突或超出范围的修改在当前入口注明受影响范围与待联动项；相关章完成核对前，不把旧细纲继续当作与新上级规划一致。若需要改变已提交正文，按 [审稿修订](../../story-skill-review/SKILL.md) 及本次授权处理，不用新规划覆盖已发生的事实。没有实质影响的部分沿用，不为一次局部调整重读或重建全书。

新建、普通修改或整理章细纲时，同章已有工具计划就核对目标、场景、停笔点、章名、卷名、篇幅及约束，在本次授权范围内同步已采用的规划；准备写作但尚无工具计划时据此建立。采用依据取当前要求或已有约定、任务记录，已明确采用无需重复确认；未决候选不写入或替换当前工具计划，冲突在当前入口注明。`context` 返回工具计划与绑定状态；已绑定时读取细纲文件核对摘要，不提供细纲内容，也不判断其语义是否与计划一致。续写前仍须定点核对当前章，两者不一致时先同步，再重新取得 context。

### 已采用细纲绑定

文档头可使用自定义一级标题；明确写出规划类型的标题也支持其他标题层级，例如 `## 章细纲`、`## 第1章 门后的雨 · 细纲`。标题支持井号形式及有效的 Setext 下划线形式；仅有章号、场景或“本章目标”的标题视为正文小节。文件开头及首个文档标题前后的状态声明一并核对；声明冲突时拒绝绑定。在文件 4 MiB 上限内扫描到首个正文小节，不截取固定行数或头部字节。HTML 注释、围栏与缩进代码中的状态示例不作声明；成对行内代码可跨普通文本行，但不跨空行、标题或围栏边界。文档标题之后再出现的章节细纲标题属于小节，其状态不覆盖文档声明。

开头 frontmatter 单独解析，仅其顶层裸值（如 `status: adopted`）可声明采用；说明文本中的嵌套状态及代码记号不参与 Markdown 状态判断。工具只支持普通裸值键值及非状态字段的缩进块文本，不是完整 YAML 解析器；未闭合或无法可靠解析的元数据拒绝绑定，不从后文借取采用声明。

已确认采用的章细纲与已保存工具章计划逐项核对后，可用 `outline-bind --book "<书根绝对路径>" --chapter N --file "<书根内相对细纲路径.md>" --sha256 "<刚审阅文件的 SHA-256>" --expect R` 登记两者的具体版本；`R` 取当前 status。短篇采用单份规划时可把同一已采用文件分别绑定到需要的章节。此操作要求调用者明确选定已采用文件，且新绑定须在首个正文小节前的文档头明确声明采用状态，例如 `状态：已采用`；可置于文档标题前后、无标题时的文件开头，或开头 frontmatter 中的裸值 `status: adopted`；章节小节中的待写、已提交等进度句不代替文档采用声明。文档头为候选、草稿、待定等状态或未写状态时不能绑定，不能靠改成 `README.md` 等中性文件名绕过。候选、草稿、历史版本及正文文件不可绑定，也不按文件名或修改时间推断采用。返回的 `outline.status=adopted` 只表示显式登记了采用声明，并且细纲文件与工具计划的版本仍匹配；工具不能证明实际采用依据已获审阅，也不能证明自由文本与工具计划在语义上相同。

`context` 与正文提交会复核绑定，`lint` 也会报告绑定状态；细纲文件或工具计划变化后，先核对并同步内容，再用新文件摘要与当前 revision 重新绑定。新绑定核对可见采用声明，随后删除或注释该声明也会因文件摘要变化而被拒绝。旧绑定未记录声明语法版本，若文件没有可见状态字段，仍按已登记版本校验；这项兼容性不能证明旧采用声明符合现行语法，须重新核对并执行绑定才能确认，不自动迁移或清理旧记录。若文件头明确标为候选等非采用状态，则停止返回 `adopted`。首次正式提交新章必须先绑定已采用细纲；新书首章和旧书后续新章同样适用，缺绑定时返回 `outline_binding_required`，不保存正文或状态。已提交的旧未绑定章仍可按其原有修订或重试流程处理，导入和历史回放不补造采用记录。候选的 `context`、`lint`、`prepare` 可返回 `unbound`，仅表示尚无机器版本核验，不授予正式采用权限，也不能报告为规划已验证一致。绑定文件的 SHA-256 必须来自本次审阅的实际字节；命令若提示版本漂移，不靠重复原命令掩盖差异。

漂移阻断 `context` 时，用 `plan-read --book "<书根绝对路径>" --chapter N --budget-bytes 16000` 只读取得已保存的完整章计划、同一快照的 `revision` 和 `plan_sha256`，再与当前细纲逐项核对。此回执只呈现保存数据，不核验采用依据、细纲语义或导出完整性，也不重绑或修复；预算不足时按错误中的 `minimum_bytes` 增大预算，不截断计划。同步与重绑仍取操作时的最新 revision，完成后重新取得 `context`。

绑定摘要覆盖整个文件，纯进度更新也会改变它。共享文件修改后，按绑定回执或漂移错误中的 `related_chapters` 核对同一路径的关联章号，逐章复核对应内容与工具计划，再以新摘要及每次最新 revision 重绑全部关联章；只重绑本次提交章不能恢复下一章的绑定。关联章号可留存在现有任务记录中，避免为记录绑定而再次修改被绑定文件。规划本来不记录提交进度时，可把进度放在未绑定的进度入口；已有规划中的进度句仍须与 status 一致，迁出这些句子也须复核并重绑；不通过忽略进度字节或自动重绑跳过复核。

整理旧规划先备份并核对约定、任务记录及各版内容，确定每个范围当前读取哪份；不能判定时保留争议和来源，不自行批准候选。迁入时保留有效内容、来源和可追溯引用，更新失效链接；不改已发生的正文事实，不移动托管正文。规划整理不把尚未发生的安排写成事实卡。

## 状态卡与工具章计划

`template notes` 展示卡片结构。每张卡保存一个会影响后续的事实/人物状态/承诺，短而具体，带来源。少量全书硬限制用 `critical: true`；局部限制加 `scope: "volume:v1"（也可 arc/line/entity:ID）`，全局用 `global`；简单伏笔用 `kind: hook` 与 `due`；人物/地点设稳定 id 和 tags。作者习惯只有用户明确要求记住时才保存为 preference，不自动积累画像。

局部硬限制同样设 `critical: true`。按 scope 自动召回时，`volume:v1` 对应 `plan.volume: "v1"`，arc、line 同理；`entity:ID` 要求该 ID 在 `plan.entities` 中，关联 ID 须有相应世界记录。`volume_dir` 只决定展示目录，不关联 scope。尚无这些关联或仅使用具名卷目录时，把本章硬限制的卡片 ID 显式加入 `plan.requires`；取回 context 后核对它们确实位于 `required_cards`，缺失时先修正关联或 requires 再起草。

`notes --input "<卡片.json>" --expect R` 更新卡片，R 取 status。新卡须提供 `id/text/source`；已有卡按 ID 合并，只覆盖显式字段，省略的 kind、critical、scope、tags、due 等沿用原值。清除到期章用 `due: null`，清空标签用 `tags: []`；解除硬限制须明确写 `critical: false`，改为全局范围用 `scope: "global"`。`kind` 仅支持 fact、character、world、hook、preference、contract。正文提交的 `changes` 仍需完整卡片对象，每项另带 `quote` 精确原句，`source` 不能替代它。不要把整份大纲拆成无用卡片。

人物卡只存会影响下一步的已知/误信/未知及获知依据；作者掌握的谜底不等于人物知道。时间地点、物件归属、伤势、关系变化另用短事实卡；承诺写明触发条件或到期章。章末更新变化项，续写前核对这些状态和上章具体后果；有冲突定点补读，不把全书重新装入上下文。

`template plan` 展示计划结构；用 `plan --chapter N --input "<计划.json>" --expect R` 保存。`constraints` 保留适用于本章正文与审查的情节、停笔、篇幅和格式要求；“本轮只做规划”“仅审稿”等操作范围放在现有任务记录或 `创作约定.md` 的授权阶段与断点，不作为章内容约束写入该字段。填写目标、人物选择导致的场景变化、停笔点、字数范围、`requires`（所需卡片 id；结构化人物放 entities，不混填世界记录 id）及 tags。不要以“每场几个事件”“对白百分比”代替戏剧功能。未知事实不写成已确定设定。

章幅、各计数口径、标题计数及旧章适用范围统一见 [章幅与计数](../../story-skill-write/references/chapter.md#章幅与计数)；在计划中保存 `length`、`count_method` 和 `count_title`。任一项采用非默认值时，新章计划必须另有 `length_exception`，记录确实存在的明确例外依据，不能只把较短范围写入 `length`：用户本次原话用 `{"source":"user_request","quote":"<准确原话>"}`；书内现行约定用 `{"source":"book_agreement","path":"创作约定.md","quote":"<该文件中的连续原文>"}`，`path` 必须是书根的 `创作约定.md`，原句须能在该文件当前版本中找到；其他草稿、候选或临时文件不能充当书内约定。`constraints` 仍保留用户的硬要求，但不能代替此依据；工具无法核对聊天原话，助手仍须亲自核实 `user_request` 引文，不根据字数愿望、旧计划或作者猜测编造用户原话、文件引文或例外。已有已提交旧章及导入基线不因新章默认值自动扩写；旧版尚未提交的非默认计划须在首次提交前核对真实依据并补齐，或改回默认值。若已绑定细纲，改动计划后重新核对并绑定其版本。

章计划填写 `title`（只填章节名称，不含“第N章”前缀）和 `volume_dir`（完整分卷目录名，格式为 `第X卷 卷名`，例如 `第一卷 雨夜`），导出为 `chapters/第一卷 雨夜/第1章 雨中来客.md`。章名在全书范围内唯一，不因进入新卷而复用；误在 `title` 填写章号会被拒绝。新写完整章节须以纯文本 `第N章 章节名称` 为首行章头，并与计划章名一致；`title` 未填时可从该章头提取名称并去掉前缀，旧稿的 Markdown H1 仍作兼容识别。仅对已提交的无章头旧章及导入基线，兼容用计划 `title` 提供章名；导出时由实际章号生成文件名。导入的无标题基线可用章名 `正文`，但仍须明确所属卷名：可在 `adopt` 传入 `--volume-dir "第一卷 雨夜"`（替换为本书实际卷名），或从已保存的该章计划取得完整目录；仅指定导入卷名无需新建章计划。

`volume_dir` 是一级目录名，必须包含卷序号、一个空格和真实卷名，不能包含路径分隔符；同卷保持同一个完整目录名，不同卷不能只换卷号而复用卷名。显式 `volume_dir` 优先；未填写但已有 `volume` 时，可沿用该稳定 ID 已保存且带卷名的目录，或采用已符合 `第X卷 卷名` 格式的世界卷记录 `title`。工具保存所选目录供同卷后续章节沿用；同一个 `volume` ID 一旦绑定目录，后续填写不同目录会被拒绝，不能借单章计划静默改掉整卷归属。若这些来源都没有完整卷名，先核对已有分卷规划；尚未命名时，依据已授权的本卷内容拟定卷名后再提交。不要用仅有卷号或内部 ID 的目录代替卷名。短篇与单卷作品也须明确首卷名称。`volume` 仍是关联世界状态的稳定 ID，展示目录用 `volume_dir` 指定。显式目录格式不完整会报 `invalid_input`；未提供或推导来源没有卷名会报 `volume_title_missing`，`lint` 和 `prepare` 会在提交前检查章名及卷名是否可用，补充缺失名称后重试。

保存计划会与已规划、已提交的章节核对名称；重名分别报 `duplicate_chapter_title` 或 `duplicate_volume_title`，同一卷序对应不同目录则报 `volume_directory_conflict`，即使未设置卷 ID 也不能分裂。没有在计划填写章名时，`lint`／`prepare` 从草稿标题提取后再核对。旧书现有文件不因打开或读取而自动改名；若发现重名，先核对采用版本，再逐章修正计划与正文文件。

`beats` 记录本章有作用的变化节点，不是逐场清单；一个节点可以跨几个场景。用 `beats.choice` 写人物面对的阻力、实际尝试及回应，或既有冲突的余波怎样影响其继续行动；用 `beats.change` 写该节点造成的可见变化与下一步条件。整章仍须能读出目标、成立的阻力、应对及后果，不要求每个节点新造一轮对抗或独立回报。`goal` 写本章争取的结果与阅读期待，中途章的 `stop` 写本章后果引出的待解问题，实际终章则可写已兑现后的收束与余韵，不强造新问题。开书第一章的具体危机与取舍也纳入这些字段，不另造“冲突分”“爽点数”字段或额外表格。

`goal` 可以写人物争取的结果，`beats.change` 则只写本章计划真正呈现的变化；尚需核实的地点、身份或因果写成待验证，不先记为已确认。相邻章节若只重复同一种查证和阻拦，具体写出各章不同的尝试、阻力和可见回报；细纲可保留未定处，不用套话填满计划。

多卷、多视角和长期连载需要结构化世界资料时补读 [超长篇状态](../../story-skill-write/references/long-form.md)。近期细纲范围按本次授权和写作需要确定；未指定范围时，默认细化近期3—5章。
