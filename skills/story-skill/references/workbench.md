# 写作工作台

仅在用户要求进度页、书架、候选编辑、材料查看或工作台管理时读取。先沿用公共入口的当前作品、授权与共享工具路径；普通规划、正文与审稿不加载本参考。以下区分静态导出、单书服务与独立书架，按所需能力执行。

查看已初始化作品的本地进度时，可运行 `python "<tool>" workbench-snapshot --book "<书目录绝对路径>" --limit 10`；需要可打开页面时运行 `python "<tool>" workbench-export --book "<书目录绝对路径>" --limit 10 --open`。前者使用只读连接，后者只在 `.story/workbench/` 写派生 HTML 和页面备份，不改正文或权威状态。书根属于 Git 仓库时，先确认整个 `.story/workbench/` 已被忽略且没有被跟踪的旧页面；不自动改 Git 索引，无法核验仓库状态时停止导出。`--open` 失败时按回执区分“页面已生成”和“浏览器未打开”，保留 `path` 与 `open_error`。默认生成三栏正文阅读页（目录、正文、章节摘要），嵌入本次已核对的正式章节；仅需摘要时显式加 `--overview-only`。`--include-text` 保留兼容。正文校验失败时报告问题，不静默退回旧界面。当前页面只含概览与本次章节页；卡片、世界、历史、分析和发布只有摘要且没有完整分区游标。发布摘要只检查导出回执所指 ZIP 的存在与字节数，不做逐字节哈希核验。草稿、候选稿、可读大纲、封面和其他作者产物没有登记时显示未登记，不按文件名或时间猜测。上述本地快照与静态导出不联网，也不执行平台上传、提交或排期；需要完整明细时仍使用对应原命令。

需要查看候选稿、创作材料或编辑时，先用 `python "<tool>" workbench-status --book "<书目录绝对路径>"` 核对已登记服务；仍在运行且代码未过期时复用返回地址。未运行时才执行 `python "<tool>" workbench-serve --book "<书目录绝对路径>" --limit 10 --open`。服务只监听本机，同书新服务只允许一份运行。升级或重启前核对所有相关页面，保留未保存文字，再用 `python "<tool>" workbench-stop --book "<书目录绝对路径>" --saved` 请求停止并核对结果；不可达不等于已退出，较早版本的未登记服务须另核对进程和页面，不按模糊名称批量结束进程。左栏可翻页、搜索正式章名与材料路径，并按实际目录打开 `.story/drafts/`、`.story/analysis/`、编号创作目录及书根文本、图片；文件存在不代表已采用。候选可再次打开编辑，每次另存 `.story/drafts/workbench/` 新文件，旁附来源及基线记录，不改变正式章节或审查状态。右栏明确版本状态，可并排对照正式稿；旧稿无记录时仅按章号建议对照，不认定版本关系。来源或书库变化会拒绝保存，保留编辑并刷新核对。停止输入后自动写入本书 `自动恢复/` 文件夹，并核对上次正文和来源记录；外部变化或保存待核对时，后续编辑另存新恢复稿，原文件保留。失败会提示；尚未完成恢复写入的文字仍可能丢失。关闭前应保存候选或下载，重新打开后从左栏恢复稿找回。采用候选仍使用 review 技能的现有修订流程。静态导出不具备这些编辑功能。

服务版的“平台草稿”入口可本地预览已冻结正式稿，启动已授权整批草稿保存及只读对账，显示本次完整回读进度。细节按 [平台草稿保存](../../story-skill-publish/references/platform-drafts.md) 处理。本轮 `host_assisted_cua` 模式只使用当前助手已连接的既有 Chrome，会检查助手工作进程是否可用；没有工作进程时阻断，不另开浏览器。关闭草稿面板不取消已启动任务，但助手断开后不会无人值守继续；结果未知先对账，不重复新建。当前编辑缓冲不会混入冻结正式稿。

用户需要不绑定书籍的固定入口时，先用 `python "<tool>" workbench-library-status` 核对独立书架服务；需要启动时用 `python "<tool>" workbench-library-serve --open`，默认 `http://127.0.0.1:8765/`，允许空书架启动。页面添加已初始化书目录，或启动时重复传入 `--library-book`；登记保存在用户目录 `~/.codex/story-workbench/`，不扫描磁盘。固定的是书架入口，打开作品仍在新标签复用或启动该书编辑服务，原页面保留。`--port` 改固定端口，`--state-dir` 改书架存储位置；状态和停止须使用同一存储位置。停止使用 `workbench-library-stop --saved`，不停止各书编辑服务。服务运行并实际验证地址可达后才交付链接；升级前保留页面编辑，不能把示例地址说成已启动入口。

服务版默认可“按章查看”细纲、已保存计划、正式稿与同章号候选，或切回原文件目录。章号匹配仅用于导航，内容与正式稿相同也不证明采用历史。顶部显示本次刷新取得的当前进度；历史报告及规划文本不自动改写。右栏显示本章目标、前章摘要、停笔点、约束及正式稿审查记录，记录只对应正式稿。

字数按已保存章计划的口径与章名计数设置核对，材料字数与正文字数分开；图片不计数。已记录范围的章节片段保留章号和上下文，统计全部片段正文，不套完整章字数目标；保存、恢复与归档保留该范围。大纲和策划支持安全的基础 Markdown 排版及源码切换，正文保持纯文本。对照用增删高亮，超长文本明确提示使用整块高亮。“审稿”为已保存文件生成含路径、校验值和范围的持久任务，可复制给助手并回填结果；基础检查不等于语义审查，页面不自行正式采用。全文搜索覆盖可读正文和文本材料，达到扫描上限或跳过异常文件时必须明示未覆盖；不把搜索完整当全文审稿完成。

需要多书切换时，启动服务可重复指定 `--library-book "<已明确的其他书目录>"`，最多30本（含当前书），不自动扫描用户磁盘。切换在新标签页打开已登记作品，复用可确认的现有服务；未启动才新开，服务不可达时先核对，不能擅自判定已退出。用户可调整字号、行距、字体及专注阅读；设置保存在当前浏览器地址的本地存储，换端口后不保证延续。上述能力仅服务版提供，静态导出保持原有只读范围。

## 助手任务与结果

需要跟踪工作台续写或审稿任务时，从“更多 → 助手任务与结果”打开记录。下一章可先选择已加载的本书要求和文风材料，再点“继续下一章”；生成时仍须有已采用并绑定的细纲。书内任务保存在 `.story/assistant-tasks/`，只作为工作材料，不推进正式章序或小说事实。复制任务后由作者交给助手，明确交接才标“已交接”；复制或交接都不证明执行完成。

助手按任务原有授权完成候选或审查，填任务附带的结果模板，保存为本书 `.story/drafts/` 下 JSON，再执行附带的 `task-return` 命令。可用 `task-get --book <书根> --task-id <任务ID>` 重新取得绑定、回填模板与当前版本。输入和候选均需实际文件 SHA-256；回执只引用本书现存候选，不自动写正文。已有结果不可被不同结果覆盖；修订改变原稿后另生成对应新版本任务。CLI 回填与人工导入均保留来源为待核验，不能仅凭回执宣称独立审稿实际完成。

页面可刷新已返回的结果、打开候选、逐项核对审稿问题并查看跨章原文。每条问题可带多个正式章或书内材料引用，绑定 SHA-256、精确原句与行号；原文快照保留，来源变化时显示过期，禁止把旧意见直接确认为新稿结论。解决或保留问题须说明依据，未解决的阻断项继续待核对。任务核对不会调用正式采用；采用沿用现有 prepare／commit 或 history 流程。只有已核对的返回稿与随后当前正式章相符，才显示正式应用匹配；这仍不代表平台状态。

回流请求失败或连接中断时先重新读取任务，核对是否已保存，不直接反复导入。任务中心不清空或替换编辑缓冲；有未保存内容时照常保存或恢复。书籍备份包含任务及其原文快照，不能把任务“已核对”当作整书审校或真实读者认可。

## 本次停机的逐页确认

支持新协议的服务在 `workbench-stop --book <书根> --saved` 时依次准备、轮询并提交停止。认证接口为 `stop-prepare`、`stop-status`、`stop-cancel`；本次挑战向当前服务登记的各页发独立 nonce，页面冻结新编辑并回报当前缓冲状态及 ACK。旧心跳、旧 ACK、已过期挑战或仅勾选已保存均不能代替本次确认。页面集合或缓冲变化、等待超时会阻止停止；取消或到期后解除冻结，原输入保留。

unknown／失联页仍需作者核对保存和关闭后，用当前 fingerprint 取得单次人工确认；这不能绕过已知未保存、保存中或恢复中的缓冲。停机准备和提交均检查平台及助手活动；执行中或退出状态未知时须先处理任务。作品操作锁内的 TTL 停机租约以 CAS 更新，与其他进程的新派发互斥；租约异常先核对原服务，不能强删记录绕过。

覆盖范围限当前服务实例签发并登记的页面，不证明全系统旧服务、未登记页或其他浏览器均已保存。未支持新协议的旧服务须另行核对；不可达仍不等于已退出，不按 PID 强杀。停止回执后继续核对 `workbench-status`，再启动新代码。

原作品目录被移走时，停止只处理原服务实例，不写入同路径的替换作品。原目录存在宿主执行记录则先恢复目录并对账；无执行记录时持有原操作锁至取消或退出。该特殊锁的过期释放由下一次页面状态核对触发。

## 本机助手的受控执行

任务中心“在本机助手中执行”显式启动本机 Codex CLI；复制任务、标记交接及人工／`task-return` 回填仍为未认证来源。受控执行只继承本机模型与推理强度配置，不加载用户定义的 hooks／MCP；模型工具使用只读沙箱，这不是文件读取白名单。调用使用当前 Codex 账号与已配置模型，可能消耗宿主用量；冻结原文是本次任务材料，不挂载可写作品，也不自动正式采用。写作结果只由控制器保存为待核对候选，审稿结果仍需作者核对。

CLI 使用当前任务版本和稳定的本次请求标识：

```sh
python "<tool>" task-execute --book "<书根>" --task-id "<任务ID>" --version <版本> --request-id "<本次请求ID>" --execute --timeout-seconds 900
python "<tool>" task-execution --book "<书根>" --task-id "<任务ID>"
python "<tool>" task-cancel --book "<书根>" --task-id "<任务ID>" --execution-id "<执行ID>"
python "<tool>" task-reconcile --book "<书根>" --task-id "<任务ID>" --execution-id "<执行ID>"
```

`--timeout-seconds` 可省略；对应工作台认证 API 为 `tasks/start`、`tasks/execution`、`tasks/cancel`、`tasks/reconcile`。同请求同参数返回原执行；改参数会冲突。断线、心跳失联、取消请求或未知结果均不能直接重新派发；先读取已有执行，再对账。输入、任务版本已变化或取消后的迟到结果保留为冲突，不直接回流。

真正调用宿主前再次核对冻结请求、绑定和取消状态；确认尚未调用时记录可核验的“未启动”，同一执行标识仍不重派。有调用线索则保留未知并对账。候选正文、章号与范围一并保存，写入中断保留待核对记录；对账只补齐相同结果，不覆盖作者改动。

“执行中”须有对应进程身份、新鲜观察及原生会话；终态须核对原生 trace、进程退出回执及绑定摘要，再由本机控制器签署持久退出记录。已核实退出与原始证据是否仍可读分别显示：同机恢复后可用签名确认已退出，原始 trace 缺失时不能继续声称结果已核验；跨机缺少本机密钥时不认证退出。工程回执不认证文学判断、真人反馈或独立复核；正式采用从不自动执行。

任务窗口内尚未导入的 JSON、核对说明和保存结果未知状态会纳入停机元数据；只发送标识和状态，不上传这些输入正文。关闭任务窗口前须先提交或复制未提交内容；这不承诺关闭窗口后的表单恢复。
