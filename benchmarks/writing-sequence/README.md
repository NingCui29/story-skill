# 连续章节与完整作品写作开发评测

用于检查单章规则在连续写作时是否落实到实际故事：人物尝试是否得到有效回应，前章行动是否影响后章，配角是否保有自身判断，阶段成果是否被人物实际体验。评阅不以账目词频、固定反转数或段长判断质量，也不把软件检查当作文学结论。

每轮先固定原创任务、篇幅口径、实际范围与待测技能源码，再在独立目录中完成规划和连续章节。检验完整作品时选择完整短篇，或正常章幅、经历多个自然阶段的长篇；阶段与章数按故事节点和待测问题确定，不靠压缩成短章模拟长篇。长篇只读到某阶段时，结论限于该范围；要验证终局和完本交付，须实际写到约定结尾并核对全文。本协议用于技能开发或用户授权验证，普通小说创作不额外执行。

写作者只接收任务及所需技能，不看预期结论或评阅反馈。保存一次完整执行的产物；记录执行中为长度、格式或工具错误进行的调整，不隐藏失败，不从多轮稿件中挑选最好的一份。

完成后把任务和实际章节交给未参与生成的独立评阅者，不提供预期结论、创作自审或过程摘要。要求针对原文说明因果与连续性、人物关系、重复解法、阅读回报和中文表达的得失，标注章次与精确引文。不要求所有场景激烈冲突，不以单轮模型判断代替读者反馈。

连读时回查前后原文：新会话及阶段切换后，叙述声线是否延续，人物是否带着此前的经历、所得和关系行动，早先选择的后果是否改变后续条件；同时观察篇幅重心、情绪变化和信息释放是否支撑阅读期待。声线允许随人物经历有依据地变化，日常、过渡和安静场景按其作用评阅，不统一要求提速或增加冲突。

涉及整书改稿时，保存改前全文与原评阅，再定位主要问题、记录实际改动并回查受影响的前后文；检验目标问题是否改善，有效人物与场景是否受损，伏笔、知情、关系和结局是否随改动承接。修改轮次按需要决定。最终全文与正式章节及修订版本逐章核对，检查章序、遗漏、重复和是否混入工作记录；导出成功只支持文件交付，不能替代文学判断。

真实目标读者反馈按 [阅读反馈方法](../../skills/story-skill-research/references/reader-validation.md#把反馈变成可定位的问题) 处理，与模型评阅分别保存所读版本、范围、条件及原意见；没有实际参与者则记真人试读未执行，不把它设为创作门槛。反馈前后对比尽量保持阅读范围、呈现方式和读者条件可比，保留分歧，说明重复阅读的熟悉效应或条件差异；改后复查与独立新样本验证分别报告。

原始归档保存在仓库外或已忽略的 `.local-writing-samples/`，不提交测试小说。归档至少包含任务、逐章正文、必要规划、原始独立评阅、实测字符数、提交及导出结果、源码与产物 SHA-256，以及结论和未验证范围。明确单版本试用还是新旧对照、模型设置是否可核实、是否经过试后修改。仅单版本单次试用时，不声称新版胜出、稳定提高文学质量或获得平台验证。

后续若据结果修改技能，保留本轮原稿和原评阅；另取未参与调试的题目验证，不把修改后的同题重写当作留出结果。发布后的远端安装及 Windows 执行须另核对，不沿用本机开发结果。
