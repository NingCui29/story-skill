# Native 再复核与修复

在上轮最终源码基线上检查重定向、当前快照、按钮标签与焦点保护，确证并修复三个相邻写入边界。

- 尚未分配远端 ID 时，SPA 改变 URL 但保留原字段，旧逻辑允许继续填写甚至点击保存。现在只有原创建地址允许继续等待首次分配；取得 ID 后仍允许匹配该 ID 的正常路由变化。8 个失败反例和 2 个正常首次分配对照分别见 `unallocated-url-red.log`、`unallocated-url-green.log`。
- 页面已经显示发布状态，或状态节点消失、重复后，旧逻辑仍可能写下一字段或点击保存。每次实际写入前增加当前 DOM 状态核对，不等待缺失节点重新出现。12 个失败反例见 `current-state-red.log`，修复结果见 `current-state-green.log`。仅适用于 DOM 状态来源；目录来源仍使用既有目录核对。
- 新建/保存按钮的标签不变、链接目标变化时，旧逻辑仍然点击。现在固定初始 href（包括无 href），最终在绑定节点的标签快照中同时核对。普通保存、同页新建、popup 新建的 9 个反例和 6 个稳定链接/无链接正向分别见 `action-href-red.log`、`action-href-green.log`。

最终定向回归 **136 项通过，0 失败、错误、跳过**，新增 5 个测试方法。覆盖普通编辑回读、Native 创建/保存、只读预览、段落序列化与输入；既有合法重定向、正文严格完整回读、按钮标签变化、焦点归属、首次分配、popup/同页创建和自动保存验证仍通过。完整回归由主线程另行记录，不能把参数组合相加为测试总数。

生产文件和测试文件 SHA256 见 `validation-summary.json`。独立交叉复核由同伴进行，记录另见主报告。当前无未解决的已确认 Native 问题。
