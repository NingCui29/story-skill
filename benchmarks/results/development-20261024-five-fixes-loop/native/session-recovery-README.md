# 原书会话初始化与恢复复核

持久日志、工作台及备份恢复交接的只读复核另见 `journal-workbench-review.json`。原有拒绝保护会保留 unknown / blocked，不会把历史成功当成本次回读，也不会从轮询自动重放平台写入。12 项相邻生命周期测试全部通过。

本轮额外确认并修复原书 Chrome 会话初始化失败后无法重连的问题。旧代码在首次 session 或 lease 发布前失败时，留下缺失元数据的会话目录，后续状态查询和重新连接抛出 FileNotFoundError；若 lease 已原子发布、但本机 fsync/验证再失败，则会留下没有外部句柄的有效租约。独立并发复核还确认两个 attach 可以同时看见“没有执行端”并各自建立活动会话。

修复采用本书根级初始化锁，覆盖发现既有执行端、创建会话元数据、发布外部句柄；会话初始化本身也持有会话锁。尚无租约、只保留有效 session 元数据（可无）、session.lock 与标准初始化 stage 的目录作为未完成初始化证据保留，允许新会话连接；含 lease、outbox、claimed、response、health 或未知文件的目录不被跳过。初始化发布后报告错误时，只有经核对属于本次、且句柄尚未发布的租约会被置为 detached。

新增 6 个测试方法，包括真实独立 Python 进程暂停在元数据发布前、另一进程查询与 attach 必须等待的验证。邻域 **82 项执行：81 通过、1 项需要原生 Windows 进程句柄而跳过，零失败错误**。包含原有完整桥接测试与 4 项备份恢复回归；完整全量由主线程记录。

独立同伴的 14 个场景全部通过，包含 12 个初始化失败/未知载荷场景、并发 attach 与真实本地已领取 create 请求超时后不重放的检查，见 `../chrome/independent-python-session/`。红证据使用匹配 SHA256 的上轮分发源码在独立进程中加载，未回退或覆盖当前生产文件。摘要和最终源码哈希见 `session-recovery-summary.json`。

边界：能进入异常清理的初始化失败可退役尚未交付句柄的本会话租约；若进程硬杀发生在 lease 已发布、handle 尚未发布之间，无法运行清理，有效租约仍保留到正常过期，不按空残留跳过，也不宣称立即重连。

范围仅本地临时作品、真实文件锁与测试进程；无真实平台、安装或发布动作。Windows 路径保留既有锁实现，未把非原生检查说成原生 Windows 验收。
