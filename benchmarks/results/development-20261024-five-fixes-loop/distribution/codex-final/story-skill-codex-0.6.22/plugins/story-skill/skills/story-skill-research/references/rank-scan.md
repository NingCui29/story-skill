# 结构化扫榜与选题交接

用于榜单、书库新书、跨榜比较和需要复用的市场样本。普通素材问答不加载本文件。工具是兄弟技能 `../../story-skill/scripts/story.py`，从实际安装位置转成绝对路径，以下记为 `<tool>`；这些命令不需要 `--book`，不会建立书库或修改正式正文。

## 确定样本

沿用用户已给的平台、长短篇、频道、题材、时间和用途。未限定时可选一个与问题相关的样本并说明范围；缺项会改变判断时再询问。新书观察、成熟作品榜、畅销榜和搜索结果分别记录。选前几页、按题材等额抽样、人工挑选都只代表该样本，不能据此推算平台题材份额或成功率。

先用现有联网工具核对当前页面与榜单口径。公开采集仅作有界 GET；登录页用已授权浏览器。遇到验证码、权限拒绝、WAF 或结构变化，保留失败原因，转到可读来源或浏览器记录。不能把挑战页、乱码书名、接口占位零或未加载列表当有效数据。

## 采集与保存

需要保存研究包时使用作者指定的研究目录，或现有书目录下的调研材料目录；不要保存到技能安装目录。一次采集或聚合使用一个新目录，工具拒绝覆盖已有目录。未要求持久保存的临时分析可在临时目录运行，交付有用结论即可。

```bash
python "<tool>" rank-template
python "<tool>" rank-collect --source qimao-library --pages 2 --output-dir "<新的采集目录>"
python "<tool>" rank-check --input "<采集目录>/snapshot.json"
python "<tool>" rank-aggregate --input "<采集A>/snapshot.json" --input "<采集B>/snapshot.json" --output-dir "<新的汇总目录>"
```

`rank-collect` 保存原始 HTML、规范化 `snapshot.json`、`report.json` 和中文 `report.md`；`rank-aggregate` 保存两种报告。这些文件是市场材料，不是已采用选题、规划或正式章的证明。采集失败不返回成功空榜。

当前内置适配为 **七猫公开书库的点击排序新书观察样本**：30 万字以下、3 天内更新、连载中，最多 10 页，每页 15 本。这些条件不证明作品近期首次发表；频道筛选未解析，`channel` 保持 `null`，不宣称覆盖全频道。它不是七猫正式排行榜，也没有公开的逐书点击数。页面筛选、排序和页码均须通过解析检查；`metric` 和 `metric_value` 保持 `null`，不能以名次冒充销量或阅读人数。最后一页、全库数量无法确认时，覆盖仍为 `partial`。

若网络请求被拦，但已授权浏览器能读页面，可按顺序保存各页 HTML 和实际源 URL，再用同一解析器导入。此适配器仅接受上述固定书库筛选地址，不能把其他频道、题材或排序的 URL 写成同一来源：

```bash
python "<tool>" rank-collect --source qimao-library --pages 2 --html "<第一页.html>" --html "<第二页.html>" --html-url "https://www.qimao.com/shuku/a-a-a-1-1-a-0-click-1/" --html-url "https://www.qimao.com/shuku/a-a-a-1-1-a-0-click-2/" --output-dir "<新的采集目录>"
```

导入 URL 是导入者提供的来源声明，程序不能证明文件最初来自该地址。导入时间也不是页面最初抓取时间。没有原始采集时间证据时，不把保存的旧 HTML 当作今日榜单；报告需保留这些限制。HTML 必须含完整筛选、排序和书目内容，单纯截图或未加载页面不能直接解析；书卡已知字数或状态与筛选矛盾时拒绝导入。完整页面标题保留在来源名称中，避免丢失可见的额外筛选信息。

番茄、起点及其他平台当前通过网页／已授权浏览器采集后按下列格式记录，再执行 `rank-check` 和 `rank-aggregate`。不宣称这些平台已有直连采集器。浏览器只提供可见部分时照实记录；动态字体造成的私用区字符、隐藏字段与页面显示不一致时，以可读页面核对，无法核对则标缺失，不猜译书名或把接口默认 `0` 当真实指标。

## 统一快照格式

`rank-template` 给出完整示例。实际采集填写已观察值，缺失字段用 `null`，无指标的来源令 `source.metric=null`。

| 字段 | 含义 |
|---|---|
| `schema_version` | 固定为 `1` |
| `platform` | 平台标识，例如 `qimao`、`fanqie`、`qidian` |
| `collected_at` | 带时区的 ISO 日期时间；保存原始来源时点，不在重新汇总时改成今天 |
| `source.url`、`board` | 可回查的源地址、真实榜单／书库名称；分页记入 `pages` |
| `source.channel`、`category`、`period` | 频道、筛选题材与榜单周期，未知用 `null` |
| `source.cohort` | `new`／`mature`／`mixed`／`unknown`，依据实际筛选条件区分新老作品 |
| `source.metric` | `null` 或 `{name, unit, window}`；名称、单位与时间窗口都按页面含义填写 |
| `source.sample_method` | 前 N 名、指定页、等额题材样本、人工选择、HTML 导入等实际方法 |
| `source.method` | 可选采集方式：`public_http_get`／`browser_html_import`／`manual`；HTML 导入须说明原始页面时点是否已知 |
| `source.pages` | 实际取得的页码数组；未读页不能填入 |
| `source.coverage` | `partial`／`complete`／`unknown`；只有实际覆盖全部目标样本才用 complete |
| `source.expected_count` | 可验证的目标记录总数；未提供或未核对时为 `null` |
| `source.limitations` | 未读页、登录限制、原始时间未知、抽样偏差、指标定义不全等 |
| `entries` | 逐书记录，至少具有平台书 ID 或绝对作品 URL、书名与正整数名次 |

逐书字段为 `book_id`／`book_url`、`title`、`author`、`rank`、`category`、`tags`、`word_count`、`status`、`metric_value`、`metric_raw`。字数统一为非负整数，保留平台指标原始文字；数值未知不能写零。没有公开指标时不能从排序名次反推数值。作品分类取平台原分类，推断题材另写在分析中，避免让模型判断变成采集事实。

## 去重与统计口径

同平台优先用书 ID，缺失时使用作品 URL；不凭书名合并同名作品，不跨平台自动认定同一作品。相同来源、同日的重复记录不增加样本权重，指标或书目信息冲突保留并提示复核。同一作品 URL 对应多个 ID 时，保留全部身份及观测，统计与抽样统一排除这些歧义作品；排除数量单列，含旧歧义记录的报告和样本需重算。不同榜出现同样书目只提示内容重复，不能仅凭前几名相同就删掉一个榜。

同日多次观察可能因正常榜位或数值变化产生冲突。本轮保守排除该作品的本组统计，不自动选最新值；分类占比也随之改变。合并统计描述这批有效记录，不代表任何一个时点的完整榜单。需要时点比较时分别对每份快照运行汇总，核对变化及覆盖后再判断。

按平台、来源、记录日期、榜单／筛选条件、作品群体、采样方法和指标定义分别汇总。不同平台、日榜月榜、阅读人数和月票等不能混算；也不把指标取最大值来消除冲突。报告列出本组去重作品数、分类计数与样本内占比、指标有效数和缺失数；中位数只描述同口径有效观测。分类缺失单列，不能悄悄从占比分母剔除。不同采样方法分组，覆盖不完整时保留限制。

快照最多 5,000 条，单次最多 32 份快照／20,000 条观测；单组不同标签最多 50,000 项，超过时缩小范围后处理。标签展示前 50 项、书名模式展示前 30 项，完整观测仍可回查。

程序核验只证明结构、数值和去重规则被执行；来源填错、页面误读、作品好看与否、商业机会是否成立仍需核对。报告不生成“全网热度”“爆款概率”或把名次折算成跨平台总分。

## 代表作抽样与模式分析

`rank-aggregate` 的分组报告还提供标签作品频次、书名模式和字数分布。标签按原文精确匹配，每本书对同一标签只计一次，未提供标签的作品单列；多标签占比相加可以超过 100%。字数统计区分未知与真实零值，不用缺失值补齐分布。

书名先做 NFKC 归一化，再观察首尾 2／4／6 字片段和冒号、逗号、问号结构，不依赖分词模型，不推断套路或人物关系。至少两本有效作品出现才列为重复模式；相同作品集合中的冗余短前后缀压缩，有限展示并保留截断说明与可回查的作品键。标题前后缀相同不证明内容相同，更不说明该命名提高点击率。需要核实具体词，使用下面的字面筛选并回读原书名。

```bash
python "<tool>" rank-sample --input "<采集A>/snapshot.json" --input "<采集B>/snapshot.json" --group "<report.json 中的 group_id>" --category "都市" --tag "经营" --title-contains "开局" --max-words 300000 --limit 5 --output-dir "<新的抽样目录>"
```

`--limit` 为 1–20，本例取 5；筛选项均可省略；多个 `--tag` 表示同时具备这些标签，分类与标签按原文匹配，`--title-contains` 按字面包含匹配。字数可用 `--min-words`／`--max-words` 限定，设置字数条件时未知字数不命中。输入仅含一个可比分组时可省略 `--group`，多个分组必须明确选定，不能混合平台或时间后用榜位排序。没有命中时明确报错且不生成输出目录，不换条件凑数。

抽样从原始快照重新计算，排除观测冲突和身份歧义。重复标签按筛选前本组全部有效作品计票，至少出现于两本书，不受报告前 50 项展示限制。确定性选择兼顾尚未覆盖的分类、重复标签和字数区间，再用组内名次与作品键稳定排序；这是阅读对象的覆盖选择，不是随机代表性估计、热度总分或质量推荐。每本保留选择理由、原始观测和来源。`sample.json` 保存可重建的输入及筛选条件，`sample.md` 供阅读；保留同名不同书，不能仅因标题相似互换。新样本使用 schema 2、算法 2；旧 schema 1 按原方法严格重算，保留原 ID 与研究证据。选用新算法须另存样本及研究版本，不直接迁移旧验证。

需要把抽样结果转成可拆文验证的假设并继续规划时，按 [研究交接](research-handoff.md) 生成研究包。仍需阅读简介、正文和有关反馈后作判断；程序不会从标签或标题自动生成故事事实。

## 从样本到选题

先读报告的来源与限制，再查看样本差异和具体作品页。交接按本次问题给出：有来源的观察、值得继续拆读的作品及理由、原创方向假设、需要试写或补证的部分。未读正文只能评价可见书名、简介和榜单表现；不能把简介推测写成作品的实际解法。

读者契约可用于筛选假设：主角靠什么选择获得结果、收益怎样持续影响后续、旧期待怎样得到兑现、下一阶段为何值得追读。已有规划有等效内容时复用，不新增逐章表单，也不从榜单模板批量换皮。继续规划时转规划技能，只有用户已授权正文时才写作；调研建议保持候选身份。

需要比较新旧榜位时，先核对同源、同周期、同覆盖与作品身份。本工具保留分日观测，但不自动推断增长原因；曝光、更新、作品阶段和平台规则变化须另查。商业判断及试读沿用 [选题与阅读验证](reader-validation.md)。
