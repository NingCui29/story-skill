## 修复与回归

| 问题 | 修复后的行为 | 对应验证 |
|---|---|---|
| 最终预览正文重载时继续等待，可能接受已经换页、换账号或变更标题的结果 | 从新预览页首次 URL 读取起绑定请求的完整地址；所有后续 URL 读取遵守同一约束。首次正文加载可等待；最终正文或标题缺失不再等待恢复。最终正文与编辑器检查后复核当前账号和完整章标题，失败不返回成功结果 | `tests/test_chrome_bridge_driver.mjs` 新增 7 项测试，覆盖 29 种场景：首次延迟、最终 pending/缺失、换作品/章节/账号/标题、最终标题缺失或重复、首次错误导航及后续切回、保存后只读确认、失败标签清理 |
| 合法抽样理由超过研究说明的 8000 字符上限，导致 research-init 失败 | 仅缩略自动生成的候选说明，按整条理由省略并指回完整来源；短理由原样保留，人工输入仍遵守原上限。完整样本、抽样算法、样本 ID 和历史验证不改 | `tests/test_research_long_reasons.py` 新增 5 项测试：三种支持格式经实际 CLI init/check/verify/render，8000/8001 字符与 Unicode 边界，其他理由保留，输入文件字节不变，历史验证不变及手填超长拒绝 |

平台修复的交叉复核发现两类中间遗漏：首次错误落页可被后续等待掩盖，以及个别 URL 读取仅检查域名与作品。已补上回归，将完整地址约束集中到统一 URL 读取入口，并保留失败预览页的清理归属。
