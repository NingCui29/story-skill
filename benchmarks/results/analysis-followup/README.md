# 深读与分析修订流程续查

本轮接续此前中断的“检查深读和修订流程实际缺口”。已有真实短篇分析与上一轮修订均已完成，本轮补清定稿后的修订和恢复方式，并处理第一轮三处遗留措辞。v0.5.1 仍为未发布开发版，本机安装已同步。

## 已落实的流程修正

运行时原本就保护已定稿分析，但分析入口没有写清 `record --replace` 的阶段边界。现在总入口明确把分析稿修订交给分析技能，分析技能区分：

- 尚未定稿的逐块记录可以替换，保留历史事件，然后继续未完成块与聚合。
- 已定稿的记录和报告保留原样，另存独立修订稿；恢复时读取修订稿旁的进度和文件哈希，旧书库的报告路径不能代表新稿状态。
- 只有外部分析文档时直接修订文档，使用实际段落或引文定位。

同时明确：重试提交同一报告要使用原提交输入，导出报告含工具附加的来源头，不能直接再次当成输入。核验依据是 [实际命令回执](runtime-boundaries.json)：未定稿替换与原输入重试成功；定稿后换记录返回 `report_already_final`，不同报告及再次提交带头导出稿返回 `report_exists`。失败后原定稿字节不变。这些属于现有保护规则，运行时代码没有改动。

## 从保存进度接续的试用

在临时分析工程中预先完成《门边》第一项修订，留下第二项待核对问题及进度。一名新代理仅得到自然任务、技能入口和临时材料，从进度恢复，核对输入哈希，完成剩余判断并联动修改建议。它保留暂时留下的解释，将再次决裂从必然结局改为尚不能确认的走向。

交付物：[完整修订分析](workflow/revised-report.md)、[完成进度](workflow/progress-after.md)、[实际读取与命令自记](workflow/agent-process.json)、[原文](workflow/source.txt)、[旧提交稿](workflow/submitted-report.md)。主代理独立核对原文、旧提交稿、工具定稿及数据库哈希未变，修订稿和进度哈希一致，11 处短引文可定位，见 [文件检查](workflow/check.json)。进度与过程日志里的临时绝对路径保留当时执行情况；材料归档位置以上述链接为准。

本试用使用本项目已有教学短文，只观察一次修订恢复行为，不是留出材料、匿名新旧对比或长篇文学质量验证。执行代理请另一代理辅助核对剩余推断，输入包含待修判断；没有把这一步称为盲评。
