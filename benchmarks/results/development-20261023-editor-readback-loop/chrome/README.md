# 普通编辑页 Chrome 回读循环修复

本目录只记录离线 public-CUA fixture，未操作真实 Chrome、账号、网站或作品。

## 实现

- 普通编辑页从打开起固定预期 URL；所有定位、目录和账号读取前后都拒绝换稿或换作品。
- 初次读取仍允许正常加载；回读终点用 `evaluateAll` 一次获取某字段的匹配数和值，不等待元素、不重试超时。
- 保留公开 locator 的扩展选择器支持，以及 DOM 和 ProseMirror 正文读取。
- 先核对已加载账号，拒绝已经观察到的缺失/错误身份；原有服务端账号刷新放在终点字段检查前。目录状态确认也放在此刷新后。
- 最后比较正文，核对当前账号，再核对章号、标题、DOM 草稿状态和固定 URL。创建回读失败后原命令仍被消费，不重复创建或保存。
- 新建编辑页达到 ready 且确认实际 ID 后，固定作品和草稿 ID，允许已配置的同 ID 新建/已保存路由切换。每次填写或保存前也核对目标，防止已经切换的另一稿被下一次操作修改。

## 红绿验证

`red.log`：新增初始 6 个顶层测试中，正向兼容 2 项通过；旧实现的换稿拼接与字段变化误报造成 4 项失败。

`green-expanded.log`：14 个新增顶层测试全部通过；其中参数化场景合计 206 个，另有自包含回调与原段落契约检查。

`create-target-red.log`：额外 2 个顶层测试在旧实现失败，两平台均复现确认新建 ID 后换目标仍写入并成功返回另一 ID；无导航对照通过。

`create-target-green.log`：额外 5 个顶层测试、18 个参数组合通过，包括每次填写后的目标切换、保存后换目标、另一稿字节值保留、创建不重放、正常初次 ID 分配和同 ID 路由切换。

`driver-full.log`：最终完整 Chrome driver 137 项测试全部通过，0 失败、0 跳过。相对本轮开始共新增 19 个顶层测试、224 个参数组合及自包含回调契约检查。运行命令、计数与最终两文件 SHA-256 见 `validation.json`。

循环复查额外发现：若先确认目录、后刷新账号，刷新期间改变的目录状态仍可被旧结果覆盖。已改为先刷新账号，再确认目录，并加入两平台、三操作的反向回归。

第二轮复查还发现既存遗漏：新建 ID 确认后没有一直固定该 ID，普通 read 固定的只是调用时的 remote，无法识别更早发生的创建目标替换。已补创建目标绑定和动作前检查；红绿结果如上。

这些检查证明受测读取边界的失败策略和正常兼容性。逐字段与跨标签读取没有跨标签事务语义，不能承诺返回后页面永远不再变化；该验证也不等于真实网站验收。
