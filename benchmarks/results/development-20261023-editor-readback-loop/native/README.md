# Native 编辑页回读与创建身份回归

本轮修复普通编辑页（七猫、起点）回读期间换稿仍返回旧 ID 的问题，并在自主复查中修复创建期间已分配 ID 被替换、未开始填写时跳到另一稿仍继续填写的问题。

- 回读先保留正常加载，再从 Playwright locator 取得句柄，在同一次页面脚本中读取当前文档的账号、作品、草稿 ID、章号、标题、正文和 DOM 草稿状态。拒绝断连、换文档、字段不唯一、字段换节点、正文或身份变化；保留扩展 selector 引擎支持。
- guard 账号使用已加载页面的无等待读取。依赖完整目录判定草稿状态时，最后一次目录扫描也不能刷新 guard 来掩盖账号变化。guard 与编辑页属于分开的观察，不宣称跨页原子性。
- 新建稿在首写前绑定原空字段和文档；ID 尚未分配时继续检查原字段，首写分配后固定 ID，后续填写和保存不得改绑另一稿。正常按钮保存、原地自动保存、已有 ID 的新建 popup 保持通过。
- 独立复查发现输入类型检查返回后仍能换稿并把下一次 fill 发给旧稿，继续补上实际动作前的当前身份检查。fill/click/press/focus 绑定已经核对的 ElementHandle；段落输入每个动作及 insert_text 前都核对目标，焦点离开正文时不继续输入。
- 共享的 ProseMirror 序列化 JavaScript 与修复前逐字节一致，见 JSON 摘要中的哈希及比较结果。

红测证据：`red.log` 为修复前 7 个方法、65 个失败子场景；`create-red.log` 为首次创建复查 2 个方法、5 个失败子场景；`create-unallocated-red.log` 为未分配 ID 创建的两处复查反例；`pre-write-red.log` 为内部类型检查/保存标签读取后跳稿的 2 个方法、3 个失败子场景。

最终定向验证：`final-green.log` 123 项通过（20 个新增方法、72 个原模块方法及 31 个 preview/段落序列化方法），无失败、错误或跳过。`green.log` 和 `preview-neighbor.log` 是前一轮中间验证，不能与最终数字相加。最终文件哈希见 `validation-summary.json`。完整全量回归由主线程统一运行。

关键事件边界：空稿检查后跳稿时没有 fill/save；未分配 ID 时章号填入后跳稿，仅出现一次 `fill #chapter`；自动保存的第二次填入后 ID 改变，不再填正文；保存后 ID 改变时仅发生一次保存，不重发。

内部动作验证还覆盖类型检查后跳稿不再写标题、保存标签读取后跳稿不再点击保存；段落模式在 editable 检查、click、select-all、backspace、focus、insert_text、Enter 任一动作返回后目标改变，都停在下一个动作之前。

所有平台事件均为离线 fixture。实际快照脚本通过 Node 在合成 DOM 上执行；该结果不等于真实网站或真实账号验收。没有安装、发布或修改真实作品。
