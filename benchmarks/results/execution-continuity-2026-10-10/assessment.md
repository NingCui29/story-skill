# 执行证据与三轮连续写作开发验证

这轮补执行验证，保留已有写作方法，不再增加一套小说品质清单。新增自然请求案例、三轮六章准备与核验工具、复核引用检查；共享技能增加一句独立复核报告约束。原始材料在本机隔离目录，测试小说和包含宿主记忆读取的原始日志不提交仓库。本页是开发记录，不是文学质量认证。

## 改动与回归

- [原生规划](../../skill-execution/cases/native-plan.json)、[原生审稿](../../skill-execution/cases/native-review.json)：送入模型的任务不含技能名或路径；负例复用 `non-story`。
- [三轮六章](../../skill-execution/sequence_prepare.py)：从用户输入开始，依次规划并写1—2章、新会话续写3—4章并跨卷、再续5—6章及完本交付。核对同一书根和书ID、真实正式章节、已写正文保护、技能冻结、完整日志和全文合并。
- [复核引用检查](../../../scripts/execution_review.py)：绑定任务、轨迹、产物和技能哈希；自填声明不能证明独立审阅，后来的安装更新不能改变历史执行版本。退出码0只说明引用可追溯。
- [共享规则](../../../skills/story-skill/SKILL.md)：实际分派并收到意见后才能报告独立复核；未取得结果或没有分派能力时按当前会话自审报告。

实际运行 `python3.12 -B -m unittest discover -s tests -p 'test_execution*.py'`，首轮80项通过。随后与实现者分开的模型代码审查发现三处缺口：早轮原始日志与结果摘要未重验，相对工作目录名被误判技能注入，空白完本回读被当作产物。均修复并增加回归，以 `python3 -B -m unittest discover -s tests -p 'test_execution*.py'` 重跑，最终87项通过：现有机械验收15项、复核引用检查48项、三轮准备与核验24项。修复前代码和原始回执保留。三轮工具测试中使用真实 Book API 建立六章事务，但测试中的宿主轨迹是合成数据，不能当作模型实写。以下模型实测另行保存。

共享规则先在隔离安装树验证，再完整备份本机八个技能并更新；51个载荷逐文件核对，实际只变更 `story-skill/SKILL.md` 的这一句。保留安装树其余原有内容，并发中的宿主适配与许可变更未随本轮同步。staging与安装版的版本、帮助、隔离 `init/status` 验收通过，版本为0.6.15。验收曾误把 `init.created` 当布尔值两次；真实初始化成功，改按实际返回的路径、书名、类型、版本和章序核对，错误记录保留。

末次核对时，共享源码的宿主调用说明另有并发修改，本轮报告约束仍保留。当前源码、当时冻结源码和实际安装树分别记哈希，未将后来的宿主说明追写进冻结版或本次安装；本机51个载荷仍等于审阅过的stage副本。

## 三轮六章

本组提供冻结技能路径，与上面的自然请求分开。六章、两卷、每章800—1000字以及免附言、图片、封面和平台材料，均是原始任务明确约定的缩小范围。初始材料没有预写正文；后两轮仅以“继续”接同一书根，不传递此前聊天历史或验收答案。

三轮实际日志分别为89、102、114条事件，线程ID各不相同，真实进程均正常结束。每轮有3条非零命令，共9条，原始记录及恢复保留：包括采用头格式、未登记卷引用、脚本编码输入、计划尚未保存、写死字数断言、审查文件缺失、一次搜索无匹配及遗漏 `--chapter`。这些性质不同，不能合并成同一种错误，也不能称零错误执行。

| 本轮提交 | 1—2 | 3—4，跨卷 | 5—6，完本交付 |
| 实测字数 | 866、881 | 863、896 | 938、946 |
| 卷归属 | 第一卷 | 第3章第一卷、第4章第二卷 | 第二卷 |

同一书ID `2f79f2d9-a2f7-40f2-b132-05aa334abe7e`，最终revision25、last_chapter6；六章共5390字，口径为 `visible_nonspace_v2`，不计章名。原始创作输入和前轮正式章保持，51个冻结技能载荷未变；全文严格匹配六份正式导出的顺序拼接，仅以空行分隔，没有重复、候选或工作说明。新版核验器的 `finish` 完成，仍为 `needs_review`。`next_chapter=7` 只是工具序号，不构成续写授权。各轮实际读取用户记忆，因此不能称模型只收到任务、书稿和冻结技能。

主代理逐章全文读了六章及最终完本回读；另一位未参与writer生成的模型先增量读1—3、4、5，再连读全部六章，并对照创作输入、约定及十份采用规划。评阅知道维护背景，不是盲评、真人反馈或稳定质量比较；它未用writer自审和完本结论替代正文。实际阅读范围内未发现确定的必须修复矛盾：有限整理和维修产生室内录放条件，本人选段产生短场安排，挪凳重放及先行离场兑现不同需要，终章按时断电收妥、锁门和各自离开。是否再办仍待重新询问，没有把一次相聚扩大成无限参与。

可选不足保留：第3章末、第4章末及第5章第43行在行动已呈现人物变化后再次概括意义，可酌情收短。没有为追求强冲突修改有效的安静场景，也未将单次模型判断换算为读者认可。

第二、第三轮的审查和交付记录继续出现无足够分派及返回证据的独立复核声明。第三轮《完本回读》第50行也声称收到实际意见，复核引用工具将该声明保留为 `unverified`、返回2；这与正文及全文机械核对的结果分开。该复核记录最初为省略host字段的原始启动回执填了不同host，工具拒绝；失败保留，另记原始缺省值 `null`，没有向旧启动凭据补写字段。CLI身份在单独宿主记录中留存。
