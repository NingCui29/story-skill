# 项目状态与近期细纲

规划和正文写作共用本说明。命令调用 `story-codex/scripts/story.py`；所有书籍命令显式传入 `--book "<书目录绝对路径>"`，`R` 取最近一次 status 的 revision。

## 书名目录与开书落点

“一书一目录”的外层是书名目录，先确定它，再保存本书材料：

- 用户明确指定最终书目录时直接使用；已有作品按 `创作约定.md`、状态和现有文件确认书根，继续规划不重复嵌套一层同名目录。
- 新书只指定写作父目录或使用当前写作工作区时，在其中建立 `<书名>/`。采用已给出的书名；未定名时按本次设定拟一个有辨识度的暂定书名并记录其暂定状态。目录使用适合本机文件名的书名，必要时替换不合法字符并记录完整书名与实际路径。目标已存在先核对归属，不把同名的另一部作品当作本书继续；另开新书也不写进已有书根。
- `init --book "<父目录>/<书名>" --title "<完整书名>" --kind long|short` 中，`--book` 是最终作品根，不是父目录；`--title` 仅保存书名。调用后核对返回的 `created/title`、实际书目录及 `.story/state.sqlite3`，再创建 `创作约定.md`，写明书名、实际书根和本轮阶段。
- 约定、策划、设定、`01_大纲细纲/`、正文 `chapters/` 与状态 `.story/` 都在同一书根内。只创建本轮需要的文件；规划阶段不生成正文。交付给出可打开的实际书目录，不能只说“已开书”或只报告隐藏的状态库。

书名暂定后变更不等于已经迁移目录。旧书若曾直接落在父目录，先核对实际书根和本书文件范围；不能靠再建空书名文件夹或重跑 `init` 把迁移报为完成，不自行搬动其他作品或托管正文。

## 可读的大纲与细纲

长篇默认按以下层级保存，沿用用户已有的等效目录，不为统一名字搬动工程：

```text
01_大纲细纲/
├── 全书总纲.md
├── 第一卷 雨夜/
│   ├── 本卷大纲.md
│   ├── 第1章 雨中来客.md
│   └── 第2章 一封旧信.md
└── 99_历史版本/                 # 修改前的版本，按日期或版本归档
```

卷名、章名取本书实际规划；细纲一章一文件，正文另存 `chapters/`。全书总纲说明主要矛盾、人物走向、结局与分卷粗纲，并链接已有卷纲；本卷大纲说明本卷目标、关键转折及结束条件，并链接已有章细纲。只细化近期需要写的章节，不为目录生成空卷、空章；短篇规划可合为一份。

同一范围维护一个清晰的当前入口，文档头注明状态、更新时间和必要的来源。保留“候选／已采用／待定”等真实状态，整理或版本号较新不代表已获采用。旧版本放入 `99_历史版本/`，保留原文件名与相对关系；修改当前稿前保留其旧版。分批继续时补写相应卷、章文件，将重叠的前三章场面设计等内容并入各章，不再平铺多份范围交叠的候选稿；未决方案可留在对应章并说明分歧。

新建、普通修改或整理章细纲时，同章已有工具计划就核对目标、场景、停笔点、章名、卷名、篇幅及约束，在本次授权范围内同步已采用的规划；准备写作但尚无工具计划时据此建立。采用依据取当前要求或已有约定、任务记录，已明确采用无需重复确认；未决候选不写入或替换当前工具计划，冲突在当前入口注明。`context` 只返回工具计划，不读取可读细纲或判断采用状态；续写前定点核对当前章，两者不一致时先同步，再重新取得 context。

整理旧规划先备份并核对约定、任务记录及各版内容，确定每个范围当前读取哪份；不能判定时保留争议和来源，不自行批准候选。迁入时保留有效内容、来源和可追溯引用，更新失效链接；不改已发生的正文事实，不移动托管正文。规划整理不把尚未发生的安排写成事实卡。

## 状态卡与工具章计划

`template notes` 展示卡片结构。每张卡保存一个会影响后续的事实/人物状态/承诺，短而具体，带来源。少量全书硬限制用 `critical: true`；局部限制加 `scope: "volume:v1"（也可 arc/line/entity:ID）`，全局用 `global`；简单伏笔用 `kind: hook` 与 `due`；人物/地点设稳定 id 和 tags。作者习惯只有用户明确要求记住时才保存为 preference，不自动积累画像。

局部硬限制同样设 `critical: true`。按 scope 自动召回时，`volume:v1` 对应 `plan.volume: "v1"`，arc、line 同理；`entity:ID` 要求该 ID 在 `plan.entities` 中，关联 ID 须有相应世界记录。`volume_dir` 只决定展示目录，不关联 scope。尚无这些关联或仅使用具名卷目录时，把本章硬限制的卡片 ID 显式加入 `plan.requires`；取回 context 后核对它们确实位于 `required_cards`，缺失时先修正关联或 requires 再起草。

`notes --input "<卡片.json>" --expect R` 更新卡片，R 取 status。新卡须提供 `id/text/source`；已有卡按 ID 合并，只覆盖显式字段，省略的 kind、critical、scope、tags、due 等沿用原值。清除到期章用 `due: null`，清空标签用 `tags: []`；解除硬限制须明确写 `critical: false`，改为全局范围用 `scope: "global"`。`kind` 仅支持 fact、character、world、hook、preference、contract。正文提交的 `changes` 仍需完整卡片对象，每项另带 `quote` 精确原句，`source` 不能替代它。不要把整份大纲拆成无用卡片。

人物卡只存会影响下一步的已知/误信/未知及获知依据；作者掌握的谜底不等于人物知道。时间地点、物件归属、伤势、关系变化另用短事实卡；承诺写明触发条件或到期章。章末更新变化项，续写前核对这些状态和上章具体后果；有冲突定点补读，不把全书重新装入上下文。

`template plan` 展示计划结构；用 `plan --chapter N --input "<计划.json>" --expect R` 保存。保留用户原始要求在 `constraints`；填写目标、人物选择导致的场景变化、停笔点、字数范围、`requires`（所需卡片 id；结构化人物放 entities，不混填世界记录 id）及 tags。不要以“每场几个事件”“对白百分比”代替戏剧功能。未知事实不写成已确定设定。

章计划填写 `title`（章节名称）和 `volume_dir`（完整分卷目录名，格式为 `第X卷 卷名`，例如 `第一卷 雨夜`），导出为 `chapters/第一卷 雨夜/第1章 雨中来客.md`。`title` 优先用于文件名；未填时从草稿首行 Markdown H1 标题提取，并去掉已有的“第X章”前缀（支持中文或阿拉伯数字），再由实际章号生成文件名。新写章须有可用章名；无标题草稿应先补章名或计划 `title`。导入的无标题基线可用章名 `正文`，但仍须明确所属卷名：可在 `adopt` 传入 `--volume-dir "第一卷 雨夜"`（替换为本书实际卷名），或从已保存的该章计划取得完整目录；仅指定导入卷名无需新建章计划。

`volume_dir` 是一级目录名，必须包含卷序号、一个空格和真实卷名，不能包含路径分隔符；同卷保持同一个完整目录名。显式 `volume_dir` 优先；未填写但已有 `volume` 时，可沿用该稳定 ID 已保存且带卷名的目录，或采用已符合 `第X卷 卷名` 格式的世界卷记录 `title`。工具保存所选目录供同卷后续章节沿用；同一个 `volume` ID 一旦绑定目录，后续填写不同目录会被拒绝，不能借单章计划静默改掉整卷归属。若这些来源都没有完整卷名，先核对已有分卷规划；尚未命名时，依据已授权的本卷内容拟定卷名后再提交。不要用仅有卷号或内部 ID 的目录代替卷名。短篇与单卷作品也须明确首卷名称。`volume` 仍是关联世界状态的稳定 ID，展示目录用 `volume_dir` 指定。显式目录格式不完整会报 `invalid_input`；未提供或推导来源没有卷名会报 `volume_title_missing`，`lint` 和 `prepare` 会在提交前检查章名及卷名是否可用，补充缺失名称后重试。

把有作用的阻力、应对和代价写进现有 `beats.choice` / `beats.change` 描述，`goal` 说明本章要争取的结果与阅读期待；不另造“冲突分”“爽点数”字段。只记录能帮助写下一场的设计，不要求作者填写额外表格。

多卷、多视角和长期连载需要结构化世界资料时补读 [超长篇状态](../../story-codex-write/references/long-form.md)。近期细纲范围按本次授权和写作需要确定；未指定范围时，默认细化近期3—5章。
