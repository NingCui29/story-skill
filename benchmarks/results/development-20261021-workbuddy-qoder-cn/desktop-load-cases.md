# WorkBuddy AI／Qoder CN 桌面加载与调用验收

每款应用使用独立的新测试会话，在原生技能列表确认八个入口，再逐项明确选择技能并发送对应问题。以下是验收方案，不是执行成功记录；实际状态见 `local-installation.json`。

统一要求：只做安装验收与规则问答。通过文件读取工具读取本宿主实际安装目录下本技能的 `SKILL.md`，以及共享入口的共同约束；同一会话已读内容可复用。不运行脚本、不创建或修改文件、不联网、不生图、不操作平台。题目中的作品与动作均是假设。每项回答控制在 120 字内，附一处支持判断的短引文和实际读取路径。

| 选择的技能 | 问题 | 核对要点 |
|---|---|---|
| `story-skill` | 已有正文的钩子改稿，与尚未写出的钩子方案设计，分别走哪个流程？共享脚本路径如何确定？ | review／plan 分流；相对实际读取的技能位置定位，不依赖终端当前目录或另一宿主。 |
| `story-skill-plan` | 用户仅要求比较三个书名，是否随即初始化书库、修改正式名称并制作封面？ | 不自动执行这三步，只处理命名比较。 |
| `story-skill-write` | 长篇完整章候选与短篇完整章，默认分别需要哪些附言和图片？长篇配图比例是多少？ | 按已安装规则答长篇附言与 9:16 配图；短篇默认不写、不存、不展示附言及配图；尊重任务明确例外。 |
| `story-skill-analyze` | 定稿分析报告需要修订，能否覆盖原报告？数据库中的 report_path 是否足以证明已交付？ | 另存修订稿、保留原记录；核对导出与真实文件。 |
| `story-skill-review` | 仅排版时发现错字和不合项目格式的标点，能否顺手修正？怎样证明改动范围正确？ | 不越权修字词标点；逐处 Unicode 码点差异只涉及获准的换行、空行、缩进。 |
| `story-skill-research` | 只读到收藏榜前 20 名，能否称为全榜销量排名？需要记录哪些覆盖信息？ | 区分收藏与销量，不扩大覆盖；记录筛选、排序、分页、截取、去重和缺失范围。 |
| `story-skill-cover` | 仅修改署名时是否同时改变人物、画风和尺寸？缺图像工具可以把提示词称为已生成封面吗？ | 保留未授权元素和尺寸；提示词不等于实际成图。 |
| `story-skill-publish` | 用户副本文字匹配冻结稿，能否报告平台已保存？ZIP 技术核验通过，能否称投稿材料齐全？ | 用户副本不等于独立远端回读；技术包与交接材料完整性分开判断。 |

每项分别保留以下证据，区分桌面原生调用与独立载荷回读：

1. 原生技能调用标签或记录，名称与该项一致。
2. 若客户端可展示，展开真实技能载荷或文件读取记录，指向本次安装的 `~/.workbuddy-ai/skills/…` 或 `~/.qoder-cn/skills/…`，并有共享规则读取证据。
3. 输出命中本项判断，短引文能与实际安装文件对应。
4. 没有执行题目假设中的写入或外部动作。

原生选择、完整消息实际发送与对应的正确答复，合起来核对桌面调用。仅列出技能、回答正确或模型自称加载，均不足以单独证明真实调用。实际载荷来源与新文件读取单列核验：客户端可直接注入技能，未展示读取时记为未核，不将模型自述当作工具记录。题目中要求的新读取若未完成，也如实保留该偏离。权限、登录或可观察性阻断须如实记录，不能用解析函数检查替代桌面验收。
