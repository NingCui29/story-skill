# 2026-09-19 审稿身份与首次提交分流

本轮区分未托管文件、尚未提交的新章与已提交章节，修正规则中的三处衔接缺口。仅修改公共规则、审稿入口及说明文档，运行程序未改。变更未发布，未更新本机安装。

## 发现与修改

1. 原审稿入口以“工具托管的新稿”进入旧章替换或历史分支，没有覆盖下一新章的首次提交。现在明确：只审或只改草稿时不提交；已有提交授权时，核对计划和状态后走正常章流程，执行首次提交。
2. 未托管文件的例外原本出现在工程步骤之后，前文又要求剧情修改同步 `plan` 和 `context`。现在先识别稿件身份，独立文件按授权直接修改，不补建书库与章计划。
3. 公共规则中的“单文件审稿不查询状态”未限定身份。现在只豁免未托管文件；正式章节即使只有一份，也核对提交身份和外改状态。

已提交最新章的替换条件、外改对账及旧章/特殊最新章的历史分支限制保留。具体前后文本见 `snapshots/`；这是范围与流程修正，没有新增文学评分或写作禁令。

## 运行时约束核对

主代理用 Python 3.12.14 建立一个有已采用计划、尚无已提交正文的临时工程。在独立副本上故意尝试两条不适用的修订路径：替换最新章返回 `chapter_order`，创建历史分支返回 `chapter_missing`；状态仍为 revision 1、last_chapter 0，正常上下文模式为 `next`。[原始结果](runtime-contract.json)

这是对既有运行时约束的直接核对，**不是修改前生成代理的失败记录**，也不是新修复的程序漏洞。运行时已经拒绝错误路径，本轮让技能先选择正确路径，避免多余报错和恢复。准备脚本的两次接口使用错误及纠正已在原始结果中单独注明，不归因于 Story Codex。

## 首版候选的两项独立用法试用

两个新代理分别读取同一份首版候选冻结技能，在隔离目录完成以下请求，不读取另一任务、规则审查意见或预期处理路径：

- [新章草稿](inputs/pending-request.md)：细纲与工具计划已采用，第 1 章尚未提交；删减重复焦急描写，保留事件与停笔点，完成审查、首次提交和导出。
- [独立文件](inputs/unmanaged-request.md)：允许调整结尾，新增得知未吃晚饭、分饼后离开的动作；保留三个既有事实，保留原文件，另存完整修改稿。

两者使用同一份合成[原稿](inputs/original-draft.md)，其中新章任务另有已采用的[工具计划](inputs/plan.json)及可读细纲。两项授权不同，不作稿件质量或耗时对照。评估要求额外保存交付说明与过程记录，这些留档不是产品的常规额外要求。

独立文件试用保留了[原文](unmanaged/original.md)，另存[修改稿](unmanaged/revised.md)。修鞋费已付、儿子来接和还伞约定均保留，新结尾按授权展开；目录未出现书库或章计划。[代理过程记录](unmanaged/process.json)

新章试用完成[262 字正文](pending/chapter.md)，根据 `last_chapter=0` 和 `context mode=next` 执行普通首次提交，未使用替换、对账或历史分支；最终 revision 为 2，导出完整。保留修鞋费、接人和还伞事实，也保留原定停笔点。[代理过程记录](pending/process.json)记录了一次模板查询误加 `--book` 的失败及纠正，没有将它隐去。记录中的“人工自审”实际为代理读稿自审，本轮没有真人评阅。

## 最终授权边界修订

独立规则复核指出：首版“不提交”的句子仍只限定未提交新章，已提交章节的候选改稿也需保护。最终把权限边界提升到所有改稿之前：只审或只改草稿，不更新已采用计划和正文状态，不提交、替换、写入式对账或历史发布；规划变化随草稿记录为候选。已授权采用的剧情调整才同步正式计划，不重复询问已有授权。

独立复核确认这项冲突已消除。前两份输出仍属于首版候选，不追认为最终规则生成。随后以最终冻结规则追加[已提交章候选改稿](inputs/draft-only-request.md)试用，使用前一任务的已提交工程副本，要求另存不同结尾，不替换当前正文。[修订版本与原因](final-candidate.json)

该试用交付[301 字候选稿](draft-only/candidate.md)，停在分饼等候、儿子尚未到来。代理记录了候选规划及状态差异，没有将它们写入正式工程。主代理独立复算原有 **12 个文件** 的哈希，数据库、现行正文、已采用细纲、约定及原审查记录全部未变。[过程记录](draft-only/process.json) · [独立文件核对](draft-only/verification.json)

## 核验与边界

[完整核验记录](validation.json)区分首版候选两项试用、最终候选一项试用与静态规则复核；实际入口、已读参考和文件哈希保存在[快照清单](snapshots/manifest.json)。[最终技能格式验证](skill-validation.json)只检验入口格式，不代替语义检查或任务完成。原始交付说明以 `.md.txt` 保存，保留临时路径原样；可读产物由本记录中的归档链接提供。

本轮没有旧规则生成对照、重复采样、人类读者或文学提升结论。纯审稿、旧章与外改的完整修订本轮不再生成一遍，保留规则并作静态核对。运行程序哈希与此前 551 项通过、7 项跳过的回归证据一致，未重跑全量测试。未改真实作品、已安装技能或旧试用记录。
