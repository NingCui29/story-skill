# 正常章幅三章候选正文比较

本轮已完成两臂各三章、共六次真实 Codex CLI 生成调用及两份独立匿名模型评阅。两份评阅整体均轻微偏好本地稿，第三章分别偏好上游和判为持平；这一小样本不证明稳定文学优势。工程与执行结果见 [执行记录](p0-writing-execution.json)，评阅范围与解盲结果见 [评阅记录](p0-writing-reviews.json)，评测工具的回归与修复见 [工具验证](p0-tool-verification.json)。

## 版本与条件

上游固定为 Oh Story v0.9.1、提交 `70d1cf426f8cbe3d374e2b06e4c2cbdbd986da06`。从固定提交归档提取技能，438个技能文件的实际字节均与该提交 GitHub tree 中的 Git blob 哈希一致；未执行安装器或更新宿主插件。

本地使用2026年10月27日冻结的0.6.27工作树写作规则，包含本轮新增的可选场景示例。每臂完整技能快照及协议 SHA-256 保存在执行记录，后续0.6.28工具和工作台改动另做工程验收，不追认为本轮已执行最终版本的全部功能。

两臂使用同一原创合成输入与三阶段路线：开篇委托、安静日常与关系积累、进入新阶段后的争议处理及有限兑现。每章要求2400—2800个 `visible_nonspace_v2` 字符，含标点、不计首行章名。每阶段独立新会话，只生成指定候选章，不创建正式书库、采用、配图或发布；也不部署上游项目 hooks 或验证宿主自动发现。

六次调用均请求 `gpt-6.1-sol`、`ultra`，CLI为 `0.164.0-alpha.11.1`，使用 `workspace-write`、忽略用户配置但保留系统沙箱及规则。每阶段一次模型调用，允许该次调用内按原任务自查修改；没有另起生成调用选择更好的稿件。服务端实际模型修订、随机种子和内部重写次数未认证。

## 工具循环复核

新增 `paired_sequence.py` 复用既有快照、启动记录、轨迹和字符计数能力，支持不同技能入口的同输入序列。程序结果始终与文学判断分开。新增测试22项在Python 3.12与3.9.6下通过，既有改稿试验相关测试35项通过；测试中的合成轨迹不充当上述真实调用。

独立复核实际发现：进程回执原先只检查退出码和超时，会忽略回执中显式写错的臂、阶段及任务哈希。修后存在的绑定字段逐项核对，独立原复现已确认矛盾会阻止推进；旧简式回执保持绑定未认证，不回填原记录。另补齐布尔退出码、输入文件路径重叠、原稿独立归档和未完成检查的非零退出码保护。

## 匿名评阅与结论边界

六份原稿用随机的A、B标签组成同一匿名包。两组沿各自原稿连续，映射不提供给评阅者；材料只含共同创作输入、六章正文和中立评阅问题，不含技能、生成自评或既有意见。独立 CLI 与全新无父历史代理分别评阅，双方完成后才汇总与解盲：A为本地稿，B为上游稿。

| 范围 | 独立 CLI 阅读观察 | 全新代理阅读观察 |
|---|---|---|
| 第1章 | 略偏本地，客户反馈真正改变专业选择 | 略偏本地，客户记忆影响交付与观看方式 |
| 第2章 | 略偏本地，所得被人物体验，安静段有持续作用 | 略偏本地，生活回报与合作关系有积累 |
| 第3章 | 略偏上游，现场不足变成具体的后续工作条件 | 持平，本地的生活记忆与上游的后续安排各有作用 |
| 整体 | 轻微偏好本地 | 轻微偏好本地 |

两份评阅均保留上游在双向协商、执行细节及后续交付条件上的优点，也指出本地部分说明仍偏密，不能把偏好写成“本地各方面更好”。CLI评阅指出上游一处把四个汉字误写成五个字的局部笔误；另一评阅没有列明确硬伤，保留一处水痕归属的跨章歧义，不能升级为确定矛盾。这些意见各自保留，没有按多数票消除分歧，也没有为了改善结果修改原稿或技巧规则。

CLI评阅为独立新会话，退出0、无超时，保存启动、原生轨迹和报告。其六章全文读取输出未见截断；112处结构化引文与指定原文行段精确匹配。全新代理的分派与返回保留在父会话，报告17处结构化引文同样匹配。两处匿名目录的输入哈希均未变；引文可定位不证明解释必然正确。执行记录生成时的“待评阅”状态保留为历史记录，当前评阅结果以上述独立记录为准。

本轮仅支持一个原创合成题的三章开发观察。它不是独立留出、真人试读、全文完本验证或长期文学优势证据；两份模型意见也不是两组真人样本。两名评阅者首次阅读顺序均为A组三章后B组三章，随后定点回读，没有交换呈现顺序复测。本轮比较的是两套不同技能，不能把偏好归因于某一条新增规则或示例。候选正文执行不证明正式采用及平台保存成功，程序检查通过不证明爽点、追更吸引力或审查判断成立。
