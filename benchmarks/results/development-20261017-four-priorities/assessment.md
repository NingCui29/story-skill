# 2026-10-17 四项方法整合与验证

本轮依次完善题材写法卡、文风统一裁决、兑现归属和写前简报，基于现有未发布开发源码实现，保留既有工作区修改。方法参考固定在 oh-story-claudecode 的 [0.8.6／86a8000](https://github.com/zenstory-ai/oh-story-claudecode/tree/86a8000cc89048e441b906b3389f1f847aeb20cd)，具体文字、案例与工具为本项目独立实现。实际检查与来源指纹见 [verification.json](verification.json)。

## 已落地能力

1. **题材写法卡。** 在现有 `drama.md` 中提供都市关系与成长、经营与职业、科幻与灾变、民俗与幻想、悬疑与推理、温暖日常六类卡。先读取选用说明，再按本场主要体验取主卡；确有交汇才补辅卡相关段。卡片不替代本书设定，也不作为平台规则、固定事件序列或市场结论。
2. **文风统一裁决。** 写作、改稿与审稿按表达维度使用当前明确要求、本书有效约定、已明确适用偏好、参考方法和通用默认的顺序。沿现有交接传递实际取舍；泛指“更自然”不撤销具体约定，表达选择不擅改事实、知情、叙述权限或授权范围。
3. **兑现归属。** 在既有高潮与阶段兑现检查中，对照实际承诺核对影响结果、作出取舍、承担后果和获得回报的人物。合作、群像、共享与有依据的主动让渡可以成立，不能把检查变成主角必须独占功劳或获胜。
4. **可选写前简报。** `writing-brief --book <书根> --chapter N` 只读组装已绑定的下一新章；可通过书根内相对路径提供 `--request-file` 和 `--style-file`。完整返回计划、采用细纲、必要状态、上章衔接及请求／文风来源和哈希。未提供来源明确列出，语义裁决保持待核；不猜题材、采用方案、提交正文或生成封面。

简报默认预算 24,000 UTF-8 字节，默认省略可选卡并报告数量；必要内容超限则报告完整最小预算，不截断。未绑定、绑定漂移、导出冲突与不可读来源继续阻断该可选组装方式；原有候选、普通 context 和已提交章修订流程不因它改变。

## 保留的机制

与本轮开始快照比较，历史依赖与修订模块、世界状态模块、存储模块及深读原文复核规则逐字节不变；`Book.commit`、`prepare` 和 `lint` 的函数语法树未变。正式正文、状态、审查回执与导出队列的事务、版本与绑定要求继续由原流程执行。书根沿用现有规范化语义，简报明确返回规范化书根与书籍 ID；书内来源拒绝链接不等于拒绝原始书根所有祖先别名。

## 独立审查与修复

独立代码审查实际复现并推动修复了三项问题：Windows 读取目录复用写入 guard、最小预算先返回内部 context 大小、读取途中父目录换绑使显示路径失真。修后复验分别核对无 guard 的 Windows 分支替身、按完整最小预算一次重试、父目录换绑拒绝，以及真实 SQLite WAL 并发下的完整旧／新快照。原始失败和修后证据分别保留。Windows 未运行原生环境；只读保证不含系统访问时间和 SQLite 临时 WAL 生命周期。

独立路由审查发现三种短篇路径漏计可选简报，已补齐相应分支与组合并复验。六张卡的标题切片独立，索引只读 H2 正文；新增锚点核对通过。212 个登记变体均在预算内，与本轮快照相比所有既有预算阈值不变。长篇基础路径从 37,385 增至 38,449 去空白字符，短故事入口短篇从 52,389 增至 53,558；新增能力的实际指令开销保留，不称作节省。
