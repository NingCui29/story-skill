# 正文中过度使用账本与手续：开发评测材料

本目录用于检验写作指导是否把内部事实核对误写成小说中的固定解法。这里的“账本与手续”泛指账目、清单、合同、回执、盖章、监控记录、逐项核验等叙事动作；它们在具体故事中可能必要，也可能遮住人物的选择。评阅依据是**情节功能与阅读感受**，不统计禁词、不规定出现次数或篇幅比例。

本目录只有合成任务和评阅办法，尚无生成结果，也不证明任何技能版本的文学质量已改善。三个任务均为开发材料；如果据此修改技能，后续要另取未参与调试的题目作留出检查。

| 任务 | 文类与检验点 |
| --- | --- |
| [01 现代亲情](tasks/01-modern-family.md) | 金额须连续，但人物关系的变化无需靠对账完成。 |
| [02 古代商铺](tasks/02-period-shop.md) | 契书内容确实改变局势；检查是否保留必要证据，同时写出人物代价。 |
| [03 现实悬疑](tasks/03-suspense-followup.md) | 前章的记录核验已经结束；检查新场景是否仍重复同一种文书解法。 |

## 最小对照步骤

1. 在生成前登记基线、候选的不可变技能快照或提交号、模型与可控设置、题目摘要、输出长度口径，以及每题预定的生成次数。建议每条件每题至少一次，能够重复则事先定次数；不能因稿子不合意而选优或重写。
2. 每次使用独立上下文，只给生成者该条件需要的技能指令和**一份**任务文件。不要给本页、评阅项、另一版本的稿件或上次反馈。两个条件使用同一模型、相同可控设置与相同题目；保存原始输出和实际字符数。
3. 给稿件随机编号，隐藏版本映射，交给未参与生成和调试的评阅者。先逐篇记录阅读反应与原文位置，再比较两稿。模型评阅和人类评阅读者分别标注，不能互相冒充。
4. 解盲后按题报告“候选较好／基线较好／相近／无法判断”、事实错误、任务遵循和分歧；不要把三题胜率写成稳定文学增益。若看过结果后又修改规则，这轮只算开发反馈。

## 评阅记录

每篇至少回答以下问题，并指向具体句段；不能只给总体印象或计算“手续词”出现频次：

- 人物本场想要什么？谁或什么阻碍？哪个行动或取舍实际改变了局面、关系或读者所知？若只有“查完就赢”，指出其依赖的原文位置。
- 稿中每处账目、凭据、记录或核查过程承担什么作用：构成必要证据、表现人物／氛围，还是重复交代已知信息？删去或压缩会损失什么？允许它是场景的核心，尤其是第 02 题。
- 阅读兴趣在哪里上升、下降，或开始想跳读？人物结果是否从行动和对方回应生出，还是只由文书盖章、数字算清后宣布？
- 既定事实和知情边界是否准确？有没有为了避开手续而省略关键因果、换成巧合、空泛抒情，或虚构额外法规／物证？这些是独立缺陷，不得因“文书少”而忽略。
- 本题有无适合安静停顿、温情或必要专业过程的段落？不要把所有场景都强迫改成争吵、打脸或反转。

可以把“手续必要性”“人物选择与回应”“读者兴趣”和“事实连续性”作为并列观察项，但不要加权合成伪精确总分。按题目目标判断第 02 题中的契书是否写得足够清楚，也按同一原则判断第 01、03 题中的非必要核查是否挤掉了人物戏。这里不安排自动判定或关键词门槛；程序最多辅助核对字数、文件完整性和匿名编号。
