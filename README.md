# Story Codex

Story Codex 是一套面向 Codex 的中文小说技能。你可以从一部参考作品开始拆解写法，也可以直接开一本新书；之后按卷规划、逐章写作、审稿和续写。它把可读稿件与写作进度保存在书目录中，方便换会话接着做。

**当前已发布版本：**macOS／Linux 使用 v0.5.9；Windows 因已知导出问题暂用 v0.4.0。本机已安装技能不会随仓库修改或 GitHub 发布自动更新。[安装指引](INSTALL.md) · [v0.5.9 变化与验证](docs/releases/v0.5.9.md)

**源码待发布变更：**短篇全文合并、旧短篇补章与合法全文文件名、完本封面联动，以及全部正式总纲的平台分类要求已加入当前工作区，尚未包含在 v0.5.9 安装包中。下文对应段落说明源码行为；按当前安装指引升级仍获得已发布的 v0.5.9。

[安装与升级](#安装与升级) · [拆书怎么用](#拆书怎么用) · [从拆书开始开新书](#从拆书开始新起一本书) · [文件目录](#文件放在哪里) · [文档导航](docs/README.md)

## 安装与升级

在 Codex 对话框发送：

```text
$skill-installer 按 https://github.com/NingCui29/story-skill/blob/main/INSTALL.md 安装或升级 Story Codex
```

Codex 会依照 [INSTALL.md](INSTALL.md) 安装或升级同一版本的七个技能，并核对结果。已有安装会先核对版本与本地修改；需要安装到指定项目时，把项目路径写在这条请求中。安装后在下一条消息点名技能，未显示时重启 Codex。

运行时需要 Python 3.10 或更新版本。只克隆仓库、下载单个 `SKILL.md` 或取得 npm 包，不等于安装了整套技能。升级技能不会自动移动小说文件或重新导入已有书库。

## 选择入口

不确定该用哪个技能时，用 `$story-codex` 直接描述目标；跨“拆书 → 开书 → 写作”的任务也从这里开始。任务明确时可以直接使用专用入口。

| 目标 | 入口 |
|---|---|
| 不确定入口，或要串起拆书、规划与写作 | `$story-codex` |
| 点评、完整拆书、修订或续跑分析 | `$story-codex-analyze` |
| 开书、设定、大纲细纲、接入已有作品 | `$story-codex-plan` |
| 写正文或续写章节 | `$story-codex-write` |
| 审稿、修改、去 AI 味、处理外部改稿 | `$story-codex-review` |
| 查询榜单、题材和写作资料 | `$story-codex-research` |
| 制作或修改小说封面 | `$story-codex-cover` |

规划、正文、分析和审稿各有自己的范围。只要求规划时，不会因为说“继续”就自动开始写正文；已有书的正文任务则沿实际断点继续。[七个技能与职责](docs/目录结构.md#仓库按功能分配技能)

## 拆书怎么用

拆书关注原文中的具体选择、因果和表达：开篇怎样建立期待，人物如何在阻力下行动，信息与情绪如何逐步变化。结论要能回到原文；提炼借鉴方法时，还要写清成立条件与失效风险。

只想点评开篇或短文，可以直接给原文和问题：

```text
$story-codex-analyze 分析我贴出的开篇。
重点看读者会期待什么、人物选择是否有吸引力、哪些地方解释过多。
请用原文说明判断，直接回复。
```

需要跨轮保存进度、完整拆解一部作品时，提供可读取的原文文件：

```text
$story-codex-analyze 完整深读 <原文文件绝对路径>。
分析保存到 <写作父目录>/作品分析/<参考书名>。
先核对原文范围与章节目录，再逐段记录证据。
说明人物选择、冲突升级、信息安排和情绪兑现如何成立，
最后汇总可迁移的方法、适用条件与风险。
已有进度从原分析目录继续。
```

中断后提供分析目录，说“继续这本书尚未完成的拆解”即可沿断点处理。原文只有预览或部分章节时，报告只评价实际取得的范围；导入的片段全部分析完，不等于已经核实全书完整。已定稿报告需要修订时保留原件，另存修订稿。[深读与修订说明](docs/作品深读与评估.md)

## 从拆书开始，新起一本书

这是一条完整的规划请求。参考作品的分析与原创新书分开保存；借鉴的是写法机制，人物、关系、核心事件和解决方式要重新设计。

```text
$story-codex 我想从拆书开始，创作一本新的中文长篇。
参考原文：<原文文件绝对路径>
写作父目录：<新书保存位置>
新书定位：<题材、目标读者、预计篇幅；未确定可注明待定>

先核对参考原文的实际范围，完成有证据的分析，
保存到“作品分析/<参考书名>”。
提炼可迁移的方法、适用条件和风险；不要沿用参考书的独特剧情。

确定正式或暂定书名，在写作父目录下建立独立书名目录。
保存“创作约定.md”；在“00_项目策划/”保存开书策划、
“参考方法与原创重建.md”和需要独立保存的设定。
方法文档写清来源范围、在新书中的具体改造，以及承接它的大纲位置。
在“01_大纲细纲/”完成全书总纲、分卷粗纲、首卷大纲
和前三章细纲；卷目录带卷名，章细纲一章一个文件。
最后列出实际文件位置、已完成范围和下一步。

本轮只完成拆书与原创规划，不写正文。
```

`00_项目策划/` 是新书独立策划文件的默认落点。已在书根或其他等效目录保存策划文件的项目继续沿用原位置，不为统一名称搬迁。只研究参考书时，到分析报告即可结束；已有原创构想时，也可以跳过拆书直接开书。[目录规范](docs/目录结构.md)

## 从开书到续写

直接开书可这样说：

```text
$story-codex-plan 在 <写作父目录> 开一本现实悬疑长篇《雾港来信》。
先保存创作约定、人物与核心设定、全书走向和分卷粗纲，
再完成首卷大纲与前三章细纲。暂时不要写正文。
```

只给写作父目录时，会在其中建立书名子目录；已经指定最终书目录或继续旧书时沿用原位置。长篇先明确全书走向和分卷，再细化近期章节，不为填目录预建空章。候选和已采用设定须分清。[开书与规划说明](docs/中文小说上手.md#开一本长篇)

当前源码新增要求：每本小说的全书总纲（短篇可用等效规划）都写明长篇／短篇、目标平台、该平台的分类栏目与拟选或已确认标签，并附本书内容依据和核对来源。多个目标平台分别列出，不混用栏目或上限。面向番茄时，长篇记录阅读标签和内容标签；短篇记录作品分类的主分类、情节、角色、情绪、背景，按[截图可见选项](skills/story-codex-plan/references/fanqie-tags.md)选择。其他平台按其当前页面核对；无法核实的选项注明待核对，不自造平台标签。[大纲字段与状态规则](skills/story-codex/references/project-state.md#大纲中的作品类型与平台分类)

准备写正文时，指向已采用的细纲和实际书目录：

```text
$story-codex-write 按 <书目录绝对路径> 的已采用细纲写第1章。
先核对创作约定、章计划和前文状态。
正文2200—2800字，含标点、不计标题。
完成审查，保存正文与状态，并留下下一断点。
```

之后可以说“继续下一章”，也可以指定连续完成的章节范围。正式章节每章独立保存；写前核对本章细纲和工具章计划，二者不一致时先同步。[开书与续写说明](docs/中文小说上手.md#开一本长篇) · [超长篇实操](docs/超长篇实操.md)

当前源码的短篇完本流程：最终章完成并导出后，运行 `assemble-short --book "<书目录>" --final-chapter N`，在书根生成 `<书名>.txt`，按顺序包含完整书名和全部章节，逐章文件保留。特殊或过长书名会得到合法文件名，按 `init`／`status` 的 `short_assembly_path` 和合并回执核对实际路径。旧短篇接入后须用 `adopt-backfill` 补齐真实原章再合并，缺原文时说明缺口。已合并的全文在正式修订或新增章节后随导出刷新，交付前核对全文状态及导出回执；同步成功不表示情节已经完结，仍须核对实际结局和全部章节。完本交付还包含实际封面图片。[完整短篇流程](docs/中文小说上手.md#写完整短篇)

每次明确要求完本交付，还会核对现行总纲或等效规划的篇幅类型、目标平台、平台原生分类、终稿内容依据、来源日期及拟选／已确认／待核对状态；缺漏或不符时保留旧版并按 [分类规则](skills/story-codex/references/project-state.md#大纲中的作品类型与平台分类) 补齐，不静默改动平台已确认值。修订旧短篇后要求完整成品，即使此前尚未合并，也会完成首次全文、实际封面和总纲分类交付。普通单章修订只核对已有全文同步；纯审稿或候选稿不自动生成首次成品，也不每章重复查平台。

需要审稿时，说明是只要问题清单，还是要直接修改：

```text
$story-codex-review 审查 <书目录绝对路径> 的第1章。
核对人物认知、因果、对白和重复解释；先列问题与修改建议。
```

换会话继续时给出书目录；如果手动修改了导出的正文，也说明要以哪份稿为依据。早期章节改动可能影响后文，修订时要沿关联内容复核。[审稿与恢复](docs/recovery.md)

## 先试写一段

v0.5.6 支持不建书库的独立片段试写：

```text
$story-codex-write 写一段约500个汉字的现代生活小说片段。
一位退休教师偶遇成年后的学生，两人各有不愿被看穿的窘迫。
先试试轻快的叙述声音，只交这一段正文。
```

独立试写后说“继续”，仍沿用片段任务。已有书若只想先看下一章候选稿，可明确说“只保存草稿，暂不提交”；采用后再进入正式章节流程。[独立试写记录](benchmarks/results/standalone-writing-2026-09-19/README.md)

## 文件放在哪里

**一书一目录，参考分析、策划、大纲细纲与正文分开。** 下图展示各阶段完成后的布局；只做规划时不会提前生成 `chapters/` 的空章。

```text
小说/
├── 作品分析/
│   └── 参考书名/
│       └── .story/analysis/来源ID/report.md
└── 雾港来信/
    ├── 创作约定.md
    ├── 00_项目策划/
    │   ├── 开书策划.md
    │   ├── 参考方法与原创重建.md
    │   └── 设定.md                 # 需要独立设定文件时
    ├── 01_大纲细纲/
    │   ├── 全书总纲.md
    │   └── 第一卷 迟到的信/
    │       ├── 本卷大纲.md
    │       └── 第1章 雨中来客.md   # 细纲
    ├── chapters/
    │   └── 第一卷 迟到的信/
    │       └── 第1章 雨中来客.md   # 正文
    └── .story/                     # 状态、草稿与恢复资料
```

卷目录固定为 `第X卷 卷名`，包括短篇和单卷作品；每章文件固定为 `第N章 章节名称.md`，N 是不补零的阿拉伯数字。细纲与正文可以同名，但位于不同目录。旧规划保留在 `01_大纲细纲/99_历史版本/`，当前范围只维护一个清楚的入口。[完整目录规则](docs/目录结构.md)

新写正文虽然使用 `.md` 文件名，内容只用纯文本章标题和自然段，不加 Markdown 排版标记；旧章不会自动转换。已有的旧版目录与数字章文件继续按记录的实际路径读取，不自动批量搬迁。`.story/` 是书籍状态与恢复资料；备份时复制整个书目录，只复制 `chapters/` 不能恢复完整进度。
