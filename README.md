# Story Skill

一套供写作助手使用的中文小说技能，覆盖拆书、开书、正文、改稿、调研、封面与投稿材料准备。支持长篇连载和短篇创作，把大纲、章节、候选稿与写作进度保存在独立书目录中，方便换会话继续。

你用自然语言提出要求，助手按任务调用技能；本地三栏工作台负责阅读、对照和编辑候选稿。

**当前发布版：v0.6.3 · 8 个技能 · Python 3.10+**

## 安装与升级

在支持技能安装的助手中发送：

```text
$skill-installer 按 https://github.com/NingCui29/story-skill/blob/main/INSTALL.md 安装或升级 Story Skill
```

按 [INSTALL.md](INSTALL.md) 核对固定版本、备份已有安装，再安装完整的八个技能目录。只下载一个 `SKILL.md`、克隆源码或取得 npm 包，都不等于完成技能安装。

安装后点名 `$story-skill` 开始使用。仓库更新不会自动升级本机技能；升级技能也不会自动搬动或改写已有小说。图像生成、浏览器和联网调研等能力由宿主应用提供。

## 快速开始

将示例中的 `<…>` 替换成自己的要求和实际路径。不确定入口时，直接用 `$story-skill` 描述目标。

### 1. 开一本新书

```text
$story-skill-plan 开一本番茄女频长篇。
写作父目录：<绝对路径>
题材与核心想法：<你的想法>
预计总篇幅：<目标字数或待定>
单章字数：<目标区间或先讨论>

先确定书名、人物动机、核心冲突、开篇看点与长期推进方向。
在独立书名目录中保存创作约定、开书策划、全书总纲、
分卷规划及前三章细纲，并按平台和长短篇类型填写适用分类。
这轮只做规划，不写正文。
```

也可以改为短篇。规划阶段先确定篇幅、结局与写作范围；只有明确授权正文后，才进入写作。

### 2. 写正文或继续已有书

```text
$story-skill-write 继续 <书目录绝对路径>。
先读取当前断点、前文衔接和本章计划，再完成下一章正文。
每章字数沿用创作约定；通过审查后保存正式章节。
人物行动优先，把尝试、阻力、回应和后果写成场景。
```

如果只想试写，明确说“先写候选稿，暂不采用”。如果是章中续写，说明“接着当前章往下写”，避免把未完成的章节当成新章。

### 3. 审稿与修改

```text
$story-skill-review 审查 <章节或候选稿绝对路径>。
重点看开篇吸引力、人物选择、情绪变化、因果衔接和段落节奏。
在保留核心剧情的前提下，另存一版修改候选，暂不替换正式稿。
```

只想了解问题时说“只审不改”；只排版时说“仅调整段落，不改字词和标点”。采用候选时再明确提出，由审稿流程核对来源、正式版本及后续章节依赖。

### 4. 从拆书开始新起一本书

```text
$story-skill 分析 <参考作品文件绝对路径>，再规划一本原创新书。
写作父目录：<绝对路径>
新书方向：<题材、读者和篇幅>

先核对原文范围，分析人物选择、冲突推进、信息安排和情绪兑现，
用原文支撑判断，提炼可迁移的方法、成立条件与风险。
分析保存到“作品分析/<参考书名>”，原创新书另建书名目录。
重新设计人物、关系、核心事件和解决方式，不做换名改写。
完成开书策划、全书总纲和前三章细纲后停下，本轮不写正文。
```

只点评开篇可以直接粘贴原文；需要完整深读和跨会话续跑时，提供可读取文件及分析保存目录。只取得部分原文，就只分析已取得的部分。[拆书方法与范围](docs/作品深读与评估.md)

## 三栏工作台

对助手说：

```text
$story-skill 打开 <书目录绝对路径> 的工作台。
我要查看细纲、正式章节与候选稿，并能编辑后保存新候选。
```

服务版工作台只在本机运行，提供以下操作：

| 区域 | 可以做什么 |
|---|---|
| 左栏：章节与文件 | 按章查看计划、细纲、正文及候选，或按目录浏览策划、分析与图片 |
| 中栏：阅读与编辑 | 阅读正文、预览大纲排版、编辑候选、查看与正式稿的增删差异 |
| 右栏：当前章节 | 查看目标字数、实际字数、前章衔接、停笔点、版本状态与正式稿审查记录 |

还支持全文搜索、选中文字数、字号与行距调整、专注阅读，以及明确登记后的多书切换。按章号关联只用于导航，不代表某份候选已被采用。

**保存候选不会覆盖正式正文。** 修改会另存新文件；自动恢复帮助找回中断编辑，关闭页面前仍应保存或下载。“审稿”按钮生成可复制的任务，交给助手执行，页面本身不会调用模型或批准稿件。

手动启动时，先查看已有服务，再按需启动：

```bash
python3 -B -X utf8 "<核心技能目录>/scripts/story.py" workbench-status --book "<书目录绝对路径>"
python3 -B -X utf8 "<核心技能目录>/scripts/story.py" workbench-serve --book "<书目录绝对路径>" --open
```

已有服务且代码未过期时复用返回地址。升级前先保存所有页面中的编辑，再停止旧服务并重新启动。`workbench-export` 生成的是只读静态页面，不具备候选编辑功能，也不会随正文变化自动刷新。

## 写作规则与交付

- **人物行动优先。** 用人物的欲望、选择、阻力与后果推动故事，避免用解释、办事流程或记录清单代替场景。
- **关注追读，也保留人物逻辑。** 开篇建立处境和期待，中段发生有效变化，章末留下值得继续阅读的问题或情绪；不为钩子强行反转或让角色降智。
- **按语义分段。** 普通纯文本稿段间空一行，不手工缩进；换人发言默认换段，同一人物紧密相关的动作和短对白可以同段。不按屏幕行数机械拆段。
- **正文与工作材料分开。** 成稿仅保留必要章名和正文，不混入分析、评分、状态卡或创作说明；使用 `.md` 扩展名也不往正文添加 Markdown 排版标记。
- **任务范围明确。** 新写、续写、润色、排版、审校分别处理。字数有硬性要求时实际统计，未完成的内容不称全文完成。

所有正式总纲按作品的长短篇类型及目标平台填写适用分类，并记录选择依据与待复核项；标签依据实际内容选择，不凭空补造平台选项。短篇完本交付还包括以书名命名的全文合并文件、全文审查与封面；封面生成需要可用的图像工具。

## 文件放在哪里

一书一目录。参考作品分析与原创新书分开，小说文件放在技能源码和安装目录之外。

下面是各阶段完成后的目录示意，名称仅用于说明结构；只做规划时不提前生成空正文。

```text
小说/
├── 作品分析/
│   └── 参考书名/
└── 新书书名/
    ├── 创作约定.md
    ├── 00_项目策划/
    │   ├── 开书策划.md
    │   └── 参考方法与原创重建.md
    ├── 01_大纲细纲/
    │   ├── 全书总纲.md
    │   └── 第一卷 卷名/
    │       ├── 本卷大纲.md
    │       └── 第1章 章节名称.md
    ├── chapters/
    │   └── 第一卷 卷名/
    │       └── 第1章 章节名称.md
    └── .story/
        └── drafts/
```

卷目录必须带卷名；章节文件统一为 `第N章 章节名称.md`，章号使用不补零的阿拉伯数字。细纲和正文可同名，分别存放。短篇与单卷作品也要确定卷名。

`.story/` 保存写作状态、草稿与恢复资料。备份时复制整个书目录，只有正文文件不能恢复完整进度。已有工程沿用已记录的路径，不自动批量搬迁。[完整目录规则](docs/目录结构.md)

## 八个技能入口

| 入口 | 适用任务 |
|---|---|
| `$story-skill` | 总入口、跨流程任务与工作台 |
| `$story-skill-plan` | 开书、设定、大纲细纲、接入已有作品 |
| `$story-skill-write` | 新写正文、章中续写与连载 |
| `$story-skill-review` | 审稿、改稿、排版、历史章节修订 |
| `$story-skill-analyze` | 开篇点评、完整深读、分析修订与断点续跑 |
| `$story-skill-research` | 榜单、题材市场与写作素材查证 |
| `$story-skill-cover` | 小说封面生成与修改 |
| `$story-skill-publish` | 七猫、番茄章节的离线投稿材料准备与复核 |

投稿准备使用已审查正式章节，生成材料包并核对所属书与当前版本；也可比较作者提供的草稿副本。**目前不执行平台上传、审核提交或定时发布。** 最终填写与发布由作者在平台后台完成。[投稿材料流程](docs/platform-publishing.md)

`skills/` 是技能源码，`scripts/` 是安装、打包与验证工具，`tests/` 是程序回归测试。本次三章测试篇及旧 `examples` 小说已移出当前仓库，保留本地备份；历史提交和既有标签仍可能包含旧副本。中文事务验收默认使用临时生成的简短合成文本，不把它作为小说质量证据。

在仓库根目录运行：

```bash
python3 -B -X utf8 -m unittest discover -s tests
python3 -B -X utf8 scripts/smoke.py --output dist/manual-smoke.json
python3 -B -X utf8 scripts/chinese_acceptance.py --output dist/manual-chinese.json
python3 -B -X utf8 scripts/package.py
```

工程检查验证程序行为、文件与状态一致性，不能证明作品一定好看或平台审核通过。固定发布版与当前源码的验证范围分别以对应记录为准。[评估方法](docs/evaluation.md)
