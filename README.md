# Story Codex

**从拆书、开书到逐章续写，用自然语言完成中文小说创作。**

Story Codex 是一套面向 Codex 的小说技能。你提供作品、想法和创作要求，它协助分析写法、设计人物与情节、整理大纲细纲、写作和审稿，并保存文件与进度，方便中断后继续。

[安装与升级](#安装与升级) · [拆书怎么用](#拆书怎么用) · [从拆书开始开新书](#从拆书开始新起一本书) · [文件目录](#文件放在哪里) · [完整文档](docs/README.md)

## 安装与升级

在 Codex 对话框发送这一行：

```text
$skill-installer 按 https://github.com/NingCui29/story-skill/blob/main/INSTALL.md 安装或升级 Story Codex
```

Codex 会按指引下载完整套件、核对文件，已有安装先保留旧版和本地修改，再验证安装结果。需要只在某个项目使用时，在请求末尾注明项目路径。安装完成后，在下一条消息点名使用技能；未显示时重启 Codex。

| 平台 | 当前固定安装版本 |
|---|---|
| macOS／Linux | **v0.5.5**，发布附件与固定标签隔离安装已核验 |
| Windows | **v0.4.0**；0.5.x 的正文和报告导出仍有文件占用错误（WinError 32） |

需要 Python 3.10 或更高版本。七个技能须整套安装，专用入口共用核心运行时；联网调研和封面生成使用当前 Codex 环境中可用的工具。只克隆仓库、下载单个 `SKILL.md` 或取得 npm 包，不等于已经安装技能。

升级技能不会自动搬动小说或重新导入书库。已用较新版本处理的书先完整备份，不直接降级。具体安装位置、备份和恢复步骤见 [INSTALL.md](INSTALL.md)。

## 拆书怎么用

拆书的目标是解释：**某个场景为什么有效，它靠什么成立，以及哪些方法能用于自己的作品。** 根据问题选择角度，不必对每一段套同一张表。

| 关注点 | 分析内容 |
|---|---|
| 开篇与阅读期待 | 读者为什么继续读，作品承诺了什么，何时开始兑现 |
| 人物与关系 | 人物想要什么，怎样选择，付出什么代价，关系如何变化 |
| 冲突与反转 | 阻力怎样升级，新信息如何改变此前判断，结果是否有因果支撑 |
| 情绪与节奏 | 哪些过程需要展开，哪些重复消耗注意力，兑现之后留下什么余波 |
| 语言与叙述 | 视角、信息顺序、对白、动作、句式和物件怎样影响理解 |
| 原创借鉴 | 提炼具体操作、成立条件与失败风险，避免照搬人物和事件链 |

### 点评片段

贴出原文，或指定文件及章节范围，再说明关心的问题：

```text
$story-codex-analyze 分析我贴出的开篇。
重点看读者会期待什么、人物选择是否有吸引力、哪些地方解释过多。
请用原文说明判断，直接回复，不建立分析工程。
```

一轮可完成的短文也可以要求直接深读。需要保存进度、跨轮处理或生成可恢复的全量分析时，再使用下面的方式。当前工作区对这两类任务的分流做了进一步修正，尚未进入固定安装版，见[版本与验证](#版本与验证)。

### 完整拆解一本书

准备可读取的原文文件，替换以下占位内容：

```text
$story-codex-analyze 完整深读 <原文文件绝对路径>。
分析保存到 <写作父目录>/作品分析/<参考书名>。

先核对原文范围和目录，再逐段分析并保存证据与进度。
重点解释人物选择、冲突升级、信息安排和情绪兑现。
全书判断要回读相关前后文，区分文本事实、分析推断和阅读感受。
最后给出综合报告，以及可用于原创的写作方法、适用条件和风险。
已有分析进度时从断点继续。
```

原文不全时，报告只覆盖实际取得的内容。网页简介、预览或部分章节不能代替全书；所有导入片段处理完，也不等于已核实全书没有缺章。正文含番外、序章和特殊标题时一并保留。

### 继续分析或修订报告

中断后提供原分析目录和当前任务，例如“继续这本书尚未完成的拆解”。已有来源和记录会沿用，不需重复导入。

需要改报告时，给出原文、旧报告和修改目标。未定稿的分析记录可以按原文修正；已经定稿的报告保留原件，另存修订稿。只有外部分析文档时，也可以直接修订，不必为此建立书库。[深读与修订说明](docs/作品深读与评估.md) · [恢复指南](docs/recovery.md#分析稿修订与续跑)

## 从拆书开始，新起一本书

使用总入口串起 **拆书 → 提炼方法 → 原创策划 → 大纲细纲**。参考分析与原创新书分别保存，参考作品的剧情不会直接成为新书设定。

```text
$story-codex 我想从拆书开始，创作一本新的中文长篇。
参考原文：<原文文件绝对路径>
写作父目录：<新书保存位置>
新书定位：<题材、目标读者、预计篇幅；未确定的注明待定>

请先完成参考作品分析，保存到“作品分析/<参考书名>”。
提炼可迁移的方法、适用条件和风险，形成“参考方法与原创重建”文档。
据此重新设计新书的人物、关系、核心机制、事件链和结局。

确定书名，未定时先拟暂定书名，在写作父目录下建立独立书名目录。
在其中保存创作约定、开书策划、人物与世界设定、全书总纲、
分卷粗纲、首卷大纲和前三章完整细纲，并保存前述方法文档作为策划依据。
卷目录带卷名，章细纲一章一个文件，候选方案与已采用设定分清。
最后交代实际文件位置、已完成范围和下一步。

本轮只完成拆书和原创规划，不写正文。
```

如果只想研究写法，到拆书报告即可结束；如果已有原创构想，可直接开书。“继续”沿用当前任务和授权，不会把“只做规划”自动改成写正文。

## 从开书到续写

下面用《雾港来信》示范。路径需替换为自己的实际位置。

### 1. 建立新书与规划

```text
$story-codex-plan 开一本现实悬疑长篇《雾港来信》。
书目录：<写作父目录>/雾港来信。
先保存创作约定、人物与核心设定、全书走向和分卷粗纲，
再完成首卷卷名、本卷大纲及前三章细纲。暂时不要写正文。
```

新书只指定写作父目录时，会先建立书名子目录；已有作品沿用实际书目录。细纲按本次要求确定范围，未指定时默认细化近期 3—5 章。规划不确定的内容保留候选状态。

### 2. 开始写正文

```text
$story-codex-write 按 <书目录绝对路径> 的已采用细纲写第1章。
先核对创作约定、章计划和人物状态。
正文2200—2800字，含标点、不计标题。
完成审查，保存正文和状态，留下下一步，再停止。
```

之后可以说“继续下一章”，也可以明确要求“连续写完前三章”。每章独立保存，并维护人物认知、关系、物件、资源和伏笔等相关状态。

### 3. 审稿与恢复

```text
$story-codex-review 审查 <书目录绝对路径> 的第1章。
核对人物认知、因果、对白和重复解释，先列问题与修改建议，不直接重写。
```

需要直接修改时，在请求中明确说明。换会话继续时提供书目录；如果手动改过正文，也说明以哪份稿为依据。早期章节改动可能影响后文，需要沿相关内容复核。[详细上手](docs/中文小说上手.md) · [历史修订与恢复](docs/recovery.md)

## 文件放在哪里

**一书一目录，大纲细纲与正文分开。** 下图是逐步形成的示例布局，只做规划时不会提前生成空章。

```text
小说/
├── 作品分析/
│   └── 参考书名/                    # 参考原文的分析与进度
└── 雾港来信/                        # 原创新书
    ├── 创作约定.md
    ├── 设定.md
    ├── 参考方法与原创重建.md
    ├── 01_大纲细纲/
    │   ├── 全书总纲.md
    │   ├── 第一卷 迟到的信/
    │   │   ├── 本卷大纲.md
    │   │   ├── 第1章 雨中来客.md
    │   │   └── 第2章 一封旧信.md
    │   └── 99_历史版本/
    ├── chapters/
    │   └── 第一卷 迟到的信/
    │       ├── 第1章 雨中来客.md
    │       └── 第2章 一封旧信.md
    └── .story/                      # 隐藏的状态与恢复资料
```

- 卷目录必须同时有卷序号和卷名，例如 `第一卷 迟到的信`；短篇和单卷作品也有明确卷名。
- 每章独立成文件，固定命名为 `第N章 章节名称.md`。章号用不补零的阿拉伯数字，如 `第1章 雨中来客.md`。
- 同一范围维护清楚的当前稿入口，旧规划归档；细纲修改后同步对应章计划。
- 备份完整书目录，先等待书籍工具退出。只复制 `chapters/` 无法带走全部状态与恢复资料。

已有等效布局继续沿用；正文的实际路径以保存结果为准，升级不会自动批量搬动旧稿。[完整目录规范](docs/目录结构.md)

## 七个技能入口

不确定选哪个时，用 `$story-codex` 描述目标；任务明确时直接使用专用入口。

| 技能 | 用途 |
|---|---|
| `$story-codex` | 选择和衔接流程，读取共同约束 |
| `$story-codex-analyze` | 开篇点评、完整深读、分析稿修订、断点续跑 |
| `$story-codex-plan` | 开书策划、人物与世界设定、大纲细纲、已有作品续写基线 |
| `$story-codex-write` | 长短篇正文、逐章续写、状态衔接 |
| `$story-codex-review` | 审稿、修改、去 AI 味、外部改稿与历史章节修订 |
| `$story-codex-research` | 榜单与题材调研、写作素材、事实查证 |
| `$story-codex-cover` | 封面构思、生成与修改、文字和尺寸核对 |

## 长篇衔接与作品质量

Story Codex 支持分卷、多故事线、人物认知、物件与资源状态、规则变化、远期伏笔及历史修订。续写前读取本章所需的计划和状态，缺少关键资料时先补齐；前文变化后，复核受影响的后文。

对作品质量的检查落在具体文本上：规划是否回应书名与简介的承诺，人物是否作出有代价的选择，关键场景是否展开，重复解释是否削弱情绪，反转是否有前因。拆书结论也须能回到原文说明依据。

程序检查字数、文件、状态和引文位置；因果是否成立、人物是否可信、作品是否吸引人，仍需读稿判断。现有试用不构成“大师级”认证，也未证明稳定的文学质量提升。[超长篇实操](docs/超长篇实操.md) · [冲突与看点](docs/中文冲突与看点.md) · [评估方法](docs/evaluation.md)
